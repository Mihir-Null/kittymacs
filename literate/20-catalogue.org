- One list says which packages make up which feature, so Elisp, the Nix flake and onboarding cannot disagree.
- [[id:5c1e7a94-8f30-4d26-b7a1-3e92d06f4c18][The features chapter]] decides from it which features are on, and installs their packages.
- Leans on nothing, and must stay that way: =emacs -Q= reads this file before any package exists.

- Each entry is a feature's name and these properties:

| Property        | Says                                                                   |
|-----------------+------------------------------------------------------------------------|
| =:group=        | where onboarding shows it                                              |
| =:packages=     | what it installs, which may be nothing; each package belongs to exactly one feature |
| =:vc=           | which of those its chapter's declaration installs from Git             |
| =:module=       | the chapter's module that declares those packages                      |
| =:profile=      | =minimal= for everyone, =full= for what that profile adds, =optional= for what stays off even then |
| =:deps=         | features it cannot work without                                        |
| =:not-on=       | values of =system-type= where it does not apply                        |
| =:one-of=       | a set of features, named by a symbol, of which at most one is on       |
| =:option=       | a setting that does nothing with the feature off, so setting it alone warns |
| =:experimental= | one sentence, in plain text with no markup: what is still untested     |
| =:hidden=       | =t= for a feature that works and that nothing offers, so it is on only where a setting names it |
| =:summary=      | one sentence: what you get                                             |
| =:example=      | one sentence: how you notice it                                        |

- =minimal= is the default on a new machine, and =full= is what a machine had before that default ([[id:2ea4f7b0-6c19-4d85-93f2-c07a1be58d36][A machine with no choice keeps what it has]]).
- =:not-on= lists exceptions rather than systems, because nearly every feature runs everywhere.
- =:vc= is a subset of =:packages=, so a list of everything stays one property.
- =:one-of= serves features that each want the same keys, such as two coding agents that both take =SPC a=.
  + Every member names the set, so a new member changes only its own entry.
  + [[id:0fb86d27-93c1-4ea5-b2d8-6a1e47c3f9d0][From the options to the answer]] lets a feature you select win over one your profile brings, so selecting a member needs no exclusion of the others.
  + A set has at least two members, and at most one of them is outside =optional=, so a profile alone never brings two.
  + No member depends on another member of its set, because the two could never both be on.
  + The coding agents are its one set: =agents= and the three alternatives that [[id:94d55283-5011-4f98-a7f0-8c6bcb51aab9][Agents]] offers.
  + =claude-code-ide= is outside the set: it takes =SPC a w=, not =SPC a=, so it runs beside whichever agent is on. =agent-claude-code-ide= depends on it, which the rule allows because it is no member.
- =:experimental= marks a feature that works and has not earned the same trust, so a person choosing it can see why.
  + [[id:c8e2f1a7-4b60-49d3-8a15-7d3e96b0c421][Onboarding]] shows it on the feature's row, =SPC o B= names it for a backend whose transport has the feature's name, and the Nix chapter adds it to the feature's option.
  + No start warns about it, because you opted in by name, and =SPC o B= shows it when you look.
  + Those three places read the sentence as it stands, so it holds no markup.
  + No feature has it now, and it stays for the next feature that needs it.
- =:hidden= keeps a feature that the owner chose not to advertise, and did not want to delete, because it still works for whoever set it.
  + [[id:c8e2f1a7-4b60-49d3-8a15-7d3e96b0c421][Onboarding]] lists it on no screen, and keeps it where a =private.el= already selects it.
  + Its keys need no rule of their own: its chapter binds them, and with the feature off that chapter does not load, so the =SPC= menu never shows them.
  + It is =optional= too, so no profile turns on a feature that nobody offered, and the catalogue tests hold that.
  + The Nix chapter keeps its option, because a Nix host sets it by hand as =private.el= does, and onboarding's Nix text names it there.
- The builder writes =nix/features.json= from this list, by reading it and never evaluating it ([[id:d702f35a-3b2f-4cb5-9b4c-c176f0711db0][the builder]]).
- [[file:../tests/kittymacs-catalogue-tests.el][The catalogue tests]] hold it to the code: every declared package appears once, in the feature of the module that declares it.
  + A package added without an entry fails =just test=, which is the point.
  + So does one that its feature's gate does not stop, and a gate that names a feature this list lacks.
