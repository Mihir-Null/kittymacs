#+TITLE: The MSYS2 fallback, for work on Windows-side files
#+FILETAGS: :apps:windows:
#+STARTUP: overview
#+PROPERTY: header-args:emacs-lisp :tangle ../lisp/kittymacs-msys2.el :eval never :comments no :padline no :mkdirp yes

- A WSL2 backend is how native Windows Emacs reaches Unix programs ([[id:3c9e7a52-1d84-4f6b-a0c3-8e5d27b1f96a][a WSL distribution]]), and this chapter is the one exception.
  + A program in WSL that reads files on the Windows side crosses a slow boundary on every read, so a large tree there can ruin performance.
  + For that work, the Unix tools have to run on Windows too.
- The =msys2-fallback= feature is off by default, even under =full=, and the catalogue rules it out everywhere but Windows.
  + With it off, this module does not load, and nothing searches for MSYS2.
  + No other chapter names it: the rest of kittymacs finds what this module puts on =exec-path=, as it finds any other program.
- Turn it on where the profile is set, and keep the line that says where MSYS2 lives, if it is not in =C:/msys64/=.

#+begin_src emacs-lisp :tangle no
(setopt kittymacs-features '(msys2-fallback)
        kittymacs-msys2-root "D:/Tools/msys64/")
#+end_src

* The warning, and what the feature does

- Each start warns once, because a fallback should not come to look like the normal way.
  + It says why a backend is preferred, and when this makes sense.
  + Its type is =(kittymacs msys2-fallback)=, so =warning-suppress-types= can quiet this one alone.
  + It also says when the root holds no MSYS2, since nothing else would.
- It puts =ucrt64/bin= and =usr/bin= last on =exec-path=, and leaves =PATH= alone, so every native program still wins and subprocesses see no change.
  + [[id:afa6b7fd-742a-4c15-86a6-32e3e8027b0e][The spell checker]] then finds =hunspell=, Git for Windows' absence no longer costs =diff=, and Tree-sitter builds find =gcc=.
  + UCRT64 comes first, because a compiler from =usr/bin= builds against the POSIX layer, and a grammar must load into native Emacs.
- It sets =DICPATH= when you have not, since MSYS2's Hunspell looks for its dictionaries there.
- This is the fallback's trigger: opening a file under =/mnt/= through a WSL backend warns that it is slow ([[id:3c9e7a52-1d84-4f6b-a0c3-8e5d27b1f96a][a WSL distribution]]), and that message offers the native file.
  + With the feature on, it adds that this module's tools work there, through =kittymacs-remote-windows-file-note=, so no other chapter names it.
  + With it off, the offer is the native file alone, and this chapter is where to read about the rest.
- =SPC o m= opens an MSYS2 UCRT64 login shell in a terminal, which is why the feature depends on =terminal=.
  + =MSYSTEM= selects the environment and =CHERE_INVOKING= keeps the directory you were in, both for the child process only.
  + It binds ghostel's options with =let=, which works before ghostel has loaded because this module declares them.

#+begin_src emacs-lisp
;;; kittymacs-msys2.el --- The MSYS2 fallback, for work on Windows-side files -*- lexical-binding: t; -*-
;; Generated from literate/37-msys2.org; edit the Org source, then tangle.

;;; Code:

(require 'kittymacs-leader)

;; Without these a `let' would bind them lexically, and ghostel would never see
;; the shell, when the first terminal of a session is this one.
(defvar ghostel-shell)
(defvar ghostel-environment)
(defvar ghostel-buffer-name)
(defvar kittymacs-remote-windows-file-note)
(declare-function ghostel "ghostel" (&optional arg))

(defcustom kittymacs-msys2-root
  (file-name-as-directory (or (getenv "MSYS2_ROOT") "C:/msys64/"))
  "Root directory of the MSYS2 installation on Windows.
It is read only when the `msys2-fallback' feature is on, so setting it alone
does nothing: add that feature to `kittymacs-features' too."
  :type 'directory
  :group 'kittymacs)

(defun kittymacs-msys2--warn ()
  "Say that this is a fallback, why, and when it makes sense."
  (display-warning
   '(kittymacs msys2-fallback)
   (concat
    "msys2-fallback is on.  This is a fallback: a WSL2 backend (`:transport wsl', SPC o b) "
    "is the normal way to reach Unix programs, since they then run on Linux, and Windows "
    "needs no Unix layer of its own.  It makes sense for work on Windows-side files, "
    "where file I/O across WSL would ruin performance."
    (unless (file-directory-p kittymacs-msys2-root)
      (format "  No MSYS2 at %s: set `kittymacs-msys2-root'." kittymacs-msys2-root)))
   :warning))

(defun kittymacs-msys2-apply ()
  "Warn, and offer MSYS2's programs to this Emacs, after every other."
  (kittymacs-msys2--warn)
  (dolist (directory '("ucrt64/bin" "usr/bin"))
    (add-to-list 'exec-path (expand-file-name directory kittymacs-msys2-root) t))
  (let ((dictionaries (expand-file-name "ucrt64/share/hunspell" kittymacs-msys2-root)))
    (when (and (not (getenv "DICPATH")) (file-directory-p dictionaries))
      (setenv "DICPATH" dictionaries))))

(defun kittymacs-terminal-msys2 (&optional arg)
  "Open an MSYS2 UCRT64 login shell in a terminal.
With prefix ARG, create another one instead of reusing the existing buffer."
  (interactive "P")
  (unless (eq system-type 'windows-nt)
    (user-error "The MSYS2 terminal is for native Windows Emacs"))
  (let ((bash (expand-file-name "usr/bin/bash.exe" kittymacs-msys2-root)))
    (unless (file-executable-p bash)
      (user-error "MSYS2 Bash not found at %s; set `kittymacs-msys2-root' in private.el"
                  bash))
    (let ((ghostel-shell (list bash "--login" "-i"))
          (ghostel-environment (append '("MSYSTEM=UCRT64" "CHERE_INVOKING=1")
                                       ghostel-environment))
          (ghostel-buffer-name "*ghostel: msys2*"))
      (ghostel arg))))

(keymap-set kittymacs-open-map "m" (cons "MSYS2 terminal" #'kittymacs-terminal-msys2))
(setq kittymacs-remote-windows-file-note "MSYS2's tools work on it there, and SPC o m is its shell.")

(kittymacs-msys2-apply)

(provide 'kittymacs-msys2)
;;; kittymacs-msys2.el ends here
#+end_src

* Check

- With the feature off, =M-: (featurep 'kittymacs-msys2)= is =nil=, and =SPC o m= is unbound.
- With it on, a start warns once, and =SPC o m= opens a UCRT64 shell.
- With it on, =C-x C-f /wslm:DISTRIBUTION:/mnt/c/Windows/win.ini= warns too, and says the shell and tools are here.
- =M-: (executable-find "hunspell")= names the one under the root, unless a native one comes first.
- =just test= runs [[file:../tests/kittymacs-msys2-tests.el][the fallback's tests]] on any machine, and =just test-features= starts with it on, as if on Windows.
