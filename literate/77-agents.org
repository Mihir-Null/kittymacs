#+TITLE: Agents: a coding agent in a buffer
#+FILETAGS: :apps:
#+STARTUP: overview
#+PROPERTY: header-args:emacs-lisp :tangle ../lisp/kittymacs-agents.el :eval never :comments no :padline no :mkdirp yes

- A coding agent you talk to in Emacs: =SPC a a= opens one in the current project, and a change it wants to make waits for your answer.
- Four packages can be that agent, and one is on at a time, so =SPC a= always means the one you chose.
  + [[*Four agents, one at a time]] has the rule and the keys.
  + =agents= is [[https://github.com/xenodium/agent-shell][agent-shell]], with [[https://github.com/ultronozm/agent-shell-attention.el][agent-shell-attention]] as its doorbell: Claude Code in a buffer of its own.
  + =agent-claude-code-ide=, =agent-eca= and =agent-gptel= are the alternatives.
- =claude-code-ide= runs beside whichever agent is on: Claude Code's own screen, its sessions under =SPC a w= ([[*claude-code-ide: Claude Code's own screen]]).
  + With =agents=, you can talk to Claude in agent-shell and keep other sessions in Claude Code's own screen.
- What Claude itself may do lives outside Emacs, in =~/.claude/settings.json=, so the command line and this buffer share it ([[*What lives in Emacs, and what does not]]).
- Leans on [[id:e5942eb0-4389-447d-9317-d9178adcaaae][the leader]] for =SPC m= and the =SPC a= group, on [[id:d2e0bc37-0bd4-4b28-a8ee-04f94ac451f8][the shells chapter]] for the login environment, and on [[id:5c1e7a94-8f30-4d26-b7a1-3e92d06f4c18][the features chapter]] for the gates.
- [[id:40302e33-d2b2-4c0b-9bc3-1f9e121307e1][=init.el=]] loads this chapter when any of the four, or =claude-code-ide=, is on, and each section below runs only for its own.
- Code outside kittymacs builds on a few names here: [[*What an integration may rely on]].
- Read [[*How agent-shell talks to Claude]] first.

* Four agents, one at a time :decision:
:PROPERTIES:
:ID: 12165e78-6e8d-4b49-bf80-e3bf7ff1cf24
:END:

- Each agent takes =SPC a=, so two could never both be on: the catalogue puts them in one =:one-of= set, =agent=.
  + =full= brings =agents=; selecting an alternative replaces it, with no exclusion to write and no warning.
  + Onboarding shows the four as a radio button: turning one on turns the others off.
  + [[id:3f8a6c02-9d14-4b7e-a2c5-1e7d90b64f31][The catalogue]] and [[id:0fb86d27-93c1-4ea5-b2d8-6a1e47c3f9d0][From the options to the answer]] have the rule.
- One owns =SPC a=, but not every agent is one of them: =claude-code-ide= takes =SPC a w= and runs beside whichever is on.

| Feature                 | Package                            | The agent                                       | It signs in with                  |
|-------------------------+------------------------------------+-------------------------------------------------+-----------------------------------|
| =agents=                | agent-shell, from Git, pinned      | Claude Code, through ACP, in an Emacs buffer    | your Claude login                 |
| =agent-claude-code-ide= | claude-code-ide, from Git, via =claude-code-ide= | Claude Code's own screen, in a terminal buffer  | your Claude login                 |
| =agent-eca=             | eca, from MELPA                    | the =eca= server, with any provider             | a provider ECA asks you for       |
| =agent-gptel=           | gptel and gptel-agent, from MELPA  | Emacs Lisp, with the model you set              | an API key, or a local model      |

- The keys are the same for every agent wherever it has the command, so changing agent changes nothing you type:

| =SPC a= | Does                     | agents | claude-code-ide | eca | gptel |
|---------+--------------------------+--------+-----------------+-----+-------|
| =a=     | start, or switch to it   | yes    | yes             | yes | yes   |
| =n=     | a new session            | yes    | yes             | yes | yes   |
| =t=     | show or hide it          | yes    | yes             | yes |       |
| =b=     | pick a session           | yes    | yes             | yes |       |
| =r=     | resume a past session    | yes    | yes             | yes |       |
| =s=     | send the region or file  | yes    | yes             | yes | yes   |
| =f=     | send a file              | yes    |                 | yes | yes   |
| =j=     | jump to one waiting      | yes    |                 | yes |       |
| =p=     | send a prompt            |        | yes             |     | yes   |
| =i=     | interrupt                |        | yes             |     | yes   |
| =?=     | the menu of commands     | yes    | yes             | yes | yes   |

- A key an agent lacks stays unbound rather than doing something else, so =SPC a= shows only what works.
- =SPC a w= is not in the table: it belongs to =claude-code-ide=, which runs beside any of the four.
- =SPC a c= is not here: [[id:0b43a1e9-2e16-4d5b-985d-342c4897634f][the suggestions chapter]] owns it, for Copilot at point, whichever agent is on.
- agent-shell and ECA interrupt from =SPC m=, inside their buffers. claude-code-ide's is a terminal and gptel's is a plain Org or Markdown buffer, and neither has a mode of its own for =SPC m=, so =SPC a i= does it.

* How agent-shell talks to Claude :concept:
:PROPERTIES:
:ID: 3645870f-b154-4dfd-9085-de3570e0c61e
:END:

- The /Agent Client Protocol/ (ACP) is JSON over a pipe between an editor and a coding agent, the way LSP is between an editor and a language server.
  + The editor sends prompts and answers permission requests; the agent streams text, tool calls and proposed edits.
  + One editor package then speaks to any agent with an adapter: Claude Code, Gemini CLI, Codex and others.
- Three processes, three jobs:

| Piece              | Is                                                         | Comes from                    |
|--------------------+------------------------------------------------------------+-------------------------------|
| agent-shell        | the Emacs buffer and the ACP client                        | MELPA, here                   |
| =claude-agent-acp= | the adapter: ACP on one side, the Claude Agent SDK on the other | your package manager |
| =claude=           | Claude Code itself, which the SDK runs                     | your package manager          |

- agent-shell starts =claude-agent-acp= as a subprocess, one per shell buffer, in the project's root.
- The adapter loads what the =claude= command line loads: =~/.claude/settings.json=, =CLAUDE.md= files, skills and hooks, user-wide and per project.

* Claude Code, through your subscription :decision:
:PROPERTIES:
:ID: e021fb07-ea2e-4dcd-b312-cabe45da9869
:END:

- agent-shell's defaults already fit, so they are not restated here:
  + =agent-shell-anthropic-authentication= is =(:login t)=: use the login =claude= stored, not an API key;
  + =agent-shell-anthropic-claude-acp-command= is =("claude-agent-acp")=, found on =exec-path=.
  + Log in once in a terminal (=claude=, then =/login=); on macOS the token lives in the Keychain.
- Agent output is kept cheap, because a reply streams into one buffer on the main thread:
  + activity groups start collapsed, source blocks are not highlighted, and the header is text rather than an SVG;
  + the busy animation stays on: it is the only sign in the buffer that an agent is still working.
- Two more settings differ from the defaults:
  + =agent-shell-preferred-agent-config= is =claude-code=, so =SPC a a= starts Claude without asking which agent;
  + the adapter inherits Emacs's environment.
- Why inherit: agent-shell otherwise starts the adapter with an almost empty environment.
  + A Dock-launched Emacs on macOS has only the =PATH= [[id:d2e0bc37-0bd4-4b28-a8ee-04f94ac451f8][the shells chapter]] imported, and the adapter, its MCP servers and every command Claude runs need that same =PATH=.
  + Behind a corporate proxy it also carries the proxy and certificate variables, without which nothing reaches the network.
  + The environment is copied once, when agent-shell first loads (the first =SPC a=), after the shells chapter's import; a change to it needs a restart of Emacs.
- Per-project state goes in =.agent-shell/= at the project root: transcripts (with the session ID, model and folder in their header) and screenshots; agent-shell adds it to =.gitignore= itself.
- agent-shell and acp.el, its protocol library, install from Git, each pinned to a commit tested with Claude's adapter, rather than from MELPA, which follows each one's latest commit.
  + agent-shell at =14e8e2a= (its source says 0.94.1), acp.el at =2959da5= (0.18.2).
  + A pin holds on a fresh install. A copy MELPA installed earlier stays until it is deleted (=M-x package-delete=, then a restart), because =use-package= installs only what is missing.
  + With Nix, both leave the package list, as every =:vc= package does, and install from Git on the first start.
- Claude's questions to you, its =AskUserQuestion= tool, arrive as a form in the shell only with =agent-shell-elicitation--experimental-feature-enabled= set.
  + The name says it: the switch is private and experimental, and a later agent-shell may rename or drop it.
  + It is on because without it agent-shell does not offer the form, so Claude cannot ask you anything mid-turn.

#+begin_src emacs-lisp
(when (kittymacs-feature-p 'agents)
  (condition-case err
      (progn
        (use-package acp
          :vc (:url "https://github.com/xenodium/acp.el"
               :rev "2959da5fa8657da17a78ac6ceef303a50e3e69de")
          :defer t)
        (use-package agent-shell
          :vc (:url "https://github.com/xenodium/agent-shell"
               :rev "14e8e2a2f2b495f83c9d7b18be7838e45d75bf56")
          :commands (agent-shell agent-shell-toggle agent-shell-new-shell agent-shell-switch-buffer
                     agent-shell-resume-session agent-shell-send-dwim agent-shell-send-file
                     agent-shell-help-menu)
          :init
          ;; Private and experimental: without it agent-shell offers no form,
          ;; so Claude's AskUserQuestion never reaches you.
          (setq agent-shell-elicitation--experimental-feature-enabled t)
          :custom
          (agent-shell-preferred-agent-config 'claude-code)
          (agent-shell-activity-group-expand-by-default nil)
          (agent-shell-highlight-blocks nil)
          (agent-shell-header-style 'text)
          :config
          (setopt agent-shell-anthropic-claude-environment
                  (agent-shell-make-environment-variables :inherit-env t))))
    (error
     (kittymacs-features-vc-warning "agent-shell" "https://github.com/xenodium/agent-shell" err)))

  (when (locate-library "agent-shell")
    (keymap-set kittymacs-agent-map "a" (cons "start or switch" #'agent-shell))
    (keymap-set kittymacs-agent-map "n" (cons "new shell" #'agent-shell-new-shell))
    (keymap-set kittymacs-agent-map "t" (cons "toggle" #'agent-shell-toggle))
    (keymap-set kittymacs-agent-map "b" (cons "switch shell" #'agent-shell-switch-buffer))
    (keymap-set kittymacs-agent-map "r" (cons "resume session" #'agent-shell-resume-session))
    (keymap-set kittymacs-agent-map "s" (cons "send region or file" #'agent-shell-send-dwim))
    (keymap-set kittymacs-agent-map "f" (cons "send a file" #'agent-shell-send-file))
    (keymap-set kittymacs-agent-map "?" (cons "menu" #'agent-shell-help-menu))))

#+end_src

- The environment is set in =:config=, not =:custom=: =agent-shell-make-environment-variables= is a function of the package, and only exists once it has loaded.
- The keys go in =SPC a=, each one a command =:commands= declares, so the first key press loads agent-shell.
  + Until agent-shell installs, they stay unbound, and a failed clone is a warning, as for every package here from Git.

* What lives in Emacs, and what does not :decision:
:PROPERTIES:
:ID: 5cf88d37-2e87-4451-989c-b957aa817990
:END:

- The agent's policy belongs to the agent, not to the editor: the same rules must hold whether Claude runs here or in a terminal.
  + So permissions, the output style, commit attribution and the skills live in =~/.claude=, written by you or by the machine's configuration, never here.
- This chapter holds only what is about Emacs: the buffers, the keys and the notifications.
- agent-shell and claude-code-ide both run the =claude= command line, so =~/.claude= governs both.
  + agent-shell runs it through =claude-agent-acp=, and claude-code-ide runs =claude= itself; each must be on =PATH=.
- ECA and gptel-agent are agents of their own, so =~/.claude= does not reach them.
  + ECA keeps its rules in its own configuration, which =M-x eca-open-global-config= opens.
  + gptel-agent asks before every tool that changes a file or runs a command, and its presets live in Emacs.
  + This chapter changes neither's rules: choosing one of them means choosing its rules too.

* MCP servers: none until you declare them
:PROPERTIES:
:ID: b9a2367d-e31a-4a30-a5e8-3ad200e4e40b
:END:

- An MCP server gives the agent tools it does not have, such as a library's documentation or a search engine for papers.
- Which servers to run is your choice or your host's, so =kittymacs-agent-mcp-servers= is empty by default.
- Declared, never ambient: a session starts with exactly this list, and no project's =.mcp.json= adds to it unless you approve that server.
- Set it at top level in =private.el= or a host file, which both load before this module reads it. Each element has the shape =agent-shell-mcp-servers= documents:

#+begin_src emacs-lisp :tangle no
(setopt kittymacs-agent-mcp-servers
        `(((name . "docs")
           (command . "docs-mcp")
           (args . ())
           (env . ()))
          ((name . "search")
           (type . "http")
           (url . "https://example.com/mcp/v1")
           (headers . ,(lambda () (my-search-headers))))))
#+end_src

- agent-shell finds a =command= on =PATH=, so your package manager can pin it and nothing downloads when a session starts.
- =headers= may be a =lambda=, which agent-shell calls as each session starts, so a key added to =auth-source= later reaches the next shell.
- The list reaches agent-shell alone.
  + claude-code-ide's Claude reads its servers from =~/.claude=, as the command line does.
  + ECA reads them from its own configuration, and =M-x eca-mcp-toggle-server= starts and stops them.
- An empty list leaves =agent-shell-mcp-servers= alone, so setting that option directly still works.
- A list set while agent-shell is off warns at startup, because the catalogue names it as =agents='s =:option=.
  + A host that moves to another agent then sees the setting it no longer needs.

#+begin_src emacs-lisp
(defcustom kittymacs-agent-mcp-servers nil
  "MCP servers every agent-shell session starts with.
Each element has the shape `agent-shell-mcp-servers' documents.  Set this
before this module loads, in `private.el' or a host file."
  :type '(repeat sexp)
  :group 'kittymacs)

(when (and (kittymacs-feature-p 'agents) kittymacs-agent-mcp-servers)
  (setopt agent-shell-mcp-servers kittymacs-agent-mcp-servers))

#+end_src

* Knowing when a shell waits for you
:PROPERTIES:
:ID: 56789f7f-90bb-4c3b-947c-16ecb6d72365
:END:

- An agent works for minutes, then stops to ask permission or to say it is done; that moment is easy to miss in another frame.
- =agent-shell-attention-mode= adds =AS:n= to the mode line: the number of shells waiting for you.
  + =SPC a j= jumps to the next one; =SPC a d= lists every shell and its state.
- Its notification function, =kittymacs-agent-notify=, also tells the desktop:
  + macOS: =osascript='s =display notification=, which needs nothing installed;
  + Linux: =notifications-notify=, over D-Bus; where there is no D-Bus session (some WSL setups), it stays silent rather than signal an error.
- A question Claude asks you as a form, its =AskUserQuestion= tool, waits for you as much as a permission does, but agent-shell-attention counts only permissions and finished turns.
  + So this chapter counts the forms too: agent-shell announces each form (=elicitation-request=) and each answer, refusal or cancellation (=elicitation-response=), and the shell is marked waiting from the one to the other, with the question as its label.
  + Clearing goes through =agent-shell-attention-acknowledge=, public since 0.0.4; marking has no public function, so it calls =agent-shell-attention--mark-buffer=, guarded by =fboundp=.
  + The desktop hears of it when the shell is not the buffer in front of you.
- Not on MELPA, so it is installed from its Git repository with =:vc=, pinned to a commit: 0.0.4, which made =-unread-p= and =-acknowledge= public.
  + =M-x package-vc-upgrade= moves it; change =:rev= here to move everyone.
- Installing it runs =git clone= on the first start, so it can fail where an archive install would not: no network, a proxy =git= is not told about, or a =git= that is not the one you expect.
  + A failed install is a warning, not an error: =use-package= would otherwise stop =init.el= there, and every chapter after this one would go unloaded.
  + The warning names the cause and the =git= Emacs found; once =git clone= of the repository works from a terminal, a restart installs it. Until then =SPC a j= and =SPC a d= stay unbound, and the rest of the chapter works.
- [[id:5905ac12-61c1-4c8e-97fa-3eff8f2bee50][The one warning for a Git install]] writes that warning, for agent-shell's and claude-code-ide's installs as well, and names the directory instead when an earlier install stopped partway.
- A key whose package did not install stays unbound, so which-key offers nothing that would fail when pressed.
  + =locate-library= finds the package wherever it came from: =package-vc=, an archive, or a Nix build.

#+begin_src emacs-lisp
(defun kittymacs-agent-notify (_buffer title body)
  "Show a desktop notification with TITLE and BODY.
The value of `agent-shell-attention-notify-function'."
  (pcase system-type
    ('darwin
     (call-process "osascript" nil 0 nil "-e"
                   (format "display notification %S with title %S" body title)))
    (_
     (when (require 'notifications nil t)
       (ignore-errors
         (notifications-notify :app-name "agent-shell" :title title :body body))))))

(defun kittymacs-agent--question-event (buffer event)
  "Count a question form in BUFFER as waiting, from EVENT, until it is answered."
  (pcase (map-elt event :event)
    ('elicitation-request
     (let ((label (concat "Question: " (or (map-elt (map-elt event :data) :message) ""))))
       (when (fboundp 'agent-shell-attention--mark-buffer)
         (agent-shell-attention--mark-buffer buffer label :force t))
       (unless (eq (window-buffer (selected-window)) buffer)
         (kittymacs-agent-notify buffer (format "%s agent" (buffer-name buffer)) label))))
    ('elicitation-response
     (when (fboundp 'agent-shell-attention-acknowledge)
       (agent-shell-attention-acknowledge buffer)))))

(defun kittymacs-agent-watch-questions ()
  "Let this agent-shell buffer's question forms count as waiting."
  (let ((buffer (current-buffer)))
    (agent-shell-subscribe-to
     :shell-buffer buffer
     :on-event (lambda (event)
                 (when (buffer-live-p buffer)
                   (kittymacs-agent--question-event buffer event))))))

(when (kittymacs-feature-p 'agents)
  (condition-case err
      (use-package agent-shell-attention
        :vc (:url "https://github.com/ultronozm/agent-shell-attention.el"
             :rev "8d5116f174fc35177aedc0f967a8fa3d6784aa1b")
        :after agent-shell
        :demand t
        :custom
        (agent-shell-attention-notify-function #'kittymacs-agent-notify)
        :config
        (agent-shell-attention-mode 1))
    (error
     (kittymacs-features-vc-warning "agent-shell-attention"
                                    "https://github.com/ultronozm/agent-shell-attention.el" err)))

  (when (locate-library "agent-shell-attention")
    (keymap-set kittymacs-agent-map "j" (cons "jump to waiting shell" #'agent-shell-attention-jump))
    (keymap-set kittymacs-agent-map "d" (cons "all shells" #'agent-shell-attention-dashboard))
    (add-hook 'agent-shell-mode-hook #'kittymacs-agent-watch-questions)))

#+end_src

* Meow in the agent's buffers :meow:
:PROPERTIES:
:ID: 51ae9070-0971-48c1-9625-283891d48d73
:END:

- The shell starts in Insert: it is a prompt, like [[id:d2e0bc37-0bd4-4b28-a8ee-04f94ac451f8][the shells]].
  + =ESC= to Normal selects in the transcript with Meow's grammar; =SPC m= then lists the shell's commands.
  + A permission prompt names its keys on its buttons: =y= allows once, =!= always, and the interrupt key rejects.
- The diff of a proposed edit starts in Motion: its own keys are the interface (=y= accept, =C-c C-c= reject, =n= / =p= hunks, =q= close).
- The viewport, agent-shell's optional two-buffer layout, starts in Motion to read and Insert to write.
- The transcript of a shell is a Markdown file under =.agent-shell/=; =SPC m t= opens it, and its header names the session.

| =SPC m= | Does                    | =SPC m= | Does                       |
|---------+-------------------------+---------+----------------------------|
| =i=     | interrupt the agent     | =f=     | send a file                |
| =m=     | next permission mode    | =y=     | copy the last reply        |
| =M=     | choose the model        | =t=     | open the transcript        |
| =c=     | compose a long prompt   | =r=     | restart the shell          |
| =?=     | every command (menu)    |         |                            |

#+begin_src emacs-lisp
(when (kittymacs-feature-p 'agents)

      (add-to-list 'meow-mode-state-list entry)))

    "i" (cons "interrupt" #'agent-shell-interrupt)
    "m" (cons "next permission mode" #'agent-shell-cycle-session-mode)

    "c" (cons "compose prompt" #'agent-shell-prompt-compose)
    "f" (cons "send file" #'agent-shell-send-file)
    "y" (cons "copy last reply" #'agent-shell-copy-last-output)

* claude-code-ide: Claude Code's own screen
:PROPERTIES:
:ID: 9fccd657-dc0b-4ad1-99a2-d7615024f438
:END:

- [[https://github.com/manzaltu/claude-code-ide.el][claude-code-ide]] runs the =claude= command line itself, in a terminal buffer, so you get Claude Code's own screen rather than an Emacs rendering of it.
- It also answers Claude's IDE protocol, the one Claude Code speaks to editors:
  + Claude sees the file and selection in front of you, and the diagnostics of the files it touches;
  + a proposed edit opens in Ediff, where you can change it before you accept it.
- The terminal is [[id:bd2638bc-735d-4849-bafe-3dab5e8e30b7][ghostel]], which upstream recommends for Claude's screen, so the feature needs =terminal=.
  + The terminal chapter's key passing applies: the screen gets its keys, and Meow keeps =SPC=.
- =claude-code-ide-emacs-tools-setup= gives Claude five tools that read Emacs: references and definitions through xref, the symbols in a file through Imenu, the tree-sitter node at a point, and the project's root and files.
- The IDE protocol adds =executeCode=, on by default: Claude evaluates any Emacs Lisp in this Emacs, and can write in your buffers with it.
  + Whether a call runs without asking is Claude's permission setting in =~/.claude=, not this chapter's ([[*What lives in Emacs, and what does not]]).
- Not on MELPA, so it installs from Git, pinned to a commit, with the warning [[*Knowing when a shell waits for you][agent-shell-attention]] uses if =git clone= fails.
  + Until it installs, its =SPC a= keys stay unbound, as agent-shell-attention's do.
- Its start command always opens a new instance, so =SPC a a= switches to this project's instance and starts one only where there is none.
- Two features share it:
  + =claude-code-ide= installs it beside whichever agent owns =SPC a=, and puts its session keys in =kittymacs-claude-code-ide-map=, on =SPC a w=;
  + =agent-claude-code-ide= makes it the agent on lowercase =SPC a= too, and depends on =claude-code-ide=, so the package is configured once.
- =SPC a w=, claude-code-ide sessions: =n= a new instance, =b= pick one, =p= send it a prompt, =i= interrupt it (=ESC=), =r= resume a past one.

* ECA: one agent, any provider
:PROPERTIES:
:ID: 07ce1d75-ea11-42dc-99e6-64e476315ea1
:END:

- [[https://github.com/editor-code-assistant/eca-emacs][ECA]] is a coding agent with a server of its own, =eca=, and a client for each editor; this is Emacs's client.
- The server speaks to many providers: Anthropic, OpenAI, GitHub Copilot, Ollama and others.
  + It signs in through the chat: =/login= there, then the provider it asks for.
- The server comes from =PATH= first, so a package manager can pin it.
  + Without one there, ECA downloads its release from GitHub on the first =SPC a a=, as Copilot's chapter does for its server.
  + The download lands under the cache directory, beside Copilot's, rather than in =~/.emacs.d=.
  + On x86-64 Linux the release is a static binary, so it runs on NixOS too.
  + On ARM Linux it links against the system's libraries, which NixOS does not have where a downloaded binary looks; there, install =eca= yourself or enable =programs.nix-ld=.
- Its chat buffer is a prompt, so it starts in Insert, as agent-shell's does.
  + A chat waiting on you shows in the chat list, and =SPC a j= goes to the next one, across projects.

| =SPC m= | Does                     | =SPC m= | Does                       |
|---------+--------------------------+---------+----------------------------|
| =i=     | stop the reply           | =y=     | accept the next tool call  |
| =m=     | next agent               | =x=     | reject the next tool call  |
| =M=     | choose the model         | =Y=     | accept every waiting call  |
| =?=     | the menu of commands     |         |                            |

* gptel-agent: an agent written in Emacs Lisp
:PROPERTIES:
:ID: 99f6054d-a275-4def-bb12-98d09ce66070
:END:

- [[https://github.com/karthink/gptel-agent][gptel-agent]] is a set of tools and prompts for [[https://github.com/karthink/gptel][gptel]], the model client; no program runs outside Emacs.
  + It reads, searches and edits files, and runs commands, asking you first for each tool that changes something.
  + Its header line switches between agent and plan, where plan has only the tools that read.
- It talks to whichever model you give gptel, so it works offline with a local one.
  + It cannot use a Claude or ChatGPT login: Anthropic and OpenAI give an agent that is not their own an API key, not a subscription.
- This chapter sets no model, because which one is yours to pay for or to run.
  + Without a setting, gptel uses OpenAI and asks for a key, so set one of these in =private.el=:

#+begin_src emacs-lisp :tangle no
;; Anthropic, with the key in ~/.authinfo.gpg on the line
;; "machine api.anthropic.com login apikey password <the key>".
(with-eval-after-load 'gptel
  (setq gptel-backend (gptel-make-anthropic "Claude" :stream t)
        gptel-model 'claude-sonnet-5-5))

;; A model Ollama runs on this machine, with no key.
(with-eval-after-load 'gptel
  (setq gptel-backend (gptel-make-ollama "Ollama" :stream t :models '(qwen3-coder))
        gptel-model 'qwen3-coder))
#+end_src

- gptel reads the key from =auth-source= when a request starts, so the key never sits in =private.el=.
- gptel-agent opens a new buffer each time, so =SPC a a= switches to this project's buffer and starts one only where there is none.
- Its buffer is an Org or Markdown buffer with =gptel-mode= on, a minor mode, so =SPC m= stays the buffer's own and =SPC a p= sends.

#+begin_src emacs-lisp
(defun kittymacs-agent-gptel-start-or-switch ()
  "Switch to this project's gptel-agent buffer, or start one where there is none."
  (interactive)
  (let ((root (expand-file-name (if-let* ((project (project-current)))
                                    (project-root project)
                                  default-directory))))
    (if-let* ((buffer (seq-find (lambda (buffer)
                                  (and (string-prefix-p "*gptel-agent:" (buffer-name buffer))
                                       (equal (expand-file-name
                                               (buffer-local-value 'default-directory buffer))
                                              root)))
                                (buffer-list))))
        (pop-to-buffer buffer)
      (gptel-agent root))))

(when (kittymacs-feature-p 'agent-gptel)
  (use-package gptel
    :ensure t
    :commands (gptel gptel-send gptel-menu gptel-add gptel-add-file gptel-abort))

  (use-package gptel-agent
    :ensure t
    :commands (gptel-agent))

  (keymap-set kittymacs-agent-map "a" (cons "start or switch" #'kittymacs-agent-gptel-start-or-switch))
  (keymap-set kittymacs-agent-map "n" (cons "new agent" #'gptel-agent))
  (keymap-set kittymacs-agent-map "s" (cons "add region or buffer" #'gptel-add))
  (keymap-set kittymacs-agent-map "f" (cons "add a file" #'gptel-add-file))
  (keymap-set kittymacs-agent-map "p" (cons "send" #'gptel-send))
  (keymap-set kittymacs-agent-map "i" (cons "interrupt" #'gptel-abort))
  (keymap-set kittymacs-agent-map "?" (cons "menu" #'gptel-menu)))

(provide 'kittymacs-agents)

* What an integration may rely on :decision:
:PROPERTIES:
:ID: 4b8d2e61-9c37-4f05-a1e8-6d3b7c0f2a95
:END:

- Code outside kittymacs, such as a Claude stack that adds its own agent workflow, loads from =conf.d= ([[id:40302e33-d2b2-4c0b-9bc3-1f9e121307e1][startup]]) and builds on these names, kept stable:
  + =kittymacs-agent-map=: the keymap on =SPC a=;
  + =kittymacs-claude-code-ide-map=: claude-code-ide's sessions on =SPC a w=, where =w=, =d= and =j= are left free;
  + =(kittymacs-agent-notify BUFFER TITLE BODY)=: a desktop notification, on macOS or over D-Bus, silent where there is none;
  + =(kittymacs-feature-p FEATURE)=: whether a catalogue feature is on;
  + =(kittymacs-diff-review-at HOST DIRECTORY BRANCH)=: a branch's review, here or over TRAMP ([[id:3f0450b0-881e-4487-b90f-49a4d03f17a7][version control]]);
  + the features =kittymacs-agents= and =kittymacs-vc=, to wait for with =with-eval-after-load=.
- Anything else here may change without notice.

* Check

- For =agents= or =agent-claude-code-ide=, once, in a terminal: =claude=, then =/login=.
- =SPC a a= in a project: the agent you chose opens, in Insert for agent-shell and ECA, and in the terminal for claude-code-ide.
- Ask it to read a file: the read happens; ask it to change one: it asks first, and agent-shell's diff opens in Motion with =y= to accept, claude-code-ide's in Ediff.
- Ask "which MCP tools do you have?": for agent-shell, the servers in =kittymacs-agent-mcp-servers= plus any your Claude configuration adds; for claude-code-ide, the five Emacs tools as well.
- With agent-shell, switch frames while it works: the mode line shows =AS:1= when it stops, and the desktop shows a notification.
- Select a different agent in onboarding: the one before turns off, and =SPC a= shows the new one's keys.
- In agent-shell, ask Claude to ask you something with its question tool: a form appears in the shell, =AS:1= shows while it waits, and it clears once you answer or decline.
- With =agents= and =claude-code-ide= both on: =SPC a a= opens agent-shell, =SPC a w n= a claude-code-ide instance, =SPC a w b= picks one, and =SPC a j= and =SPC a d= stay agent-shell-attention's.
- =just test-packages=: the verifier fails on any warning at startup, and checks that every =SPC= key runs a command.
