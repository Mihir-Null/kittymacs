#+TITLE: Agents: a coding agent in a buffer
#+FILETAGS: :apps:
#+STARTUP: overview
#+PROPERTY: header-args:emacs-lisp :tangle ../lisp/kittymacs-agents.el :eval never :comments no :padline no :mkdirp yes

- A coding agent you talk to in Emacs: =SPC a a= opens one in the current project, and a change it wants to make waits for your answer.
- Four packages can be that agent, and one is on at a time, so =SPC a= always means the one you chose.
  + [[*Four agents, one at a time]] has the rule and the keys.
  + =agents= is [[https://github.com/xenodium/agent-shell][agent-shell]], with [[https://github.com/ultronozm/agent-shell-attention.el][agent-shell-attention]] as its doorbell: Claude Code in a buffer of its own.
  + =agent-claude-code-ide=, =agent-eca= and =agent-gptel= are the alternatives.
- What Claude itself may do lives outside Emacs, in =~/.claude/settings.json=, so the command line and this buffer share it ([[*What lives in Emacs, and what does not]]).
- Leans on [[id:e5942eb0-4389-447d-9317-d9178adcaaae][the leader]] for =SPC m= and the =SPC a= group, on [[id:d2e0bc37-0bd4-4b28-a8ee-04f94ac451f8][the shells chapter]] for the login environment, and on [[id:5c1e7a94-8f30-4d26-b7a1-3e92d06f4c18][the features chapter]] for the gates.
- [[id:40302e33-d2b2-4c0b-9bc3-1f9e121307e1][=init.el=]] loads this chapter when any of the four is on, and each section below runs only for its own.
- Read [[*How agent-shell talks to Claude]] first.

* Four agents, one at a time :decision:
:PROPERTIES:
:ID: 12165e78-6e8d-4b49-bf80-e3bf7ff1cf24
:END:

- Each agent takes =SPC a=, so two could never both be on: the catalogue puts them in one =:one-of= set, =agent=.
  + =full= brings =agents=; selecting an alternative replaces it, with no exclusion to write and no warning.
  + Onboarding shows the four as a radio button: turning one on turns the others off.
  + [[id:3f8a6c02-9d14-4b7e-a2c5-1e7d90b64f31][The catalogue]] and [[id:0fb86d27-93c1-4ea5-b2d8-6a1e47c3f9d0][From the options to the answer]] have the rule.

| Feature                 | Package                            | The agent                                       | It signs in with                  |
|-------------------------+------------------------------------+-------------------------------------------------+-----------------------------------|
| =agents=                | agent-shell, from MELPA            | Claude Code, through ACP, in an Emacs buffer    | your Claude login                 |
| =agent-claude-code-ide= | claude-code-ide, from Git          | Claude Code's own screen, in a terminal buffer  | your Claude login                 |
| =agent-eca=             | eca, from MELPA                    | the =eca= server, with any provider             | a provider ECA asks you for       |
| =agent-gptel=           | gptel and gptel-agent, from MELPA  | Emacs Lisp, with the model you set              | an API key, or a local model      |

- The keys are the same for every agent wherever it has the command, so changing agent changes nothing you type:

| =SPC a= | Does                     | agents | claude-code-ide | eca | gptel |
|---------+--------------------------+--------+-----------------+-----+-------|
| =a=     | start, or switch to it   | yes    | yes             | yes | yes   |
| =n=     | a new session            | yes    | yes             | yes | yes   |
| =t=     | show or hide it          | yes    | yes             | yes |       |
| =b=     | pick a session           | yes    | yes             | yes |       |
| =r=     | resume a past session    | yes    | yes             | yes |       |
| =s=     | send the region or file  | yes    | yes             | yes | yes   |
| =f=     | send a file              | yes    |                 | yes | yes   |
| =j=     | jump to one waiting      | yes    | yes             | yes |       |
| =d=     | every session's state    | yes    | yes             |     |       |
| =C=     | start a Change session   |        | yes             |     |       |
| =p=     | send a prompt            |        | yes             |     | yes   |
| =i=     | interrupt                |        | yes             |     | yes   |
| =?=     | the menu of commands     | yes    | yes             | yes | yes   |

- A key an agent lacks stays unbound rather than doing something else, so =SPC a= shows only what works.
- =SPC a c= is not here: [[id:0b43a1e9-2e16-4d5b-985d-342c4897634f][the suggestions chapter]] owns it, for Copilot at point, whichever agent is on.
- Under claude-code-ide, =j=, =d= and =C= are its Change sessions' ([[*Change sessions: their status, a board and a doorbell]]); =C= is capital because =c= is taken.
- agent-shell and ECA interrupt from =SPC m=, inside their buffers. claude-code-ide's is a terminal and gptel's is a plain Org or Markdown buffer, and neither has a mode of its own for =SPC m=, so =SPC a i= does it.

* How agent-shell talks to Claude :concept:
:PROPERTIES:
:ID: 3645870f-b154-4dfd-9085-de3570e0c61e
:END:

- The /Agent Client Protocol/ (ACP) is JSON over a pipe between an editor and a coding agent, the way LSP is between an editor and a language server.
  + The editor sends prompts and answers permission requests; the agent streams text, tool calls and proposed edits.
  + One editor package then speaks to any agent with an adapter: Claude Code, Gemini CLI, Codex and others.
- Three processes, three jobs:

| Piece              | Is                                                         | Comes from                    |
|--------------------+------------------------------------------------------------+-------------------------------|
| agent-shell        | the Emacs buffer and the ACP client                        | MELPA, here                   |
| =claude-agent-acp= | the adapter: ACP on one side, the Claude Agent SDK on the other | your package manager |
| =claude=           | Claude Code itself, which the SDK runs                     | your package manager          |

- agent-shell starts =claude-agent-acp= as a subprocess, one per shell buffer, in the project's root.
- The adapter loads what the =claude= command line loads: =~/.claude/settings.json=, =CLAUDE.md= files, skills and hooks, user-wide and per project.

* Claude Code, through your subscription :decision:
:PROPERTIES:
:ID: e021fb07-ea2e-4dcd-b312-cabe45da9869
:END:

- agent-shell's defaults already fit, so they are not restated here:
  + =agent-shell-anthropic-authentication= is =(:login t)=: use the login =claude= stored, not an API key;
  + =agent-shell-anthropic-claude-acp-command= is =("claude-agent-acp")=, found on =exec-path=.
  + Log in once in a terminal (=claude=, then =/login=); on macOS the token lives in the Keychain.
- Agent output is kept cheap, because a reply streams into one buffer on the main thread:
  + activity groups start collapsed, source blocks are not highlighted, and the header is text rather than an SVG;
  + the busy animation stays on: it is the only sign in the buffer that an agent is still working.
- Two more settings differ from the defaults:
  + =agent-shell-preferred-agent-config= is =claude-code=, so =SPC a a= starts Claude without asking which agent;
  + the adapter inherits Emacs's environment.
- Why inherit: agent-shell otherwise starts the adapter with an almost empty environment.
  + A Dock-launched Emacs on macOS has only the =PATH= [[id:d2e0bc37-0bd4-4b28-a8ee-04f94ac451f8][the shells chapter]] imported, and the adapter, its MCP servers and every command Claude runs need that same =PATH=.
  + Behind a corporate proxy it also carries the proxy and certificate variables, without which nothing reaches the network.
  + The environment is copied once, when agent-shell first loads (the first =SPC a=), after the shells chapter's import; a change to it needs a restart of Emacs.
- Per-project state goes in =.agent-shell/= at the project root: transcripts (with the session ID, model and folder in their header) and screenshots; agent-shell adds it to =.gitignore= itself.

#+begin_src emacs-lisp
(when (kittymacs-feature-p 'agents)
  (use-package agent-shell
    :ensure t
    :commands (agent-shell agent-shell-toggle agent-shell-new-shell agent-shell-switch-buffer
               agent-shell-resume-session agent-shell-send-dwim agent-shell-send-file
               agent-shell-help-menu)
    :custom
    (agent-shell-preferred-agent-config 'claude-code)
    (agent-shell-activity-group-expand-by-default nil)
    (agent-shell-highlight-blocks nil)
    (agent-shell-header-style 'text)
    :config
    (setopt agent-shell-anthropic-claude-environment
            (agent-shell-make-environment-variables :inherit-env t)))

  (keymap-set kittymacs-agent-map "a" (cons "start or switch" #'agent-shell))
  (keymap-set kittymacs-agent-map "n" (cons "new shell" #'agent-shell-new-shell))
  (keymap-set kittymacs-agent-map "t" (cons "toggle" #'agent-shell-toggle))
  (keymap-set kittymacs-agent-map "b" (cons "switch shell" #'agent-shell-switch-buffer))
  (keymap-set kittymacs-agent-map "r" (cons "resume session" #'agent-shell-resume-session))
  (keymap-set kittymacs-agent-map "s" (cons "send region or file" #'agent-shell-send-dwim))
  (keymap-set kittymacs-agent-map "f" (cons "send a file" #'agent-shell-send-file))
  (keymap-set kittymacs-agent-map "?" (cons "menu" #'agent-shell-help-menu)))

#+end_src

- The environment is set in =:config=, not =:custom=: =agent-shell-make-environment-variables= is a function of the package, and only exists once it has loaded.
- The keys go in =SPC a=, each one a command =:commands= declares, so the first key press loads agent-shell.

* What lives in Emacs, and what does not :decision:
:PROPERTIES:
:ID: 5cf88d37-2e87-4451-989c-b957aa817990
:END:

- The agent's policy belongs to the agent, not to the editor: the same rules must hold whether Claude runs here or in a terminal.
  + So permissions, the output style, commit attribution and the skills live in =~/.claude=, written by you or by the machine's configuration, never here.
- This chapter holds only what is about Emacs: the buffers, the keys and the notifications.
- agent-shell and claude-code-ide both run the =claude= command line, so =~/.claude= governs both.
  + agent-shell runs it through =claude-agent-acp=, and claude-code-ide runs =claude= itself; each must be on =PATH=.
- ECA and gptel-agent are agents of their own, so =~/.claude= does not reach them.
  + ECA keeps its rules in its own configuration, which =M-x eca-open-global-config= opens.
  + gptel-agent asks before every tool that changes a file or runs a command, and its presets live in Emacs.
  + This chapter changes neither's rules: choosing one of them means choosing its rules too.

* MCP servers: none until you declare them
:PROPERTIES:
:ID: b9a2367d-e31a-4a30-a5e8-3ad200e4e40b
:END:

- An MCP server gives the agent tools it does not have, such as a library's documentation or a search engine for papers.
- Which servers to run is your choice or your host's, so =kittymacs-agent-mcp-servers= is empty by default.
- Declared, never ambient: a session starts with exactly this list, and no project's =.mcp.json= adds to it unless you approve that server.
- Set it at top level in =private.el= or a host file, which both load before this module reads it. Each element has the shape =agent-shell-mcp-servers= documents:

#+begin_src emacs-lisp :tangle no
(setopt kittymacs-agent-mcp-servers
        `(((name . "docs")
           (command . "docs-mcp")
           (args . ())
           (env . ()))
          ((name . "search")
           (type . "http")
           (url . "https://example.com/mcp/v1")
           (headers . ,(lambda () (my-search-headers))))))
#+end_src

- agent-shell finds a =command= on =PATH=, so your package manager can pin it and nothing downloads when a session starts.
- =headers= may be a =lambda=, which agent-shell calls as each session starts, so a key added to =auth-source= later reaches the next shell.
- The list reaches agent-shell alone.
  + claude-code-ide's Claude reads its servers from =~/.claude=, as the command line does.
  + ECA reads them from its own configuration, and =M-x eca-mcp-toggle-server= starts and stops them.
- An empty list leaves =agent-shell-mcp-servers= alone, so setting that option directly still works.
- A list set while agent-shell is off warns at startup, because the catalogue names it as =agents='s =:option=.
  + A host that moves to another agent then sees the setting it no longer needs.

#+begin_src emacs-lisp
(defcustom kittymacs-agent-mcp-servers nil
  "MCP servers every agent-shell session starts with.
Each element has the shape `agent-shell-mcp-servers' documents.  Set this
before this module loads, in `private.el' or a host file."
  :type '(repeat sexp)
  :group 'kittymacs)

(when (and (kittymacs-feature-p 'agents) kittymacs-agent-mcp-servers)
  (setopt agent-shell-mcp-servers kittymacs-agent-mcp-servers))

#+end_src

* Knowing when a shell waits for you
:PROPERTIES:
:ID: 56789f7f-90bb-4c3b-947c-16ecb6d72365
:END:

- An agent works for minutes, then stops to ask permission or to say it is done; that moment is easy to miss in another frame.
- =agent-shell-attention-mode= adds =AS:n= to the mode line: the number of shells waiting for you.
  + =SPC a j= jumps to the next one; =SPC a d= lists every shell and its state.
- Its notification function, =kittymacs-agent-notify=, also tells the desktop:
  + macOS: =osascript='s =display notification=, which needs nothing installed;
  + Linux: =notifications-notify=, over D-Bus; where there is no D-Bus session (some WSL setups), it stays silent rather than signal an error.
- Not on MELPA, so it is installed from its Git repository with =:vc=, pinned to a commit.
  + =M-x package-vc-upgrade= moves it; change =:rev= here to move everyone.
- Installing it runs =git clone= on the first start, so it can fail where an archive install would not: no network, a proxy =git= is not told about, or a =git= that is not the one you expect.
  + A failed install is a warning, not an error: =use-package= would otherwise stop =init.el= there, and every chapter after this one would go unloaded.
  + The warning names the cause and the =git= Emacs found; once =git clone= of the repository works from a terminal, a restart installs it. Until then =SPC a j= and =SPC a d= stay unbound, and the rest of the chapter works.
- =kittymacs-agent-vc-warning= writes that warning, for claude-code-ide's install as well.
- A key whose package did not install stays unbound, so which-key offers nothing that would fail when pressed.
  + =locate-library= finds the package wherever it came from: =package-vc=, an archive, or a Nix build.

#+begin_src emacs-lisp
(defun kittymacs-agent-notify (_buffer title body)
  "Show a desktop notification with TITLE and BODY.
The value of `agent-shell-attention-notify-function'."
  (pcase system-type
    ('darwin
     (call-process "osascript" nil 0 nil "-e"
                   (format "display notification %S with title %S" body title)))
    (_
     (when (require 'notifications nil t)
       (ignore-errors
         (notifications-notify :app-name "agent-shell" :title title :body body))))))

(defun kittymacs-agent-vc-warning (package url err)
  "Warn that PACKAGE, from the Git repository URL, did not install: ERR."
  (display-warning 'kittymacs
                   (format "%s was not installed: %s
Check that `git clone %s' works from a terminal, and which git Emacs runs: %s"
                           package (error-message-string err) url (executable-find "git"))
                   :warning))

(when (kittymacs-feature-p 'agents)
  (condition-case err
      (use-package agent-shell-attention
        :vc (:url "https://github.com/ultronozm/agent-shell-attention.el"
             :rev "aaf599121445ead597a14da62bad580c8897ee6c")
        :after agent-shell
        :demand t
        :custom
        (agent-shell-attention-notify-function #'kittymacs-agent-notify)
        :config
        (agent-shell-attention-mode 1))
    (error
     (kittymacs-agent-vc-warning "agent-shell-attention"
                                 "https://github.com/ultronozm/agent-shell-attention.el" err)))

  (when (locate-library "agent-shell-attention")
    (keymap-set kittymacs-agent-map "j" (cons "jump to waiting shell" #'agent-shell-attention-jump))
    (keymap-set kittymacs-agent-map "d" (cons "all shells" #'agent-shell-attention-dashboard))))

#+end_src

* Meow in the agent's buffers :meow:
:PROPERTIES:
:ID: 51ae9070-0971-48c1-9625-283891d48d73
:END:

- The shell starts in Insert: it is a prompt, like [[id:d2e0bc37-0bd4-4b28-a8ee-04f94ac451f8][the shells]].
  + =ESC= to Normal selects in the transcript with Meow's grammar; =SPC m= then lists the shell's commands.
  + A permission prompt names its keys on its buttons: =y= allows once, =!= always, and the interrupt key rejects.
- The diff of a proposed edit starts in Motion: its own keys are the interface (=y= accept, =C-c C-c= reject, =n= / =p= hunks, =q= close).
- The viewport, agent-shell's optional two-buffer layout, starts in Motion to read and Insert to write.
- The transcript of a shell is a Markdown file under =.agent-shell/=; =SPC m t= opens it, and its header names the session.

| =SPC m= | Does                    | =SPC m= | Does                       |
|---------+-------------------------+---------+----------------------------|
| =i=     | interrupt the agent     | =f=     | send a file                |
| =m=     | next permission mode    | =y=     | copy the last reply        |
| =M=     | choose the model        | =t=     | open the transcript        |
| =c=     | compose a long prompt   | =r=     | restart the shell          |
| =?=     | every command (menu)    |         |                            |

  + Until it installs, its =SPC a= keys stay unbound, as agent-shell-attention's do.
- Its start command always opens a new instance, so =SPC a a= switches to this project's instance and starts one only where there is none.

* Claude in your buffers: notes, snippets and secrets
:PROPERTIES:
:ID: 6b0f3c52-8a4e-4d17-9e21-3f5c7a9d1e84
:END:

- Functions Claude calls in this Emacs, through =executeCode= or =emacsclient --eval=, for the things it does most while you pair: a remark beside a line, a snippet in a file, a secret you type.
  + Named functions rather than Lisp written on the spot, so each does one thing the same way every time, and its docstring is the contract.
  + Plain Emacs: they load with this chapter and need no package, so they work with any agent that can evaluate Lisp here.
- A /note/ or a /comment/ is an overlay: drawn beside or below a line, never part of the text, so saving writes nothing of it.
  + =kittymacs-pair-comment= marks a line and adds its remark after it; =kittymacs-pair-note= adds a block below a line, for an explanation or a question.
  + =M-x kittymacs-pair-clear= removes them all, or a buffer's.
- A /snippet/ is real text: =kittymacs-pair-snippet= inserts it at a line, or replaces lines there.
  + It saves the buffer when the buffer had no unsaved changes before, so the gutter ([[id:f6ccd2da-4b3f-4392-b439-3966fc9d3db8][version control]]) marks Claude's lines as changed.
  + When you had unsaved changes there, it leaves its own unsaved too: saving would write yours along with it. Its return value says which happened, so Claude can tell you.
  + Each snippet is one undo step, and the inserted lines flash once.
- =kittymacs-pair-secret= asks for a secret in your minibuffer, with echo off, and pipes it to a script of the repository (=tools/secret.sh= unless =kittymacs-pair-secret-script= says otherwise).
  + The text goes from =read-passwd= to the script's standard input and nowhere else; the caller sees only which script ran, with which arguments.

(defun kittymacs-pair-snippet (buffer line text &optional replace)
  "Put TEXT into BUFFER at LINE, replacing REPLACE lines there (none by default).
Save the buffer when it had no unsaved changes before, so the gutter marks
the edit; otherwise leave it unsaved, since saving would write the owner's
unsaved edits too.  Return a sentence saying which."
  (with-current-buffer (kittymacs-pair--buffer buffer)
    (barf-if-buffer-read-only)
    (let ((modified (buffer-modified-p))
          (text (if (string-suffix-p "\n" text) text (concat text "\n"))))
      (undo-boundary)
      (save-excursion
        (kittymacs-pair--goto-line line)
        (unless (bolp) (insert "\n"))   ; past a last line with no newline
        (let ((start (point)))
          (when (and replace (> replace 0))
            (delete-region start (progn (forward-line replace) (point))))
          (goto-char start)
          (insert text)
          (pulse-momentary-highlight-region start (point))))
      (undo-boundary)
      (cond ((not buffer-file-name)
             (format "Wrote into %s, which visits no file" (buffer-name)))
            (modified
             (format "Left %s unsaved: it had unsaved changes of the owner's" (buffer-name)))
            (t (save-buffer)
               (format "Saved %s" buffer-file-name))))))

                               t t nil args)))
            (if (eq status 0)
                (format "%s: written" what)
              (error "%s exited %s: %s" what status (buffer-string)))))
      (clear-string plain))))

* Change sessions: their status, a board and a doorbell :decision:
:PROPERTIES:
:ID: 2d9e5a17-4c3b-4f60-8b1a-7e2c9d4f6a03
:END:

- A /Change session/ is Claude working on a branch of its own, in a worktree of its own, while you do something else: several can run at once, and each stops to ask you in its own buffer.
  + What a session may do, and when it starts one, is Claude's policy in =~/.claude= ([[*What lives in Emacs, and what does not]]). This section is the Emacs half: seeing them, reaching them, starting them.
- Each session keeps a /status file/ under the Git directory every worktree shares, and calls a hook here each time it writes it: [[*The status file: what a session's tools rely on]].
- The mode line counts the sessions by state, and only when one is live: =CC ⚙2 ⏳1 ✓1= is two working, one waiting for you, one ready for review.
  + /Waiting/ includes /idle/: a session that ended its turn without asking for review is waiting for you too.
  + Clicking it opens the board.
- A session that starts waiting, or becomes ready for review, rings once: the desktop notification [[*Knowing when a shell waits for you][agent-shell's doorbell]] uses.
- =SPC a j= switches to the session that has waited longest, and the next one on a second press.
- =SPC a d= is the board: one row per session, with its branch, its state, its review's viewed files, open threads and verdict, and its last message.
  + It finds the sessions of every project Emacs knows (=project-known-project-roots=), reading their status files once when it opens and on =g=, and nothing in between: no timer.
  + It skips a repository on another machine, as [[id:6e1f2a90-4c7b-4d35-9f18-2b7c0d6e3a41][the remote chapter]]'s guards skip anything that would reach one unasked.
  + The verdict reads =stale= once the branch moves past the commit you gave it on.

#+begin_src emacs-lisp
(defvar kittymacs-pair-status-functions nil
  "Functions called with the path of a Change session's status file.
Whatever writes that file calls this hook through emacsclient after each
write, so Emacs learns of a change without watching for it.")

(defconst kittymacs-pair--board-name "*Change sessions*"
  "The board's buffer.")

(defvar kittymacs-pair--sessions (make-hash-table :test #'equal)
  "Each status file's name, to its contents as an alist when last read.")

(defun kittymacs-pair--read-json (file)
  "FILE's JSON object as an alist, or nil when it is missing or unreadable."
  (when (file-readable-p file)
    (ignore-errors
      (with-temp-buffer
        (insert-file-contents file)
        (json-parse-buffer :object-type 'alist :null-object nil :false-object nil)))))

(defun kittymacs-pair--waiting-p (status)
  "Whether STATUS is a session waiting for the owner."
  (member (alist-get 'state status) '("waiting" "idle")))

(defun kittymacs-pair--load (file)
  "Read status FILE into the table, or drop it when it is gone.
Return its contents before and after, as a cons."
  (let* ((file (expand-file-name file))
         (old (gethash file kittymacs-pair--sessions))
         (new (kittymacs-pair--read-json file)))
    (if new
        (puthash file new kittymacs-pair--sessions)
      (remhash file kittymacs-pair--sessions))
    (cons old new)))

(defun kittymacs-pair-status-update (file)
  "Read the status FILE, ring when it starts to need the owner, redraw.
The function `kittymacs-pair-status-functions' runs."
  (pcase-let* ((`(,old . ,new) (kittymacs-pair--load file))
               (state (alist-get 'state new)))
    (when (and (member state '("waiting" "review"))
               (not (equal state (alist-get 'state old))))
      (let ((message (alist-get 'message new)))
        (kittymacs-agent-notify nil (format "Claude: %s" (alist-get 'branch new))
                                (cond ((equal state "review") "ready for review")
                                      ((and message (not (string-empty-p message))) message)
                                      (t "waiting for you")))))
    (force-mode-line-update t)
    (when-let* ((board (get-buffer kittymacs-pair--board-name)))
      (with-current-buffer board
        (kittymacs-pair--board-print)))))

(defun kittymacs-pair-mode-line ()
  "The live Change sessions by state, for the mode line; empty when none is."
  (let ((working 0) (waiting 0) (review 0))
    (maphash (lambda (_file status)
               (pcase (alist-get 'state status)
                 ((or "starting" "working") (cl-incf working))
                 ((or "waiting" "idle") (cl-incf waiting))
                 ("review" (cl-incf review))))
             kittymacs-pair--sessions)
    (if (zerop (+ working waiting review))
        ""
      (propertize (concat " CC"
                          (if (> working 0) (format " ⚙%d" working) "")
                          (if (> waiting 0) (format " ⏳%d" waiting) "")
                          (if (> review 0) (format " ✓%d" review) "")
                          " ")
                  'help-echo "Change sessions: mouse-1 or SPC a d opens the board"
                  'mouse-face 'mode-line-highlight
                  'local-map (make-mode-line-mouse-map 'mouse-1 #'kittymacs-pair-board)))))

(defun kittymacs-pair--common-dir (root &optional remote)
  "The Git directory every worktree of ROOT shares, or nil.
Read from the files, so it starts no process.  A remote ROOT gives nil
unless REMOTE is non-nil, so a scan never reaches another machine unasked."
  (unless (and (file-remote-p root) (not remote))
    (let ((dotgit (expand-file-name ".git" root)))
      (cond
       ((file-directory-p dotgit) (file-name-as-directory dotgit))
       ((file-regular-p dotgit)
        (when-let* ((gitdir (with-temp-buffer
                              (insert-file-contents dotgit)
                              (and (looking-at "gitdir: \\(.*\\)$")
                                   (file-name-as-directory
                                    (expand-file-name (match-string 1) root))))))
          (let ((commondir (expand-file-name "commondir" gitdir)))
            (file-name-as-directory
             (if (file-readable-p commondir)
                 (expand-file-name (string-trim (with-temp-buffer
                                                  (insert-file-contents commondir)
                                                  (buffer-string)))
                                   gitdir)
               gitdir)))))))))

(defun kittymacs-pair-scan ()
  "Read the status files of every project Emacs knows into the table, afresh."
  (require 'project)
  (let ((dirs (delete-dups
               (append
                (mapcar #'file-name-directory (hash-table-keys kittymacs-pair--sessions))
                (delq nil (mapcar (lambda (root)
                                    (when-let* ((common (kittymacs-pair--common-dir root)))
                                      (expand-file-name "agents/" common)))
                                  (project-known-project-roots)))))))
    (clrhash kittymacs-pair--sessions)
    (dolist (dir dirs)
      (when (file-directory-p dir)
        (dolist (file (directory-files dir t "\\.json\\'"))
          (kittymacs-pair--load file))))
    (force-mode-line-update t)))

(defun kittymacs-pair--session (status)
  "The live claude-code-ide session in STATUS's worktree, or nil."
  (when-let* ((worktree (alist-get 'worktree status))
              ((fboundp 'claude-code-ide-mcp--sessions-for-project)))
    (cl-some (lambda (dir)
               (cl-find-if (lambda (session)
                             (buffer-live-p (claude-code-ide-mcp-session-buffer session)))
                           (claude-code-ide-mcp--sessions-for-project dir)))
             (list (file-name-as-directory worktree) (directory-file-name worktree)))))

(defun kittymacs-pair--session-buffer (status)
  "The terminal buffer of STATUS's claude-code-ide session, or nil."
  (when-let* ((session (kittymacs-pair--session status)))
    (claude-code-ide-mcp-session-buffer session)))

(defun kittymacs-pair--outside (status)
  "Say that STATUS's session runs where Emacs cannot show it."
  (message "%s runs outside Emacs (%s), as %s"
           (alist-get 'branch status) (or (alist-get 'how status) "unknown")
           (alist-get 'session status)))

(defun kittymacs-pair-jump ()
  "Switch to the Change session that has waited longest for you.
Pressed again from that session, go on to the next one."
  (interactive)
  (dolist (file (hash-table-keys kittymacs-pair--sessions))
    (kittymacs-pair--load file))
  (let* ((waiting (sort (cl-loop for status being the hash-values of kittymacs-pair--sessions
                                 when (kittymacs-pair--waiting-p status) collect status)
                        (lambda (a b) (string< (or (alist-get 'at a) "") (or (alist-get 'at b) "")))))
         (buffers (delq nil (mapcar #'kittymacs-pair--session-buffer waiting)))
         (next (or (cl-find-if (lambda (b) (not (eq b (current-buffer)))) buffers)
                   (car buffers))))
    (cond (next (pop-to-buffer next))
          (waiting (kittymacs-pair--outside (car waiting)))
          (t (message "No Change session is waiting for you")))))

** The status file: what a session's tools rely on :concept:
:PROPERTIES:
:ID: 0e6b4d29-7f13-4a8c-b5d2-9c1a3e7f4b60
:END:

- The tools that start and run a Change session live outside Emacs, so this is the interface between the two, kept stable: a file's fields, a hook, and two naming rules.
- The file is =agents/NAME.json= under the Git directory every worktree shares (=git rev-parse --git-common-dir=), beside diff-review's =review/=. Its fields:
  + =branch=, =worktree= (an absolute path on the session's machine), =session= (the session's name, NAME), =how= (=emacs= or =tmux=) and =brief= (a path);
  + =state=: =starting=, =working=, =waiting=, =idle=, =review= or =done=; =message=: what Claude said when it last stopped to ask; =at=: when the file was written, ISO 8601;
  + =host=: the name this Emacs reaches the session's machine by over SSH, or =cloud= for a session in the cloud;
  + =route=: how the branch is reviewed once the session finishes, =tramp=, =fetch= or =pr-review=, and null until then.
- After each write, whatever wrote the file calls =kittymacs-pair-status-functions= with its path, through =emacsclient=, so Emacs need not watch any directory.
- The review of a session on another machine opens over TRAMP, at =/ssh:HOST:WORKTREE= (=kittymacs-pair-tramp-method= names another method).
  + When =host= is this machine's short name, or =worktree= exists here, it opens the local path instead.
  + The review file then stays in that machine's =.git=, where the session reads your threads.
- A session started in tmux runs in a window named after =session=, on =host=, so a verdict reaches it with =tmux send-keys=.
- Beside the status file, a session keeps its /manifest/: what it was set up with and what it can reach, at the status file's path with =.json= replaced by =.manifest.json=. The status file names no manifest.
  + Its shape: ={at, mode, settings: {budget, learn, socratic, extras}, skills: {linked, missing, unexpected}, hooks, permission_mode, mcp: {configured}, reach: {emacs, emacs_sees_repo, gh, ollama, route}}=.
  + =mode= is =assist= or =change=; =extras=, the three =skills= lists, =hooks= and =configured= are lists of names.
  + In =reach=: =emacs= and =gh= are true or false; =emacs_sees_repo= and =ollama= may also be null, for not checked; =route= is =tramp=, =fetch=, =pr-review= or null.
  + After writing it, the session calls =kittymacs-pair-status-functions= with the status file's path, as for any change of state.

** The board
:PROPERTIES:
:ID: 8e3a6f21-5b7c-4d94-a0e2-1c9f4b7d5e36
:END:

- One row per status file: =RET= opens the session's buffer, =r= reviews its branch in [[id:3f0450b0-881e-4487-b90f-49a4d03f17a7][diff-review]], =i= shows its manifest, =g= reads the files again, =q= closes.
  + The /Reach/ column sums up the manifest: =E✓ gh✗ tramp= is a session that reaches this Emacs, not GitHub, and is reviewed over TRAMP; =?= means it has written no manifest yet.
  + =E✓= needs both that the session reaches Emacs and that this Emacs sees its repository.
  + =i= shows the manifest as indented JSON, read-only, in Motion, =q= to close.
  + A session started in tmux has no buffer here: =RET= says where it runs instead.
  + =r= opens the review where the session runs: here, or over TRAMP on its =host=. =M-x kittymacs-pair-review= does the same for any host, worktree and branch, starting from the row at point.
  + A session in the cloud has no worktree to reach: its branch is reviewed as a pull request, with =SPC v R= or =SPC v u= ([[id:3f0450b0-881e-4487-b90f-49a4d03f17a7][the version-control chapter]]).
- The review's columns come from =review/BRANCH.json=, the file diff-review and the session both write: the files marked viewed, the threads not resolved, and the verdict.
  + Reading the verdict asks Git for the branch's tip once per row, the only process the board starts.

#+begin_src emacs-lisp
(defun kittymacs-pair--review (file status)
  "The review of STATUS, whose status file is FILE: (VIEWED OPEN VERDICT).
Each is a string, empty when there is no review yet."
  (let* ((common (file-name-directory (directory-file-name (file-name-directory file))))
         (branch (alist-get 'branch status))
         (review (and branch (kittymacs-pair--read-json
                              (expand-file-name (concat "review/" branch ".json") common)))))
    (if (not review)
        (list "" "" "")
      (let* ((verdict (alist-get 'verdict review))
             (tip (ignore-errors
                    (let ((default-directory (file-name-as-directory
                                              (or (alist-get 'worktree status) common))))
                      (car (process-lines "git" "rev-parse" branch))))))
        (list (number-to-string (length (alist-get 'viewed review)))
              (number-to-string (cl-count-if-not (lambda (c) (alist-get 'resolved c))
                                                 (alist-get 'comments review)))
              (cond ((not verdict) "")
                    ((equal (alist-get 'head verdict) tip) (alist-get 'state verdict))
                    (t "stale")))))))

(defun kittymacs-pair--manifest-file (file)
  "The manifest beside the status FILE."
  (concat (string-remove-suffix ".json" file) ".manifest.json"))

(defun kittymacs-pair--reach (file)
  "A short summary of what the session of status FILE reaches, or \"?\".
JSON's false and null stay apart here: null is a check not made."
  (if-let* ((manifest (ignore-errors
                        (with-temp-buffer
                          (insert-file-contents (kittymacs-pair--manifest-file file))
                          (json-parse-buffer :object-type 'alist :null-object nil
                                             :false-object :false)))))
      (let ((reach (alist-get 'reach manifest))
            (mark (lambda (value) (if (eq value t) "✓" "✗"))))
        (string-trim-right
         (format "E%s gh%s %s"
                 (funcall mark (and (eq (alist-get 'emacs reach) t)
                                    (not (eq (alist-get 'emacs_sees_repo reach) :false))))
                 (funcall mark (alist-get 'gh reach))
                 (or (alist-get 'route reach) ""))))
    "?"))

(defun kittymacs-pair--board-print ()
  "Fill the board from the table, keeping point on its row."
  (setq tabulated-list-entries
        (cl-loop for file being the hash-keys of kittymacs-pair--sessions
                 using (hash-values status)
                 collect (list file
                               (apply #'vector
                                      (or (alist-get 'branch status) "?")
                                      (or (alist-get 'state status) "?")
                                      (append (kittymacs-pair--review file status)
                                              (list (kittymacs-pair--reach file)
                                                    (or (alist-get 'message status) "")))))))
  (tabulated-list-print t))

(defun kittymacs-pair--board-revert ()
  "Read the status files again, for `revert-buffer'."
  (kittymacs-pair-scan)
  (kittymacs-pair--board-print))

(defun kittymacs-pair--board-status ()
  "The status of the session on this row."
  (or (gethash (tabulated-list-get-id) kittymacs-pair--sessions)
      (user-error "No session on this line")))

(defun kittymacs-pair-board-visit ()
  "Open the terminal of the session on this row."
  (interactive)
  (let ((status (kittymacs-pair--board-status)))
    (if-let* ((buffer (kittymacs-pair--session-buffer status)))
        (pop-to-buffer buffer)
      (kittymacs-pair--outside status))))

(defcustom kittymacs-pair-tramp-method "ssh"
  "The TRAMP method that reaches a Change session on another machine."
  :type 'string
  :group 'kittymacs)

(defun kittymacs-pair--this-host-p (host)
  "Whether HOST names this machine, compared by the short name."
  (let ((short (lambda (name) (car (split-string name "\\.")))))
    (equal (funcall short host) (funcall short (system-name)))))

(defun kittymacs-pair--path (host worktree)
  "WORKTREE as this Emacs reaches it.
The local path when it is here, else a TRAMP path on HOST."
  (if (or (null host) (string-empty-p host) (kittymacs-pair--this-host-p host)
          (file-directory-p worktree))
      worktree
    (format "/%s:%s:%s" kittymacs-pair-tramp-method host worktree)))

(defun kittymacs-pair-review (host worktree branch)
  "Review BRANCH in diff-review, from WORKTREE on HOST.
Over TRAMP when HOST is another machine, so the review file stays in that
machine's Git directory, where the session reads the threads.
Interactively, the defaults come from the board's row at point."
  (interactive
   (let ((status (and (derived-mode-p 'kittymacs-pair-board-mode)
                      (gethash (tabulated-list-get-id) kittymacs-pair--sessions))))
     (list (read-string "Host: " (or (alist-get 'host status) (system-name)))
           (read-string "Worktree: " (alist-get 'worktree status))
           (read-string "Branch: " (alist-get 'branch status)))))
  (unless (fboundp 'diff-review-branch)
    (user-error "diff-review is not installed: turn on the branch-review feature"))
  (when (equal host "cloud")
    (user-error "A cloud session has no worktree to reach: review its pull request instead"))
  (let ((default-directory (file-name-as-directory (kittymacs-pair--path host worktree))))
    (diff-review-branch branch)))

  (let ((status (kittymacs-pair--board-status)))
    (kittymacs-pair-review (alist-get 'host status) (alist-get 'worktree status)
                           (alist-get 'branch status))))

(define-derived-mode kittymacs-pair-manifest-mode js-json-mode "Manifest"

(defun kittymacs-pair-board-manifest ()
  "Show the manifest of the session on this row."
  (interactive)
  (let* ((file (kittymacs-pair--manifest-file (tabulated-list-get-id)))
         (branch (alist-get 'branch (kittymacs-pair--board-status))))

** Starting a Change session
:PROPERTIES:
:ID: 5f1c8b39-2e6d-4a07-b4c3-9d0a7e2f8b15
:END:

- =SPC a C= starts one on a new branch of this project: it asks for the branch, then takes the region as the brief, or opens a buffer to write one in (=C-c C-c= starts it, =C-c C-k= drops it).
  + A brief is what the session reads first: the goal, the context you and Claude gathered, the checks to run.
- The starting itself is not Emacs's: =kittymacs-pair-dispatch-command= names a program, called as =PROGRAM REPO BRANCH BRIEF-FILE=, that makes the worktree, writes the status file and starts the session.
  + Unset, it is =pair-dispatch= on =exec-path=, or the copy a Claude skill keeps at =~/.claude/skills/pair/pair-dispatch=; without either, =SPC a C= stays unbound.
  + Its output goes to =*Change dispatch*=, which opens only when it fails.
- =kittymacs-pair-start= is what such a program calls back to start the session here, through =emacsclient=: claude-code-ide in the worktree, under a name and with variables of its own.
  + Its first message waits until the session is connected to this Emacs and its screen asks nothing, then =kittymacs-pair-ready-delay= more: a new worktree opens on Claude Code's question whether to trust the folder, with /No, exit/ chosen, and a message typed into it would answer it.
  + While such a question waits, the status file says so, so the board and the doorbell show the session waiting for you.
  + It refuses a worktree that has a session already, since claude-code-ide would then stop to ask for a name, and nothing answers a question asked through =emacsclient=.

#+begin_src emacs-lisp
(defcustom kittymacs-pair-dispatch-command nil
  "The program that starts a Change session, or nil to find pair-dispatch.
Nil looks on `exec-path', then at ~/.claude/skills/pair/pair-dispatch.
It is called as PROGRAM REPO BRANCH BRIEF-FILE."
  :type '(choice (const :tag "Find pair-dispatch" nil) file)
  :group 'kittymacs)

(defcustom kittymacs-pair-ready-delay 1.5
  "Seconds between a new session's editor connection and its first message."
  :type 'number
  :group 'kittymacs)

(defun kittymacs-pair--dispatch-program ()
  "The command that starts a Change session, as a list, or nil."
  (when-let* ((file (or kittymacs-pair-dispatch-command
                        (executable-find "pair-dispatch")
                        (expand-file-name "~/.claude/skills/pair/pair-dispatch")))
              ((file-exists-p file)))
    (if (file-executable-p file) (list file) (list "bash" file))))

(defun kittymacs-pair--repo ()
  "The root of this buffer's project, or its directory."
  (let ((dir (if-let* ((project (project-current)))
                 (project-root project)
               default-directory)))
    (when (file-remote-p dir)
      (user-error "A Change session starts in a repository on this machine"))
    (expand-file-name dir)))

(defun kittymacs-pair--dispatch (repo branch brief)
  "Start a Change session on BRANCH of REPO, with the text BRIEF."
  (let* ((program (or (kittymacs-pair--dispatch-program)
                      (user-error "No pair-dispatch: set `kittymacs-pair-dispatch-command'")))
         (file (make-temp-file "change-brief-" nil ".md" brief))
         (output (get-buffer-create "*Change dispatch*"))
         (default-directory (expand-file-name "~/")))
    (with-current-buffer output
      (goto-char (point-max))
      (insert (format "\n%s %s\n" (string-join program " ") branch)))
    (make-process
     :name "pair-dispatch" :buffer output :noquery t
     :command (append program (list repo branch file))
     :sentinel (lambda (process _event)
                 (unless (process-live-p process)
                   (ignore-errors (delete-file file))
                   (if (zerop (process-exit-status process))
                       (message "Change session started on %s" branch)
                     (display-buffer output)
                     (message "Could not start a Change session on %s" branch)))))))

(defvar-local kittymacs-pair--brief-target nil
  "In a brief buffer, the repository and the branch, as a cons.")

(defvar-keymap kittymacs-pair-brief-mode-map
  :doc "Keys of a Change session's brief."
  "C-c C-c" #'kittymacs-pair-brief-send
  "C-c C-k" #'kittymacs-pair-brief-cancel)

  :lighter " Brief")

(defun kittymacs-pair-brief-send ()
  "Start the Change session this buffer is the brief of."
  (interactive)

              (brief (buffer-string)))
    (kittymacs-pair--dispatch repo branch brief)
    (quit-window t)))

(defun kittymacs-pair-brief-cancel ()
  "Drop this brief."
  (interactive)
  (quit-window t))

(defun kittymacs-pair-dispatch (branch &optional brief)
  "Start a Change session on a new BRANCH of this project, from BRIEF.
Interactively, BRIEF is the region; without one, a buffer opens to write it."
  (interactive (list (read-string "Branch for the Change session: ")
                     (when (use-region-p)
                       (buffer-substring-no-properties (region-beginning) (region-end)))))
  (let ((repo (kittymacs-pair--repo)))
    (if brief
        (kittymacs-pair--dispatch repo branch brief)
      (pop-to-buffer (generate-new-buffer (format "*Change brief: %s*" branch)))
      (text-mode)
      (insert "Goal:\n\nContext:\n\nChecks:\n")
      (goto-char (point-min))
      (end-of-line)
      (insert " ")
      (setq kittymacs-pair--brief-target (cons repo branch))
      (kittymacs-pair-brief-mode 1)
      (setq header-line-format
            (substitute-command-keys
             "Brief for a Change session: \\[kittymacs-pair-brief-send] starts it, \\[kittymacs-pair-brief-cancel] drops it"))
      (when (fboundp 'meow--switch-state)
        (meow--switch-state 'insert)))))

(defun kittymacs-pair--asking-p (buffer)
  "Whether Claude's screen in BUFFER shows a question waiting for a choice.
Only the last lines count: the screen, not what scrolled away."
  (with-current-buffer buffer
    (save-excursion
      (goto-char (point-max))
      (let ((end (point)))
        (forward-line -12)
        (search-forward "Enter to confirm" end t)))))

(defun kittymacs-pair--mark-waiting (status-file message)
  "Mark the session of STATUS-FILE as waiting, with MESSAGE, and tell the hook."
  (when-let* ((status (and status-file (kittymacs-pair--read-json status-file)))
              ((not (equal (alist-get 'state status) "waiting"))))
    (setf (alist-get 'state status) "waiting"
          (alist-get 'message status) message
          (alist-get 'at status) (format-time-string "%FT%T%:z"))
    (let ((new (concat status-file ".new")))
      (with-temp-file new (insert (json-encode status) "\n"))
      (rename-file new status-file t))
    (run-hook-with-args 'kittymacs-pair-status-functions status-file)))

(defun kittymacs-pair--send-when-ready (session prompt status-file tries &optional settled)
  "Send PROMPT to SESSION once it is connected and asks nothing.
Claude Code can open on questions of its own, such as whether to trust the
folder, and a message typed into one would answer it.  While one waits,
STATUS-FILE, when given, says so.  TRIES counts the seconds waited; after
an hour this gives up.  SETTLED is set on the check after
`kittymacs-pair-ready-delay', which sends."
  (let ((buffer (claude-code-ide-mcp-session-buffer session)))
    (cond
     ((not (buffer-live-p buffer)))
     ((and (claude-code-ide-mcp-session-client session)
           (not (kittymacs-pair--asking-p buffer)))
      (if settled
          (claude-code-ide-send-prompt prompt session)
        (run-with-timer kittymacs-pair-ready-delay nil #'kittymacs-pair--send-when-ready
                        session prompt status-file tries t)))
     ((< tries 3600)
      (when (kittymacs-pair--asking-p buffer)
        (kittymacs-pair--mark-waiting status-file "Claude Code asks a question before it starts"))
      (run-with-timer 1 nil #'kittymacs-pair--send-when-ready
                      session prompt status-file (1+ tries)))
     (t (message "Claude in %s did not get ready within an hour; its first message was not sent"
                 (claude-code-ide-mcp-session-project-dir session))))))

(defun kittymacs-pair-start (worktree name prompt &rest environment)
  "Start claude-code-ide in WORKTREE as NAME, then send it PROMPT.
ENVIRONMENT is \"VARIABLE=value\" strings for the session's process; a
CC_PAIR_STATUS among them names its status file.  Return the session's
buffer name."
  (require 'claude-code-ide)
  (let* ((default-directory (file-name-as-directory (expand-file-name worktree)))
         (process-environment (append environment process-environment))
         (claude-code-ide-cli-extra-flags
          (string-trim (concat claude-code-ide-cli-extra-flags " -n "
                               (shell-quote-argument name))))
         (current-prefix-arg nil)
         (dir (claude-code-ide--get-working-directory)))
    (when (claude-code-ide-mcp--sessions-for-project dir)
      (user-error "%s has a Claude session already" dir))
    (claude-code-ide)
    (let ((session (car (claude-code-ide-mcp--sessions-for-project dir))))
      (kittymacs-pair--send-when-ready
       session prompt
       (cl-some (lambda (pair) (and (string-prefix-p "CC_PAIR_STATUS=" pair)
                                    (substring pair (length "CC_PAIR_STATUS="))))
                environment)
       0)
      (buffer-name (claude-code-ide-mcp-session-buffer session)))))

** A verdict wakes the session
:PROPERTIES:
:ID: 3a7d2c58-6f1e-4b09-8d34-5e0b9a1c7f62
:END:

- Approving a branch in diff-review (=A=), or asking for changes (=C=), sends that branch's session a message, so it starts on your threads without you switching to it.
  + The message names the verdict, the commit and how many threads are open; the session reads the threads from the review file itself.
  + A claude-code-ide session in this Emacs gets it typed into its buffer.
  + Any other, in tmux here or on the machine the review was opened from over TRAMP, gets it through =tmux send-keys=, run by =process-file= so TRAMP runs it there; one =tmux list-windows= finds the window first.
  + With no status file for the branch, nothing happens; with one but no window, the echo area says the message was not sent.
- diff-review has no hook for a verdict, so this follows =diff-review--set-verdict=, the one function both commands end in, with =:after= advice.
  + That name is internal to diff-review, which is pinned; the behaviour check fails if a newer version drops it.

#+begin_src emacs-lisp
(defvar diff-review--head-name)
(defvar diff-review--tip)
(defvar diff-review--root)
(defvar diff-review--comments)

(defcustom kittymacs-pair-verdict-prompt
  "The owner's verdict on %s is %s; open threads: %d. Read the review's threads and answer them."
  "The message a Change session gets on a verdict.
Its arguments are the commit, the verdict and the number of open threads."
  :type 'string
  :group 'kittymacs)

(defun kittymacs-pair--status-for-branch (root branch)
  "The status file and contents of BRANCH's session in ROOT's repository, a cons.
ROOT may be remote: the review asked for it."
  (when-let* ((common (kittymacs-pair--common-dir root t))
              (dir (expand-file-name "agents/" common))
              ((file-directory-p dir)))
    (cl-loop for file in (directory-files dir t "\\.json\\'")
             for status = (kittymacs-pair--read-json file)
             when (equal (alist-get 'branch status) branch)
             return (cons file status))))

(defun kittymacs-pair--tmux-target (name)
  "The tmux window named NAME on the machine of `default-directory', or nil.
As SESSION:INDEX, from one list of every window."
  (with-temp-buffer
    (when (eq 0 (ignore-errors
                  (process-file "tmux" nil t nil "list-windows" "-a"
                                "-F" "#{session_name}:#{window_index} #{window_name}")))
      (goto-char (point-min))
      (when (re-search-forward (concat "^\\(\\S-+\\) " (regexp-quote name) "$") nil t)
        (match-string 1)))))

(defun kittymacs-pair--tmux-send (name prompt)
  "Type PROMPT into the tmux window NAME, on the machine of `default-directory'.
Say so in the echo area when there is no such window."
  (if-let* ((target (kittymacs-pair--tmux-target name)))
      (progn (process-file "tmux" nil nil nil "send-keys" "-t" target "-l" prompt)
             (process-file "tmux" nil nil nil "send-keys" "-t" target "Enter")
             t)
    (message "No tmux window %s on %s: the session did not get the verdict"
             name (or (file-remote-p default-directory 'host) (system-name)))
    nil))

(defun kittymacs-pair--nudge (state)
  "Tell the Change session of this review's branch about the verdict STATE.
Runs after `diff-review--set-verdict', in the review's buffer."
  (when-let* ((branch diff-review--head-name)
              (tip diff-review--tip)
              (root diff-review--root)
              (found (kittymacs-pair--status-for-branch root branch)))
    (let* ((status (cdr found))
           (prompt (format kittymacs-pair-verdict-prompt (substring tip 0 (min 7 (length tip)))
                           state (cl-count-if-not (lambda (c) (eq (gethash "resolved" c) t))
                                                  diff-review--comments)))
           (session (unless (file-remote-p root) (kittymacs-pair--session status))))
      (if session
          (claude-code-ide-send-prompt prompt session)
        (let ((default-directory (file-name-as-directory root)))
          (kittymacs-pair--tmux-send (alist-get 'session status) prompt))))))

- For =agents= or =agent-claude-code-ide=, once, in a terminal: =claude=, then =/login=.
- =SPC a a= in a project: the agent you chose opens, in Insert for agent-shell and ECA, and in the terminal for claude-code-ide.
- Ask it to read a file: the read happens; ask it to change one: it asks first, and agent-shell's diff opens in Motion with =y= to accept, claude-code-ide's in Ediff.
- Ask "which MCP tools do you have?": for agent-shell, the servers in =kittymacs-agent-mcp-servers= plus any your Claude configuration adds; for claude-code-ide, the five Emacs tools as well.
- With agent-shell, switch frames while it works: the mode line shows =AS:1= when it stops, and the desktop shows a notification.
- Select a different agent in onboarding: the one before turns off, and =SPC a= shows the new one's keys.
- With claude-code-ide, =SPC a C= in a project, a branch name, and a brief that asks for a one-word reply: a worktree appears, a session starts in it, and once its trust question is answered it gets the brief by itself; =CC ⚙1= shows in the mode line.
- =SPC a d=: the board lists that session; =RET= opens its buffer, =r= its review. Set a verdict there with =C=: the session gets a message naming it.
- =M-: (kittymacs-pair-snippet (current-buffer) 1 ";; hi")= in a saved file: the line appears, flashes, and the file is saved, so the gutter marks it; type something first, and the same call leaves the buffer unsaved and says so.
- =just test-packages=: the verifier fails on any warning at startup, and checks that every =SPC= key runs a command.
