Ownership: *user configuration*. [[https://github.com/davidshepherd7/frames-only-mode][frames-only-mode]] supplies the frame lifecycle;
this module integrates it with Lambda's deferred Magit setup and leader keys.
An Emacs frame is an OS window; an Emacs window is a pane inside that frame.
Load this module after Help and Org so their defaults cannot undo the policy.

* Keep ordinary editor frames native

Native decorations, positioning and sizing remain under the desktop window
manager's control. This module does not load Lambda's undecorated, recentering
frame module. Ordinary file and buffer switching still uses the current frame;
commands that would pop up an auxiliary buffer can create a separate frame.

* Android has no window manager to delegate to

This chapter's premise is that /the desktop window manager arranges Emacs/.
Android has no such thing. It does map frames one-to-one onto activities, so
the policy technically works — and the result is that every Help buffer, Magit
status and completion panel becomes a separate full-screen entry in the task
switcher, which the user then has to dismiss by hand. The premise fails, so the
policy is off by default and Emacs's own windows do the arranging.

The option is real rather than a hard-coded refusal: a tablet in desktop mode,
or a device driving an external display, is a plausible place to want it back.

#+begin_src emacs-lisp
(defcustom kittymacs-frames-only
  (not (eq system-type 'android))
  "Whether every auxiliary buffer becomes its own operating-system window.
Off on Android, where an Emacs frame is an activity in the task switcher
rather than a window some desktop window manager arranges for you.  Set
it in `private.el', before this module is loaded, to override."
  :type 'boolean
  :group 'kittymacs)
#+end_src

* Magit gets a frame

[[file:66-vc.org][The version-control chapter]] sets Magit's display function: a frame while
this mode is on, the traditional split otherwise. Modern Magit closes frames
it created through =quit-window=. The package's own legacy Magit overrides are
excluded below: they can delete terminal frames and unbind Magit variables
when the mode is disabled after Magit loaded lazily.


* Enable frames and preserve completion panels

The package uses =pop-up-frames= only on graphical displays. Its defaults put
Org agenda and source editing in frames and clean up temporary frames when
quitting their buffers. Vertico's top side window, Transient menus and Corfu's
child-frame suggestions remain attached to their editor. These are temporary
controls, so they should not become separate desktop editing windows.

Lambda's Popper normally forces Help and compilation into top side windows.
Turn off only its display control while frame mode is active; popup tracking
and cycling remain available, and disabling frame mode restores its placement.

The standard split keys (=C-x 2=, =C-x 3=) are remapped to frame creation
inside the minor mode map, so =M-x frames-only-mode= restores them when
disabled. The leader's =SPC w h= and =SPC w v= remain real in-frame splits.

#+begin_src emacs-lisp
(use-package frames-only-mode
  :ensure t
  :if kittymacs-frames-only
  :demand t
  :custom
  (frames-only-mode-use-windows-for-completion t)
  :config
  (setq frames-only-mode-configuration-variables
        (seq-remove (lambda (setting)
                      (memq (car setting)
                            '(magit-commit-show-diff magit-bury-buffer-function)))
                    frames-only-mode-configuration-variables))
  (add-to-list 'frames-only-mode-configuration-variables
               '(popper-display-control nil))
  (frames-only-mode-remap-common-window-split-keybindings)
  ;; Re-evaluating this file must not overwrite the mode's saved defaults.
  (unless frames-only-mode
    (frames-only-mode 1)))

#+end_src

* Diagnostics are not editing surfaces

A warning, a byte-compilation log or a backtrace is something Emacs is telling
you, not a buffer you work in, so it does not deserve an operating-system
window of its own. Left alone it gets one: the first Magit of a session used
to raise a =*Warnings*= window on top of the Magit window it had just made,
which looks exactly like the command having gone wrong.

These appear in a small window at the bottom of the frame you are in instead.
=q= dismisses them and the frame is untouched. This is the same rule as the
sidebars above — a panel that serves the buffer next to it stays inside the
frame — applied to the buffers Emacs raises on its own.

#+begin_src emacs-lisp
(dolist (pattern '("\\`\\*Warnings\\*\\'"
                   "\\`\\*Compile-Log\\*\\'"
                   "\\`\\*Backtrace\\*\\'"
                   "\\`\\*Native-compile-Log\\*\\'"
                   "\\`\\*Async-native-compile-log\\*\\'"))
  (add-to-list 'display-buffer-alist
               `(,pattern
                 (display-buffer-reuse-window display-buffer-at-bottom)
                 (window-height . 0.25)
                 (dedicated . t)
                 (reusable-frames . visible))))

(provide 'kittymacs-frames)

#+end_src

* What stays inside the frame

Only *full buffers* go to frames. Panels that ask for a side window keep it:
the file-tree and outline sidebars (=SPC t d=, =SPC t o=), Vertico's
candidate list, which-key, Transient menus and Corfu. The mode line, the
fringe gutters and the minibuffer are per frame anyway. The rule of thumb
when adding a package: a buffer you read or edit gets a frame; a panel that
serves the buffer next to it uses =display-buffer-in-side-window=, which this
mode leaves alone.

* Everyday commands and recovery

- =C-x 2= / =C-x 3= and =SPC w n= create native frames; =SPC w h= / =SPC w v= split inside one.
- =C-x 4= uses the other-frame commands normally under =C-x 5=.
- =C-x 5 f= visits a file in another frame; =C-x 5 b= selects a buffer there.
- =C-x 5 0= closes a frame. Desktop window-manager shortcuts can arrange it.
- =M-x frames-only-mode= toggles this policy for the session. Internal panes
  already on screen are not deleted when enabling the mode.

The graphical integration checks are in [[file:../tests/kittymacs-frames-tests.el][kittymacs-frames-tests.el]]. Load them after
ordinary GUI startup and run =M-x ert RET ^kittymacs-frames- RET=. They exercise
auxiliary-frame creation and cleanup, the completion side window, and Magit's
lazy load and return to internal splits when the mode is disabled.
