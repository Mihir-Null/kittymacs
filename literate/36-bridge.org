* What this gives you                                               :concept:

- Day-to-day editing stays in the Emacs built for the device: Windows'
  native build, or the Android port.
  - Its frames, input, fonts, clipboard and window manager integration are
    the convenient part, and it keeps them.
- The work Windows and Android do badly, or cannot do, runs in a Linux
  environment instead:
  - language servers, Git, compilers, =rg=, =nix=, LaTeX;
  - Org operations that need Linux paths or Linux tools.
- Back ends in scope:
  - *WSL* on Windows (=mcqueenix=, NixOS);
  - *Termux* on Android, sharing Emacs's user ID;
  - *nix-on-droid* on Android, over SSH.
- Today, on Windows with WSL installed:
  - =C-x C-f /wsl:NixOS:~/= opens your WSL home; =TAB= after =/wsl:=
    completes the distributions;
  - a file opened from Explorer as =\\wsl.localhost\NixOS\…= arrives through
    the same method;
  - =M-x kittymacs-bridge-find-file= and =M-x kittymacs-bridge-dired= start
    in the back end's home.

* The split: where things run                                       :concept:

** Why a daemon cannot serve native frames

- =emacsclient= is a messenger; the *server* draws every frame.
- A frame is drawn by the display code compiled into that Emacs binary.
  - A Linux build draws X, Wayland (pgtk) or terminal frames.
  - Only a Windows build draws Win32 frames.
- So "a Linux daemon showing native Windows frames" would need a new display
  back end in Emacs, not configuration.
- What a Linux daemon *can* show on Windows:
  - WSLg frames, the current =mcqueenix= setup (see the WSLg decisions in
    [[file:../ARCHITECTURE.md][ARCHITECTURE.md]]);
  - terminal frames through =wsl.exe emacsclient -t=.
- The bridge therefore inverts the model, like VS Code's remote mode:
  - *front*: the native Emacs owns Lisp, buffers and frames;
  - *back*: Linux owns files, processes and, optionally, a worker Emacs.

** What TRAMP moves, and what it does not

- TRAMP is the core: a buffer visiting =/wsl:NixOS:/path= reads, writes and
  starts its programs on the Linux side.
  - =default-directory= decides where a process runs, so compile, Magit,
    Eglot and Org Babel follow the buffer with no extra code.
- TRAMP moves *I/O and subprocesses*; it does not move *Lisp*.
  - Org's parser, the agenda, export and Org-roam's indexing still run in
    the front end.
- So the two slow things split cleanly:
  - *slow processes* (LSP, Git, compilers): solved by layers 1–4;
  - *slow Lisp over many files* (agenda, Org-roam over a large tree):
    TRAMP makes this /slower/, one round trip per file operation; only
    layer 5 helps.

** Why the cost is process creation                                   :procs:

- Windows starts processes slowly, and Defender scans NTFS file access.
  - Magit runs dozens of =git= calls per refresh, which is why it feels
    slow on native Windows.
- Plain TRAMP keeps one shell open for file operations: good.
- Without direct processes, TRAMP opens a whole new connection (a fresh
  =wsl.exe=, then a shell handshake) for every asynchronous process.
- Direct async processes still start one =wsl.exe= per process, but skip
  the handshake.
  - =wsl.exe= has a start-up cost of its own (unmeasured; see the benchmark
    task).
- A long-lived server on the back end, multiplexing every operation over
  one pipe, avoids both costs: that is what tramp-rpc does.

* Back ends                                                         :concept:

** WSL (=mcqueenix=)

- Reached by running =wsl.exe -d DISTRO -u USER --exec PROGRAM=, over
  stdio; no network, no SSH server.
- Windows can also read WSL's files as =\\wsl.localhost\DISTRO\…=, but
  through a slow file-sharing protocol; the bridge redirects those names to
  the method.
- Inside a WSL distribution, Windows interop puts =wsl.exe= on =PATH= too,
  so a Linux Emacs there reaches its sibling distributions the same way.
- The distro already runs a kittymacs daemon when the home-manager module's
  =daemon= option is on: the natural worker for layer 5.

** Termux (Android, shared user ID)

- Already handled by [[id:38153b3e-8907-4731-a009-c115ebcd654e][the platform chapter]]: =kittymacs-termux-program= and
  =kittymacs-termux-bin-directory= discover Termux, and its programs are
  local executables.
- No transport and no TRAMP: the back end *is* the local process table.
- The bridge only adds what the platform chapter does not: presets for
  language servers and the capability commands of layer 5.

** nix-on-droid (Android, separate application)

- A second device, not a layer under the port (see the nix-on-droid
  decision in [[file:../ARCHITECTURE.md][ARCHITECTURE.md]]): Nix store paths exist only inside its
  PRoot, under another user ID.
- So it is an SSH back end on =localhost=:
  - its wiki runs =sshd= by hand on port 8022 with key authentication;
  - a pull request (#203) adds supervised services and an OpenSSH module.
- tramp-rpc publishes =aarch64-linux= servers, so this back end can use
  the fast path.

* Architecture: the layers                                          :concept:

- Layers 1–4 are the core: presets and polish around TRAMP.
- Layers 5–7 let the front end run what it cannot run natively.

** 1. Profiles                                                     :profiles:

- One entry per back end; the first whose =:when= holds is active.
  - With none usable, WSL's default distribution, when =wsl.exe= exists.
- Built: =:transport= and =:home=.
- Planned:
  - =:files= — how to read and write (=tramp=, =tramp-rpc=);
  - =:exec= — which programs must run there.
- An option, not a macro, so =setopt= and =private.el= work as everywhere
  else in kittymacs.

** 2. Transport                                                   :transport:

- =wsl=: =wsl.exe -d DISTRO -u USER --exec …=.
- =ssh=: host, port, user (nix-on-droid, homelab machines).
- =local=: Android with Termux paired.
- Gotcha: =wsl.exe='s own messages (=wsl -l=) are UTF-16, or UTF-8 when
  =WSL_UTF8= is set; programs' output passes through as bytes.

** 3. Files                                                           :files:

- A TRAMP method named =wsl=, written like TRAMP's container methods
  (=docker=, =podman=, =toolbox=): a login program plus arguments, on top
  of TRAMP's shell back end.
- File names: =/wsl:mihir@NixOS:/home/mihir/emptynet/flake.nix=.
- Windows share paths are redirected to it.
- Fast path, planned: tramp-rpc with a =wsl.exe= transport.

** 4. Processes                                                       :procs:

- Remote buffers: direct async processes for the =wsl= method; Eglot and
  Magit then start =nil=, =basedpyright=, =git= in Linux.
- Planned: shims for local buffers that need a Linux tool
  (=rg.cmd= → =wsl.exe --exec rg=), with Windows ↔ Linux path translation.
  - Argument translation is where bugs live: shims are the exception, not
    the plan.

** 5. Capability delegation                                       :delegate:

Three tiers, cheapest first.

*** Tier 1: already built in

- A remote =default-directory= sends work to Linux with no new code:
  - Org Babel: =:dir /wsl:mihir@NixOS:~/= on a block or subtree;
  - =compile=, =shell-command=, =async-shell-command=.
- Most "Linux-only operations" need only the method and documented
  presets.

*** Tier 2: one-shot commands

- =kittymacs-bridge-run=: a command line, run in the back end, output in a
  compilation buffer, paths translated.
- Uses: =nix build=, =latexmk=, =just= recipes.
  - The personal overlay already runs EmptyNet's recipes in WSL; that is
    the first caller to generalise.

*** Tier 3: the worker Emacs

- The back end's daemon evaluates forms and returns printed results.
- First transport: =wsl.exe --exec emacsclient --eval FORM= per call.
  - Later, if the per-call cost matters: a TCP server on =localhost=
    (=server-use-tcp=; the server file holds address and key).
- What it is for: Lisp that should run beside the files.
  - Agenda and Org QL views over notes kept in WSL, rendered there.
  - Tangling and export with Linux paths and tools.
  - Long jobs that should outlive the front end.
- How results travel: =prin1= prints a propertised string as
  =#("text" 0 4 (face bold))= and =read= rebuilds it, so faces survive.
- What does not travel: markers, overlays, buffers, closures.
  - Read-only views are easy.
  - Acting on an item (jump, change TODO state) needs a callback: the view
    carries file and position, and the action is sent back as a form.
- Two Lisp images: keep the protocol small (=-eval=, =-tangle=, =-export=,
  =-agenda=).

** 6. Reverse channel                                               :reverse:

- Programs in the back end open files in the front end:
  =EDITOR=emacsclient= with =EMACSCLIENT_TRAMP=/wsl:mihir@NixOS:=.
- =git commit= in a WSL terminal then edits the message in native Emacs.
- Needs the front end's server reachable from Linux (TCP; task below).

** 7. Glue                                                             :glue:

- Terminal: ghostel uses ConPTY on Windows, so a ghostel buffer whose
  shell is =wsl.exe -d NixOS= is a WSL terminal with nothing new.
- Clipboard, =browse-url= and "open externally" go to the front end's OS.
- Meow: no new states; bridge buffers behave like any file buffer.
- Keys: proposed in [[id:4a7b9655-3b18-41f8-8b2c-689836711b6d][the keys chapter]], the single owner of the tree
  (task below).

* Proposed decisions                                               :decision:

** Packaging: mechanism upstream, policy here

- Proposal:
  - the =wsl= TRAMP method and the share-path redirect: a small standalone
    package, then proposed to TRAMP itself, beside the container methods
    in =tramp-container.el=;
  - the =wsl.exe= transport for tramp-rpc: a pull request upstream;
  - presets, profiles, capability commands, keys: this chapter.
- Why:
  - "This configuration is only the policy" ([[id:c5c8e943-3679-4b11-bd79-730d4b6d2dc0][reading guide]], three layers).
  - "Built-in commands over wrappers": once TRAMP ships the method, this
    chapter enables it instead of defining it.
  - The method is useful to every Windows Emacs user; inside kittymacs only
    kittymacs users would find it.
- Path: prototype in this chapter → extract the package → upstream.

** The module declares no packages

- Shipped; recorded in [[file:../ARCHITECTURE.md][ARCHITECTURE.md]].
- Everything here is Emacs's own: TRAMP, =files-x=, =seq=.
- So its tests run with no packages, like the platform module's, and the
  module may load on any machine without installing anything.

** Automatic where there is nothing to configure

- Shipped; recorded in [[file:../ARCHITECTURE.md][ARCHITECTURE.md]].
- The =wsl= method and the share-path redirect turn on by themselves when
  =wsl.exe= is on =exec-path=; on any other machine the module does
  nothing.
- With no back end configured, the active one is WSL's default
  distribution.
- Configured back ends win, so Android and other machines opt in through
  =kittymacs-bridge-backends=.

** Notes live in WSL

- The user is willing to keep Org notes only in WSL, rather than synced to
  both sides.
- Consequence: agenda and Org-roam from the native front end read every
  file over TRAMP, which is slow; tier 3 is the remedy.
- Open until the benchmark says how slow (task below).

* The module                                                           :impl:

- Only Emacs's own libraries; TRAMP is configured once it loads.
  - TRAMP is not loaded at startup: Emacs loads it the first time a remote
    name such as =/wsl:…= is used, and the method is added as it loads, so
    startup pays nothing.

* Finding =wsl.exe= and the distributions                       :impl:transport:

- The bridge needs =wsl.exe= on =exec-path=.
  - Windows' own =System32= puts it there; so does WSL's interop inside a
    distribution, and the test suite's stand-in.
- =wsl.exe --list --quiet= names the installed distributions.
  - It writes UTF-16 (little-endian, CRLF line ends) unless =WSL_UTF8=1=,
    so the bytes are read raw and decoded by looking for zero bytes, which
    UTF-8 text never contains.
  - The default distribution is listed first (unverified on a real Windows
    machine; see the live-trial task).
- The list is cached: a call to =wsl.exe= is not free, and it changes only
  when you install or remove a distribution.
  - =C-u M-x kittymacs-bridge-wsl-distros= rereads it.

#+begin_src emacs-lisp
(defcustom kittymacs-bridge-wsl-program "wsl.exe"
  "The program that runs commands in a WSL distribution."
  :type 'string
  :group 'kittymacs-bridge)

(defun kittymacs-bridge-wsl-available-p ()
  "Return the full name of `kittymacs-bridge-wsl-program', or nil."
  (executable-find kittymacs-bridge-wsl-program))

(defun kittymacs-bridge--decode-wsl-output (bytes)
  "Decode BYTES that wsl.exe printed itself: UTF-16LE, or UTF-8 with WSL_UTF8."
  (decode-coding-string bytes (if (string-search "\0" bytes) 'utf-16le 'utf-8)))

(defun kittymacs-bridge--parse-wsl-list (text)
  "Return the distribution names in TEXT, the output of wsl.exe --list --quiet."
  (seq-remove #'string-empty-p
              (mapcar #'string-trim
                      (split-string (string-replace "\ufeff" "" text) "[\r\n]+"))))

(defvar kittymacs-bridge--wsl-distros nil
  "The installed WSL distributions, the default first, once read.")

(defun kittymacs-bridge-wsl-distros (&optional refresh)
  "Return the installed WSL distributions, the default first.
The list is read once; REFRESH, or a prefix argument, reads it again."
  (interactive "P")
  (when (or refresh (null kittymacs-bridge--wsl-distros))
    (setq kittymacs-bridge--wsl-distros
          (when (kittymacs-bridge-wsl-available-p)
            (with-temp-buffer
              (set-buffer-multibyte nil)
              (let ((coding-system-for-read 'binary)
                    (default-directory temporary-file-directory))
                (when (eql 0 (call-process kittymacs-bridge-wsl-program nil t nil
                                           "--list" "--quiet"))
                  (kittymacs-bridge--parse-wsl-list
                   (kittymacs-bridge--decode-wsl-output (buffer-string)))))))))
  (when (called-interactively-p 'interactive)
    (message "WSL distributions: %s"
             (if kittymacs-bridge--wsl-distros
                 (string-join kittymacs-bridge--wsl-distros ", ")
               "none")))
  kittymacs-bridge--wsl-distros)

#+end_src

* The =wsl= method                                                :impl:files:

- A TRAMP /method/ is a recipe for reaching a machine: what to run locally,
  and which shell to drive at the other end.
  - TRAMP's container methods (=docker=, =podman=, =toolbox=) are the model:
    a login program and its arguments, on top of TRAMP's shell back end.
- Each key, in order:
  - =tramp-login-program=: what TRAMP starts, =wsl.exe=;
  - =tramp-login-args=: its arguments; =%h= is the host (the distribution),
    =%u= the user, =%l= the remote shell with its login arguments;
    - TRAMP drops an argument pair whose placeholder is empty, so a name
      without a user leaves out =-u=;
  - =tramp-direct-async=: what follows the login arguments for a direct
    process (next section);
    - TRAMP drops the =--exec %l= pair there, since =%l= is empty, so
      =--exec= must come back in this list: without it =wsl.exe= hands its
      arguments to your login shell as one command line, and a =cd= in it
      would not reach the command that follows (caught by the test suite);
  - =tramp-remote-shell= and friends: the shell TRAMP drives, =/bin/sh=,
    which NixOS still provides.
- =setf= on =alist-get= replaces an earlier definition, so enabling twice is
  harmless.
- Completion: after =/wsl:= TRAMP asks the function named here for hosts,
  and gets the distribution list.
- On Windows TRAMP starts the login program through =cmdproxy.exe=, not
  =/bin/sh=; that path is not exercised by the Linux tests (live-trial task).

#+begin_src emacs-lisp
(defun kittymacs-bridge--wsl-completion (&rest _)
  "Offer the installed WSL distributions as host names after /wsl:."
  (mapcar (lambda (distro) (list nil distro)) (kittymacs-bridge-wsl-distros)))

(defun kittymacs-bridge-enable-wsl-method ()
  "Teach TRAMP the `wsl' method, so /wsl:USER@DISTRO:/path visits a file in WSL."
  (interactive)
  (require 'tramp)
  (setf (alist-get "wsl" tramp-methods nil nil #'equal)
        `((tramp-login-program ,kittymacs-bridge-wsl-program)
          (tramp-login-args (("-d" "%h") ("-u" "%u") ("--exec" "%l")))
          (tramp-direct-async ("--exec" "/bin/sh" "-c"))
          (tramp-remote-shell "/bin/sh")
          (tramp-remote-shell-login ("-l"))
          (tramp-remote-shell-args ("-i" "-c"))))
  (tramp-set-completion-function "wsl" '((kittymacs-bridge--wsl-completion "")))
  (kittymacs-bridge--apply-direct-async))

#+end_src

* Starting processes directly                                     :impl:procs:

- By default TRAMP starts an asynchronous remote process by opening a whole
  new connection and typing the command into its shell.
- A /direct/ process skips that: TRAMP runs =wsl.exe -d DISTRO --exec
  /bin/sh -c COMMAND= itself, one process per command.
- TRAMP asks for it per connection, through a /connection-local/ variable,
  =tramp-direct-async-process=: a value that applies only in buffers whose
  =default-directory= matches some criteria, here every =wsl= connection.
- What it costs: no password prompts in that process (WSL asks for none),
  and no direct processes over multiple hops (=/wsl:…|sudo:…=); TRAMP falls
  back by itself there.
- Off with =(setopt kittymacs-bridge-wsl-direct-async nil)=; the =:set=
  applies it to connections opened from then on.

#+begin_src emacs-lisp
(defun kittymacs-bridge--apply-direct-async ()
  "Make `tramp-direct-async-process' follow the option on `wsl' connections."
  (connection-local-set-profile-variables
   'kittymacs-bridge-wsl
   `((tramp-direct-async-process . ,(bound-and-true-p kittymacs-bridge-wsl-direct-async))))
  (connection-local-set-profiles '(:application tramp :protocol "wsl")
                                 'kittymacs-bridge-wsl))

(defcustom kittymacs-bridge-wsl-direct-async t
  "Non-nil to start processes in WSL buffers directly, without TRAMP's shell."
  :type 'boolean
  :group 'kittymacs-bridge
  :initialize #'custom-initialize-default
  :set (lambda (symbol value)
         (set-default-toplevel-value symbol value)
         (when (featurep 'tramp) (kittymacs-bridge--apply-direct-async))))

(with-eval-after-load 'tramp
  (when (kittymacs-bridge-wsl-available-p)
    (kittymacs-bridge-enable-wsl-method)))

#+end_src

* Back ends                                                    :impl:profiles:

- =kittymacs-bridge-backends= lists the back ends, best first; each is a
  name and a property list:
  - =:when=: a function of no arguments; the entry counts only when it
    returns non-nil (always, when absent);
  - =:transport=: =(wsl :distro D :user U)=, =(ssh :host H :port P :user U)=
    or =(local)=;
  - =:home=: where the commands start, =~/= by default.
- With no usable entry, the active back end is WSL's default distribution,
  when there is a =wsl.exe=.
- Examples for =private.el=:

#+begin_src emacs-lisp :tangle no
(setopt kittymacs-bridge-backends
        '((mcqueenix :when (lambda () (eq system-type 'windows-nt))
                     :transport (wsl :distro "NixOS" :user "mihir"))
          (droid :when (lambda () (eq system-type 'android))
                 :transport (ssh :host "localhost" :port 8022 :user "nix-on-droid"))))
#+end_src

- =kittymacs-bridge-root= turns a back end into the prefix that reaches it:
  =/wsl:mihir@NixOS:=, =/ssh:nix-on-droid@localhost#8022:=, or nothing for a
  local one.

#+begin_src emacs-lisp
(defcustom kittymacs-bridge-backends nil
  "Linux back ends, best first; the first usable one is active.
Each entry is (NAME . PLIST) with the keys :when (a function of no
arguments; the entry is usable when it returns non-nil, or when :when
is absent), :transport ((wsl :distro DISTRO :user USER), (ssh :host
HOST :port PORT :user USER) or (local)) and :home (a directory, \"~/\"
when absent).  With no usable entry, WSL's default distribution is
active when wsl.exe is available."
  :type '(alist :key-type symbol :value-type plist)
  :group 'kittymacs-bridge)

(defun kittymacs-bridge--usable-p (plist)
  "Non-nil when the back end described by PLIST may be used here."
  (let ((test (plist-get plist :when)))
    (or (null test) (funcall test))))

(defun kittymacs-bridge-active ()
  "Return the active back end as (NAME . PLIST), or nil when there is none."
  (or (seq-find (lambda (entry) (kittymacs-bridge--usable-p (cdr entry)))
                kittymacs-bridge-backends)
      (when-let* (((kittymacs-bridge-wsl-available-p))
                  (distro (car (kittymacs-bridge-wsl-distros))))
        `(wsl :transport (wsl :distro ,distro)))))

(defun kittymacs-bridge-root (&optional backend)
  "Return the file name prefix that reaches BACKEND, the active one by default.
It is empty for a local back end, and nil when there is no back end."
  (when-let* ((backend (or backend (kittymacs-bridge-active))))
    (let* ((transport (plist-get (cdr backend) :transport))
           (args (cdr transport))
           (user (plist-get args :user))
           (at (if user (concat user "@") "")))
      (pcase (car transport)
        ('wsl (format "/wsl:%s%s:" at
                      (or (plist-get args :distro)
                          (car (kittymacs-bridge-wsl-distros))
                          (user-error "No WSL distribution is installed"))))
        ('ssh (format "/ssh:%s%s%s:" at (plist-get args :host)
                      (if-let* ((port (plist-get args :port))) (format "#%s" port) "")))
        ('local "")
        (_ (user-error "Unknown transport in back end %s: %S" (car backend) transport))))))

(defun kittymacs-bridge-home ()
  "Return the active back end's home directory as a file name."
  (if-let* ((backend (kittymacs-bridge-active)))
      (concat (kittymacs-bridge-root backend) (or (plist-get (cdr backend) :home) "~/"))
    (user-error "No Linux back end here; see `kittymacs-bridge-backends'")))

(defun kittymacs-bridge-find-file ()
  "Visit a file in the active back end, starting from its home directory."
  (interactive)
  (let ((default-directory (file-name-as-directory (kittymacs-bridge-home))))

* Windows share paths                                             :impl:files:

- Windows names WSL's files =\\wsl.localhost\DISTRO\path=, or the older
  =\\wsl$\DISTRO\path=.
  - Explorer passes such names to "Open with"; Emacs reads them through
    Windows' slow file-sharing protocol, and every program it starts runs
    in Windows.
- =kittymacs-bridge-unc-mode= rewrites them to =/wsl:DISTRO:/path= before
  any file operation sees them, so the buffer becomes an ordinary =wsl=
  buffer.
- The mechanism is a /file name handler/: an entry in
  =file-name-handler-alist= whose regular expression matches the name, and
  a function that every file primitive (=expand-file-name=,
  =insert-file-contents=, …) calls instead of doing the work itself.
  - The handler translates every share name among the arguments and calls
    the primitive again.
  - It inhibits itself while it does, so a name it cannot translate (a share
    with no distribution) falls through to Emacs instead of looping.
- Both separators and any letter case match: Windows paths are
  case-insensitive.
- The mode turns on by itself on Windows when =wsl.exe= is available.

#+begin_src emacs-lisp
(defconst kittymacs-bridge--unc-prefix-regexp
  (rx bos (= 2 (any "/\\")) (any "Ww") (any "Ss") (any "Ll") (any ".$"))
  "Matches the start of every WSL share name; `file-name-handler-alist' uses it.")

(defconst kittymacs-bridge--unc-regexp
  (rx bos (= 2 (any "/\\")) (any "Ww") (any "Ss") (any "Ll")
      (or "$" (seq "." (any "Ll") (any "Oo") (any "Cc") (any "Aa") (any "Ll")
                   (any "Hh") (any "Oo") (any "Ss") (any "Tt")))
      (any "/\\") (group (+ (not (any "/\\")))) (group (* anychar)) eos)
  "Matches a WSL share name; the groups are the distribution and the path.")

(defun kittymacs-bridge-unc-to-tramp (name)
  "Return the /wsl: name for NAME, a \\\\wsl.localhost\\ or \\\\wsl$\\ name, else nil."
  (when (string-match kittymacs-bridge--unc-regexp name)
    (let ((distro (match-string 1 name))
          (path (string-replace "\\" "/" (match-string 2 name))))
      (concat "/wsl:" distro ":" (if (string-empty-p path) "/" path)))))

(defun kittymacs-bridge--unc-handler (operation &rest args)
  "Run file OPERATION with every WSL share name in ARGS as a /wsl: name."
  (let ((inhibit-file-name-handlers
         (cons #'kittymacs-bridge--unc-handler
               (and (eq inhibit-file-name-operation operation)
                    inhibit-file-name-handlers)))
        (inhibit-file-name-operation operation))
    (apply operation
           (mapcar (lambda (arg)
                     (or (and (stringp arg) (kittymacs-bridge-unc-to-tramp arg)) arg))
                   args))))

(define-minor-mode kittymacs-bridge-unc-mode
  "Visit \\\\wsl.localhost\\ and \\\\wsl$\\ names through the `wsl' method."
  :global t
  :group 'kittymacs-bridge
  (setq file-name-handler-alist
        (rassq-delete-all #'kittymacs-bridge--unc-handler file-name-handler-alist))
  (when kittymacs-bridge-unc-mode
    (push (cons kittymacs-bridge--unc-prefix-regexp #'kittymacs-bridge--unc-handler)
          file-name-handler-alist)))

(when (and (eq system-type 'windows-nt) (kittymacs-bridge-wsl-available-p))
  (kittymacs-bridge-unc-mode 1))

#+end_src

* Risks and unknowns                                                   :risk:

- Native Windows: TRAMP drives =cmdproxy.exe=, not =/bin/sh=, to start
  =wsl.exe=; the pipe handshake itself is tested on Linux.
- =wsl.exe= start-up cost multiplies with every direct process.
- Quoting through =wsl.exe= for anything passed as an argument.
- WSL2 runs in a VM: Unix sockets do not cross to Windows (as far as known,
  unverified), so servers talk over stdio or TCP.
- Org-roam over TRAMP: its sync reads every file remotely.
- Two Emacs images can drift: worker and front end should run the same
  kittymacs revision.
