Ownership: *user configuration*.

- [[https://github.com/dakra/ghostel][ghostel]] by Daniel Kraus is the terminal emulator.
- This chapter chooses its settings, wires it to the packages already in
  use and teaches it Meow's states; the integration recipes follow
  ghostel's manual.

* What this gives you

- =SPC o e= opens a real terminal inside Emacs: programs cannot tell it from
  a terminal window, so =htop=, =vim=, =less=, =lazygit=, a TUI coding agent,
  a test runner that draws progress bars and asks =y/n= all behave.
- The terminal knows:
  - where it is: =cd= moves Emacs's directory with it;
  - what you ran: =SPC m n= jumps between prompts;
  - what it printed: links are clickable, colours exact.
- Ghostel is a thin Emacs Lisp layer over =libghostty-vt=, the terminal
  engine behind [[https://ghostty.org/][Ghostty]].
  - The engine is a small native library: the first =SPC o e= offers to
    download it, about a megabyte, once per machine.

* Where the native module lives

- The native module is kept in =var/ghostel/=, not beside ghostel's package
  directory (its default) under =var/elpa/=.
  - =M-x package-upgrade= rewrites =var/elpa/=; outside it, upgrading ghostel
    never deletes a library this Emacs has already mapped into memory.
  - This is the one thing this chapter must decide *before* ghostel loads.
- The module is downloaded on the first =SPC o e=, after asking; nothing is
  fetched when Emacs starts or when this file loads.

#+begin_src emacs-lisp
(defcustom kittymacs-terminal-module-directory
  (expand-file-name "ghostel/" kittymacs-var-dir)
  "Directory holding ghostel's native module.
Kept outside `package-user-dir' so upgrading the package never deletes a
module file this Emacs has already loaded."
  :type 'directory)

(defun kittymacs-terminal-module-installed-p ()
  "Return non-nil when ghostel's native module has been downloaded or built.
Nil also when this Emacs was built without dynamic module support, which
is what the terminal needs."
  (and module-file-suffix
       (file-exists-p
        (expand-file-name (concat "ghostel-module" module-file-suffix)
                          kittymacs-terminal-module-directory))))

#+end_src

** Not on Android

- Ghostel needs two things Android does not grant:
  - =git=: it is installed with =:vc=, so the first start clones it, and the
    Android port ships no =git=;
  - a native module: upstream publishes prebuilt ones for the desktop
    platforms, none for =android-aarch64=, and the Android port is commonly
    built without dynamic module support, leaving =module-file-suffix= nil:
    no module could load however it arrived.
- Neither is worth an error on every start, so ghostel is not installed
  there and Eshell takes =SPC o e=.
  - Eshell is Lisp, needs no module and no subprocess to start, and where
    Termux is paired it runs Termux's programs like any other shell.
  - A genuine loss, and the honest one to take: Eshell is not a terminal and
    will not run =htop= or a full-screen editor.

#+begin_src emacs-lisp
(defcustom kittymacs-terminal-ghostel
  (not (eq system-type 'android))
  "Whether ghostel provides the terminal.
Off on Android, which has neither `git' for ghostel's `:vc' checkout nor a
prebuilt native module.  `kittymacs-terminal-open' falls back to Eshell
whenever this is nil."
  :type 'boolean)
#+end_src

* The terminal

- A terminal closes its buffer when the shell exits, asking first if a
  command is still running.
- Terminals opened with =SPC o p= carry their project's name;
  =ghostel-buffer-name-function= can make them follow the title or the
  directory instead.
- Five megabytes of scrollback is kept, searchable with =consult-line= and
  =isearch= like any buffer.
- OSC 52 is left off: it lets a program in the terminal write your system
  clipboard, convenient over SSH and unpleasant when the output you just
  =cat='d was hostile. Turn it on per machine in =private.el=.
- Ghostel and its Consult extension are installed from their *repository*,
  with =:vc=, not from an archive.
  - A =:vc= package is an ordinary Git checkout under =var/elpa/=, about ten
    megabytes, cloned once; =M-x package-vc-upgrade= updates it.
  - MELPA carries both, and upstream's README installs from it. Moving
    them to =:ensure t= means deleting the two checkouts on every machine:
    package.el counts a checkout as installed and would keep it.

#+begin_src emacs-lisp
(use-package ghostel
  :vc (:url "https://github.com/dakra/ghostel" :lisp-dir "lisp" :rev :newest)
  :if kittymacs-terminal-ghostel
  :defer t
  :commands (ghostel ghostel-project ghostel-other ghostel-list-buffers
             ghostel-create ghostel-exec ghostel-compile ghostel-recompile)
  :custom
  (ghostel-module-directory kittymacs-terminal-module-directory)
  (ghostel-kill-buffer-on-exit t)
  (ghostel-query-before-killing 'auto)
  (ghostel-max-scrollback (* 5 1024 1024))
  (ghostel-scroll-on-input t)
  (ghostel-enable-osc52 nil)
  (ghostel-detect-password-prompts t)
  :config
  ;; Ghostel runs $SHELL, which native Windows does not set; follow the shell
  ;; the platform chapter picked instead of ghostel's /bin/sh fallback.
  (when (and (eq system-type 'windows-nt) (not (getenv "SHELL")))
    (setopt ghostel-shell (or explicit-shell-file-name shell-file-name)))

  ;; A shell inside the terminal can call these Emacs commands by name:
  ;;   ghostel_cmd find-file README.md
  ;;   ghostel_cmd magit-status
  ;; Only the listed commands can be reached, and every argument is a string.
  (dolist (command '(("magit-status" magit-status)
                     ("find-file-other-frame" find-file-other-frame)
                     ("treemacs-find-file" treemacs-find-file)))
    (add-to-list 'ghostel-eval-cmds command))

  ;; Integrations that ship with ghostel and only make sense once it is here:
  ;; ghostel: links in Org, bookmarks that reopen a terminal where it was,
  ;; terminals that survive a desktop session, and Lisp input methods
  ;; (Hangul, Quail) composing into the terminal rather than the buffer.
  (require 'ghostel-org nil t)
  (require 'ghostel-bookmark nil t)
  (require 'ghostel-desktop nil t)
  (when (require 'ghostel-ime nil t)
    (add-hook 'ghostel-mode-hook #'ghostel-ime-mode)))

* Meow in the terminal

- A terminal is the one buffer where the keys are not ours: =d= must delete a
  character in =vim=, not a selection.
- So terminals start in *Insert* state, and ghostel's semi-char mode forwards
  almost everything to the program.
  - Emacs keeps =C-c=, =C-x=, =C-u=, =C-h=, =M-x= and =M-:= (ghostel's
    =ghostel-keymap-exceptions=), so =C-c C-SPC= still opens the leader.
- =ESC= *freezes* the terminal: Meow enters Normal state, ghostel enters copy
  mode, and the whole scrollback becomes an ordinary read-only buffer to
  select, search and copy from with Meow's grammar.
- =i= thaws it: output resumes and the keys go back to the shell.
- The two hooks below keep those two ideas in step; being buffer-local, they
  only apply to a terminal.

#+begin_src emacs-lisp
(defun kittymacs-terminal--freeze ()
  "Freeze the terminal when Meow leaves Insert state.
The buffer becomes read-only, so Meow's grammar can select its output."
  (when (and (derived-mode-p 'ghostel-mode) (not buffer-read-only))
    (ghostel-readonly-enter)))

(defun kittymacs-terminal--thaw ()
  "Give the keyboard back to the terminal when Meow enters Insert state."
  (when (and (derived-mode-p 'ghostel-mode) buffer-read-only)
    (ghostel-semi-char-mode)))

(defun kittymacs-terminal--meow-setup ()
  "Keep Meow's state and ghostel's input mode in step in this buffer."
  (add-hook 'meow-insert-exit-hook #'kittymacs-terminal--freeze nil t)
  (add-hook 'meow-insert-enter-hook #'kittymacs-terminal--thaw nil t))

(add-hook 'ghostel-mode-hook #'kittymacs-terminal--meow-setup)

#+end_src

** Where the escape key goes

- =ESC= is the one genuinely ambiguous key:
  - in a shell it should leave Insert state;
  - in =vim=, =less=, =htop= or a full-screen coding agent it *is* the
    program's most important key; stealing it makes the program unusable.
- Those programs all switch the terminal to its /alternate screen/, so
  =auto= sends =ESC= to the program exactly while one is running, and
  otherwise leaves Insert state.
  - When the guess is wrong, =SPC m ESC= toggles this buffer for its
    lifetime.
- Outside a terminal the command is plain =meow-insert-exit=; nothing else
  changes.

#+begin_src emacs-lisp
(defcustom kittymacs-terminal-escape 'auto
  "Where the escape key goes in a terminal while Meow is in Insert state.
`auto'     to the program while it is drawing a full-screen interface
           (vim, less, htop, a TUI agent), and to Meow otherwise.
`terminal' always to the program.
`meow'     always to Meow, leaving Insert state."
  :type '(choice (const :tag "Full-screen programs only" auto)
                 (const :tag "Always the terminal" terminal)
                 (const :tag "Always Meow" meow)))

(defvar-local kittymacs-terminal--escape nil
  "This buffer's override of `kittymacs-terminal-escape', or nil to follow it.")

(defun kittymacs-terminal--escape-target ()
  "Return `terminal' or `meow': where the escape key should go here."
  (pcase (or kittymacs-terminal--escape kittymacs-terminal-escape)
    ('terminal 'terminal)
    ('meow 'meow)
    (_ (if (ghostel-alt-screen-p) 'terminal 'meow))))

(defun kittymacs-terminal-escape-dwim ()
  "Leave Meow's Insert state, or send escape to a full-screen program."
  (interactive)
  (if (and (derived-mode-p 'ghostel-mode)
           (eq (kittymacs-terminal--escape-target) 'terminal))
      (ghostel-send-key "escape")
    (call-interactively #'meow-insert-exit)))

(defun kittymacs-terminal-toggle-escape ()
  "Switch where the escape key goes in this terminal, and say where."
  (interactive)
  (unless (derived-mode-p 'ghostel-mode)
    (user-error "This is not a terminal buffer"))
  (setq kittymacs-terminal--escape
        (if (eq (kittymacs-terminal--escape-target) 'terminal) 'meow 'terminal))
  (message "Escape %s"
           (if (eq kittymacs-terminal--escape 'terminal)
               "now goes to the program in the terminal"
             "now leaves Insert state")))

#+end_src

- Terminals start in Insert; a finished =ghostel-compile= run is a report, so
  it starts in Motion like every other application buffer.
- Rebinding =ESC= in Meow's Insert-state map lets the command above run at
  all: that emulation map is consulted before the terminal's own keys.

#+begin_src emacs-lisp
(with-eval-after-load 'meow
  (dolist (entry '((ghostel-mode . insert)
                   (ghostel-compile-view-mode . motion)))
    (add-to-list 'meow-mode-state-list entry))
  (keymap-set meow-insert-state-keymap "<escape>" #'kittymacs-terminal-escape-dwim))

#+end_src

* Opening one

- =SPC o e= and =SPC o p= are thin wrappers over =ghostel= and
  =ghostel-project=, for one reason: the native module is downloaded on first
  use.
  - A user who declines would otherwise meet
    =Symbol's function definition is void: ghostel--new= instead of a
    sentence saying what is missing and which command installs it.

** MSYS2 on Windows

- PowerShell stays the ordinary shell; =SPC o m= is the separate, explicit
  choice of an MSYS2 UCRT64 login shell, where a Windows machine keeps its
  Unix tools.
  - =MSYSTEM= selects the environment and =CHERE_INVOKING= keeps the
    directory you were in, both for the child process only: Emacs's own
    environment is untouched.
  - [[file:30-platform.org][The platform chapter]] owns =kittymacs-msys2-root=.
- Unlike the terminal this replaces, nothing here translates paths or
  substitutes a POSIX helper: ghostel talks to Windows ConPTY directly.

#+begin_src emacs-lisp
(defun kittymacs-terminal--without-module (error)
  "Re-signal ERROR, or explain that the native module is missing."
  (if (kittymacs-terminal-module-installed-p)
      (signal (car error) (cdr error))
    (user-error "The terminal needs its native module: %s"
                (substitute-command-keys "\\[ghostel-download-module]"))))

(defun kittymacs-terminal-open (&optional arg)
  "Open a terminal.  With prefix ARG, open another one.
Ghostel offers to fetch its native module the first time; declining that
offer leaves the terminal unavailable, so say so in words.  Where ghostel
is not used at all, Eshell answers this key instead."
  (interactive "P")
  (if (not kittymacs-terminal-ghostel)
      (eshell arg)
    (condition-case error (ghostel arg)
      (void-function (kittymacs-terminal--without-module error)))))

(defun kittymacs-terminal-project (&optional arg)
  "Open a terminal at the current project's root.  ARG is passed through."
  (interactive "P")
  (if (not kittymacs-terminal-ghostel)
      (kittymacs-eshell-project)
    (condition-case error (ghostel-project arg)
      (void-function (kittymacs-terminal--without-module error)))))

(defun kittymacs-terminal-msys2 (&optional arg)
  "Open an MSYS2 UCRT64 login shell in a terminal.
With prefix ARG, create another one instead of reusing the existing buffer."
  (interactive "P")
  (unless (eq system-type 'windows-nt)
    (user-error "The MSYS2 terminal is for native Windows Emacs"))
  (let ((bash (expand-file-name "usr/bin/bash.exe" kittymacs-msys2-root)))
    (unless (file-executable-p bash)
      (user-error "MSYS2 Bash not found at %s; set `kittymacs-msys2-root' in private.el"
                  bash))
    (let ((ghostel-shell (list bash "--login" "-i"))
          (ghostel-environment (append '("MSYSTEM=UCRT64" "CHERE_INVOKING=1")
                                       ghostel-environment))
          (ghostel-buffer-name "*ghostel: msys2*"))
      (ghostel arg))))

#+end_src

* Integrations with the rest of this configuration

- *Projects.* =ghostel-project= opens a terminal at the project root, named
  after the project, so =SPC o p= in any file lands where builds are run.
  - It joins the switch-project menu (=C-x p p=) on =t=.
  - The key is named here because =ghostel-project= has none in
    =project-prefix-map=; without one the menu shows the entry but cannot
    run it.
- *Consult.* =consult-ghostel= picks a terminal with live preview, as
  =SPC b b= picks a buffer, and creates one when you type a new name.
  - =consult-ghostel-history= completes against the *shell's own* history
    (bash, zsh, fish and nushell) and types the choice at the prompt without
    submitting it, so you can edit before running.
  - Loading it also teaches =consult-line= about soft-wrapped terminal rows,
    so a path that wrapped mid-word is still findable.
  - It lives in ghostel's own repository and is fetched from there, as above;
    its code is in =extensions/consult-ghostel/=, which the =:lisp-dir= below
    names.
  - The Consult it needs is already installed by [[file:60-completion.org][the completion chapter]].
  - On Emacs 31, package-vc builds a checkout from the first spec it finds
    for the package's name, and an archive's spec counts:
    - MELPA's spec for =consult-ghostel= is only the URL, so the build used
      package-vc's guess, ghostel's =lisp/=, and =consult-ghostel= was never
      defined;
    - package-vc reads =package-vc-selected-packages= before the archives,
      so the spec goes there whenever package-vc loads, and installs,
      rebuilds and upgrades all use it.
  - =M-x package-vc-rebuild RET consult-ghostel= repairs a checkout already
    built from =lisp/= (=SPC o E= fails: =consult-ghostel= is not defined).

#+begin_src emacs-lisp
(when kittymacs-terminal-ghostel
  (with-eval-after-load 'project
    (add-to-list 'project-switch-commands '(ghostel-project "Terminal" ?t) t)))

(defvar package-vc-selected-packages)
(when kittymacs-terminal-ghostel
  (with-eval-after-load 'package-vc
    (add-to-list 'package-vc-selected-packages
                 '(consult-ghostel :url "https://github.com/dakra/ghostel"
                                   :lisp-dir "extensions/consult-ghostel"))))

(use-package consult-ghostel
  :vc (:url "https://github.com/dakra/ghostel"
       :lisp-dir "extensions/consult-ghostel" :rev :newest)
  :if kittymacs-terminal-ghostel
  :after (ghostel consult)
  :demand t
  :bind (:map ghostel-semi-char-mode-map
         ("C-c h" . consult-ghostel-history)))

#+end_src

- *Eshell.* [[file:35-shells.org][Eshell]] is a Lisp shell and cannot draw a full-screen
  program, so it hands those to a real terminal:
  - the commands in =eshell-visual-commands= (=htop=, =less=, =vim=,
    =git log=) open in a ghostel buffer;
  - =ghostel foo= at the Eshell prompt does the same for anything else, once.
- *M-M-x shell and REPLs.* Comint's colour handling understands the eight ANSI
  colours; ghostel's parser understands everything a modern program emits:
  true colour, curly and coloured underlines, clickable =OSC 8= links, and the
  directory the shell reports.
  - It is a stream filter, not a terminal: full-screen programs still belong
    in =SPC o e=.
  - It needs the native module, so it is on only once that exists; a machine
    that has never opened a terminal keeps Emacs's own handling and nothing
    breaks.

#+begin_src emacs-lisp
(with-eval-after-load 'eshell
  (when (require 'ghostel-eshell nil t)
    (ghostel-eshell-visual-command-mode 1)))

(defun kittymacs-terminal--comint-colours ()
  "Render this comint buffer's output with ghostel's terminal parser."
  (when (and (kittymacs-terminal-module-installed-p)
             (require 'ghostel-comint nil t))
    (ghostel-comint-mode 1)))

(add-hook 'shell-mode-hook #'kittymacs-terminal--comint-colours)

#+end_src

- *Compiling.* =ghostel-compile= runs a build in a real terminal, then
  presents it as a =compilation-mode= report.
  - While it runs: coloured output and progress bars, and =C-c C-j= when the
    command wants an answer.
  - When it finishes: =next-error= and clickable file references.
  - =SPC m t= runs it in any programming buffer.
  - Emacs's own =compile= is left alone, because =SPC m c=, Flymake and
    =project-compile= all go through it; =(ghostel-compile-global-mode 1)= in
    =private.el= routes those through the terminal too.

(autoload 'ghostel-recompile "ghostel-compile" "Re-run the last command." t)

  (require 'ghostel-compile nil t))

      (keymap-set map "t" (cons "compile in a terminal" #'ghostel-compile))
      (keymap-set map "T" (cons "recompile in a terminal" #'ghostel-recompile))
      (kittymacs-refresh-localleaders))))

#+end_src

- *Themes.* Ghostel paints the terminal's sixteen colours from the active
  theme and repaints them on Emacs's own =enable-theme-functions=, so
  =SPC t t= changes the terminal with everything else; nothing is needed
  here.
- *Frames.* A terminal is a buffer you work in, so [[file:45-frames.org][frames-only mode]] gives it
  its own OS window: =SPC o e= from a second project puts its terminal beside
  that project's code, not on top of it.

* Try it

- =SPC o e=, then =htop=; =q= quits it. Now =SPC o e= and =vim=: =ESC= reaches
  vim, because vim is drawing a full screen; =:q= leaves, and =ESC= means Meow
  again.
- Run something long, press =ESC=: output freezes; you are in Normal state.
  Select a line with =x=, copy it with =y=, press =i= to thaw.
- =cd= somewhere in the terminal, then =SPC f f=: Emacs offers files from the
  shell's directory.
- Type =ghostel_cmd find-file README.md= in the terminal: Emacs opens it.
- =SPC o E= lists every terminal with a preview; a new name creates one.
