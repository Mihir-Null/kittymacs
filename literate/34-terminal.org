#+TITLE: The terminal: ghostel
#+FILETAGS: :apps:
#+STARTUP: overview
#+PROPERTY: header-args:emacs-lisp :tangle ../lisp/kittymacs-terminal.el :eval never :comments no :padline no :mkdirp yes

- =SPC o e= opens a real terminal inside Emacs: programs cannot tell it from a terminal window, so =htop=, =vim=, =less=, =lazygit=, a TUI coding agent, or a test runner that draws progress bars and asks =y/n= all behave.
  + It knows where it is: =cd= moves Emacs's directory with it.
  + It knows what you ran: =SPC m n= jumps between prompts.
  + It knows what it printed: links are clickable, colours exact.
- [[https://github.com/dakra/ghostel][ghostel]] by Daniel Kraus is the emulator: a thin Emacs Lisp layer over =libghostty-vt=, the engine behind [[https://ghostty.org/][Ghostty]].
  + This chapter chooses its settings, wires it to the packages already in use and teaches it Meow's states; the integration recipes follow ghostel's manual.
- Leans on [[id:afa6b7fd-742a-4c15-86a6-32e3e8027b0e][the platform chapter]] (the system shell, =kittymacs-msys2-root=) and [[id:e5942eb0-4389-447d-9317-d9178adcaaae][the leader]]; falls back to Eshell from [[id:d2e0bc37-0bd4-4b28-a8ee-04f94ac451f8][the shells chapter]] without requiring it.
- Read [[id:a1607a41-b741-428a-9de3-c16e7c8d3ecc][the editing chapter]] first, then [[*Meow in the terminal]]: here Meow's states decide who gets each key.

* Where the native module lives :decision:
:PROPERTIES:
:ID: 7fb4e31f-ca2c-4bc1-94f0-c0e3e94ac76e
:END:

- The engine is a small native library, about a megabyte: the first =SPC o e= offers to download it, once per machine.
  + Nothing is fetched when Emacs starts or when this file loads.
- It is kept in =var/ghostel/=, not beside ghostel's package directory (its default) under =var/elpa/=.
  + =M-x package-upgrade= rewrites =var/elpa/=; outside it, upgrading ghostel never deletes a library this Emacs has already mapped into memory.
  + The one thing this chapter must decide /before/ ghostel loads.
- =kittymacs-terminal-module-installed-p= answers whether the module is there; it is also nil when this Emacs has no dynamic module support.

;; module sets its options, loads the integrations it ships for Eshell, comint,
;; Org, bookmarks, desktop, input methods and Consult, and bridges its five
;; input modes to Meow's states.

;;; Code:

(require 'kittymacs-defaults)
(require 'kittymacs-leader)
(require 'kittymacs-platform)

(declare-function meow-insert-exit "meow-command" ())

(declare-function ghostel-readonly-enter "ghostel" ())
(declare-function ghostel "ghostel" (&optional arg))
(declare-function ghostel-project "ghostel" (&optional arg))

;; by `init.el', but this module does not require it.

;; Ghostel's options, which `kittymacs-terminal-msys2' binds with `let'.  The

(defvar ghostel-shell)
(defvar ghostel-environment)
(defvar ghostel-buffer-name)

(defgroup kittymacs-terminal nil

* No terminal on Android :android:decision:
:PROPERTIES:
:ID: 00029072-b3ab-471e-990e-f7a7735dc960
:END:

- Ghostel needs a native module, and the Android port is commonly built without dynamic module support, leaving =module-file-suffix= nil: no module could load however it arrived.
  + Upstream does ship an =aarch64-android= module, built for Termux's Emacs.
- That is not worth an error on every start, so =kittymacs-terminal-ghostel= is nil there: ghostel is not installed and Eshell takes =SPC o e=.
  + Eshell is Lisp, needs no module and no subprocess to start, and where Termux is paired it runs Termux's programs like any other shell.
  + A genuine loss, and the honest one to take: Eshell is not a terminal and will not run =htop= or a full-screen editor.

#+begin_src emacs-lisp
(defcustom kittymacs-terminal-ghostel
  (not (eq system-type 'android))
  "Whether ghostel provides the terminal.
Off on Android, whose port is commonly built without the dynamic module
support ghostel needs.  `kittymacs-terminal-open' falls back to Eshell
whenever this is nil."
  :type 'boolean)
#+end_src

* How the terminal behaves

- When the shell exits, its buffer closes; killing a terminal asks first if a command is still running.
- Five megabytes of scrollback, searchable with =consult-line= and =isearch= like any buffer.
- Terminals opened with =SPC o p= carry their project's name; =ghostel-buffer-name-function= can make them follow the title or the directory instead.
- OSC 52 stays off: it lets a program in the terminal write your system clipboard.
  + Convenient over SSH, unpleasant when the output you just =cat='d was hostile.
  + Turn it on per machine in =private.el=.
- Native Windows sets no =$SHELL=, so there the terminal runs the shell [[id:afa6b7fd-742a-4c15-86a6-32e3e8027b0e][the platform chapter]] picked instead of ghostel's =/bin/sh= fallback.
- A shell inside the terminal can call listed Emacs commands by name, such as =ghostel_cmd find-file README.md=.
  + This adds =magit-status=, =find-file-other-frame= and =treemacs-find-file= to =ghostel-eval-cmds=.
  + Only the listed commands can be reached, and every argument is a string.
- Integrations that ship with ghostel load once it does:
  + =ghostel-org=: links to terminals in Org;
  + =ghostel-bookmark=: bookmarks that reopen a terminal where it was;
  + =ghostel-desktop=: terminals that survive a desktop session;
  + =ghostel-ime=: Lisp input methods (Hangul, Quail) compose into the terminal rather than the buffer.
- Ghostel and its Consult extension come from MELPA, as upstream's README installs them; =M-x package-upgrade= updates them like any package.
  + Both declarations sit inside =(when kittymacs-terminal-ghostel ...)=: =:ensure= installs a package even when its =:if= is nil, and Android should not download a terminal it will not run.
  + A Git checkout of either, left by an install made with =:vc=, stays: package.el counts it as installed. =M-x package-delete= =consult-ghostel=, then =ghostel=, and a restart installs MELPA's.

#+begin_src emacs-lisp
(when kittymacs-terminal-ghostel
  (use-package ghostel
    :ensure t
    :defer t
    :commands (ghostel ghostel-project ghostel-other ghostel-list-buffers
               ghostel-create ghostel-exec ghostel-compile ghostel-recompile)
    :custom
    (ghostel-module-directory kittymacs-terminal-module-directory)
    (ghostel-kill-buffer-on-exit t)
    (ghostel-query-before-killing 'auto)
    (ghostel-max-scrollback (* 5 1024 1024))
    (ghostel-scroll-on-input t)
    (ghostel-enable-osc52 nil)
    (ghostel-detect-password-prompts t)
    :config
    ;; Ghostel runs $SHELL, which native Windows does not set; follow the shell
    ;; the platform chapter picked instead of ghostel's /bin/sh fallback.
    (when (and (eq system-type 'windows-nt) (not (getenv "SHELL")))
      (setopt ghostel-shell (or explicit-shell-file-name shell-file-name)))

    ;; A shell inside the terminal can call these Emacs commands by name:
    ;;   ghostel_cmd find-file README.md
    ;;   ghostel_cmd magit-status
    ;; Only the listed commands can be reached, and every argument is a string.
    (dolist (command '(("magit-status" magit-status)
                       ("find-file-other-frame" find-file-other-frame)
                       ("treemacs-find-file" treemacs-find-file)))
      (add-to-list 'ghostel-eval-cmds command))

    ;; Integrations that ship with ghostel and only make sense once it is here:
    ;; ghostel: links in Org, bookmarks that reopen a terminal where it was,
    ;; terminals that survive a desktop session, and Lisp input methods
    ;; (Hangul, Quail) composing into the terminal rather than the buffer.
    (require 'ghostel-org nil t)
    (require 'ghostel-bookmark nil t)
    (require 'ghostel-desktop nil t)
    (when (require 'ghostel-ime nil t)
      (add-hook 'ghostel-mode-hook #'ghostel-ime-mode))))

#+end_src

* Meow in the terminal :meow:
:PROPERTIES:
:ID: d3a778cf-de0a-479b-99a8-09eb5a156ca2
:END:

- A terminal is the one buffer where the keys are not ours: =d= must delete a character in =vim=, not a selection.
- So terminals start in /Insert/ state, and ghostel's semi-char mode forwards almost everything to the program.
  + Emacs keeps =C-c=, =C-x=, =C-u=, =C-h=, =M-x= and =M-:= (ghostel's =ghostel-keymap-exceptions=), so =C-c C-SPC= still opens the leader.
- A finished =ghostel-compile= run is a report, so it starts in /Motion/, like every other application buffer.
- =ESC= /freezes/ the terminal: Meow enters Normal state, ghostel enters copy mode, and the whole scrollback becomes an ordinary read-only buffer to select, search and copy from with Meow's grammar.
- =i= thaws it: output resumes and the keys go back to the shell.
- The two hooks below keep Meow's state and ghostel's input mode in step; being buffer-local, they apply only to a terminal.
- =SPC m= is [[*The terminal's mode menu]]; it lives in Normal state, so =ESC= first.

#+begin_src emacs-lisp
(defun kittymacs-terminal--freeze ()
  "Freeze the terminal when Meow leaves Insert state.
The buffer becomes read-only, so Meow's grammar can select its output."
  (when (and (derived-mode-p 'ghostel-mode) (not buffer-read-only))
    (ghostel-readonly-enter)))

(defun kittymacs-terminal--thaw ()
  "Give the keyboard back to the terminal when Meow enters Insert state."
  (when (and (derived-mode-p 'ghostel-mode) buffer-read-only)
    (ghostel-semi-char-mode)))

(defun kittymacs-terminal--meow-setup ()
  "Keep Meow's state and ghostel's input mode in step in this buffer."
  (add-hook 'meow-insert-exit-hook #'kittymacs-terminal--freeze nil t)
  (add-hook 'meow-insert-enter-hook #'kittymacs-terminal--thaw nil t))

(add-hook 'ghostel-mode-hook #'kittymacs-terminal--meow-setup)

#+end_src

* Where the escape key goes :decision:
:PROPERTIES:
:ID: e504b158-aa89-494a-9f26-6f1235531f25
:END:

- =ESC= is the one genuinely ambiguous key:
  + in a shell it should leave Insert state;
  + in =vim=, =less=, =htop= or a full-screen coding agent it /is/ the program's most important key; stealing it makes the program unusable.
- Those programs all switch the terminal to its /alternate screen/, so =auto= sends =ESC= to the program exactly while one is running, and otherwise leaves Insert state.
  + When the guess is wrong, =SPC m ESC= toggles this buffer for its lifetime.
- =kittymacs-terminal-escape= sets the default:
  + =auto= :: to the program while it draws a full-screen interface, to Meow otherwise;
  + =terminal= :: always to the program;
  + =meow= :: always to Meow, leaving Insert state.
- Outside a terminal the command is plain =meow-insert-exit=; nothing else changes.

#+begin_src emacs-lisp
(defcustom kittymacs-terminal-escape 'auto
  "Where the escape key goes in a terminal while Meow is in Insert state.
`auto'     to the program while it is drawing a full-screen interface
           (vim, less, htop, a TUI agent), and to Meow otherwise.
`terminal' always to the program.
`meow'     always to Meow, leaving Insert state."
  :type '(choice (const :tag "Full-screen programs only" auto)
                 (const :tag "Always the terminal" terminal)
                 (const :tag "Always Meow" meow)))

(defvar-local kittymacs-terminal--escape nil
  "This buffer's override of `kittymacs-terminal-escape', or nil to follow it.")

(defun kittymacs-terminal--escape-target ()
  "Return `terminal' or `meow': where the escape key should go here."
  (pcase (or kittymacs-terminal--escape kittymacs-terminal-escape)
    ('terminal 'terminal)
    ('meow 'meow)
    (_ (if (ghostel-alt-screen-p) 'terminal 'meow))))

(defun kittymacs-terminal-escape-dwim ()
  "Leave Meow's Insert state, or send escape to a full-screen program."
  (interactive)
  (if (and (derived-mode-p 'ghostel-mode)
           (eq (kittymacs-terminal--escape-target) 'terminal))
      (ghostel-send-key "escape")
    (call-interactively #'meow-insert-exit)))

(defun kittymacs-terminal-toggle-escape ()
  "Switch where the escape key goes in this terminal, and say where."
  (interactive)
  (unless (derived-mode-p 'ghostel-mode)
    (user-error "This is not a terminal buffer"))
  (setq kittymacs-terminal--escape
        (if (eq (kittymacs-terminal--escape-target) 'terminal) 'meow 'terminal))
  (message "Escape %s"
           (if (eq kittymacs-terminal--escape 'terminal)
               "now goes to the program in the terminal"
             "now leaves Insert state")))

#+end_src

- The command runs at all because =ESC= is rebound in Meow's Insert-state map: that emulation map is consulted before the terminal's own keys.
- The same block sets the starting states from [[*Meow in the terminal]].

#+begin_src emacs-lisp
(with-eval-after-load 'meow
  (dolist (entry '((ghostel-mode . insert)
                   (ghostel-compile-view-mode . motion)))
    (add-to-list 'meow-mode-state-list entry))
  (keymap-set meow-insert-state-keymap "<escape>" #'kittymacs-terminal-escape-dwim))

#+end_src

* Opening a terminal

- =SPC o e= and =SPC o p= are thin wrappers over =ghostel= and =ghostel-project=, for two reasons:
  1. The native module is downloaded on first use; a user who declines would otherwise meet =Symbol's function definition is void: ghostel--new= instead of a sentence saying what is missing and which command installs it.
  2. Where =kittymacs-terminal-ghostel= is nil (by default on Android), they open Eshell instead.

#+begin_src emacs-lisp
(defun kittymacs-terminal--without-module (error)
  "Re-signal ERROR, or explain that the native module is missing."
  (if (kittymacs-terminal-module-installed-p)
      (signal (car error) (cdr error))
    (user-error "The terminal needs its native module: %s"
                (substitute-command-keys "\\[ghostel-download-module]"))))

(defun kittymacs-terminal-open (&optional arg)
  "Open a terminal.  With prefix ARG, open another one.
Ghostel offers to fetch its native module the first time; declining that
offer leaves the terminal unavailable, so say so in words.  Where ghostel
is not used at all, Eshell answers this key instead."
  (interactive "P")
  (if (not kittymacs-terminal-ghostel)
      (eshell arg)
    (condition-case error (ghostel arg)
      (void-function (kittymacs-terminal--without-module error)))))

(defun kittymacs-terminal-project (&optional arg)
  "Open a terminal at the current project's root.  ARG is passed through."
  (interactive "P")
  (if (not kittymacs-terminal-ghostel)
      (kittymacs-eshell-project)
    (condition-case error (ghostel-project arg)
      (void-function (kittymacs-terminal--without-module error)))))

(defun kittymacs-terminal-msys2 (&optional arg)
  "Open an MSYS2 UCRT64 login shell in a terminal.
With prefix ARG, create another one instead of reusing the existing buffer."
  (interactive "P")
  (unless (eq system-type 'windows-nt)
    (user-error "The MSYS2 terminal is for native Windows Emacs"))
  (let ((bash (expand-file-name "usr/bin/bash.exe" kittymacs-msys2-root)))
    (unless (file-executable-p bash)
      (user-error "MSYS2 Bash not found at %s; set `kittymacs-msys2-root' in private.el"
                  bash))
    (let ((ghostel-shell (list bash "--login" "-i"))
          (ghostel-environment (append '("MSYSTEM=UCRT64" "CHERE_INVOKING=1")
                                       ghostel-environment))
          (ghostel-buffer-name "*ghostel: msys2*"))
      (ghostel arg))))

#+end_src

* MSYS2 on Windows :windows:
:PROPERTIES:
:ID: 09cab91d-8282-4581-b102-988f6b7675dd
:END:

- PowerShell stays the ordinary shell; =SPC o m= is the separate, explicit choice of an MSYS2 UCRT64 login shell, where a Windows machine keeps its Unix tools.
  + =MSYSTEM= selects the environment and =CHERE_INVOKING= keeps the directory you were in, both for the child process only: Emacs's own environment is untouched.
  + [[id:afa6b7fd-742a-4c15-86a6-32e3e8027b0e][The platform chapter]] owns =kittymacs-msys2-root=; set it in =private.el= if Bash is elsewhere.
- Unlike the terminal this replaces, nothing here translates paths or substitutes a POSIX helper: ghostel talks to Windows ConPTY directly.
- The command, =kittymacs-terminal-msys2=, is the last function in [[*Opening a terminal]]; it binds ghostel's options with =let=, which works before ghostel has loaded because the module header declares them.

* Projects and Consult

- =ghostel-project= opens a terminal at the project root, named after the project, so =SPC o p= in any file lands where builds are run.
  + It joins the switch-project menu (=C-x p p=) on =t=.
  + The key is named here because =ghostel-project= has none in =project-prefix-map=; without one the menu shows the entry but cannot run it.
- =consult-ghostel= (=SPC o E=) picks a terminal with live preview, as =SPC b b= picks a buffer, and creates one when you type a new name.
- =consult-ghostel-history= (=C-c h= while typing) completes against the /shell's own/ history (bash, zsh, fish and nushell) and types the choice at the prompt without submitting it, so you can edit before running.
- =consult-ghostel-mode= turns on once ghostel and Consult have loaded:
  + =consult-line= matches across soft-wrapped terminal rows, so a path that wrapped mid-word stays findable;
  + =g= narrows =consult-buffer= and =consult-project-buffer= to terminals, and =consult-bookmark= to terminal bookmarks;
  + Marginalia shows each terminal's title beside its name.
- The Consult it needs is already installed by [[id:42b02bb4-ea68-4981-b427-35705bf162f4][the completion chapter]].

#+begin_src emacs-lisp
(when kittymacs-terminal-ghostel
  (with-eval-after-load 'project
    (add-to-list 'project-switch-commands '(ghostel-project "Terminal" ?t) t))

  (use-package consult-ghostel
    :ensure t
    :after (ghostel consult)
    :demand t
    :bind (:map ghostel-semi-char-mode-map
           ("C-c h" . consult-ghostel-history))
    :config
    (consult-ghostel-mode 1)))

#+end_src

* Eshell and M-x shell

- [[id:d2e0bc37-0bd4-4b28-a8ee-04f94ac451f8][Eshell]] is a Lisp shell and cannot draw a full-screen program, so it hands those to a real terminal:
  + the commands in =eshell-visual-commands= (=htop=, =less=, =vim=, =git log=) open in a ghostel buffer;
  + =ghostel foo= at the Eshell prompt does the same for anything else, once.
- =M-x shell= renders its output with ghostel's parser.
  + Comint's colour handling understands the eight ANSI colours; ghostel's understands everything a modern program emits: true colour, curly and coloured underlines, clickable =OSC 8= links, and the directory the shell reports.
  + It is a stream filter, not a terminal: full-screen programs still belong in =SPC o e=.
  + It needs the native module, so it is on only once that exists; a machine that has never opened a terminal keeps Emacs's own handling and nothing breaks.

#+begin_src emacs-lisp
(with-eval-after-load 'eshell
  (when (require 'ghostel-eshell nil t)
    (ghostel-eshell-visual-command-mode 1)))

(defun kittymacs-terminal--comint-colours ()
  "Render this comint buffer's output with ghostel's terminal parser."
  (when (and (kittymacs-terminal-module-installed-p)
             (require 'ghostel-comint nil t))
    (ghostel-comint-mode 1)))

(add-hook 'shell-mode-hook #'kittymacs-terminal--comint-colours)

#+end_src

* Compiling in a terminal

- =ghostel-compile= runs a build in a real terminal, then presents it as a =compilation-mode= report.
  + While it runs: coloured output and progress bars, and =C-c C-j= when the command wants an answer.
  + When it finishes: =next-error= and clickable file references.
- =SPC m t= runs it in any programming buffer, =SPC m T= runs it again.
  + Both are autoloaded here, since =ghostel-recompile= carries no autoload cookie and the keys must work before a terminal has ever been opened.
  + They are added to the =prog-mode= map [[id:97c04bd3-1404-4b0a-8018-20d77bc671bc][the programming chapter]] built: =kittymacs-define-localleader= would replace that whole map.
- Emacs's own =compile= is left alone, because =SPC m c=, Flymake and =project-compile= all go through it.
  + =(ghostel-compile-global-mode 1)= in =private.el= routes those through the terminal too.

#+begin_src emacs-lisp
;; `ghostel-recompile' carries no autoload cookie, and `SPC m t' must work
;; before the terminal has ever been opened.
(autoload 'ghostel-compile "ghostel-compile" "Run a command in a terminal." t)
(autoload 'ghostel-recompile "ghostel-compile" "Re-run the last command." t)
(with-eval-after-load 'ghostel
  (require 'ghostel-compile nil t))

;; `kittymacs-define-localleader' replaces a mode's whole map, and prog-mode's
;; belongs to the programming chapter, so add to the map it built.
(when kittymacs-terminal-ghostel
  (with-eval-after-load 'kittymacs-programming
    (when-let* ((map (alist-get 'prog-mode kittymacs-localleader-alist)))
      (keymap-set map "t" (cons "compile in a terminal" #'ghostel-compile))
      (keymap-set map "T" (cons "recompile in a terminal" #'ghostel-recompile))
      (kittymacs-refresh-localleaders))))

#+end_src

* Themes and frames

- Ghostel paints the terminal's sixteen colours from the active theme and repaints them on Emacs's own =enable-theme-functions=, so =SPC t t= changes the terminal with everything else; nothing is needed here.
- A terminal is a buffer you work in, so [[id:f1d045c2-e2dc-4514-ab17-dd982ed6be00][frames-only mode]] gives it its own OS window: =SPC o e= from a second project puts its terminal beside that project's code, not on top of it.

* The terminal's mode menu

- Every entry but =k=, =b=, =ESC= and =M= is also on a =C-c= key that works while you type, the keys ghostel's manual documents; these are the labelled versions.
- The five input modes, so you can pick one by name:
  + =i= :: semi-char, typing in the terminal (the Insert-state default);
  + =I= :: char mode, every key to the program;
  + =e= :: Emacs mode, reading live output;
  + =c= :: copy mode, frozen (what =ESC= gives you);
  + =l= :: line mode, composing a line before sending it.

#+begin_src emacs-lisp
(kittymacs-define-localleader 'ghostel-mode
  "i" (cons "type in the terminal" #'ghostel-semi-char-mode)
  "I" (cons "send every key (char mode)" #'ghostel-char-mode)
  "e" (cons "read live output" #'ghostel-emacs-mode)
  "c" (cons "freeze and copy" #'ghostel-copy-mode)
  "l" (cons "compose a line first" #'ghostel-line-mode)
  "y" (cons "copy everything" #'ghostel-copy-all)
  "p" (cons "paste" #'ghostel-paste)
  "k" (cons "clear" #'ghostel-clear)
  "K" (cons "clear scrollback" #'ghostel-clear-scrollback)
  "n" (cons "next prompt" #'ghostel-next-prompt)
  "N" (cons "previous prompt" #'ghostel-previous-prompt)
  "f" (cons "next link" #'ghostel-next-hyperlink)
