#+TITLE: Maintenance: the loop, the builder, and machine overrides
#+FILETAGS: :core:
#+STARTUP: overview
#+PROPERTY: header-args:emacs-lisp :eval never :comments no :padline no :mkdirp yes

- How to change kittymacs: edit a chapter, tangle, check, restart; the [[file:../justfile][justfile]] is the reference card once this page is read.
- Writes two files, each from its own heading:
  + [[*Machine-specific settings]] → =lisp/private.example.el=, the template for your =private.el=;
  + [[*Building from inside Emacs]] → =lisp/kittymacs-literate.el=, the =SPC C= commands.
- The build uses only the Org that ships with Emacs; startup never tangles, so a fresh clone runs without a build step.

* The loop :concept:
:PROPERTIES:
:ID: 12926a91-6016-43ae-9309-c28a293ce78e
:END:

1. *Edit a chapter.* Prose and code block together; a block without a bullet saying why is unfinished.
2. *Tangle*: =just tangle=, or =SPC C t= inside Emacs.
   + Every =literate/NN-name.org= writes the files its =:tangle= headers name ([[*How a chapter becomes files]]).
3. *Check*: =just check=, before every commit. In turn:
   + =tangle-check= :: tangles into a temporary directory and fails if any committed generated file differs;
   + =doc-test= :: every page follows [[id:7edccfdc-3c38-489a-bc9e-4c002b432ab4][the conventions]]: IDs, tags, links, a closing Check;
   + =test= :: the suites that need no packages: the builder, every operating system's platform branch, the Tree-sitter policy, Org table wrapping.
4. *Restart Emacs*, then commit the chapter and its generated file together.
- One decision per commit, with its generated files.
- For a quick experiment, evaluate a block with =C-c C-c= or a form with =SPC e e=: it changes the running Emacs without rebuilding anything.

** The recipes

| Recipe            | Needs              | Does                                                                         |
|-------------------+--------------------+------------------------------------------------------------------------------|
| =tangle=          | Emacs              | write every generated file from its chapter                                  |
| =tangle-check=    | Emacs              | fail if a generated file differs from its chapter                            |
| =doc-test=        | Emacs              | check IDs, tags and links on every page                                      |
| =test=            | Emacs              | builder, platform and Tree-sitter tests                                      |
| =check=           | Emacs              | the three above; the default recipe                                          |
| =install=         | Emacs, network     | start the configuration once in batch, installing what this machine's profile needs into =var/elpa=; on a fresh clone, =minimal= |
| =compile=         | the full profile's packages | byte-compile every module under =full=, to catch load errors        |
| =test-packages=   | the full profile's packages | leader, Org-roam, theme, load-order, remote and diff-review adapter tests, and the startup verifier, under =full= |
| =test-minimal=    | the minimal profile's packages | leader, theme and remote tests, and the verifier, which also checks the directory holds exactly those |
| =test-features=   | every feature's packages | one real start per feature, off in turn and on in turn                 |
| =test-quickstart= | installed packages | the startup verifier, starting from a quickstart file it writes first        |
| =test-new-machine= | Emacs, network | a machine with nothing, start by start: the quickstart file comes, a new feature installs, removing it lasts |
| =quickstart=, =quickstart-remove= | installed packages | write the file that starts this machine without scanning =var/elpa=, or delete it and keep it off |
| =size=            | Emacs              | count the code and prose, and report the counts                              |
| =bench=           | installed packages | start Emacs many times and report what startup costs                         |
| =frames-test=     | a display          | the frame-policy tests, in a graphical Emacs                                 |
| =lint=            | Nix tools          | =deadnix=, =statix= and =nixfmt= over the generated Nix                      |
| =eval=            | Nix                | evaluate the flake, on unstable and on stable, and both example hosts        |
| =sources=         | Nix                | fail if an Emacs package's source clones a whole ELPA repository (in =eval=) |
| =nix-selection=   | Nix                | start Emacs from real Home Manager hosts' generated files, and compare its answers with their options |
| =nix-check=       | Nix                | =lint=, =eval= and =nix-selection=                                           |
| =all=             | Nix, network       | everything CI runs on Linux, in order, installing =full=                     |
| =update=          | Nix, network       | =update-flake=, =update-packages=, =update-grammars=                         |

- =nix develop= gives a shell with Emacs, =just= and the Nix linters ([[id:d25a5063-1439-4ae0-8fbe-b0162d05a0e0][the Nix chapter]]); outside it, any Emacs 31.1 or later runs the Emacs recipes.
- On Windows, =just= runs recipes with the =sh= Git for Windows installs.
- =test-packages= reads =KITTYMACS_TEST_PACKAGES=, defaulting to this checkout's =var/elpa=.
  + It and =compile= name =full= themselves, so a fresh clone needs =KITTYMACS_TEST_PROFILE=full just install= first.

** Updating

- =flake.lock= moves by itself: Dependabot opens a pull request each week, and CI's =merge-flake-bump= job merges it once the =tangle=, =startup=, =features= and =nix= jobs pass.
  + That job merges directly, so it needs no branch rule or repository setting, and a failed job leaves the pull request open for a person.
  + =bench= is not among them, because it reports and never decides.
  + CI evaluates the flake and does not build it, so a bump can reach =main= that then fails to build on a machine: =git revert= it, and pin the input until upstream is fixed.
- =just update= is for a machine: it runs three recipes, and each also works alone:
  + =update-flake= :: =nix flake update=: moves nixpkgs, and so the Emacs, its packages and the tools the Nix modules install. Commit =flake.lock=.
  + =update-packages= :: a batch Emacs refreshes the archives and upgrades every package in =var/elpa=, without loading the configuration; packages Nix installed are not in =var/elpa= and move with =update-flake= instead.
  + =update-grammars= :: rebuilds every Tree-sitter grammar at the revision [[id:560fcdca-6cb8-49d9-bf27-eb78f32b9285][the languages chapter]] pins; needs =git= and a C compiler.
- =var/= is not tracked, so only =flake.lock= (and a changed pin) reaches a commit.
- Run =just test-packages= after =update-packages=: the verifier is what notices an upstream change.

* How a chapter becomes files :concept:
:PROPERTIES:
:ID: d57943d1-4bdf-4776-a19c-d6120fbd87a5
:END:

- Org Babel's /tangle/ copies a chapter's source blocks into files; kittymacs uses only that.
- Header arguments, set once per chapter by its =#+PROPERTY: header-args= line:
  + =:tangle ../lisp/kittymacs-NAME.el= :: where the blocks go, relative to the chapter; chapters live in =literate/=, so every target starts with =../=;
  + =:padline no= :: no blank line between blocks; Babel drops a block's trailing blank line, so a block that should follow one says =:padline yes=;
  + =:comments no= :: no links back to the chapter in the output; the file header names its chapter instead;
  + =:eval never= :: =C-c C-c= cannot run a block by accident;
  + =:mkdirp yes= :: create the directory if needed.
- A chapter writing several files sets =:tangle= in each heading's property drawer instead, as this one does; blocks under that heading go to that file.
- A block's own arguments win over the page's: =:tangle no= marks an example to read, not to load.
- Inside a block, a line starting with =*= or =#+= is written =,*= or =,#+=; Babel strips the comma.

** The builder :decision:
:PROPERTIES:
:ID: d702f35a-3b2f-4cb5-9b4c-c176f0711db0
:END:

- [[file:../tools/tangle.el][tools/tangle.el]] runs in =emacs -Q --batch=: no personal startup, no packages, no file-local variables, and no block is ever evaluated.
- It finds the chapters by name: every =literate/NN-name.org=; adding the file is enough, there is no list to register it in.
- Before writing anything it checks every target:
  + Emacs Lisp may go only to =early-init.el=, =init.el= or a file directly in =lisp/=, never =lisp/private.el=, which is yours;
  + Nix may go only to =flake.nix= or =nix/=, at most one directory deep;
  + a block's language must match its target's;
  + no two chapters may write one file;
  + a =lisp/kittymacs-*.el= or =nix/**.nix= that no chapter writes is an error: startup would go on loading a module whose source is gone, and the flake importing a file nothing explains.
- It writes =nix/features.json= from [[id:3f8a6c02-9d14-4b7e-a2c5-1e7d90b64f31][the catalogue]], which it reads and never evaluates, so the flake and the configuration share one list.
- It tangles into a temporary directory, checks that every Lisp file's parentheses balance, and only then copies the files that changed.
  + =--check= copies nothing and fails on any difference: the guard against a hand edit to a generated file, or a forgotten tangle.
- Chapters and outputs are UTF-8 with LF line endings on every platform; =.gitattributes= keeps Git from converting them.
- After renaming or deleting a chapter, delete its old generated file too; the orphan check says which.

** Add a chapter

1. Create =literate/NN-name.org= with the header of a neighbouring chapter: a fresh =:ID:=, a kind tag, and =:tangle ../lisp/kittymacs-name.el=.
   + The two digits are the load order ([[id:40302e33-d2b2-4c0b-9bc3-1f9e121307e1][startup]] has the list).
2. Add =(require 'kittymacs-name)= to =init.el= in the startup chapter, where it belongs in that order.
3. Give a package with its own buffers a =:meow:= heading: its starting state and a =kittymacs-define-localleader= form for =SPC m= ([[id:e5942eb0-4389-447d-9317-d9178adcaaae][the leader]]).
4. Bind its =SPC= keys in the chapter, in the groups [[id:e5942eb0-4389-447d-9317-d9178adcaaae][the leader]] defines, after a =(require 'kittymacs-leader)=.
5. Add a row to [[id:52a45bf9-9521-4e0d-9867-1c54721844a3][the reading guide]]'s table; =just doc-test= fails until you do.
6. List any package it declares in [[id:3f8a6c02-9d14-4b7e-a2c5-1e7d90b64f31][the catalogue]]; =just test= fails until you do.

* Measuring :decision:
:PROPERTIES:
:ID: b49b309f-e505-422a-bd12-733e11e77411
:END:

- A claim that a change is faster needs a number from before the change, and a cost nothing counts only grows.
- =just size= counts without starting Emacs:
  + Lisp lines and cons cells, because joining lines lowers the first and not the second;
  + declared packages, in any gate, =:vc= included;
  + lines of prose across every =literate/*.org=, =ARCHITECTURE.md= and the README, so moving text between pages changes nothing;
  + =org-lines=, those chapters alone, because a target for the literate source compares with them and not with the two Markdown pages;
  + =default-loaded-lines= and =default-loaded-conses=, the files a start on the default profile loads, and =default-packages=, the packages that profile installs.
- The total =elisp-lines= counts every file under =lisp/=, so onboarding looks like a cost of starting, and only the =default-= counts say what a start pays.
  + They follow =require= from =init.el=, past the gates that are on, without starting Emacs.
  + A whole file counts once it loads, because a form behind a gate that is off is still read.
  + =just test-minimal= holds the list of modules to what a real start loads.
- =just bench= starts Emacs repeatedly from [[file:../tools/bench.el][tools/bench.el]], after =just install=:
  + it warns when =lisp/private.el= or a host file exists, because either changes what it measures;
  + in a terminal it starts under its own pty, and in a frame too when =DISPLAY= is set (=xvfb-run= provides one);
  + a first run compiles what startup loads and waits for that queue to empty, so no later run pays for compilation;
  + each configuration throws away three runs and keeps twenty, or =KITTYMACS_BENCH_RUNS=; the table gives the median and the p90, by nearest rank.
- Each number exists to catch a way of looking faster without being faster:

| Number                  | What it catches                                                        |
|-------------------------+------------------------------------------------------------------------|
| first idle              | wall clock from before the process starts, so it includes the dump     |
| CPU, settled            | work moved behind a timer, which first idle would no longer see        |
| open =.el=, open =.org= | work moved from startup to the first file                              |
| =SPC t m=               | work moved from startup to the first key                               |
| ratio to =emacs -Q=     | a slow or busy machine: both sides run in the same job                 |

- The counts of features, loaded files and activated packages come from a real start and repeat exactly on one machine, while times differ between machines.
  + The counts from a start, =features=, =files-loaded=, =packages-activated=, =dependency-closure=, =org-loaded-at-start= and =magit-loaded-at-start=, are of the default profile, =minimal=, and =just bench= warns if its starts ran on another.
  + CI's =bench= job reports them from the dev shell's Emacs, on a fresh clone with no profile.
  + Another build of Emacs loads a different number of features and files, so compare under =nix develop=, where a machine can still differ from CI by a few.
- Every count and time is a report, and none fails a change.
- =TERM= is =linux= under the pty: an xterm-like =TERM= makes Emacs wait up to =xterm-query-timeout= for a reply a bare pty never sends.
- A run that dies is listed with its exit status and last output, and the rest carry on, because one Emacs failing among dozens is itself a result.
- A =lisp/private.el= changes every number, so =just bench= warns when one exists.
- =just bench= needs a pty, so it does not run on native Windows.

* When Emacs stalls
:PROPERTIES:
:ID: 7c0b2a54-6d1e-4f3a-9b57-2e8d41a6c930
:END:

- A stall that ends in a forced quit leaves no evidence, so capture it while Emacs is still frozen, before quitting.
- In order, from another terminal where a step needs one:
  1. Press =C-g= once, and note whether Emacs recovers: code that checks for quit is interruptible, and a C loop is not.
  2. Sample the native stack, which works even if Lisp never runs again: on macOS =sample Emacs 10 -file ~/emacs-stall.txt=, elsewhere =gdb -p PID -batch -ex bt=.
  3. Ask for a Lisp backtrace with =pkill -USR2 -x Emacs= (=emacs= outside macOS): =debug-on-event= opens =*Backtrace*= at the next point that checks for quit.
- The main thread's stack, in the =sample= call graph, says where to look next:

| On the main thread's stack          | Means                                            |
|-------------------------------------+--------------------------------------------------|
| =read_char= down to =ns_select_1= and =mach_msg=, in every sample | idle, waiting for input: Emacs is healthy |
| =garbage_collect=, =mark_object=    | garbage collection, and undo in large buffers    |
| =redisplay_internal=, face code     | redisplay, faces, the mode line                  |
| =wait_reading_process_output= below Lisp frames | Lisp waiting for a process, such as =accept-process-output= |
| =exec_byte_code=, =eval_sub=        | Lisp: the backtrace from the third step names it |

- After a recovery, =M-: (list gcs-done gc-elapsed)= shows how much time garbage collection has taken in this session.
- For a slowdown rather than a freeze, =M-x profiler-start=, repeat the slow action, then =M-x profiler-report=.

* What CI proves
:PROPERTIES:
:ID: b01690a2-51c1-471b-9c70-39cb2c3e1e64
:END:

- [[file:../.github/workflows/ci.yml][The CI workflow]] runs the recipes above on every push and pull request; it never deploys anything.
  + =tangle= job :: =just check=: the chapters match the generated files, and the package-free tests pass.
  + =startup= job :: a fresh clone runs =just install=, =just compile= and =just test-packages= on Emacs 31.1 on Linux, plus informational macOS and Windows runs.
    A second Linux run installs the minimal profile and runs =just test-minimal=: it has a package cache of its own that nothing older can seed, so leftovers cannot hide a removal, and the verifier fails on a package too many or too few.
    Every run then ends with =just test-quickstart=, which fails if the start ignored [[id:7b4e2f19-6d03-4a58-9c21-e8f05d7a3c64][the quickstart file]] or lost a package to it.
    The minimal, macOS and Windows runs also run =just test-new-machine=, the only check that starts with no profile chosen, which is what makes a machine new.
  + =features= job :: =just test-features= after installing every feature's packages: one real start per feature ([[*Testing a selection]]).
  + =nix= job :: =just nix-check= in =nix develop=, then the home-manager module's clone options read as a device would see them.
    =eval= checks the flake twice: on its own nixpkgs-unstable, and on the stable release in the justfile's =stable= variable, since a host that makes the flake follow its nixpkgs evaluates it there; move =stable= to each new release.
  + =bench= job :: a fresh clone with no package cache, and so the default profile, runs =just bench= in =nix develop= under =xvfb-run= and writes the tables to the job's summary ([[*Measuring]]); it is informational and cannot fail a pull request.
- A weekly run repeats the fresh install without the package cache, so upstream breakage shows up even when nothing here changed.
- =just frames-test= is the one suite CI cannot run: it needs a graphical session.
- Dependabot proposes weekly updates to the workflow's actions, for a person to review, and to =flake.lock=, which merge themselves ([[*Updating]]).

* Testing a selection
:PROPERTIES:
:ID: 3b7f2c94-e1a6-4d08-9c35-81f6d0a7b2e4
:END:

- =KITTYMACS_TEST_PROFILE= says what =just install= installs into this checkout's =var/elpa=: =minimal=, =full=, or =every=, which adds each optional feature.
  + Unset, this machine's own settings decide, as on any start: a fresh clone gets the default, =minimal=, and an older checkout stays on =full= ([[id:2ea4f7b0-6c19-4d85-93f2-c07a1be58d36][the rule]]).
  + Use a separate clone per value, so one profile's packages cannot help another's test.
- =just test-minimal= is for a directory that holds the =minimal= profile and nothing else.
  + The verifier then also fails on a package missing from it, or one nothing there needs.
- =just test-features= starts Emacs once per selection, from [[file:../tests/kittymacs-feature-probes.el][the probes]]: each feature beyond =minimal= off in turn from =full=, and on in turn from =minimal=.
  + Each start activates only what its selection needs, through =package-load-list=, so one directory with everything in it behaves like a separate one per selection.
  + Each must start with no warning, every =SPC= key callable, no empty group, no key naming a package that is off, and neither Org nor Tramp loaded.
  + A feature that is on must also have loaded its chapter and bound the key its example quotes.
- =KITTYMACS_PROBE_ONLY=, a regexp, narrows the probes to the names it matches.
- =just test-quickstart= runs the verifier on the profile that =KITTYMACS_TEST_PROFILE= names, or =full=, from a file it writes first.
- =just test-onboard-start= answers [[id:c8e2f1a7-4b60-49d3-8a15-7d3e96b0c421][the onboarding screens]] with scripted keys for several selections, and starts the verifier on each =private.el= they wrote.
  + =KITTYMACS_TEST_PRIVATE= names a file for the verifier to start its =private.el= with, and =KITTYMACS_TEST_EXPECT= an alist of what =kittymacs-feature-p= must answer.
  + It needs the same directory as the probes, and runs after them in CI's =features= job.

* Why the generated files are committed :decision:
:PROPERTIES:
:ID: 023e8794-b0b7-4bf3-8b37-b5ceb7c6f6c4
:END:

- Startup loads plain Lisp, never Org: a clone starts with no build step, and a broken chapter cannot stop Emacs from starting.
- Nix sees only files Git tracks, so the generated =.nix= must be committed too.
- The cost: every change shows twice in a diff.
  + =.gitattributes= marks the generated files =linguist-generated=, so GitHub folds them and review happens on the chapter.
  + Locally, =git diff -- '*.org'= is the diff you read.

* Machine-specific settings
:PROPERTIES:
:header-args:emacs-lisp: :tangle ../lisp/private.example.el :eval never :comments no :padline no :mkdirp yes
:END:

- =lisp/private.el= holds what belongs to one account or machine: paths, fonts, opt-in language servers, your own keys.
  + =SPC C p= creates it from =lisp/private.example.el=, written below, and opens it.
  + Git ignores it, and no chapter may tangle to it, so rebuilding never replaces it.
- =M-x customize= saves to =var/etc/custom.el=, also ignored; back both up yourself.

** When private.el is read, and why that needs two forms :concept:
:PROPERTIES:
:ID: cf00615b-7150-4504-9adf-199876070b0b
:END:

- =init.el= loads =private.el= early, right after the defaults and platform chapters, because most chapters read a =kittymacs-= option while they load.
  + The languages chapter picks packages to install from =kittymacs-language-packages=; the appearance chapter loads =kittymacs-theme=.
- Early has a price: a later chapter that sets a package's option replaces your value.
  + The terminal chapter sets =ghostel-enable-osc52= to =nil=; a top-level =setopt= of it in =private.el= would be undone a moment later.
- So the example uses two forms:
  + a =kittymacs-= option :: at top level with =setopt=; it works before the option's chapter loads, because the chapter's =defcustom= keeps an existing value;
  + any other package's option :: inside the =after-init-hook= function at the end, which Emacs runs once =init.el= has finished; depth 90 puts it after the chapters' own functions.
- A chapter that sets an option only as its package loads (in =:config= or =with-eval-after-load=) needs your =setopt= wrapped in =with-eval-after-load= inside the hook: forms waiting for a package run in registration order, and by then every chapter has registered its own.
- Tabspaces is the exception: it turns on at depth 95, after your function, so it reads your settings.
- Customize needs neither form: =init.el= loads =custom.el= after every chapter.
- [[file:../ARCHITECTURE.md][ARCHITECTURE.md]] ("Customize and =private.el= get the last word") has the reasoning; the startup verifier replays a real startup and checks that both kinds of override survive.

- =SPC C t= and =SPC C k= run =tools/tangle.el= in a separate =emacs -Q= process, exactly as =just= does, and show its output in =*kittymacs literate build*=.
  + Unsaved chapters are refused first, so a build never reads a stale file.
  + A successful tangle still needs a restart: the running Emacs keeps the modules it loaded.

#+begin_src emacs-lisp
(defun kittymacs-literate--build (write)
  "Run the isolated literate builder; WRITE selects generation over checking."
  (let ((source-dir (expand-file-name "literate/" user-emacs-directory))
        (output (get-buffer-create "*kittymacs literate build*")))
    (dolist (buffer (buffer-list))
      (when-let* ((file (buffer-file-name buffer)))
        (when (and (file-in-directory-p file source-dir)
                   (buffer-modified-p buffer))
          (user-error "Save %s before building the literate configuration" file))))
    (with-current-buffer output
      (let ((inhibit-read-only t)) (erase-buffer)))
    (let ((status
           (call-process (expand-file-name invocation-name invocation-directory)
                         nil (list output t) nil
                         "-Q" "--batch" "-l"
                         (expand-file-name "tools/tangle.el" user-emacs-directory)
                         "--" (if write "--write" "--check"))))
      (display-buffer output)
      (unless (equal status 0)
        (user-error "Literate build failed; see %s" (buffer-name output)))
      (message (if write
                   "Lisp regenerated. Restart Emacs to apply configuration changes."
                 "Literate sources and deployed Lisp agree.")))))
(defun kittymacs-literate-tangle ()
  "Regenerate deployed Lisp from saved literate sources."
  (interactive)
  (kittymacs-literate--build t))
(defun kittymacs-literate-check ()
  "Check that deployed Lisp matches saved literate sources without writing it."
  (interactive)
  (kittymacs-literate--build nil))
