Ownership: *user configuration*.

- The directory and capture templates are the user's own minimal policy.
- The defaults are distilled from Lambda-Emacs by Colin McLear
  (=lem-setup-org-base=, =lem-setup-org-settings=), without his personal
  files and export workflows.

* What this gives you

- One inbox file under a portable Org directory, two capture templates, an
  agenda, and searches by tag and by query.
- Org looks clean: hidden markup, indented headings, pretty entities.
- Org behaves predictably: no editing inside folded text; tasks log when
  done.
- =SPC m= in an Org buffer lists the structure commands; =SPC o a= opens the
  agenda from anywhere.

* How Org looks and behaves

- Markup is hidden and headings are indented, so a document reads like a
  document.
  - Indenting also hides every star of a heading but the last.
- Editing inside folded text is refused rather than silently mangling it.
- New headings go after the current subtree's content.
- =RET= follows links; =C-a=/=C-e= respect heading stars.
- Source blocks keep their indentation exactly as written; their language's
  colours and =TAB= are already the default.
- Files open unfolded.
  - Org 9.7 spells that =nofold= and no longer accepts =nil=; =setopt=
    checks the type at startup, so the symbol matters.

* Tasks and the agenda

- A task is =TODO=, then maybe =NEXT= or =WAITING=, then =DONE= or
  =CANCELED=.
- Finishing a task records the time in a drawer.
- A parent cannot be done while its children are not.
- The agenda:
  - starts on today;
  - hides done scheduled items;
  - offers a =d= dashboard: today's agenda, tasks due soon and the next
    actions.
- Log mode is on from the start, listing closed and clocked items.
  - =t= used to mean that, before the option's type asked for the list
    itself.
- Refiling completes across every agenda file to eight levels deep.

#+begin_src emacs-lisp
(setopt org-todo-keywords '((sequence "TODO(t)" "NEXT(n)" "WAITING(w@/!)" "|" "DONE(d)" "CANCELED(c@)"))
        org-use-fast-todo-selection 'expert
        org-enforce-todo-dependencies t
        org-enforce-todo-checkbox-dependencies t
        org-log-done 'time
        org-log-into-drawer t)

(setopt org-agenda-start-with-log-mode '(closed clock)
        org-agenda-tags-column 0

* Finding headings by tag and by query

- Where tags come from:
  - a heading's own tags end its line: =* Services :decision:=;
  - =#+filetags:= at the top of a file tags every heading in it;
  - a heading inherits the tags of its file and of the headings above it.
- So a file tag matches every heading of its file. A tag for a kind of
  heading, such as =decision= or =assignment=, is the precise one to search for.
- Org has three ways in; this chapter adds the last two:

| Keys      | Searches           | Gives                                            |
|-----------+--------------------+--------------------------------------------------|
| =C-c / m=   | this buffer        | the outline, folded to the matching headings     |
| =SPC s h=   | this buffer        | a jump list in which each heading shows its tags |
| =SPC o A m= | the agenda files   | an agenda list of the matching headings          |
| =SPC s q=   | the Org files here | a jump list that follows an Org QL query         |
| =SPC s Q=   | the Org files here | an agenda-style list, grouped by file            |

- /The Org files here/: the project's Org files when the buffer belongs to a
  project, otherwise every Org file under =org-directory=.

** Org's match syntax

- =C-c / m= and =SPC o A m= read it:
  - =decision+nixos=: both tags;
  - =machine|module=: either tag;
  - =nixos-assignment=: the first tag without the second.
- =C-c C-c= clears the highlighting a match leaves.

** Org QL

- [[https://github.com/alphapapa/org-ql][Org QL]] is a query language for Org files.
- Its plain syntax is =predicate:argument= words that must all hold:
  - =tags:decision=, or =tags-local:decision= for the heading's own tags only;
  - =todo:NEXT=, =heading:services=, =level:1=;
  - a word without a colon searches the text;
  - =!= in front of a word negates it: =!tags:done=.
- =SPC s q= runs the query at every keystroke and jumps to the heading you
  choose.
- =SPC s Q= asks for a query and lists the matches in an agenda buffer:
  - =RET= visits a heading; =g= runs the search again;
  - =v= opens a menu that changes the query, the files, the order or the
    grouping;
  - to group by tags instead of files: =v=, =g=, choose =tags=, then =r=.

#+begin_src emacs-lisp
(declare-function org-ql-find "org-ql-find")
(declare-function org-ql-search "org-ql-search")
(declare-function project-files "project")

(use-package org-ql
  :ensure t
  :defer t)

(defun kittymacs--org-files-here ()
  "Return the Org files that a search started in this buffer covers.
In a project, the project's Org files; anywhere else, every Org file
under `org-directory'."
  (or (if-let* ((project (project-current)))
          (seq-filter (lambda (file) (string-suffix-p ".org" file))
                      (project-files project))
        (directory-files-recursively org-directory "\\.org\\'"))
      (user-error "No Org files here")))

(defvar kittymacs--org-ql-history nil
  "Queries given to `kittymacs-org-ql-search'.")

(defun kittymacs-org-ql-find ()
  "Jump to a heading in the Org files here, found with an Org QL query.
The files are the project's, or your notes' outside a project.  The
results follow the query as you type it: tags:decision, todo:NEXT, words."
  (interactive)
  (org-ql-find (kittymacs--org-files-here) :prompt "Org QL: "))

(defun kittymacs-org-ql-search (query)
  "List the headings in the Org files here that match QUERY, grouped by file.
In the list, RET visits a heading, g runs the search again, and v changes
the query, the files, the order or the grouping."
  (interactive (list (read-string "Org QL query: " nil 'kittymacs--org-ql-history)))
  (org-ql-search (kittymacs--org-files-here) query
    :super-groups '((:auto-category t))
    :title query))

#+end_src

** Grouping

- [[https://github.com/alphapapa/org-super-agenda][org-super-agenda]] groups the lists; Org QL depends on it.
- Its mode is on, so an agenda command of your own groups its entries by
  setting =org-super-agenda-groups= in its settings; the package's README
  lists the groups. The dashboard above does not group.
- Group headers have no keymap of their own:
  - upstream gives each header a copy of the agenda's map as a text property;
  - a keymap property outranks every minor mode's map, Meow's state maps
    included, so on a header =j=, =k= and =SPC= ran agenda commands;
  - with =org-super-agenda-header-map= nil a header has the same keys as the
    lines around it.
- An Org QL list is an agenda buffer: it starts in Motion state, and =SPC m=
  is the agenda's menu.
  - =SPC m g= there runs the search again through Org QL;
    =org-agenda-redo= only rebuilds Org's own agenda views.

#+begin_src emacs-lisp
(declare-function org-ql-view-refresh "org-ql-view")
(defvar org-ql-view-buffers-files)

(use-package org-super-agenda
  :ensure t
  :after org-agenda
  :custom
  (org-super-agenda-show-message nil)
  :config
  (setq org-super-agenda-header-map nil)
  (org-super-agenda-mode 1))

(defun kittymacs-org-agenda-refresh ()
  "Run this agenda buffer's search again, whether Org or Org QL made it."
  (interactive)
  (if (bound-and-true-p org-ql-view-buffers-files)
      (org-ql-view-refresh)
    (org-agenda-redo)))

#+end_src

** Plain queries on Emacs 31

- Org QL parses a plain query by evaluating a =with-peg-rules= form with
  dynamic binding ([[https://github.com/alphapapa/org-ql/issues/498][Org QL issue 498]]).
- Emacs 31's =peg= makes every rule an OClosure, which needs lexical
  binding, so every plain query failed with
  =(cl-assertion-failed lexical-binding)=.
- The advice below turns such a form into =(eval '(with-peg-rules ...) t)=:
  the same form, evaluated with lexical binding.
  - Lexical code expands as before, so the advice does nothing once Org QL
    fixes its call.
  - It is not limited to Emacs 31: =peg= is also a GNU ELPA package, so the
    new =peg= can reach Emacs 30.

#+begin_src emacs-lisp
(defun kittymacs--peg-rules-lexically (expand &rest args)
  "Expand `with-peg-rules' ARGS with EXPAND, under lexical binding.
Code that is already lexical expands as before."
  (if lexical-binding
      (apply expand args)
    `(eval '(with-peg-rules ,@args) t)))

(with-eval-after-load 'peg
  (advice-add 'with-peg-rules :around #'kittymacs--peg-rules-lexically))

#+end_src

* Meow in Org

- Org buffers are text, so they start in Normal state with the full grammar.
- =@= counts as part of a word, so tags select cleanly.
- The agenda, a special buffer, starts in Motion state.
- The localleader collects the structure commands a new user needs.
  - Most also have Org's own =C-c= key, which =C-h m= lists.

* Try it

- =SPC o c t= from anywhere captures a task into the inbox.
- In =inbox.org=, =SPC m t= cycles its state; =SPC m s= schedules it.
- =SPC m a= shows today, due-soon and next actions together.
- =SPC s Q= and =todo:TODO= list your open tasks grouped by file; =v g=,
  =tags=, =r= regroups them by their tags.
- In a project with tagged headings, =SPC s q= and =tags-local:decision=
  jump straight to one of its decisions.
