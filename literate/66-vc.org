#+TITLE: Version control: Magit and VC
#+FILETAGS: :apps:
#+STARTUP: overview
#+PROPERTY: header-args:emacs-lisp :tangle ../lisp/kittymacs-vc.el :eval never :comments no :padline no :mkdirp yes

- Magit is the Git interface: =SPC v s= opens the status buffer for the repository you are in, and everything happens from there.
  + Stage with =s=, commit with =c c=, push with =P p=; every prefix opens a menu that lists its options.
- Emacs's own VC layer handles the small things: following symlinks, annotating lines, resolving conflict markers.
- Five optional features extend Magit, each behind its own entry in [[id:3f8a6c02-9d14-4b7e-a2c5-1e7d90b64f31][the catalogue]]:
  + =pull-requests=: issues and pull requests from the forge, and line-by-line review;
  + =git-extras=: modes for Git's own files, and the repository's TODOs in the status buffer;
  + =git-links=: links to a line on the forge, and Org links to commits;
  + =structural-diffs=: diffs that compare syntax trees instead of lines;
  + =branch-review=: a branch reviewed inside Emacs as a pull request page shows it, with no forge.
- Leans on [[id:e5942eb0-4389-447d-9317-d9178adcaaae][the leader]] for =SPC m=, [[id:afa6b7fd-742a-4c15-86a6-32e3e8027b0e][the platform chapter]] for the spell checker, and [[id:f1d045c2-e2dc-4514-ab17-dd982ed6be00][the frames chapter]] for frames-only mode.
- Distilled from Lambda-Emacs by Colin McLear (=lem-setup-vc=).

* VC, diffs and merge conflicts

- Emacs's VC layer handles Git only, and follows symlinks into version-controlled files without asking.
- Logs:
  + a file's log uses the short, one-line-per-commit style;
  + a file's log follows it across renames;
  + revision prompts complete branch names only.
- Diffs:
  + =vc= diffs carry a =--patch-with-stat= summary;
  + changes are refined word by word as you move to a hunk;
  + file headers are prettified, and hunks use diff colours only, because highlighting each hunk as its language costs too much on a large diff.
- =vc-annotate= colours lines on a scale by age; Ediff keeps its control panel in the same frame.
- When a merge leaves conflict markers in a file, =smerge-mode= offers to keep one side or the other.
  + Its commands live under =C-c v= here as well as the default =C-c ^=: =C-c v n= next conflict, =C-c v u= keep upper, =C-c v l= keep lower.
  + All of them are in =smerge-basic-map=, which =smerge-mode-map= puts under =C-c ^=; binding the same map under =C-c v= makes the shorter prefix work without changing anything else.
  + =C-c ^= keeps working, as the Emacs manual describes.
  + =SPC m C= holds the same map while a file has conflicts, as a group beside the file's own menu ([[id:f468e425-28ac-46ac-b6d1-92b644d07e61][minor modes in =SPC m=]]): =SPC m C n= next conflict, =SPC m C u= keep upper.
  + With =repeat-mode= on, =n= again after any of them moves on to the next conflict.

* Magit

- Magit buffers are full buffers, so they open in their own frame when [[id:f1d045c2-e2dc-4514-ab17-dd982ed6be00][frames-only mode]] is on in a graphical session, and in the other window otherwise.
- =display-buffer= is given three ways to place the buffer (reuse a window, pop up a frame, use some window), and the last always succeeds.
  + Magit selects whatever window it gets back, and a =nil= there is an error rather than a fallback.
- Hunks are refined word by word; the log margin shows the date and time, not the author.
- Commit summaries are kept to 50 characters.
- The status buffer refreshes on =g= and after Magit's own commands, not on every save: =auto-save-visited-mode= saves often, and each refresh runs Git synchronously.
- Stashes, untracked files and unpushed commits start folded.

#+begin_src emacs-lisp
(defun kittymacs-magit-display-buffer (buffer)
  "Show Magit BUFFER in a frame under frames-only mode, otherwise traditionally."
  (if (and (bound-and-true-p frames-only-mode) (display-graphic-p))
      (display-buffer buffer
                      '((display-buffer-reuse-window
                         display-buffer-pop-up-frame
                         display-buffer-use-some-window)
                        (reusable-frames . t)))
    (magit-display-buffer-traditional buffer)))

(use-package magit
  :ensure t
  :commands (magit-status magit-log magit-diff magit-commit magit-blame magit-dispatch magit-file-dispatch)

  (magit-section-initial-visibility-alist '((stashes . hide) (untracked . hide) (unpushed . hide)))
  (magit-no-message '("Turning on magit-auto-revert-mode..."))
  (git-commit-summary-max-length 50))

* Opening the status buffer from anywhere :decision:
:PROPERTIES:
:ID: ac8ccc5b-3c55-4a5c-9bfe-558d0899c24b
:END:

- =magit-status= works out which repository you mean from =default-directory=.
  + A buffer visiting a file has the right one.
  + The home page, a terminal, the scratch buffer and =*Messages*= do not: they keep whatever directory they happened to be created in.
- When that directory is not a repository, =magit-status= asks for one, or offers to /create/ one.
  + Declining leaves you where you started, which reads as the key having done nothing at all.
- So =SPC v s= (=kittymacs-magit-status=) asks in a better order:
  1. this buffer's repository;
  2. the repository of the current project;
  3. only then Magit's own prompt.
- From the home page both checks start from the page's own =default-directory=; when neither finds a repository, Magit's prompt appears.
- =SPC v= holds this command and Magit's everyday ones, with =SPC v q= for Emacs's own quick commit.
- =SPC p G= is Magit's status for the project.
  + The command =C-x p G= runs, =project-or-external-find-regexp=, has no key under =SPC p=, so use =C-x p G= for it.

* The commit message buffer :concept:
:PROPERTIES:
:ID: 3704479c-008d-4fed-aafd-3350568459d3
:END:

- A commit message is prose you are about to write, so the buffer:
  + wraps at eighty columns, comments and text alike;
  + checks spelling when [[id:afa6b7fd-742a-4c15-86a6-32e3e8027b0e][a checker is installed]];
  + starts in Meow's Insert state rather than Normal.
    - Meow's states are minor modes, but only =meow--switch-state= also moves the cursor shape and the mode line with them.
- All three hang on =git-commit-setup-hook=, and /when/ they are added matters.
- Magit keeps the older name =git-commit-mode-hook= working by making it a =defvaralias= of =git-commit-setup-hook=.
  + Aliasing a variable that already has a value throws that value away, and says so:

: Warning (defvaralias): Overwriting value of ‘git-commit-mode-hook’ by
: aliasing to ‘git-commit-setup-hook’

- That is exactly what =use-package='s =:hook (git-commit-mode . flyspell-mode)= caused:
  + Magit is deferred, so the hook was added at startup, hours of wall-clock time before =git-commit.el= loaded to alias it;
  + the spell checker it asked for was silently discarded on the way.
- The warning then cost more than it looked:
  + a warning buffer is displayed, and [[id:f1d045c2-e2dc-4514-ab17-dd982ed6be00][under frames-only mode]] a displayed buffer is an /operating-system window/;
  + so the first =SPC v s= of a session opened a warning window over the Magit window you asked for.
- Magit itself is careful: it gives the hook a =:get= function that merges a value set before the library loaded with its own defaults, so nothing Magit needs was lost.
- The rule stands anyway: add to a package's hooks only after the file that declares them has loaded.

#+begin_src emacs-lisp
(defun kittymacs--git-commit-setup ()
  "Prepare a commit message buffer for writing."
  (setq fill-column 80)
  (setq-local comment-auto-fill-only-comments nil)
  (kittymacs--flyspell-text)
  ;; Meow's states are minor modes, but only `meow--switch-state' also moves
  ;; the cursor and the mode line with them.
  (when (fboundp 'meow--switch-state)
    (meow--switch-state 'insert)))

;; Never touch `git-commit-setup-hook' -- or its alias `git-commit-mode-hook'
;; -- before git-commit.el has declared them.  See the prose above.
(with-eval-after-load 'git-commit
  (add-hook 'git-commit-setup-hook #'kittymacs--git-commit-setup))

#+end_src

* Changes in the gutter

- =diff-hl= marks added, changed and deleted lines in the left fringe each time a file is saved, in programming and text buffers.
  + =auto-save-visited-mode= saves after 15 idle seconds, so the gutter can lag the buffer by that long; =diff-hl-flydiff-mode= would close the gap by running a diff process while you type.
  + It updates asynchronously, and refreshes after Magit operations.
- It uses the margin instead when there is no fringe (a terminal).
- =SPC t g= toggles it in a buffer.

#+begin_src emacs-lisp

    (add-hook 'magit-pre-refresh-hook #'diff-hl-magit-pre-refresh)
    (add-hook 'magit-post-refresh-hook #'diff-hl-magit-post-refresh)))

* Pull requests: Forge and pr-review
:PROPERTIES:
:ID: 0d6b1f3e-5a2c-4c8e-9f71-2b4e8a6d3c15
:END:

- Issues and pull requests live on the forge, and Forge brings them into Magit, so a pull request is one more section of the status buffer.
  + Forge keeps a copy of each repository's topics in a SQLite database in the cache, so lists open at once and read offline.
  + =N / a= in the status buffer adds a repository to that database; after that, =f n= pulls what changed.
  + =SPC v g= opens Forge's menu: list, create, check out and merge pull requests, and the same for issues.
  + Forge's buffers are Magit buffers, so they start in Motion state and share =SPC m= with Magit.
- Forge cannot comment on a line of a diff, which is most of a review, so pr-review does that part.
  + One buffer holds one pull request: its description, commits, diff, review threads and checks.
  + =SPC v R= runs =kittymacs-pr-review=, which reviews the pull request at point in a Forge list or buffer, or else the current branch's; anywhere else, it asks for a URL.
  + It loads Forge if nothing has yet, so the first =SPC v R= of a session, from a file, still finds the branch's pull request.
  + =SPC v N= lists GitHub's notifications, with the pull requests waiting on your review among them.
- One token serves both: pr-review reads Forge's entry, rather than one of its own.
  + The entry is a line in an =auth-sources= file such as =~/.authinfo.gpg=: =machine api.github.com login USERNAME^forge password TOKEN=.
  + The token is a classic one with the =repo=, =user= and =read:org= scopes; =SPC v N= also needs =notifications=.
  + Forge's manual has the full setup, with the =github.user= Git setting, in its Initial Setup node: =M-x info-display-manual RET forge=.
  + kittymacs stores no token.
- orgit-forge adds an =orgit-topic:= Org link: =org-store-link= in a Forge topic stores one, and export turns it into the topic's URL.

#+begin_src emacs-lisp
(declare-function forge-current-pullreq "forge-pullreq" (&optional demand))
(declare-function forge-get-url "forge-commands" (obj))

(defun kittymacs-pr-review ()
  "Review a pull request with pr-review.
The one at point in Forge, or else the current branch's; otherwise ask."
  (interactive)
  (if-let* ((pullreq (and (require 'forge nil t)
                          (magit-toplevel)
                          (forge-current-pullreq))))
      (pr-review (forge-get-url pullreq))
    (call-interactively #'pr-review)))

    :custom

  (use-package pr-review
    :ensure t
    :defer t
    :custom
    (pr-review-ghub-auth-name 'forge))

  (use-package orgit-forge
    :ensure t
    :defer t)

  (keymap-set kittymacs-vc-map "g" (cons "forge menu" #'forge-dispatch))
  (keymap-set kittymacs-vc-map "R" (cons "review a pull request" #'kittymacs-pr-review))

* Meow in pull request reviews :meow:

* Git's own files and the repository's TODOs

- git-modes gives =.gitignore=, =.gitattributes= and =.git/config= files major modes of their own: comments, highlighting and indentation that know the format.
- magit-todos adds a section to the status buffer that lists every =TODO=, =FIXME= and the like in the repository.
  + Its words are the ones [[id:0286f652-e861-4e61-9ca6-91e225c8939d][the appearance chapter]]'s hl-todo highlights, so what stands out in a buffer is what the section lists.
  + It searches with =rg= in the background, so a refresh does not wait for it.
  + It skips repositories on a remote machine unless asked, because a search there runs over the connection: =M-x magit-todos-update= scans one by hand.
  + =SPC v t= lists the TODOs in a buffer of their own.

* Links to lines and commits

- =SPC v o= runs =git-link=: it copies the forge's URL for this line, or for the selected lines, at the commit you are on.
  + The URL names the commit rather than the branch, so a link pasted into a note still shows the same lines after the branch moves.
- orgit adds Org links to Magit buffers: =orgit:= for a status buffer, =orgit-log:= for a log and =orgit-rev:= for a commit.
  + =SPC m L= in a Magit buffer stores one, for each selected commit if there are several; =org-store-link= does the same.
  + Exported, an =orgit-rev:= link becomes the commit's URL on the forge.
  + Both register only once Org and Magit have loaded, so neither loads the other.

* Diffs by syntax

- A line diff marks a moved function, or a rewrapped argument list, as lines deleted and lines added; =difft= compares syntax trees, so it shows what changed.
- difftastic shows its output in a buffer of its own, beside Magit's diff rather than instead of it.
  + =SPC v D= compares this file with the last commit.
  + In Magit's diff menu, =M-d= shows the diff at point this way and =M-c= a whole commit; in a blame, =M-RET= shows the commit of the line.
  + Magit's menus gain those keys when Magit loads, because the keys extend them.
- =difft= is a separate program: the Nix modules install it with the feature, and elsewhere it comes from the system's packages.
- It runs =git= on this machine, so it works in local repositories only.

* Reviewing a branch: diff-review
:PROPERTIES:
:ID: 3f0450b0-881e-4487-b90f-49a4d03f17a7
:END:

- A pull request page shows a branch's whole change: the files it touched, comments on lines, and a verdict at the end.
  + diff-review gives a branch that page inside Emacs, from Git alone, so it needs no forge and no token.
- =SPC v v= reviews a branch against its base: pick one that another worktree has checked out, or type any.
  + The base is the branch =origin/HEAD= points at, else =main= or =master=.
  + The overview lists the counts and the changed files as a tree; a sidebar shows the same tree beside each file.
  + Each file opens as the real file in its own major mode, so xref, Eglot and editing all work during a review.
  + Overlays put each removed line back in place, before the lines that replaced it, and tint the added ones.
  + You mark files viewed, start comment threads on lines, and give the head a verdict: approved, or changes requested.
- =SPC v V= reviews what this worktree has not committed yet, against the same base.
  + Its file is =review/NAME.worktree.json= in the same place, NAME being the worktree's directory, so it never meets a branch's review: =git worktree add ../feature= names the new branch =feature= too.
  + =kittymacs-diff-review-worktree= passes diff-review the worktree as well as the file, because diff-review cannot find a worktree from a file inside =.git=, and its own =M-x diff-review-find-file= asks for a file name with no default.
- The review is a JSON file, =review/BRANCH.json=, under the =.git= that every worktree shares.
  + Git never commits it, and every worktree of the repository opens the same review.
  + It follows the branch: after a new commit, =g= rescans, viewed marks clear on the files that changed, and threads follow their lines.
- =diff-review-magit-mode= adds two things to Magit once Magit loads:
  + a /Worktree branches/ section in the status buffer: each other worktree's branch, its commits ahead of the base and its review's state, with =RET= opening the review;
  + =d v=, "Review" in Magit's diff menu, which reviews the selected commits, or the one at point; =SPC m v= in a Magit buffer does the same.
  + It waits for Magit, so neither package loads at startup.
- It is not on MELPA, so it installs from Git, pinned to a commit, as [[id:56789f7f-90bb-4c3b-947c-16ecb6d72365][agent-shell-attention]] does.
  + A failed clone is a warning, not a stopped startup; until a restart installs it, its keys and the Magit additions stay off.

* Meow in branch reviews :meow:
:PROPERTIES:
:ID: 80f63f69-9645-451e-9e8b-1fe1ade12a68
:END:

- The overview and its sidebar are lists to move through, so they start in Motion state.
  + Motion adds only =j=, =k= and the leader, so diff-review's own one-letter keys work as its README describes.
  + They need no =SPC m= menu: the keys are single letters already, and =C-h m= lists them.

| Key      | Does                                     | Key       | Does                                    |
|----------+------------------------------------------+-----------+-----------------------------------------|
| =RET=    | show the file at point, or fold a folder | =t=       | show or hide the sidebar                |
| =n=, =p= | next, previous file                      | =A=       | approve the head                        |
| =u=      | next unviewed file                       | =C=       | request changes                         |
| =v=      | toggle the viewed mark                   | =C-c C-c= | the review as its JSON, and back        |
| =g=      | rescan the diff                          | =q=       | end the review; in the sidebar, hide it |

- A file under review is a file you may edit, so it keeps its usual state, Normal.
  + The review is a minor mode there, so it adds one group to =SPC m=, =SPC m R=, and the rest stays the major mode's menu ([[id:f468e425-28ac-46ac-b6d1-92b644d07e61][minor modes in =SPC m=]]).
  + The group holds diff-review's own command map, so =SPC m R c= is =C-c _ c=, and the table below serves both.
  + =C-c _= keeps working: Meow leaves =C-c= to Emacs in Normal and Insert state alike.
  + No =kittymacs-define-localleader= binds =R=, so the group hides no key of any major mode's menu.
  + With =repeat-mode= on, the prefix is needed once for a run: =C-c _ n n v= walks two hunks and marks the file viewed, and =SPC m R n n= does the same; =M-g n= and =M-g p= walk the hunks too.
- Each key below follows =C-c _= or =SPC m R=.

| Key      | Does                                | Key      | Does                                 |
|----------+-------------------------------------+----------+--------------------------------------|
| =n=, =p= | next, previous hunk, across files   | =x=      | resolve the thread, or reopen it     |
| =v=      | mark viewed, show the next unviewed | =D=      | delete the thread                    |
| =z=      | fold the unchanged lines            | =o=      | open every thread                    |
| =d=      | show or hide the removed lines      | =N=, =P= | next, previous thread                |
| =c=      | comment on the region or the line   | =t=      | show or hide the sidebar             |
| =r=      | reply to the thread                 | =l=, =q= | back to the overview; end the review |

* Meow in Magit :meow:
:PROPERTIES:
:ID: 8c1af730-24e5-4926-88dd-d2f54a63c584
:END:

- Magit buffers start in Motion state: Magit's keys are the interface, so Meow steps back and adds only =j=/=k= and the leader.
- Commit message buffers are for typing: [[*The commit message buffer]] starts them in Insert state.
- =SPC m= labels the most common Magit commands for anyone who does not yet know them.
  + Most open Magit's own menu; stage, unstage, discard and refresh act directly.
  + =L= stores an Org link to the commits or buffer at point, with the =git-links= feature on.
  + =v= reviews the selected commits, or the one at point, with =branch-review= on: [[*Reviewing a branch: diff-review]].
- A blame (=SPC v b=, then =b=) is a minor mode over the file, so its commands are the group =SPC m B= while it is on, beside the file's own menu.
  + Its keys are Magit's own blame keys, which a blamed buffer also takes directly where Meow leaves them free.
  + Magit gives these commands no repeat map, so each takes the group keys.

| =SPC m B= | Does                         | =SPC m B= | Does               |

- =SPC v s= in any file of a Git project: the status buffer opens; =TAB= folds sections.
- On a changed file: =s= stages it, =c c= opens the commit message in Insert state, =C-c C-c= commits.
- =SPC m= in the status buffer lists what else you can do.
- Edit a tracked file: the fringe marks the changed lines.
- =*Warnings*= stays empty after the first =SPC v s= of a session.
- =just test-packages=: the startup verifier replays a real startup and fails on any warning, such as the =defvaralias= one above.
- With =pull-requests= on and a token stored: =N / a= in a GitHub repository's status buffer adds it; =SPC v g= then lists its pull requests.
  + On a pull request, =SPC v R= opens the review; =SPC m c= on a diff line starts a comment in Insert state.
- With =git-extras= on: the status buffer of a repository with a =TODO= has a TODOs section; a =.gitignore= opens in its own mode.
- With =git-links= on: =SPC v o= in a tracked file copies a URL that opens that line on the forge.
  + =SPC m L= on a commit in a Magit log, then =C-c C-l= in an Org buffer, inserts an =orgit-rev:= link.
- With =structural-diffs= on and =difft= installed: =SPC v D= in a changed file opens a difftastic buffer in Motion state.
- With =branch-review= on, in a repository with a second worktree on a branch:
  + the status buffer has a /Worktree branches/ section; =RET= on the branch opens its review in Motion state;
  + =SPC v v= from a file of the repository offers the same branch, and opens the same review;
  + =RET= on a file shows it with removed lines in place; =C-c _ c= there starts a comment, and =C-c _ v= marks the file viewed;
  + =q= in the overview ends the review; =.git/review/BRANCH.json= keeps the comment and the mark;
  + =SPC m v= on a commit in a Magit log, or =d v=, reviews that commit;

  + =SPC v V= in a worktree with an uncommitted edit opens a review of that edit, kept in =.git/review/NAME.worktree.json=.
