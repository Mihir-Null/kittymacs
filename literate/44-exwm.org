#+TITLE: EXWM: Emacs as the X window manager
#+FILETAGS: :interface:linux:
#+STARTUP: overview
#+PROPERTY: header-args:emacs-lisp :tangle ../lisp/kittymacs-exwm.el :eval never :comments no :padline no :mkdirp yes

- In an X session that has no other window manager (a remote desktop, say), Emacs arranges every window itself: Chrome and other X programs become buffers, shown in Emacs windows, switched like any buffer.
- The keys are LeopardWM's, the tiler on Windows: one modifier (Hyper here), the same letters, the nearest EXWM action.
  + The key table is data, separate from what each action does, so a Wayland compositor such as EWM can bind the same table later.
- Leans on nothing in kittymacs; [[id:f1d045c2-e2dc-4514-ab17-dd982ed6be00][the frames chapter]] reads =kittymacs-exwm=, so this chapter loads just before it.
- Does not know how Hyper is made: the session maps a key to it, such as Caps Lock or F13.

* Only when the session asks :decision:
:PROPERTIES:
:ID: 09277c62-e114-4ae6-a53b-f22650c0a4c0
:END:

- EXWM is on only when the program that starts Emacs sets =KITTYMACS_EXWM=1= and the first frame is on X.
  + An Emacs started any other way (the daemon, a WSLg window, a Wayland session) loads none of this, and EXWM is never installed into it.
  + An environment variable, not a command-line switch: the session script sets it, and =init.el= can read it before any chapter loads.
- Selecting the =window-manager= feature installs EXWM for such a session, and turns on nothing by itself.
  + =KITTYMACS_EXWM=1= on X selects the feature too, and =kittymacs-exwm-session-p= in [[id:5c1e7a94-8f30-4d26-b7a1-3e92d06f4c18][the features chapter]] is the one place that asks: the installer needs the answer before this chapter loads.
  + This chapter always loads, because =kittymacs-wm-keys= and the other options are public, and a host may set them on any machine.
- The first frame is already on X when =init.el= runs, so =window-system= is =x= by then; a daemon has no frame yet, which is why the daemon can never be the window manager here.
- The session's Emacs takes over from the daemon while the session lasts:
  + the session stops the daemon before starting it, so [[id:3fd783cd-deb8-48aa-bb44-0d9b16535365][the defaults]], which start a server only if none runs, start one here, under the daemon's name;
  + =emacsclient=, from a shell in the session or over SSH, then reaches this Emacs and its buffers: one Emacs, not two;
  + when the session ends, the session starts the daemon again.
- How the daemon is stopped and started belongs to whatever starts the session, not to this chapter.

* The key grammar, from LeopardWM :decision:
:PROPERTIES:
:ID: 44577bed-4dfb-4432-b608-98e3e79e791b
:END:

- The grammar carries over; the mechanics are EXWM's:
  + =H-key= :: act on the focused thing;
  + =H-S-key= :: move it;
  + =H-C-key= and =H-C-S-key= :: monitors, unbound while a session has one screen ([[*Actions with no EXWM equivalent]]).
- Each entry is =(KEY ACTION . ARGS)=: a key in =kbd= notation, an action named as LeopardWM names it (=focus_left= is =focus-left=), and its arguments.
  + A shifted letter is its capital, =H-H=; a shifted digit or symbol is the character it types on a US layout, =H-!= for Shift+1, =H-+= for Shift+=.
- Set it in =private.el= before this chapter loads, or change it later and press =H-R=.

* What each action does

  "Close the focused thing.
An X window's buffer is killed, which asks its program to close it; then
the Emacs window goes too, unless it is the frame's last."
  (interactive)
  (let ((window (selected-window)))
    (when (derived-mode-p 'exwm-mode)
      (kill-current-buffer))
    (when (and (window-live-p window) (not (one-window-p)))
      (delete-window window))))

(defun kittymacs-exwm-maximize ()
  "Show only the selected window; pressed again, bring the others back."
  (interactive)
  (if-let* ((saved (frame-parameter nil 'kittymacs-exwm-maximized)))
      (progn (set-frame-parameter nil 'kittymacs-exwm-maximized nil)
             (set-window-configuration saved))
    (unless (one-window-p)
      (set-frame-parameter nil 'kittymacs-exwm-maximized
                           (current-window-configuration))
      (delete-other-windows))))

(defun kittymacs-exwm--cycle (presets step horizontal)
  "Resize the selected window to the preset STEP (1 or -1) away in PRESETS.
PRESETS are fractions of the frame, in increasing order; HORIZONTAL
means widths.  Past the last preset, the first comes round again."
  (let* ((total (window-total-size (frame-root-window) horizontal))
         (now (/ (float (window-total-size nil horizontal)) total))
         (next (if (> step 0)
                   (or (seq-find (lambda (p) (> p (+ now 0.01))) presets)
                       (car presets))
                 (or (seq-find (lambda (p) (< p (- now 0.01))) (reverse presets))
                     (car (last presets))))))
    (condition-case err
        (window-resize nil (- (round (* next total))
                              (window-total-size nil horizontal))
                       horizontal)
      (error (message "%s" (error-message-string err))))))

(defun kittymacs-exwm-scratchpad-stash ()
  "Float the focused X window and hide it, to call back with `scratchpad-toggle'."
  (interactive)
  (unless (derived-mode-p 'exwm-mode)
    (user-error "Only an X window can be stashed"))
  (setq kittymacs-exwm--scratchpad (current-buffer))
  (unless exwm--floating-frame
    (exwm-floating-toggle-floating))
  (exwm-floating-hide))

(defun kittymacs-exwm-scratchpad-toggle ()
  "Show the stashed X window, or hide it again if it is showing."
  (interactive)
  (let* ((buffer kittymacs-exwm--scratchpad)
         (window (and (buffer-live-p buffer) (get-buffer-window buffer t))))
    (cond ((not (buffer-live-p buffer))
           (user-error "Nothing is stashed: the stash key stashes an X window"))
          (window (with-selected-window window (exwm-floating-hide)))
          (t (switch-to-buffer buffer)))))

** Starting a program :decision:
:PROPERTIES:
:ID: 66502132-05ee-4b9d-a3ec-3e8ceb585c9f
:END:

- EXWM runs inside this Emacs, so while Emacs waits for a program, nothing manages the windows and no key works.
- =M-!=, =shell-command=, waits for its command to exit unless the command ends in =&=.
  + =M-! google-chrome= freezes the whole session until Chrome quits: Emacs sits reading Chrome's output, and EXWM cannot draw, focus or pass on a key meanwhile.
  + With a trailing =&=, =M-!= runs the command as =M-&= does.
- =M-&=, =async-shell-command=, is the other safe way.
  + It shows the program's output in a buffer, and killing that buffer asks first, then ends the program.
- =H-d= asks for a command and starts it detached, as [[https://github.com/emacs-exwm/exwm/wiki][EXWM's example configuration]] does on =s-&=.
  + =TAB= completes program names from =PATH=, as in =M-!=, because both read the command with =read-shell-command=.
  + The program has no buffer, so its output goes nowhere, and no buffer can take the program with it.
  + It talks to Emacs through a pipe, not a terminal, so a program that forks into the background gets no hang-up signal when its shell exits.
  + Emacs does not ask about it on exit.
- A program that exits with an error says so in the echo area, with the last line it printed: a mistyped name gives code 127, and the shell's complaint that it found no such command.
- =start-process-shell-command=, not =call-process= with =0= as its destination.
  + Both return at once, but only the process object the first returns can report a failure.

(defun kittymacs-exwm--launch-filter (process output)
  "Keep the latest OUTPUT of PROCESS, for its sentinel to quote."
  (process-put process 'kittymacs-exwm-output output))

(defun kittymacs-exwm--launch-sentinel (process _event)
  "Say in the echo area if PROCESS, from `kittymacs-exwm-launch', failed."
  (when (and (eq (process-status process) 'exit)
             (/= (process-exit-status process) 0))
    (message "%s exited with code %d: %s"
             (process-name process) (process-exit-status process)
             (or (car (last (split-string
                             (or (process-get process 'kittymacs-exwm-output) "")
                             "\n" t)))
                 "no output"))))

(defun kittymacs-exwm-launch (command)
  "Start the shell COMMAND detached, so that Emacs never waits for it.
\\`TAB' completes program names from `exec-path'.  If COMMAND exits
with an error, the echo area says so."
  (interactive (list (read-shell-command "Launch: ")))
  (let* ((process-connection-type nil)
         (process (start-process-shell-command command nil command)))
    (set-process-query-on-exit-flag process nil)
    (set-process-filter process #'kittymacs-exwm--launch-filter)
    (set-process-sentinel process #'kittymacs-exwm--launch-sentinel)
    process))

** Actions with no EXWM equivalent
:PROPERTIES:
:ID: bcba57df-d1a1-4412-b064-b6d10c5cb1b4

- LeopardWM scrolls an endless strip of columns; Emacs splits a fixed frame. What only a strip can do stays unbound:

| LeopardWM key and action                          | Why it stays unbound                                         |
|---------------------------------------------------+--------------------------------------------------------------|
| =C= =center_column=                                   | nothing scrolls, so nothing to centre                        |
| =,= =.= =consume_from_left=, =_right=                   | a window holds one buffer; columns hold windows              |
| =Shift+[= =Shift+]= =expel_to_left=, =_right=           | the same                                                     |
| =Home= =End=, with Shift: the strip's ends            | no strip; =H-h= and =H-l= reach the frame's edges              |
| =N= =toggle_new_window_placement=                     | EXWM shows a new window in the selected one                  |
| =P= =toggle_pause=, =Y= =toggle_sticky=                 | no counterpart worth a key yet                               |
| =Ctrl+HJKL=, =Ctrl+Shift+HJKL=: monitors              | a remote session has one screen; =exwm-randr-mode= when not    |

* Binding the table

- =exwm-input-global-keys= holds keys that work everywhere: in Emacs buffers, and in X windows, which would otherwise receive every key.
- Set with =setopt=, not =setq=: the option's setter binds the keys, and tells a running EXWM about them.
- An action the actions list lacks is an error naming it, so a typo in the table is found at once.

#+begin_src emacs-lisp

(defun kittymacs-exwm--command (action args)
  "The command for ACTION, called with ARGS."
  (let ((function (alist-get action kittymacs-exwm-actions)))
    (unless function
      (error "`kittymacs-wm-keys' names %s, which `kittymacs-exwm-actions' lacks"
             action))
    (if args
        (lambda () (interactive) (apply function args))
      function)))

(defun kittymacs-exwm-apply-keys ()
  "Bind `kittymacs-wm-keys' everywhere, in Emacs buffers and X windows."
  (interactive)
  (setopt exwm-input-global-keys
          (mapcar (lambda (entry)
                    (cons (kbd (car entry))
                          (kittymacs-exwm--command (cadr entry) (cddr entry))))
                  kittymacs-wm-keys)))

* EXWM itself

- Four workspaces to begin with; =H-5= to =H-9= make the rest when first used.
- An X window's buffer is named after its program and title, =Google-chrome: Inbox=, so =C-x b= and Consult find it by either.
- =exwm-wm-mode= waits for =window-setup-hook= when called while the first frame is still being set up, so it can be turned on from here.
- =C-x=, =C-h=, =M-x= and the other prefix keys reach Emacs even from an X window ([[https://github.com/emacs-exwm/exwm/wiki][EXWM's wiki]]); =C-q= sends the next key to the program instead.
- A key whose modifier the X server lacks must not stop EXWM.
  + =xcb:keysyms:event->keysyms= documents =((0 . 0))= for a key it cannot convert, and EXWM warns "Key unavailable" on that value.
  + With no mask for a modifier, it returns nil instead, and EXWM's arithmetic on that turns EXWM off, leaving a plain frame.
  + An xorgxrdp session can start like that, because it rebuilds the keyboard about 2 s in, and a bare X server has no Hyper at all.
  + So a filter reads nil as the documented value.
  + EXWM's input code treats that value as a failed key, and its input-method code sends key 0 where nil would signal an error.
  + The =H-= keys are dead while the modifier is missing, with a warning for each, and the rest of EXWM works.
  + When the modifier returns, xelb reads the new masks and EXWM grabs the keys again, so a session that reloads its keymap gets them back.
- xelb asks =xauth= for the X server's cookie, and without one on =PATH= it connects with none.
  + A server that asks for a cookie, as xrdp's does, then refuses EXWM with "Authorization required, but no authorization protocol specified".
  + Emacs's own frame still opens, because libX11 reads =~/.Xauthority= itself, so the session shows a plain frame that nothing manages, and its windows take no input and do not resize.
  + So the start says so first, in =*Warnings*=, and still tries, because a server with no cookie, such as a bare Xvfb, accepts EXWM anyway.

(defun kittymacs-exwm--warn-without-xauth ()
  "Warn if xelb cannot find the X server's cookie, because there is no xauth."
  (unless (executable-find "xauth")
    (display-warning
     'kittymacs
     "No xauth on PATH, so EXWM connects to X with no cookie, and a server that asks for one refuses it.
If EXWM does not start, install xauth where this Emacs's PATH finds it, then start the session again."
     :warning)))

(defun kittymacs-exwm--keysyms-or-failure (keysyms)

  (or keysyms '((0 . 0))))

** The screen's size can change :decision:
:PROPERTIES:
:ID: 2d48b60f-6466-4b44-b1ca-db4328ad1889
:END:

- A remote desktop's screen is as large as the client's window, and the client says so again whenever its window is resized: the RDP client sends a display update, and xrdp resizes the X screen through RandR.
- EXWM itself sizes its workspaces once, at start, and ignores a root window that changes size afterwards; =exwm-randr-mode= listens for RandR's change notices and fits every workspace to the screen again (=exwm-randr-refresh=).
  + With no =exwm-randr-workspace-monitor-plist=, every workspace goes to the primary monitor, or the only one: one screen needs no configuration.
- Turned on before =exwm-wm-mode=, so it starts with EXWM; on a desk with several monitors it is also what places workspaces on them.
