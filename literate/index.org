* Start here

kittymacs is a personal Emacs configuration written as a book. Every chapter
in this folder explains one part of the editor, shows the small piece of
Lisp that configures it, and says why. The Lisp blocks are *tangled* (copied
out) into =lisp/*.el= and the two startup files, which is what Emacs actually
loads. You read and edit the chapters; Emacs runs the generated files.

Three ideas hold it together:

- *Meow* is the editing model: select something, then act on it. The
  [[file:40-editing.org][editing chapter]] explains it in a page.
- *SPC* is a real keymap, not a translation trick. Press =SPC=, wait, and
  which-key shows every group; =SPC m= shows the menu for the current mode.
  The [[file:41-leader.org][leader chapter]] explains the mechanism and the [[file:42-keys.org][keys chapter]] lists the tree.
- *Frames, not windows*: new editing surfaces are OS windows so your window
  manager arranges them. The [[file:45-frames.org][frames chapter]] explains the exceptions.

If you only read one other thing, read [[file:../lisp/keybindings.org][the cheat sheet]]: =SPC h ?= opens
it from inside Emacs, and =M-x meow-tutor= teaches the grammar.

* How to read a chapter

Open a chapter, press =TAB= on a heading to fold or unfold it, =S-TAB= to see
the outline. Each chapter has the same shape: what it gives you, one section
per concern with a short explanation and a small code block, a "Meow in…"
section describing states and the =SPC m= menu, and "Try it" at the end.
=C-c '= edits a code block in its own buffer.

* Three layers

*Emacs* supplies the mechanisms: keymaps, hooks, faces, =package.el=,
=use-package=, which-key, project.el, Dired, Org, Tree-sitter, Eglot.
*Packages* supply the features we chose: Meow, the completion stack, Magit,
EAT, doom-modeline, and the rest; each is declared in the chapter that uses
it with =use-package … :ensure t=, so a fresh clone installs what it needs.
*This configuration* is only the policy: which packages, how they are set,
and the =SPC= tree that ties them together. Much of the policy was distilled
from [[https://codeberg.org/Lambda-Emacs/lambda-emacs][Lambda-Emacs]] by Colin McLear; the chapters say where.

* Change something

1. Edit the chapter: the prose and the code block together.
2. =SPC C t= (or =M-x kittymacs-literate-tangle=) rebuilds the generated files in
   a clean Emacs subprocess and reports in =*kittymacs literate build*=.
   Unsaved chapters are refused, so a build never uses a stale file.
3. =SPC C k= checks that chapters and generated files agree without writing.
4. Restart Emacs. Commit the chapter and the generated file together.

From a shell, without loading the configuration:

#+begin_src sh
emacs -Q --batch -l tools/tangle.el -- --write
emacs -Q --batch -l tools/tangle.el -- --check
#+end_src

For a quick experiment, evaluate a block with =C-c C-c= or =SPC e e= on a
form; that changes the running Emacs without rebuilding anything.

* Machine-specific settings

Copy =lisp/private.example.el= to =lisp/private.el= (=SPC C p= does it) and
set paths, fonts, opt-in language servers or your own keys there. Git ignores
it. =M-x customize= saves to =var/etc/custom.el=, also ignored. Back both up
yourself. The last section of [[file:10-startup.org][the startup chapter]] explains when each file is
read, and why a package option in =private.el= goes in a hook.

* Add a chapter

1. Create =literate/NN-name.org= with the header of any existing chapter,
   changing the =:tangle= target to =../lisp/kittymacs-name.el=. The two
   digits and the dash matter: the builder treats every file named that way
   as a chapter and reads its outputs from the =:tangle= headers, so there
   is no list to register the chapter in.
2. Add =(require 'kittymacs-name)= to =init.el= in the [[file:10-startup.org][startup chapter]] where
   it belongs in the order.
3. Give the package a Meow section: which state its buffers start in, and a
   =kittymacs-define-localleader= form for its =SPC m= menu.

The builder also refuses to run when =lisp/= holds a =kittymacs-*.el= that
no chapter produces, because startup would go on loading a module whose
source is gone. After renaming or deleting a chapter, delete its old
generated file too.

* Where things are on disk

#+begin_example
.emacs.d/
  early-init.el, init.el   generated from literate/10-startup.org
  literate/                these chapters
  lisp/                    generated modules, the cheat sheet, themes/, private.el
  tests/                   tangle tests, startup verifier, leader tests, frame tests
  tools/tangle.el          the builder
  var/                     packages, caches, custom.el: ignored by Git
#+end_example
