- What every programming buffer gets, whatever the language: rainbow delimiters, self-closing pairs, structural editing that never unbalances a paren, Flymake in the fringe, compiling, and one =SPC m= menu.
- Language parsers and language servers are in [[id:560fcdca-6cb8-49d9-bf27-eb78f32b9285][the languages chapter]]; the menu is a localleader from [[id:e5942eb0-4389-447d-9317-d9178adcaaae][the leader chapter]].
- Distilled from Lambda-Emacs by Colin McLear: =lem-setup-programming=, and compilation from =lem-setup-shell=.
- Read [[id:a1607a41-b741-428a-9de3-c16e7c8d3ecc][the editing chapter]] first: programming buffers use its selection grammar.

* Delimiters and structure

- =rainbow-delimiters= colours each nesting level.
- =electric-pair-mode= inserts the closing bracket.
- =show-paren-mode= highlights the match at once, and shows the opening line when it is off screen.
- Puni is structural editing for every language, and for Org, Markdown, TeX and the =M-:= prompt:
  + deleting never breaks a pair;
  + =C-)= and =C-(= slurp the next or previous expression into the current one; =C-}= and =C-{= barf it out.
- Embrace adds, changes and removes surrounding pairs (=SPC c s=); Org and Markdown get their own pairs (=*=, =_=, =`=, =$= in Markdown).
- =iedit= edits every occurrence of a symbol at once (=SPC s c=).
- =prettify-symbols-mode= is on everywhere and shows the real text when point is on a symbol; =rainbow-identifiers= is available as a command.

(defun kittymacs--embrace-markdown ()
  "Markdown pairs for Embrace."
  (dolist (pair '((?* "*" . "*") (?_ "_" . "_") (?` "`" . "`") (?$ "$" . "$")))
    (embrace-add-pair (car pair) (cadr pair) (cddr pair))))

* Indentation: guides everywhere, re-indenting only in Lisp :decision:
:PROPERTIES:
:ID: 2bbfeaaa-f982-4661-8e26-2c0aa1e92800
:END:

- Guides draw a thin =│= at each indentation level; the guide of the current level is highlighted.
  + Graphical frames only: the package cannot derive its faces without a display.
- In Lisp buffers =aggressive-indent= re-indents as you type, which is how Lisp is meant to feel.
  + In other languages it fights with formatters, so it stays off.
  + It does not re-indent inside comments, and does not run after =comment-dwim=.

#+begin_src emacs-lisp
(defun kittymacs--indent-guides ()
  "Show indent guides in graphical frames.
The package cannot derive its faces without a display."
  (when (display-graphic-p)
    (highlight-indent-guides-mode 1)))

(use-package highlight-indent-guides
  :ensure t
  :hook (prog-mode . kittymacs--indent-guides)
  :custom
  (highlight-indent-guides-method 'character)
  (highlight-indent-guides-character ?│)
  (highlight-indent-guides-responsive 'top)
  (highlight-indent-guides-auto-odd-face-perc 5)
  (highlight-indent-guides-auto-even-face-perc 5)
  (highlight-indent-guides-auto-character-face-perc 15))

(use-package aggressive-indent
  :ensure t
  :hook ((emacs-lisp-mode lisp-interaction-mode lisp-mode) . aggressive-indent-mode)
  :custom
  (aggressive-indent-comments-too nil)
  :config
  (add-to-list 'aggressive-indent-protected-commands 'comment-dwim))

#+end_src

* Linting with Flymake

- Flymake is built in and runs a checker for the current language when one is available:
  + Eglot provides one for any language server;
  + =package-lint= checks Emacs Lisp packages;
  + =flymake-collection= adds checkers for common tools.
- Problems show in the left fringe and as counters in the mode line (zero counts hidden); =SPC F= lists them.
- Checks run on save, not on a timer after each change; next and previous stop at the last error instead of wrapping.
- Flymake's own commands carry no autoload cookie:
  + until some buffer has switched =flymake-mode= on, =flymake-start= and its neighbours are not defined and the =SPC F= keys would fail;
  + =:commands= declares them as autoloads, so each key loads Flymake the first time it is pressed.
- =savehist= keeps =package-archive-contents= once =package-lint= loads.

#+begin_src emacs-lisp
(use-package flymake
  :ensure nil
  :hook (prog-mode . flymake-mode)
  :commands (flymake-start flymake-goto-next-error flymake-goto-prev-error
             flymake-show-buffer-diagnostics flymake-show-project-diagnostics)
  :custom
  (flymake-fringe-indicator-position 'left-fringe)
  (flymake-suppress-zero-counters t)
  (flymake-no-changes-timeout nil)
  (flymake-start-on-save-buffer t)
  (flymake-wrap-around nil)
  (flymake-mode-line-counter-format '("" flymake-mode-line-error-counter flymake-mode-line-warning-counter flymake-mode-line-note-counter ""))
  (flymake-mode-line-format '(" " flymake-mode-line-exception flymake-mode-line-counters)))

(use-package package-lint
  :ensure t
  :commands (package-lint-current-buffer package-lint-buffer)
  :config
  (with-eval-after-load 'savehist
    (add-to-list 'savehist-additional-variables 'package-archive-contents)))

(use-package flymake-collection
  :ensure t
  :demand t
  :config
  (flymake-collection-hook-setup))

#+end_src

* Compiling

- =compile= runs a command and links errors to source lines.
- A new compilation kills the old one, buffers save without asking, and the output scrolls to the first error.
- The compilation buffer is truncated as output arrives, so a long build cannot grow it without bound.

#+begin_src emacs-lisp
(setopt compilation-always-kill t
        compilation-ask-about-save nil
        compilation-scroll-output 'first-error)
(with-eval-after-load 'compile
  (add-hook 'compilation-filter-hook #'comint-truncate-buffer))

#+end_src

* Emacs Lisp

- Documentation shows in the echo area at once (=eldoc-idle-delay= is 0).
- Lisp buffers (Emacs Lisp, IELM, =*scratch*=) get:
  + =elisp-def= for jumping to definitions;
  + trailing whitespace marked, so it never creeps into a commit.
- =lambda= is drawn as =λ= by the global =prettify-symbols-mode= in [[*Delimiters and structure]], which switches itself on in every mode that defines symbols to prettify.
- Shell scripts named like zsh files (=.zsh=, =zshrc=, =zshenv=, =zprofile=, =zlogin=, =zlogout=) open in =sh-mode=.

#+begin_src emacs-lisp
(setopt eldoc-idle-delay 0)

(use-package elisp-def
  :ensure t
  :hook ((emacs-lisp-mode ielm-mode lisp-interaction-mode) . elisp-def-mode))

(defun kittymacs--show-trailing-whitespace ()
  "Mark trailing whitespace in this buffer."
  (setq show-trailing-whitespace t))
(dolist (hook '(emacs-lisp-mode-hook ielm-mode-hook lisp-interaction-mode-hook))
  (add-hook hook #'kittymacs--show-trailing-whitespace))

(dolist (pattern '("\\.zsh\\'" "zlogin\\'" "zlogout\\'" "zprofile\\'" "zshenv\\'" "zshrc\\'"))
  (add-to-list 'auto-mode-alist (cons pattern 'sh-mode)))

#+end_src

* Meow in programming buffers :meow:
:PROPERTIES:
:ID: 2642875a-5c0b-4b38-bab8-b4d15b2713a1
:END:

- Programming buffers are ordinary text buffers: they start in Normal state and the whole selection grammar applies.
- =SPC m= gives every language the same first menu, set on =prog-mode= and inherited by every programming mode.
- Emacs Lisp adds its evaluation commands on top: they take over =c=, =r=, =e=, =d=, =D= and =i=; the rest of the menu stays.
- A language chapter can add more for its own mode the same way.

| Key | Every programming mode     | Emacs Lisp                                    |
|-----+----------------------------+-----------------------------------------------|
| =c= | =compile=                  | byte compile                                  |
| =r= | =recompile=                | eval region                                   |
| =e= | choose an error (Consult)  | eval last sexp                                |
| =E= | error list                 |                                               |
| =f= | format (=indent-region=)   |                                               |
| =;= | comment                    |                                               |
| =s= | surround (Embrace)         |                                               |
| =i= | edit all occurrences       | IELM                                          |
| =d= | definition                 | eval defun                                    |
| =D= | references                 | find definition (=elisp-def=)                 |
| =b= |                            | eval buffer                                   |
| =x= |                            | eval expression                               |
| =g= |                            | edebug defun                                  |
| =l= |                            | package lint                                  |
| =m= |                            | macroexpand                                   |
| =?= |                            | Casual's Elisp menu                           |

#+begin_src emacs-lisp
(kittymacs-define-localleader 'prog-mode
  "c" (cons "compile" #'compile)
  "r" (cons "recompile" #'recompile)
  "e" (cons "errors" #'consult-flymake)
  "E" (cons "error list" #'flymake-show-buffer-diagnostics)
  "f" (cons "format" #'indent-region)
  ";" (cons "comment" #'comment-dwim)
  "s" (cons "surround" #'embrace-commander)
  "i" (cons "edit all occurrences" #'iedit-mode)
  "d" (cons "definition" #'xref-find-definitions)
  "D" (cons "references" #'xref-find-references))

(kittymacs-define-localleader 'emacs-lisp-mode
  "e" (cons "eval last sexp" #'eval-last-sexp)
  "d" (cons "eval defun" #'eval-defun)
  "b" (cons "eval buffer" #'eval-buffer)
  "r" (cons "eval region" #'eval-region)

* Check

- In a Lisp buffer, put point after a form and press =SPC m e=: the echo area shows its value.
- Type =(= inside code: the =)= appears.
- Select an expression with =o= and press =d=: it is gone, and the parens around it stay balanced.
- Break something on purpose: the fringe marks it; =SPC m E= lists it.
- =SPC m= in a Python or shell buffer: =compile=, the error list and =format=, with no evaluation keys.
- =just test-packages= runs the verifier, which starts the real configuration and fails if this module does not load or a startup warning appears.
