Ownership: *user configuration*. These are the only two files Emacs reads on
its own. Together they are about a hundred lines: the first decides where
files live and how packages are fetched, the second loads the chapters in
order. Nothing else is special.

* What happens when Emacs starts

1. Emacs reads =early-init.el= *before* it creates a frame or activates
   packages. That is the moment to say where packages live, to switch off
   toolbars so they never flash, and to postpone garbage collection.
2. Emacs then reads =init.el=. It activates the installed packages, loads
   =use-package=, and requires each generated module in dependency order:
   defaults and platform first, then the look, then editing and the
   integrations, then the applications, and frames policy last so nothing
   later can undo it.
3. Packages are declared where they are used, with =use-package … :ensure t=.
   A fresh clone installs them on first start; an existing =var/elpa= is used
   as is. GNU ELPA's index is signed, and Emacs verifies it with =gpg=;
   install [[https://gpg4win.org/][Gpg4win]] on Windows so that check can run; the startup file puts it
   first on =exec-path=, because the =gpg= that Git for Windows ships comes
   first otherwise and cannot use a Windows keyring directory. On macOS an
   Emacs started from the Dock has no shell =PATH=, so the startup file puts
   the Nix profiles and Homebrew's directory on =exec-path= when they exist;
   =brew install gnupg= or the [[file:../nix/README.org][Nix module]] is enough. Without a native =gpg=
   the check is skipped rather than silently losing the archive.

* early-init.el
:PROPERTIES:
:header-args:emacs-lisp: :tangle ../early-init.el :eval never :comments no :padline no :mkdirp yes
:END:

Everything Emacs writes goes under =var/=, which Git ignores: packages,
caches, native-compiled files, saved settings. Package activation is left to
=init.el= so it happens in one known place. Three settings make startup
quicker: no garbage collection until the end, no implied frame resizing, and
frames created without the toolbar rather than with one that is then removed.

#+begin_src emacs-lisp
;;; early-init.el --- Before the first frame -*- lexical-binding: t; -*-
;; Generated from literate/10-startup.org; edit the Org source, then tangle.

;;; Code:

(defvar kittymacs-lisp-dir (expand-file-name "lisp/" user-emacs-directory)
  "Directory of the generated configuration modules.")

(defvar kittymacs-var-dir (expand-file-name "var/" user-emacs-directory)
  "Directory for everything Emacs writes on its own.  Ignored by Git.")

(defvar kittymacs-cache-dir (expand-file-name "cache/" kittymacs-var-dir)
  "Directory for caches that can be deleted at any time.")

(defvar kittymacs-etc-dir (expand-file-name "etc/" kittymacs-var-dir)
  "Directory for state worth keeping: saved customizations, shell history.")

(setq package-user-dir (expand-file-name "elpa/" kittymacs-var-dir)
      package-gnupghome-dir (expand-file-name "gnupg/" package-user-dir)
      package-enable-at-startup nil)
(setopt package-archives '(("gnu" . "https://elpa.gnu.org/packages/")
                           ("nongnu" . "https://elpa.nongnu.org/nongnu/")
                           ("melpa" . "https://melpa.org/packages/")))
;; An Emacs.app started from the Dock inherits no shell PATH, so the gpg,
;; git and language servers that Nix or Homebrew installed are invisible
;; until the shells chapter imports the login environment.  Put those
;; directories on `exec-path' now (later entries win) so the archive check
;; below can find gpg.  The title bar is made transparent here, before the
;; first frame; the platform chapter gives it the theme's appearance.
(when (eq system-type 'darwin)
  (dolist (directory (list "/usr/local/bin"
                           "/opt/homebrew/bin"
                           "/nix/var/nix/profiles/default/bin"
                           (expand-file-name "~/.nix-profile/bin")
                           (concat "/etc/profiles/per-user/" (user-login-name) "/bin")
                           "/run/current-system/sw/bin"))
    (when (and (file-directory-p directory) (not (member directory exec-path)))
      (push directory exec-path)))
  (push '(ns-transparent-titlebar . t) default-frame-alist))

;; GNU ELPA signs its archive index and Emacs verifies it with the first
;; gpg on `exec-path'.  On Windows that is Git for Windows' MSYS gpg, which
;; cannot open a Windows keyring directory: every signature then fails and
;; the archives silently vanish.  Put Gpg4win's native gpg first when it is
;; installed; without one, skip the check rather than lose the archives.
(let ((gpg4win (or (and (file-directory-p "C:/Program Files/GnuPG/bin") "C:/Program Files/GnuPG/bin")
                   (and (file-directory-p "C:/Program Files (x86)/GnuPG/bin") "C:/Program Files (x86)/GnuPG/bin"))))
  (cond (gpg4win (push gpg4win exec-path))
        ((or (eq system-type 'windows-nt) (not (executable-find "gpg")))
         (setq package-check-signature nil))))

(when (featurep 'native-compile)
  (startup-redirect-eln-cache (expand-file-name "eln-cache/" kittymacs-cache-dir))
  (setopt native-comp-async-report-warnings-errors 'silent))

(setq gc-cons-threshold most-positive-fixnum)
(add-hook 'emacs-startup-hook (lambda () (setq gc-cons-threshold (* 64 1024 1024))))

(setopt frame-inhibit-implied-resize t
        inhibit-startup-screen t
        initial-scratch-message nil
        load-prefer-newer t)
(push '(tool-bar-lines . 0) default-frame-alist)
(push '(menu-bar-lines . 0) default-frame-alist)
(push '(vertical-scroll-bars) default-frame-alist)

(when (eq system-type 'windows-nt)
  (setq w32-get-true-file-attributes nil
        inhibit-compacting-font-caches t))

;;; early-init.el ends here
#+end_src

* init.el
:PROPERTIES:
:header-args:emacs-lisp: :tangle ../init.el :eval never :comments no :padline no :mkdirp yes
:END:

The composition root. Each =require= is one chapter of this guide. The
order matters only where a module uses another: defaults define the
directories, the platform chapter defines the paths that =private.el= may
override, the UI must exist before the dashboard measures text, Meow must be
up before the keys chapter binds the leader, the terminal comes after the
programming chapter whose mode menu it extends, and frames policy goes last.
Two files of your own are read along the way: =private.el= early, right after
the platform chapter, and the Customize file at the very end; the last
section of this chapter explains why they sit where they do.

#+begin_src emacs-lisp
;;; init.el --- kittymacs -*- lexical-binding: t; -*-
;; Generated from literate/10-startup.org; edit the Org source, then tangle.

;;; Code:

(add-to-list 'load-path kittymacs-lisp-dir)
(package-initialize)
(unless package-archive-contents
  (package-refresh-contents))
(require 'use-package)
(setopt use-package-enable-imenu-support t)

;; Foundation: defaults, platform paths, machine overrides, the look.
(require 'kittymacs-defaults)
(require 'kittymacs-platform)
(let ((private (expand-file-name "private.el" kittymacs-lisp-dir)))
  (when (file-exists-p private)
    (load private nil t)))
(kittymacs-platform-apply)
(require 'kittymacs-ui)
(require 'kittymacs-literate)
(require 'kittymacs-dashboard)

;; Editing: completion, help, files, git, navigation, then Meow and the leader.
(require 'kittymacs-completion)
(require 'kittymacs-help)
(require 'kittymacs-dired)
(require 'kittymacs-treemacs)
(require 'kittymacs-vc)
(require 'kittymacs-navigation)
(require 'kittymacs-meow)
(require 'kittymacs-keys)

;; Applications: shells, programming, Org, and finally frame policy.
(require 'kittymacs-shell)
(require 'kittymacs-programming)
(require 'kittymacs-treesit)
(require 'kittymacs-languages)
(require 'kittymacs-terminal)
(require 'kittymacs-org)
(require 'kittymacs-org-roam)
(require 'kittymacs-frames)

;; Settings saved by M-x customize come last, so they override the chapters.
(load custom-file 'noerror 'nomessage)

;;; init.el ends here
#+end_src

* Machine-specific settings

=private.el= next to the generated modules is loaded once, after the
platform variables exist and before anything reads them. It is ignored by
Git. Copy =private.example.el= to start one, or press =SPC C p=.

Loading it early is deliberate, and it has one consequence worth
understanding. Many chapters read a =kittymacs-= option /while they load/:
the languages chapter looks at =kittymacs-language-packages= to decide which
packages to install, and the appearance chapter loads =kittymacs-theme=. Those
options must already have your value when the chapter runs, so =private.el=
comes first. But the chapters that load afterwards also set options of the
packages they configure, with =setopt= or =use-package ... :custom=, and a
later setting simply replaces an earlier one. If =private.el= said
=(setopt ghostel-enable-osc52 t)= at top level, the terminal chapter would
set it back to =nil= a moment later and you would never know why.

So =private.el= has two kinds of settings, written two ways:

- *kittymacs options* go at top level with =setopt=. They are read while
  the chapters load, which is exactly why the file is early.
- *Options of packages that a chapter also sets* go in a function on
  =after-init-hook=, which Emacs runs once =init.el= has finished:

  #+begin_src emacs-lisp :tangle no
  (add-hook 'after-init-hook
            (lambda ()
              (setopt ghostel-enable-osc52 t)
              (with-eval-after-load 'ghostel
                (setopt ghostel-shell '("/bin/zsh" "--login"))))
            90)
  #+end_src

  The =90= is the hook's /depth/: functions run in order of depth, and the
  chapters add theirs at the default of 0, so yours runs after them. The
  =with-eval-after-load= inside is for the options a chapter sets only when
  its package loads, in =:config= or its own =with-eval-after-load=. Emacs
  runs the forms waiting for a package in the order they were registered;
  registering yours inside the hook puts it after every chapter's, so it runs
  last there too.

Settings saved with =M-x customize= need none of this. The Customize file,
=var/etc/custom.el=, is loaded on the last line of =init.el=, after every
chapter, so what you set there wins over the chapters. Customize is the right
place for package options; a =kittymacs-= option that a chapter reads while it
loads belongs in =private.el=, because by the time the Customize file loads,
that chapter has already made its decision.
