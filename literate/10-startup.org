#+TITLE: Startup: early-init.el and init.el
#+FILETAGS: :core:
#+STARTUP: overview
#+PROPERTY: header-args:emacs-lisp :eval never :comments no :padline no :mkdirp yes

- The only two files Emacs reads on its own, about a hundred lines together:
  + =early-init.el= decides where files live and how packages are fetched;
  + =init.el= loads the chapters in order.
- Leans on nothing; every other chapter is loaded from here, starting with [[id:3fd783cd-deb8-48aa-bb44-0d9b16535365][the defaults]] and [[id:afa6b7fd-742a-4c15-86a6-32e3e8027b0e][the platform chapter]].
- Read this chapter first, after [[id:52a45bf9-9521-4e0d-9867-1c54721844a3][the reading guide]]; [[*Machine-specific settings]] says where your own settings go.

* What happens when Emacs starts :concept:
:PROPERTIES:
:ID: 648ce638-001c-4814-bcc5-e375641109a6
:END:

1. Emacs reads =early-init.el= /before/ it creates a frame or activates packages: the moment to
   + say where packages live;
   + switch off toolbars, so they never flash;
   + collect garbage less often until the start ends.
2. Emacs reads =init.el=, which activates the installed packages, loads =use-package= and requires each generated module in dependency order:
   + defaults and platform first, then the look, then editing and the integrations, then the applications;
   + frames policy last, so nothing later can undo it.
3. Host files and =private.el= choose the features, and the installer fetches what those need ([[id:5c1e7a94-8f30-4d26-b7a1-3e92d06f4c18][the features chapter]]), all before the chapters that use them load.
4. =after-init-hook= runs once =init.el= has finished ([[*Machine-specific settings]]).

* Packages are declared where they are used :decision:
:PROPERTIES:
:ID: 49e57ad2-871b-438e-9420-429781799704
:END:

- Each chapter declares its packages with =use-package … :ensure t=.
  + A fresh clone installs what its features need on first start, through [[id:a9d3e1c7-52f8-4b06-8e14-6c07f2b1d945][the installer]]; an existing =var/elpa= is used as is.
  + With [[id:d25a5063-1439-4ae0-8fbe-b0162d05a0e0][the Nix module]], Nix has already installed nearly all of them, pinned by the flake's lock; =:ensure t= finds them installed and fetches nothing, and only what nixpkgs lacks comes from the archives.
- Global modes are switched on one way throughout:
  + a built-in mode :: =(mode 1)= right after its settings;
  + a package's mode :: in the =:config= of its =use-package=, which runs once the package has loaded;
  + a mode that must be on from the start :: also =:demand t=, because =:bind= and =:hook= would otherwise postpone loading until a key or hook is used;
  + Tabspaces and envrc :: the two exceptions, turned on from =after-init-hook= with =kittymacs-after-init=: Tabspaces reads some options only as it turns on, so it waits for your settings ([[id:e4d65984-892d-4046-b718-d4265ab74215][the navigation chapter]] explains); envrc must be enabled after every other mode ([[id:a121fda8-198e-498c-8867-eb1ecba8236d][the shells chapter]] explains).

* A stale archive index :decision:
:PROPERTIES:
:ID: 8d3b6e0f-5a41-4c2e-9f7a-2b6c1e4d9a53
:END:

- Emacs keeps a copy of each archive's index under =var/elpa/archives/=, and installs from it without asking the archive again.
- MELPA keeps only the /latest/ build of each package: once a package is rebuilt, the tarball an older index names is gone.
  + So an index a couple of weeks old names tarballs that answer =404=, and =:ensure t= fails for any package not yet installed (*seen* 2026-10-27: a new =envrc= declaration against an index from 2026-10-15 stopped the daemon).
  + =use-package-ensure-elpa= refreshes only when a package is /missing/ from the index, never when the version it names is stale.
- =kittymacs-ensure-package= is =use-package-ensure-function=: before the /first/ install of a session it refreshes the index, then hands the install to =use-package-ensure-elpa=.
  + Nothing is refreshed while every declared package is installed, so a normal start, and every start under the Nix module, stays off the network.
  + One refresh per session at most: a fresh clone fetches the index once, not once per package.
  + Refreshing first, rather than retrying after a failure, means no install is ever tried against a stale index, so no "Failed to install" warning appears for a failure that a retry then mends.
  + Offline, the refresh fails with a warning and the install goes ahead from the cached index; a package it lists may still be there.
- =init.el= no longer refreshes an empty index up front for the same reason: under Nix nothing needs it.

* GNU ELPA's signature check needs a native gpg :windows:macos:
:PROPERTIES:
:ID: acfae6fb-7d39-4d14-befc-8151be4bb5a6
:END:

- GNU ELPA signs its archive index; Emacs verifies it with the first =gpg= on =exec-path=.
- Windows: install [[https://gpg4win.org/][Gpg4win]].
  + =early-init.el= puts its =gpg= first on =exec-path=.
  + Otherwise Git for Windows' own =gpg=, a POSIX build, comes first; it cannot open a Windows keyring directory, so every signature fails and the archives silently vanish.
- macOS: an Emacs started from the Dock has no shell =PATH=.
  + =early-init.el= puts Homebrew's directories and the Nix profiles on =exec-path= when they exist (later entries win).
  + It remembers them in =kittymacs-launcher-path=, so [[id:d2e0bc37-0bd4-4b28-a8ee-04f94ac451f8][the shells chapter]] can put back any its import of the login shell's =PATH= drops.
  + =brew install gnupg= or [[id:d25a5063-1439-4ae0-8fbe-b0162d05a0e0][the Nix module]] is enough.
  + [[id:d2e0bc37-0bd4-4b28-a8ee-04f94ac451f8][The shells chapter]] later imports the full login environment, for =git= and the language servers too.
- Without a native =gpg= (always on Windows without Gpg4win) the check is skipped rather than silently losing the archives.
- No mirror of the archives, even where the official hosts are hard to reach (*decided* 2026-10-15):
  + A mirror copies a tarball once and keeps it under the same name, while GNU ELPA re-signs its tarballs when its key changes; a mirrored =spinner-1.7.4.tar= still carried a signature by the key that expired in 2024, so Emacs refused it, and the package that needed =spinner= failed to install on every machine.
  + Behind a proxy that inspects TLS, give Emacs the proxy and the certificate bundle instead (=https_proxy=, which =url.el= reads, and the trust store nixpkgs' GnuTLS reads from =NIX_SSL_CERT_FILE=); the machine's configuration sets both.

* early-init.el: before the first frame
:PROPERTIES:
:header-args:emacs-lisp: :tangle ../early-init.el :eval never :comments no :padline no :mkdirp yes
:END:

- Everything Emacs writes goes under =var/=, which Git ignores: packages, caches, native-compiled files, saved settings.
  + =kittymacs-cache-dir= (=var/cache/=) holds what can be deleted at any time; =kittymacs-etc-dir= (=var/etc/=) holds state worth keeping.
  + Native compilation writes its =eln-cache/= into the cache and reports warnings silently.
- This file sets options with =setq=; every later chapter uses =setopt=, apart from the one option [[id:6a1d4e90-2f7b-4c63-8e15-b93c07d2a4f8][Org loads on first use]] names.
  + =setopt= checks a value against the option's type; to know the type it loads Customize and the library that defines the option.
  + For the package options that is =package.el= with its URL and EIEIO libraries: some thirty milliseconds before the first frame appears.
  + =init.el= loads them a moment later anyway, once the frame is on screen.
- Package activation is left to =init.el=, so it happens in one known place (=package-enable-at-startup= is nil).
- The archives are GNU ELPA, NonGNU ELPA, MELPA and MELPA Stable; signatures: [[*GNU ELPA's signature check needs a native gpg]].
  + Only packages pinned to it install from MELPA Stable: today ghostel and its Consult extension ([[id:bd2638bc-735d-4849-bafe-3dab5e8e30b7][the terminal chapter]] says why).
- Three settings make startup quicker:
  + a garbage collection threshold of 128 MB until the end, then 64 MB;
  + no implied frame resizing;
  + frames created without the toolbar and the menu bar, rather than with ones that are then removed.
- The startup threshold is finite, because a start can hang.
  + With the collector held off completely, a start stalled on a login that never answered allocated about 200 MB a second until the kernel killed Emacs at 6.4 GB.
  + At 128 MB a normal start collects as often as it did with no limit, and takes no measurably longer.
- =menu-bar-mode= is turned off too, to agree with the frame parameter; otherwise the first =SPC t m= would switch a hidden menu bar "off" and show nothing.
  + =SPC t m= brings the menu bar back.
- No startup screen, no message in =*scratch*= unless [[id:0286f652-e861-4e61-9ca6-91e225c8939d][the appearance chapter]] sets one, no scroll bars, and =load-prefer-newer=.
- Frames are sized by the pixel, not by whole lines and columns.
  + A tiling window manager asks for an exact rectangle; rounded down to the character grid, the frame falls a few pixels short of its tile, and a manager that checks the result may keep asking again.
  + Set here, before the first frame exists, so that frame is sized the same way as every later one.
- Under WSLg, frames have no title bar or border of their own (=undecorated=).
  + WSLg's compositor draws a frame around every X11 window, and GTK one around Wayland windows; on Windows the window manager already shows where each window is, so that frame only takes space.
  + Windows is where WSLg windows are moved and resized, by a tiling window manager or by keyboard.
  + WSLg is recognised by =/mnt/wslg=, which every WSL distribution sees: the daemon is started by systemd, whose environment may lack =WSL_DISTRO_NAME=.
- macOS: the title bar is made transparent before the first frame; [[id:afa6b7fd-742a-4c15-86a6-32e3e8027b0e][the platform chapter]] gives it the theme's appearance.
- Windows: =w32-get-true-file-attributes= off and =inhibit-compacting-font-caches= on.

;;; early-init.el --- Before the first frame -*- lexical-binding: t; -*-
;; Generated from literate/10-startup.org; edit the Org source, then tangle.

;;; Code:

(defvar kittymacs-lisp-dir (expand-file-name "lisp/" user-emacs-directory)
  "Directory of the generated configuration modules.")

(defvar kittymacs-var-dir (expand-file-name "var/" user-emacs-directory)
  "Directory for everything Emacs writes on its own.  Ignored by Git.")

(defvar kittymacs-cache-dir (expand-file-name "cache/" kittymacs-var-dir)
  "Directory for caches that can be deleted at any time.")

(defvar kittymacs-etc-dir (expand-file-name "etc/" kittymacs-var-dir)
  "Directory for state worth keeping: saved customizations, shell history.")

;; `setq', not `setopt', throughout this file: `setopt' would load Customize
;; and, for the package options, package.el with url and EIEIO, all before
;; the first frame is drawn.  See the startup chapter.
(setq package-user-dir (expand-file-name "elpa/" kittymacs-var-dir)
      package-gnupghome-dir (expand-file-name "gnupg/" package-user-dir)
      package-enable-at-startup nil
      package-archives '(("gnu" . "https://elpa.gnu.org/packages/")
                         ("nongnu" . "https://elpa.nongnu.org/nongnu/")
                         ("melpa" . "https://melpa.org/packages/")
                         ("melpa-stable" . "https://stable.melpa.org/packages/")))
;; An Emacs.app started from the Dock inherits no shell PATH, so the gpg,
;; git and language servers that Nix or Homebrew installed are invisible
;; until the shells chapter imports the login environment.  Put those
;; directories on `exec-path' now (later entries win) so the archive check
;; below can find gpg, and remember them for the shells chapter.  The title
;; bar is made transparent here, before the first frame; the platform
;; chapter gives it the theme's appearance.
(defvar kittymacs-launcher-path nil
  "Directories `early-init.el' put on `exec-path' for an Emacs from the Dock.")
(when (eq system-type 'darwin)
  (dolist (directory (list "/usr/local/bin"
                           "/opt/homebrew/bin"
                           "/nix/var/nix/profiles/default/bin"
                           (expand-file-name "~/.nix-profile/bin")
                           (concat "/etc/profiles/per-user/" (user-login-name) "/bin")
                           "/run/current-system/sw/bin"))
    (when (file-directory-p directory)
      (push directory kittymacs-launcher-path)
      (unless (member directory exec-path)
        (push directory exec-path))))
  (push '(ns-transparent-titlebar . t) default-frame-alist))

;; GNU ELPA signs its archive index and Emacs verifies it with the first
;; gpg on `exec-path'.  On Windows that is Git for Windows' POSIX gpg, which
;; cannot open a Windows keyring directory: every signature then fails and
;; the archives silently vanish.  Put Gpg4win's native gpg first when it is
;; installed; without one, skip the check rather than lose the archives.
(let ((gpg4win (or (and (file-directory-p "C:/Program Files/GnuPG/bin") "C:/Program Files/GnuPG/bin")
                   (and (file-directory-p "C:/Program Files (x86)/GnuPG/bin") "C:/Program Files (x86)/GnuPG/bin"))))
  (cond (gpg4win (push gpg4win exec-path))
        ((or (eq system-type 'windows-nt) (not (executable-find "gpg")))
         (setq package-check-signature nil))))

(when (featurep 'native-compile)
  (startup-redirect-eln-cache (expand-file-name "eln-cache/" kittymacs-cache-dir))
  (setq native-comp-async-report-warnings-errors 'silent))

(setq gc-cons-threshold (* 128 1024 1024))
(add-hook 'emacs-startup-hook (lambda () (setq gc-cons-threshold (* 64 1024 1024))))

;; Size frames by the pixel, so a tiling window manager's tile is filled
;; exactly instead of to the nearest whole character cell.
(setq frame-resize-pixelwise t)

(setq frame-inhibit-implied-resize t
      inhibit-startup-screen t
      initial-scratch-message nil
      load-prefer-newer t)
(push '(tool-bar-lines . 0) default-frame-alist)
(push '(menu-bar-lines . 0) default-frame-alist)
(push '(vertical-scroll-bars) default-frame-alist)
;; WSLg: no compositor frame; Windows already frames and places the window.
(when (file-directory-p "/mnt/wslg")
  (push '(undecorated . t) default-frame-alist))
;; The frame parameter hides the menu bar; the mode has to agree, or the
;; first `SPC t m' would switch a hidden menu bar "off" and show nothing.
(menu-bar-mode -1)

(when (eq system-type 'windows-nt)
  (setq w32-get-true-file-attributes nil
        inhibit-compacting-font-caches t))

#+end_src

** The quickstart file :decision:
:PROPERTIES:
:ID: 7b4e2f19-6d03-4a58-9c21-e8f05d7a3c64
:END:

- A start pays for reading every installed package's description, and the archive index, before it can activate anything.
  + Emacs's own =package-quickstart-refresh= writes one file holding what those activations would do, so a start can load that instead.
  + [[file:../ARCHITECTURE.md][ARCHITECTURE.md]] has what it saves.
- A new machine gets the file without asking, and any other machine scans until it asks.
  + A new machine is one with the stamp =var/started-on-default=, so it started on the default profile, as [[id:2ea4f7b0-6c19-4d85-93f2-c07a1be58d36][the rule in the features chapter]] explains.
  + A machine with no stamp calls =package-initialize= as it always has, and adds nothing to =after-init-hook=, until =just quickstart= or =M-x kittymacs-quickstart-write= writes the file.
  + No option decides this, because packages activate before host files and =private.el= load.
- The file comes once the packages have settled, so the install that fills a new machine pays nothing for it.
  + =just install= writes it as its last step, and a start writes it at its first idle moment after init, which leaves the second start to load it.
  + A session that quits before going idle writes nothing, and the next start tries again.
  + A session where a package failed to install writes nothing either, so a partial install leaves no file, and the next start retries the package.
- =just quickstart-remove= or =M-x kittymacs-quickstart-remove= turns it off for good.
  + The missing file cannot say so, because a new machine has no file either, so removing writes =var/quickstart-off= as well.
  + =just quickstart= or =M-x kittymacs-quickstart-write= turns it on again, and deletes that marker.
  + Deleting =var/= loses the marker along with the stamp, and the machine then counts as new.
- A hash in the file's name covers =emacs-version=, =package-user-dir= and =package-directory-list=, so a file written for anything else is never loaded.
  + Each directory goes through =file-truename=, because a Nix profile keeps its path while its contents move to another store path.
  + The version counts because which packages activate depends on what Emacs has built in.
  + The file lives in =var/cache/=, so deleting that directory only loses the speed.
- =just quickstart= leaves out =-Q=, because a Nix Emacs's =site-start.el= sets =package-directory-list=, and =-Q= would hash a different list from a real start.
- A file is loaded only while its compiled form is newer than every package directory.
  + Installing, upgrading or removing a package changes the directory's time, from this Emacs, another one or a shell, so a stale file is detected and the start scans instead.
  + Only a change made inside a package's own directory goes unseen; =just quickstart= after one.
- From =after-init-hook=, a machine with a quickstart file of any name keeps the right one current.
  + It writes the file if this start could not load one: an install, a removal, or a Nix switch that moved the store paths.
  + It sets =package-quickstart=, so Emacs refreshes the file after each later install, upgrade and removal, =:vc= packages included.
  + During =init.el= that option stays nil: refreshing there would call =package-initialize= a second time, which warns.
- A file that cannot load does not stop startup: =package-activate-all= demotes the error and scans, and =kittymacs-activate-packages= deletes the compiled file so the hook writes a new one.
  + A file naming a package that has gone only adds a directory that does not exist to =load-path=: a declaration that loads the package at startup warns, as it would after a failed install, and the start goes on.
- A start from the file has the same packages active, and knows less about them until something asks:
  + =package-alist= and the archive index stay empty until a package command fills them, and each one does ([[id:5c1e7a94-8f30-4d26-b7a1-3e92d06f4c18][the features chapter]] reads =package-activated-list= as well);
  + =package-installed-p= answers from =package-activated-list= rather than from what is on disk, so =kittymacs-ensure-package= asks =package-initialize= before it believes a package is missing;
  + the file loads the =info= library when a package ships a manual, because it must add that directory to =Info-directory-list=, and the scan's =finder-inf= waits for the first question about a built-in package.

#+begin_src emacs-lisp
(defvar kittymacs-quickstart-loaded nil
  "Non-nil when this start activated its packages from the quickstart file.")

(defun kittymacs-quickstart-file ()
  "Return the quickstart file's name for this Emacs and these package directories."
  (expand-file-name
   (format "package-quickstart-%s.el"
           (sha1 (prin1-to-string
                  (cons emacs-version
                        (mapcar #'file-truename
                                (cons package-user-dir package-directory-list))))))
   kittymacs-cache-dir))

(defun kittymacs-quickstart--written ()
  "Return every quickstart file here, whatever directories it was written for."
  (and (file-directory-p kittymacs-cache-dir)
       (directory-files kittymacs-cache-dir t "\\`package-quickstart-[0-9a-f]+\\.elc?\\'")))

(defun kittymacs-quickstart--current-p (file)
  "Return non-nil when FILE is compiled, and newer than every package directory."
  (let ((compiled (concat file "c")))
    (not (memq nil (mapcar (lambda (directory) (file-newer-than-file-p compiled directory))
                           (cons package-user-dir package-directory-list))))))

(defun kittymacs-activate-packages ()
  "Activate the installed packages, from the quickstart file when it is current.
With no such file, `package-initialize' does what it always did."
  (let ((file (kittymacs-quickstart-file)))
    (if (not (kittymacs-quickstart--current-p file))
        (package-initialize)
      (setq kittymacs-quickstart-loaded t)
      (let ((package-quickstart-file file))
        (package-activate-all))
      ;; Only a scan fills this: the file did not load, so have it written again.
      (when package-alist
        (delete-file (concat file "c"))))))

(defun kittymacs-quickstart--off-file ()
  "Return the file saying that this machine turned the quickstart file off."
  (expand-file-name "quickstart-off" kittymacs-var-dir))

(defun kittymacs-quickstart--delete ()
  "Delete every quickstart file."
  (setq package-quickstart nil)
  (mapc #'delete-file (kittymacs-quickstart--written)))

(defun kittymacs-quickstart-remove ()
  "Delete every quickstart file, and keep this machine scanning until it asks again."
  (interactive)
  (kittymacs-quickstart--delete)
  (make-directory kittymacs-var-dir t)
  (write-region "kittymacs-quickstart-write turns the quickstart file on again.\n"
                nil (kittymacs-quickstart--off-file) nil 'silent))

(defvar warning-minimum-log-level)

(defun kittymacs-quickstart--quietly (refresh)
  "Call REFRESH with no compile warning, from this code or from Emacs's own refresh.
An autoloads file may name a function only its package defines.  Batch prints
whatever gets logged, so hiding it from the display would not be enough."
  (require 'warnings)
  (let ((warning-minimum-log-level :error))
    (funcall refresh)))

(advice-add 'package-quickstart-refresh :around #'kittymacs-quickstart--quietly)

(defun kittymacs-quickstart-write ()
  "Write the quickstart file for this Emacs and these package directories.
This also undoes `kittymacs-quickstart-remove'; see the startup chapter."
  (interactive)
  (require 'package)
  (kittymacs-quickstart--delete)
  (delete-file (kittymacs-quickstart--off-file))
  (make-directory kittymacs-cache-dir t)
  (setq package-quickstart-file (kittymacs-quickstart-file)
        package-quickstart t)
  (package-quickstart-refresh))

(defun kittymacs-quickstart--keep-current ()
  "Keep this machine's quickstart file right from now on; it has written one before."
  (setq package-quickstart-file (kittymacs-quickstart-file)
        package-quickstart t)
  (unless (kittymacs-quickstart--current-p package-quickstart-file)
    (kittymacs-quickstart-write)))

(defun kittymacs-quickstart--wanted-p ()
  "Return non-nil on a new machine that has no quickstart file and has not refused one."
  (and (file-exists-p (kittymacs-features--stamp-file))
       (not (file-exists-p (kittymacs-quickstart--off-file)))
       (not (kittymacs-quickstart--written))))

(defun kittymacs-quickstart--settle ()
  "Write the file on a new machine, unless this session failed to install a package."
  (when (and (kittymacs-quickstart--wanted-p)
             (not kittymacs-features--failed))
    (kittymacs-quickstart-write)))

(defun kittymacs-quickstart--settle-when-idle ()
  "Call `kittymacs-quickstart--settle' once this start has gone idle."
  (run-with-idle-timer 2 nil #'kittymacs-quickstart--settle))

;;; early-init.el ends here
#+end_src

* init.el: the load order
:PROPERTIES:
:header-args:emacs-lisp: :tangle ../init.el :eval never :comments no :padline no :mkdirp yes
:END:

- The composition root: each =require= is one chapter.
- The order matters only where a module uses another:
  + defaults define the directories;
  + the platform chapter defines the paths that =private.el= may override, and =kittymacs-platform-apply= runs right after it;
  + the UI must exist before the dashboard measures text;
  + the first chapter that binds a key requires [[id:e5942eb0-4389-447d-9317-d9178adcaaae][the leader]], which defines the groups, so no chapter has to load before another for its keys;
  + the terminal comes after the programming chapter, whose mode menu it extends;
  + [[id:86fcd506-34c8-476d-8903-acbef46275bf][EXWM]] comes just before the frames policy, which reads =kittymacs-exwm= for its default;
  + frames policy goes last.
- Files from outside this repository are read along the way: [[*Host files][host files]] and then =private.el= right after the platform chapter, the Customize file at the end; [[*Machine-specific settings]] says why there.
- =kittymacs-features-resolve= runs straight after them, so everything later asks a settled question, and =kittymacs-features-install= right after that ([[id:5c1e7a94-8f30-4d26-b7a1-3e92d06f4c18][the features chapter]]).
- =kittymacs-activate-packages= comes first, before anything can need a package ([[*The quickstart file]]).
- The archive index is fetched only when a package has to be installed, by =kittymacs-ensure-package= ([[*A stale archive index]]); a start that installs nothing touches no network.
- A chapter that is one feature and nothing else loads only when that feature is on: Treemacs, the dashboard, Org extras, Org-roam, reading, notebooks, agents and suggestions.
  + Mixed chapters always load, and put a =when= around each optional package and its keys.
  + [[id:5c1e7a94-8f30-4d26-b7a1-3e92d06f4c18][The features chapter]] answers both.
- A group under =SPC= that nothing bound a key in leaves the tree at the end of startup ([[id:e5942eb0-4389-447d-9317-d9178adcaaae][the leader]]).
- From the UI on, each chapter is loaded with =kittymacs-require-module=, not a bare =require=:
  + an error while a chapter loads (most often a package that failed to install, so its variables do not exist) becomes a warning naming the chapter, and the chapters after it still load;
  + a bare =require= would end =init.el= there, leaving every later chapter, frames included, unloaded, for a failure in one;
  + under =--debug-init= the error is not caught (=condition-case-unless-debug=), so the backtrace is still there when you ask for it.
  + Defaults and platform keep a bare =require=: nothing after them works without them, and stopping early is the clearer failure.
- A function a chapter puts on =after-init-hook= runs /after/ that guard has returned, so it is added with =kittymacs-after-init= instead of a bare =add-hook=:
  + a function whose package failed to install is skipped with a warning naming it, instead of a void-function error;
  + an error inside it becomes a warning, like a chapter's;
  + an uncaught error in =after-init-hook= aborts startup, and for the daemon (=--fg-daemon=) that means exiting: one package that did not install would take the whole server down on every restart.
- kittymacs needs Emacs 31.1 or later ([[id:0a7aaddc-ecdf-4349-9218-e4a1d058379f][the Tree-sitter chapter]] relies on what 31 added); an older Emacs stops at the first line with a message that says so.
  + An error in =init.el= ends the file there; Emacs reports it and starts without the configuration, instead of failing in a dozen chapters for reasons that would not name the version.
- =lisp/= joins =load-path= after packages activate, so it comes first and a chapter's =require= stops at the first directory ([[file:../ARCHITECTURE.md][ARCHITECTURE.md]] has what that saves).

(defun kittymacs-ensure-package (name args state &optional no-refresh)
  "Install the package that `use-package' NAME's `:ensure' ARGS names.
The `use-package-ensure-function' of kittymacs.  Before the session's
first install it refreshes the cached archive index, whose tarballs may
be gone; then `use-package-ensure-elpa' installs.  STATE and NO-REFRESH
are passed through.  A package the installer already failed on is left
alone, since it warned once.  A start from the quickstart file knows only
what that file activated, so it reads the package directories before it
believes that a package is missing."
  (unless (memq name (bound-and-true-p kittymacs-features--failed))
    (let ((installed-p
           (lambda ()
             (seq-every-p (lambda (ensure)
                            (let ((package (if (eq ensure t) (use-package-as-symbol name) ensure)))
                              (or (null package)
                                  (package-installed-p (if (consp package) (car package) package)))))
                          args))))
      (unless (or kittymacs--archives-refreshed
                  (funcall installed-p)
                  (and (bound-and-true-p kittymacs-quickstart-loaded)
                       (not (bound-and-true-p package--initialized))
                       (progn (package-initialize t)
                              (funcall installed-p))))
        (setq kittymacs--archives-refreshed t)
        (condition-case-unless-debug err
            (package-refresh-contents)
          (error
           (display-warning 'kittymacs
                            (format "Could not refresh the package archives: %s
Installing from the cached index, which may name tarballs that are gone."
                                    (error-message-string err))
                            :warning)))))
    (use-package-ensure-elpa name args state no-refresh)))

(defun kittymacs-require-module (feature)
  "Load the kittymacs module FEATURE; on an error, warn and carry on.
Under `--debug-init' the error is not caught, so it shows a backtrace."

      (require feature)
    (error
     (display-warning 'kittymacs
                      (format "%s did not finish loading: %s
The chapters after it still load; `--debug-init' shows the backtrace."
                              feature (error-message-string err))
                      :error))))

(defun kittymacs-after-init (function &optional depth)
  "Call FUNCTION from `after-init-hook' at DEPTH; on an error, warn and carry on.
FUNCTION is skipped, with a warning, when nothing has defined it by then:
its package failed to install.  Under `--debug-init' an error is not
caught, so it shows a backtrace."
  (add-hook 'after-init-hook
            (lambda ()
              (if (not (fboundp function))
                  (display-warning 'kittymacs
                                   (format "%s is not defined, so it was not called after init; did its package install?"
                                           function)
                                   :error)
                (condition-case-unless-debug err
                    (funcall function)
                  (error
                   (display-warning 'kittymacs
                                    (format "%s failed after init: %s"
                                            function (error-message-string err))
                                    :error)))))
            depth))

* Machine-specific settings :decision:
:PROPERTIES:
:ID: 6c9aefe0-32af-453b-a075-6ed429993d3a
:END:

- =lisp/private.el=, next to the generated modules, is loaded once: after the platform variables exist, before anything reads them.
  + Git ignores it; copy =lisp/private.example.el= to start one, or press =SPC C p=.
  + [[id:c8e2f1a7-4b60-49d3-8a15-7d3e96b0c421][The onboarding screens]] write a marked block in it, and leave the rest alone.
- Loading it early is deliberate, with one consequence:
  + many chapters read a =kittymacs-= option /while they load/, so it must already have your value: the languages chapter reads =kittymacs-language-packages= to decide which packages to install, the appearance chapter loads =kittymacs-theme=;
  + but chapters loading afterwards also set options of the packages they configure (=setopt=, =use-package … :custom=), and a later setting replaces an earlier one;
  + a top-level =(setopt ghostel-enable-osc52 t)= in =private.el= would be set back to =nil= by the terminal chapter a moment later, and you would never know why.
- So =private.el= holds two kinds of settings, written two ways:
  + kittymacs options, read while the chapters load :: at top level, with =setopt=;
  + options of packages that a chapter also sets :: in a function on =after-init-hook=, which Emacs runs once =init.el= has finished.

#+begin_src emacs-lisp :tangle no
(add-hook 'after-init-hook
          (lambda ()
            (setopt ghostel-enable-osc52 t)
            (with-eval-after-load 'ghostel
              (setopt ghostel-shell '("/bin/zsh" "--login"))))
          90)
#+end_src

- The =90= is the hook's /depth/: functions run in order of depth, and the chapters add theirs at the default of 0, so yours runs after them.
  + Tabspaces is the exception: it turns on at 95, after yours, so it reads your settings.
- The =with-eval-after-load= inside is for options a chapter sets only when its package loads, in =:config= or its own =with-eval-after-load=.
  + Emacs runs the forms waiting for a package in the order they were registered; registering yours inside the hook puts it after every chapter's, so it runs last there too.
- Settings saved with =M-x customize= need none of this:
  + the Customize file, =var/etc/custom.el=, is loaded on the last line of =init.el=, after every chapter, so its settings win over the chapters;
  + Customize is the right place for package options;
  + a =kittymacs-= option that a chapter reads while it loads still belongs in =private.el=: by the time the Customize file loads, that chapter has already decided.
- An error in =private.el= becomes a warning, and the rest of kittymacs still starts, so a mistake there does not leave you without an editor to fix it in.

** Host files :decision:
:PROPERTIES:
:ID: 2c7e91d4-5b08-4f3a-8e16-a4d09c37b5e2
:END:

- A machine's own configuration, such as a Nix module or a dotfiles repository, needs somewhere to put Elisp without editing this repository or a person's =private.el=.
- Every =*.el= file in these directories loads in name order, just before =private.el=:
  + =/etc/kittymacs/conf.d/=, for a whole system;
  + =~/.config/kittymacs/conf.d/=, or under =XDG_CONFIG_HOME= when that is set, for one user.
- The order decides who wins: the system, then the user's host files, then =private.el=, then Customize.
- A host file follows the same two rules as =private.el= above, and a broken one warns without stopping the rest.
- Names that start with =.= or =#= are skipped, because editors use them for lock and auto-save files.
- =kittymacs-host-directories= names the directories; set it before =init.el= loads, as a test does.
