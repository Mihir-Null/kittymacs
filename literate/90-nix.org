#+TITLE: Nix: the flake, its modules and example hosts
#+FILETAGS: :nix:
#+STARTUP: overview
#+PROPERTY: header-args:nix :eval never :comments no :padline no :mkdirp yes

- The repository is a flake, but it does not put the configuration in the Nix store.
  + The configuration keeps its state under =var/= and =private.el= beside its modules; both must stay writable.
- What the flake provides is everything the configuration /uses/: Emacs with [[*The Emacs packages][the packages the chapters declare]], every program the chapters look for, and its fonts.
  + A fresh Mac needs one =darwin-rebuild switch= and one =git clone=; with the Home Manager module, not even the clone.
- The Nix layer is a convenience: Homebrew, a package manager or a manual install work as well, and every chapter degrades quietly when a program is missing.
- Each top heading writes one file; =just lint= and =just eval= check them ([[id:9ea539a0-f1a3-4d05-aa10-6f2d2ff3e335][the loop]]).

- Each module is also exported as =kittymacs=, beside =default=, for a host that imports several flakes' modules by name.
- The configuration itself is in none of these, as =ARCHITECTURE.md= records: =packages.minimal= and =packages.full= still need a checkout to start from.

* The flake
:PROPERTIES:
:header-args:nix: :tangle ../flake.nix :eval never :comments no :padline no :mkdirp yes
:END:

- One input, nixpkgs-unstable, so a host's =follows= decides the Emacs version.
- Three systems: Apple Silicon, ARM Linux (phones, through nix-on-droid) and x86_64 Linux.
  + nixpkgs-unstable dropped =x86_64-darwin= in 26.11; an Intel Mac points this flake's =nixpkgs= input at the =nixpkgs-26.05-darwin= branch.
- =forEachSystem= hands every per-system output the package set and [[*The tools][the tool list]], so that list is read in one place.
- [[*The packages][nix/profiles.nix]] holds the packages, so the overlay builds the same set from the host's nixpkgs.
- The formatter is =nixfmt-tree=, the walking form of the =nixfmt= that =just lint= runs, because =nix fmt= hands a bare =nixfmt= no files.
- The Home Manager module is a function of the flake itself, so its clone can default to the revision the host locked ([[*Cloning the checkout on first activation]]).
- The dev shell adds =just=, =nixfmt=, =deadnix= and =statix= to Emacs and the tools: everything =just all= needs.

#+begin_src nix
# Generated from literate/90-nix.org; edit the Org source, then tangle.
{
  description = "kittymacs: a Meow-first Emacs configuration, with the tools it looks for";

  inputs.nixpkgs.url = "github:NixOS/nixpkgs/nixpkgs-unstable";

  outputs =
    { self, nixpkgs }:
    let
      # nixpkgs-unstable dropped x86_64-darwin in 26.11; an Intel Mac can
      # point this flake's nixpkgs input at the nixpkgs-26.05-darwin branch.
      systems = [
        "aarch64-darwin"
        "aarch64-linux"
        "x86_64-linux"
      ];
      # Each per-system output gets the package set and the tool list.
      forEachSystem =
        f:
        nixpkgs.lib.genAttrs systems (
          system:
          let
            pkgs = nixpkgs.legacyPackages.${system};
          in
          f pkgs (import ./nix/tools.nix { inherit pkgs; })
        );
    in
    {
      darwinModules.default = import ./nix/system-module.nix {
        moduleName = "nix-darwin";
        packageNote = "`pkgs.emacs` is the Cocoa build; `pkgs.emacs-macport` is the Mitsuharu port.";
      };
      darwinModules.kittymacs = self.darwinModules.default;

      nixosModules.default = import ./nix/system-module.nix {
        moduleName = "NixOS";
        packageNote = "`pkgs.emacs-pgtk` speaks Wayland; `pkgs.emacs-nox` has no GUI.";
      };
      nixosModules.kittymacs = self.nixosModules.default;

      # The module is given the flake itself, so the clone can default to
      # this flake's revision.
      homeManagerModules.default = import ./nix/home-module.nix { inherit self; };
      homeManagerModules.kittymacs = self.homeManagerModules.default;

      overlays.default = final: _: { kittymacs = import ./nix/profiles.nix { pkgs = final; }; };

      packages = forEachSystem (pkgs: _: import ./nix/profiles.nix { inherit pkgs; });

      apps = forEachSystem (pkgs: tools: import ./nix/apps.nix { inherit pkgs tools; });

      checks = forEachSystem (
        pkgs: tools:
        import ./nix/checks.nix {
          inherit nixpkgs pkgs tools;
          nixosModule = self.nixosModules.default;
          overlay = self.overlays.default;
        }
      );

      formatter = forEachSystem (pkgs: _: pkgs.nixfmt-tree);

      templates = {
        home-manager = {
          path = ./nix/template-home-manager;
          description = "A Home Manager home with kittymacs, on any Linux";
          welcomeText = "Edit flake.nix: its first lines name what to change.";
        };
        nix-darwin = {
          path = ./nix/template-nix-darwin;
          description = "A nix-darwin Mac with kittymacs";
          welcomeText = "Edit flake.nix: its first lines name what to change.";
        };
        nixos = {
          path = ./nix/template-nixos;
          description = "A NixOS machine with kittymacs";
          welcomeText = "Edit flake.nix: its first lines name what to change.";
        };
        wsl-backend = {
          path = ./nix/template-wsl-backend;
          description = "The Linux side of a Windows setup: the tools, with no Emacs or fonts";
          welcomeText = "Edit flake.nix: its first lines name what to change.";
        };
      };

      # Emacs and the tools, plus just and the Nix linters for the recipes.
      devShells = forEachSystem (
        pkgs: tools: {
          default = pkgs.mkShell {
            packages = [
              tools.emacs
            ]
            ++ tools.programs
            ++ [
              pkgs.just
              pkgs.nixfmt
              pkgs.deadnix
              pkgs.statix
            ];
            shellHook = ''
              echo "kittymacs: just --list"
            '';
          };
        }
      );
    };
}

- Each entry also names the catalogue's feature that needs it, or null for every machine, and the command that shows it is there.
  + =programs= stays the whole list in its old order, for what has no selection to read: =packages.tools=, the =default= app and the dev shell.
  + =programsFor= and =fontsFor= filter by a list of features and keep that order, so a host keeps the store paths of the tools it keeps.
  + The modules, =packages.minimal= and =packages.full= install through them, so [[*The tools of a host][a host's tools follow its selection]], and =minimal= means more than fewer Emacs packages.
  + =commands= is what [[*The apps][the doctor]] checks. Its =name= is how a package shows in a host's list, for the checks.
- =backendPrograms= is what a machine needs when Emacs runs elsewhere and reaches it over a remote connection.
  + On Linux that includes =kittymacs-open=, which [[id:9e4c2a61-7b05-4d13-8f6e-1a0d3c95b7e2][opens a folder from a WSL shell]].
  + =git=, =rg=, =fd= and =direnv= from the list, because Magit, the project commands and envrc run them on the remote side.
  + =inotify-tools=, on Linux, because Tramp's file notification watches through =inotifywait=.
  + Language servers for the languages most projects have: =nil=, =pyright= and =bash-language-server=. A project's own come from its =.envrc=, which is why direnv is here.
  + No Emacs, no fonts, nothing with a GUI: [[*The flake's checks][a check]] holds that by name, since evaluation cannot read a store path.
- Fonts: the three [[id:0286f652-e861-4e61-9ca6-91e225c8939d][the appearance chapter]] looks for.
  + Google Sans Code, the editing font, as its Nerd Font build, the family the configuration asks for first, where this nixpkgs has one.
    nixos-26.05 does not, and a host that makes this flake follow its nixpkgs gets the plain =googlesans-code= instead, which the configuration also accepts: its icons come from the icon font either way.
  + Google Sans Flex, the prose font, is not in nixpkgs yet: nixpkgs' =google-fonts= is built from a revision of Google's font repository older than it.
    So a fixed derivation fetches its one file from a pinned commit of that repository; once =google-fonts= carries it, =google-fonts.override { fonts = [ "GoogleSansFlex" ]; }= replaces the derivation.
  + Symbols Nerd Font Mono for the icons.
- =emacs= is an argument, so each module installs the Emacs its =package= option names.
- =epdfinfo= is the one program nixpkgs does not ship on its own: its pdf-tools build puts the server beside the Lisp, so a small derivation links it into =bin/=.
  + Only the server is taken; the Lisp still comes from MELPA, as every package does ([[id:15f489d8-1307-491d-9a1a-ecabbd2984e6][why]]).
- =mutool= comes from =mupdf-headless=, MuPDF built without its X11 and OpenGL viewer: pdf-text wants only the command-line tool.
- =kittymacs-zmq-module= is a one-line script that prints the path of emacs-zmq's native module, which nixpkgs builds for its own zmq package; the notebooks chapter links the module beside =zmq.el= ([[id:040a7e96-594a-4485-8c51-9cf7926b2275][why]]).
  + Built with =emacsPackagesFor emacs=, so the module is compiled for the Emacs this file was given, not nixpkgs' default one.
  + =jupytext= is the Python package's command alone: =python3Packages.jupytext= is a library, so it is wrapped with =toPythonApplication=, which keeps its Python out of the profile beside =python3=.
- =copilot-language-server=, for [[id:0b43a1e9-2e16-4d5b-985d-342c4897634f][the suggestions chapter]], is not in this list: nixpkgs marks it unfree, and an unfree package here would make every user of the flake allow one.
  + Each module installs it behind its own =suggestions.enable= option instead, off by default ([[id:9e0c1f52-7a43-4d0e-b1a8-63c2f5d48e17][the opt-in]]).

# Generated from literate/90-nix.org; edit the Org source, then tangle.
{
  pkgs,
  emacs ? pkgs.emacs,
}:

let
  inherit (pkgs) lib;
  tool = feature: command: package: { inherit feature command package; };
  font = feature: package: { inherit feature package; };
  isOn = features: entry: entry.feature == null || lib.elem entry.feature features;
  packagesOf = map (entry: entry.package);

  programTable =
    with pkgs;
    [
      (tool "version-control" "git" git) # version control chapter (Magit)
      (tool "structural-diffs" "difft" difftastic) # version control chapter: structural diffs
      (tool "completion" "rg" ripgrep) # navigation chapter (consult-ripgrep)
      (tool "completion" "fd" fd) # navigation chapter (consult-fd)
      (tool null "gpg" gnupg) # startup chapter: GNU ELPA's signed index
      (tool "spelling" "hunspell" (hunspell.withDicts (d: [ d.en_US ]))) # platform chapter: spelling
      (tool "file-tree" "python3" python3) # Treemacs chapter: directory collapsing and the extended (colouring) git mode
      (tool "terminal" "zig" zig) # terminal chapter: builds ghostel's native module
      # reading chapter: pdf-tools' server, linked out of nixpkgs' pdf-tools build
      (tool "pdf-reading" "epdfinfo" (
        runCommand "epdfinfo" { } ''
          mkdir -p $out/bin
          ln -s ${emacsPackages.pdf-tools}/share/emacs/site-lisp/elpa/pdf-tools-*/epdfinfo $out/bin/epdfinfo
        ''
      ))
      (tool "pdf-reading" "mutool" mupdf-headless) # reading chapter: pdf-text's extractor
      (tool "project-environment" "direnv" direnv) # shells chapter: envrc, each project's own environment
      (tool "notebooks" "jupytext" (python3Packages.toPythonApplication python3Packages.jupytext)) # notebooks chapter: .ipynb files
      (tool "notebooks" "math-preview" math-preview) # notebooks chapter: LaTeX drawn with MathJax
      # notebooks chapter: prints the path of emacs-zmq's native module, built by nixpkgs
      (tool "jupyter" "kittymacs-zmq-module" (
        runCommand "kittymacs-zmq-module" { } ''
          module=$(echo ${(emacsPackagesFor emacs).zmq}/share/emacs/site-lisp/elpa/zmq-*/emacs-zmq.*)
          mkdir -p $out/bin
          printf '#!%s\necho %s\n' ${runtimeShell} "$module" > $out/bin/kittymacs-zmq-module
          chmod +x $out/bin/kittymacs-zmq-module
        ''
      ))
    ]
    ++ lib.optionals stdenv.hostPlatform.isDarwin [
      (tool null "gls" coreutils-prefixed) # Dired chapter: GNU ls as `gls'
      (tool null "trash" darwin.trash) # platform chapter: Trash with Finder's "Put Back"
    ];

  # The editing font, the prose font and the icon font.
  fontTable = with pkgs; [
    # Older nixpkgs (nixos-26.05) has no Nerd Font build of it.
    (font null (nerd-fonts.googlesanscode or googlesans-code))
    (font null (
      stdenvNoCC.mkDerivation {
        pname = "google-sans-flex";
        version = "0-unstable-2026-10-27";
        # Not yet in nixpkgs' google-fonts; replace with
        # `google-fonts.override { fonts = [ "GoogleSansFlex" ]; }` once it is.
        src = fetchurl {
          name = "GoogleSansFlex.ttf";
          url = "https://raw.githubusercontent.com/google/fonts/ddf386ba1b9fbc6b2c818f1ddcd9148f54ced94b/ofl/googlesansflex/GoogleSansFlex%5BROND%2Copsz%2Cslnt%2Cwdth%2Cwght%5D.ttf";
          hash = "sha256-qax3B5iFfV6KxZPO1Csi5Ap8CM7Jgxn5Kw7Mwng6d7o=";
        };
        dontUnpack = true;
        installPhase = ''
          install -Dm444 $src $out/share/fonts/truetype/GoogleSansFlex.ttf
        '';
        meta.license = lib.licenses.ofl;
      }
    ))
    (font "icons" nerd-fonts.symbols-only)
  ];
in
{
  inherit emacs;

  programs = packagesOf programTable;
  fonts = packagesOf fontTable;
  programsFor = features: packagesOf (lib.filter (isOn features) programTable);
  fontsFor = features: packagesOf (lib.filter (isOn features) fontTable);

  # What the doctor looks for, and the feature that asks for each.
  commands = map (entry: {
    inherit (entry) feature command;
    name = lib.getName entry.package;
  }) programTable;

  # The server behind the wsl-rpc transport, which no list here installs by itself.
  rpcServer = pkgs.callPackage ./tramp-rpc-server.nix { };

  # A machine that Emacs reaches from elsewhere: no Emacs, no fonts, no GUI.
  backendPrograms =

      lib.filter (
        entry:
        lib.elem entry.command [
          "git"
          "rg"
          "fd"
          "direnv"
        ]

    )
    ++ lib.optionals pkgs.stdenv.hostPlatform.isLinux [

        runtimeInputs = [ pkgs.coreutils ];

      pkgs.nil
      pkgs.pyright
      pkgs.bash-language-server

* The Emacs packages :decision:
:PROPERTIES:
:ID: 3c7f2a90-8e15-4b6d-a2c4-5d9e0f1b7a68
:header-args:nix: :tangle ../nix/packages.nix :eval never :comments no :padline no :mkdirp yes
:END:

- Every package a chapter declares with =:ensure t=, read feature by feature from =nix/features.json=, [[id:3f8a6c02-9d14-4b7e-a2c5-1e7d90b64f31][the catalogue]]'s generated copy, and built by Nix into the Emacs the modules install when =packagesFromNix= is on; it is off by default.
- Why Nix installs them, when the configuration could install them itself:
  + the flake's lock pins them, so a machine starts with the versions the lock names rather than whatever MELPA built last night;
  + they are in the store before Emacs starts, so startup needs no network and cannot fail on an archive that is down or out of date;
  + an index of MELPA a few weeks old names tarballs MELPA has since deleted ([[id:8d3b6e0f-5a41-4c2e-9f7a-2b6c1e4d9a53][the startup chapter]] tells the story); a package Nix installed is never fetched from one.
- Nothing in the configuration changes: =use-package … :ensure t= asks =package-installed-p=, which sees the packages nixpkgs' wrapper puts on =package-directory-list=, and installs nothing.
  + A package nixpkgs lacks still comes from the archives into =var/elpa=, as on a machine without Nix.
  + So the clone stays the configuration and stays writable; Nix only supplies what it loads.
- Why it is off by default: no binary cache carries these packages.
  + Hydra does not build nixpkgs' Emacs package sets, so the first switch after each =nix flake update= fetches every package's source and compiles all of them on the machine.
  + Any one source host being down then stops the whole switch, where the archives would have failed one package at startup.
  + Turn it on for a machine that should start without network, and accept the build.
- The Emacs is built from =emacs.pkgs=, the package set of the Emacs's own nixpkgs, not the host's =emacsPackagesFor=, so a host whose Emacs comes from a second nixpkgs (unstable on a stable system, say) still gets packages built against it.
- No source may be a clone of a whole ELPA repository from Savannah.
  + MELPA builds a package that moved to GNU or NonGNU ELPA from that ELPA's Git repository, which holds every package's history; nixpkgs fetches it whole, slowly, from a host that is often unreachable.
  + Such a package is taken from =elpaPackages= or =nongnuPackages= instead, ELPA's own release tarball: today only =ws-butler=, which the =let= below lays over =epkgs=.
  + =just eval= fails if any derivation behind the package build, a dependency's included, fetches from =savannah.gnu.org/git/elpa=, on unstable and on stable nixpkgs.
- Two are left to the archives on purpose, in =archiveOnly=, and =tests/kittymacs-startup-tests.el= keeps what this file builds and the chapters' declarations in step, with these two as the only exceptions:
  + =copilot= :: nixpkgs marks it unfree with its server, and an unfree package here would make every user of the flake allow it ([[id:9e0c1f52-7a43-4d0e-b1a8-63c2f5d48e17][the server's opt-in]] has the same reasoning);
  + =consult-ghostel= :: not in nixpkgs.
- Upgrading: =nix flake update= (=just update-flake=) moves these with nixpkgs; =package-upgrade-all= leaves them alone, since they are not in =var/elpa=.
- This file reads the list by feature, so a host that chose its features builds only those ([[id:b7e4d1a6-20c9-4f3e-8a57-c61f09d3e248][Choosing features]]).
  + =features= is a list of the catalogue's names; null, the default, builds every feature, as the flake's =with-packages= does.
  + A host that chose nothing passes null too, so it builds what it always did.
  + A feature that =private.el= adds beyond this list still installs from the archives.
- A package added to a chapter goes under its feature in the catalogue, and nowhere here. The test fails until it does.
  + The catalogue's =:vc= packages are not in nixpkgs' sets, so they stay out too.
- The result is sorted by name with hyphens ignored, because the order is part of the derivation.
  + That is the order the list had when this file wrote it out, so a host that chose nothing keeps its store path and rebuilds nothing.
- =extraPackages= goes after the list, unsorted: a host's own packages, handed the same package set.

#+begin_src nix
# Generated from literate/90-nix.org; edit the Org source, then tangle.
# EMACS with the packages of FEATURES, or of every feature when FEATURES is
# null, then EXTRAPACKAGES.  copilot (unfree), consult-ghostel (not in nixpkgs)
# and the catalogue's Git packages stay out.
{
  emacs,
  features ? null,
  extraPackages ? null,
}:

let
  catalogue = builtins.fromJSON (builtins.readFile ./features.json);
  archiveOnly = [
    "copilot"
    "consult-ghostel"
  ];
  fromNix =
    feature:
    let
      entry = catalogue.${feature};
      left = archiveOnly ++ entry.vc or [ ];
    in
    builtins.filter (package: !(builtins.elem package left)) entry.packages;
  chosen = if features == null then builtins.attrNames catalogue else features;
in
emacs.pkgs.withPackages (
  epkgs:
  let
    # MELPA builds ws-butler from a clone of Savannah's whole NonGNU ELPA

let
  catalogue = builtins.fromJSON (builtins.readFile ./features.json);
  names = builtins.attrNames catalogue;
  depsOf = name: catalogue.${name}.deps or [ ];
  setOf = name: catalogue.${name}.one-of or null;
  withDeps =
    features:
    let
      grown = lib.unique (features ++ lib.concatMap depsOf features);
    in
    if lib.length grown == lib.length features then features else withDeps grown;
  answered = cfg: value: lib.filter (name: cfg.features.${name}.enable == value) names;

  settingType =
    let
      value =
        lib.types.nullOr (
          lib.types.oneOf [
            lib.types.bool
            lib.types.int
            lib.types.float
            lib.types.str
            (lib.types.listOf value)
            (lib.types.submodule {
              options.elisp = lib.mkOption {
                type = lib.types.str;
                description = "Elisp to write as it stands, such as `'modus-vivendi`.";
              };
            })
          ]
        )
        // {
          description = "Elisp value";
        };
    in
    value;

    value:
    if value == null || value == false then
      "nil"
    else if value == true then
      "t"
    else if builtins.isString value then
      builtins.toJSON value
    else if builtins.isList value then
      if value == [ ] then "nil" else "(list ${lib.concatMapStringsSep " " renderValue value})"
    else if builtins.isAttrs value then

    else

** From the options to the features

- =enabled= answers which features are on, so the module can build their packages, and takes the same five steps as [[id:0fb86d27-93c1-4ea5-b2d8-6a1e47c3f9d0][From the options to the answer]].
  + =just nix-selection= holds the two answers equal on real starts.
- It answers null for a host that chose nothing, which builds every package as it always did.
- With no =profile= it starts from =full=, whatever the configuration's default is.
  + Nix cannot see the rule that decides for a machine with no choice, and too many packages cost only build time.
- It sees only what these options say, because =private.el= is outside the store.
  + What =private.el= adds installs from the archives, as on a machine without Nix.

#+begin_src nix :padline yes

  # The features that are on for SYSTEMTYPE, Emacs's name for the system, or
  # null when the options chose nothing.
  enabled =
    systemType: cfg:
    let
      selected = answered cfg true;
      excluded = answered cfg false;
      inProfile = profile: lib.filter (name: catalogue.${name}.profile == profile) names;
      floor = inProfile "minimal";
      dropUnmet =
        features:
        let
          kept = lib.filter (name: lib.all (dep: lib.elem dep features) (depsOf name)) features;
        in
        if lib.length kept == lib.length features then features else dropUnmet kept;
      keepOneOfEach =
        features:
        let
          winner =
            name:
            lib.findFirst (other: setOf other == setOf name) null (
              lib.filter (other: lib.elem other features) (withDeps selected) ++ features
            );
        in
        lib.filter (name: setOf name == null || winner name == name) features;
      removed = lib.subtractLists floor excluded;
      wanted = lib.unique (
        floor ++ lib.optionals (cfg.profile != "minimal") (inProfile "full") ++ withDeps selected
      );
      applies = name: !(lib.elem systemType (catalogue.${name}.not-on or [ ]));
    in
    if cfg.profile == null && selected == [ ] && excluded == [ ] then
      null
    else
      dropUnmet (keepOneOfEach (lib.filter (name: !(lib.elem name removed) && applies name) wanted));

  # Emacs's name for the system PKGS is for.
  systemType = pkgs: if pkgs.stdenv.hostPlatform.isDarwin then "darwin" else "gnu/linux";

  # The features of the profile PROFILE, for the flake's packages.
  profileFeatures =
    system: profile:
    enabled system {
      inherit profile;
      features = lib.mapAttrs (_: _: { enable = null; }) catalogue;
    };

  # The Emacs a module installs and runs.
  emacsFor =
    system: cfg:
    if cfg.packagesFromNix then
      import ./packages.nix {
        emacs = cfg.package;
        features = enabled system cfg;
        inherit (cfg) extraPackages;
      }
    else if cfg.extraPackages != null then
      cfg.package.pkgs.withPackages cfg.extraPackages
    else
      cfg.package;

** The tools of a host

- A host's tools follow its selection, so turning a feature off also takes away what only that feature runs.
- =features.<name>.enable = false= takes out the tools keyed to that feature and to features that needed it, and =true= brings them in.
- =toolFeatures= is =enabled=, except for a host that chose nothing, which gets what =full= selects.
  + That leaves out only the tools of the optional features: today =kittymacs-zmq-module=, for =jupyter=, and without that script emacs-zmq's own download or build applies.
  + =enabled= answers null there so that =packages.nix= builds every package, and a tool list has no reason to do the same.
- =backend.enable= does not read the selection, because a backend's tools are about what runs on it.
  + A selection could not take them away anyway: =git=, =rg=, =fd= and =direnv= belong to features the =minimal= profile always keeps, and the rest belong to no feature.
- Nix cannot see what =private.el= adds, or what a host's =settings= or =hostFiles= set.
  + Such a feature gets no tools until =features.<name>.enable = true= names it and the host rebuilds.
  + =nix run .#doctor= is how a person finds out: it reads =private.el= and the host layer, and names each missing tool with the feature that would use it.
- To add one tool and not its feature, put it in the host's own =home.packages= or =environment.systemPackages=. No option here does that, because those lists already do.

- Each module adds these assertions, so a mistake stops at evaluation and names its option.

- The second refuses an Emacs older than 31, because =init.el= would refuse it at every start, where the cause is further away.

- The guard: the assertion reads =package= only when the module installs or runs it (=usesPackage=).

- A host that does install the default on nixos-26.05, which has no Emacs 31, now fails here instead of at its first start.
  + So its message names the override, and [[*The templates][each template]] shows it: =kittymacs.packages.<system>.default= is Emacs 31 once the =kittymacs= input stops following that nixpkgs.
- The last three refuse a selection that contradicts itself, because a host's own file should not ask for what it cannot get.
  + One refuses =false= on a feature the =minimal= profile always keeps, such as =features.meow.enable=.
  + One refuses =true= on a feature while its dependency, direct or through other dependencies, is =false=.
  + One refuses =true= on two members of one =:one-of= set.

  + Leaving a feature to the profile is no conflict: excluding =icons= under =full= still drops =file-tree= quietly, as [[*From the options to the features][the steps above]] say.
  + Elisp still warns about both, because a hand-written setting and a checkout can drift.

** The generated host file

- The module writes this text to =~/.config/kittymacs/conf.d/10-nix.el=, in [[id:40302e33-d2b2-4c0b-9bc3-1f9e121307e1][the host layer]], which loads before =private.el=.

  + The name =10-= leaves room on both sides for a host's own files.
- It is null when no option asks for anything, and each =setopt= appears only when its option was set.
- The file is a link into the store, and holds only these settings; the configuration stays a writable checkout.
- A list renders as a =list= call rather than a quoted list, so an =elisp= value inside one is still evaluated.
- =builtins.toJSON= writes a string: its escapes are all ones Elisp reads the same way.
- =hostLayer= is what a module writes there: this file, when it has text, and one file per =hostFiles= entry.
  + Each =hostFiles= entry starts with the =lexical-binding= cookie, since Emacs warns about a Lisp file without one.

** Cloning the checkout on first activation :decision:
:PROPERTIES:
:ID: 41497b01-c9a9-4aa9-b658-7fda73fce4a8
:END:

- The checkout is ordinary user data, so activation clones it into the home directory rather than building it into the generation.
- Four cases, told apart by what is at =source=:
  1. A symbolic link to nothing (probably a disk that is not mounted) stops activation instead of being cloned over.
  2. Nothing there, or a directory holding nothing but =var/=: fetch only the pinned commit, with =origin= set to =repository= so the checkout can pull later.
     + The work happens in a temporary directory beside =source=, moved into place only once =HEAD= is that commit: a failed fetch leaves nothing half-made.
     + =mktemp= makes that directory private (mode 700); the checkout is given the usual mode before it moves into place.
     + A =var/= already there is Emacs's own: packages, caches and saved settings. It is carried into the new checkout, so starting over keeps them.
     + A failure only warns: the network may not be up yet (Home Manager runs at boot on NixOS), and the rest of the home should not wait for it. The next activation tries again; until then =~/.config/emacs= points at nothing.
     + The subshell runs with =errexit= and not as an =if= condition, where bash would ignore =set -e= and go on past a failed fetch.
  3. A directory that is no checkout and holds other things: warn, naming them, and touch nothing. Move them away and activate again.
  4. A Git checkout at another commit: say so in one line, and touch nothing.
- So bumping the input in =flake.lock= never rewrites your configuration: from the first clone on, the checkout is yours to pull, commit in and switch branches in.
- The first clone is shallow and detached; =git fetch --unshallow origin= then =git switch main= turns it into an ordinary checkout.
- To start over, remove =source= itself (=rm -rf ~/src/kittymacs=) and activate again.
  + Not the link: =rm -rf ~/.config/emacs/=, with its trailing slash, follows the link and empties the checkout instead, and the link stays.
  + Case 2 is what makes that mistake recoverable: what is left behind is a directory with only =var/= in it, which the next activation clones into.
- =DRY_RUN= (=home-manager switch --dry-run=) prints what would be cloned and does nothing.

#+begin_src nix :padline yes
    home.activation = {
      cloneKittymacs = lib.mkIf (cfg.source != null && cfg.revision != null) (
        lib.hm.dag.entryAfter [ "writeBoundary" ] ''
          source=${lib.escapeShellArg cfg.source}
          repository=${lib.escapeShellArg cfg.repository}
          revision=${lib.escapeShellArg cfg.revision}
          if [[ -L $source && ! -e $source ]]; then
            errorEcho "kittymacs: $source is a symbolic link to nothing"
            exit 1
          elif [[ -e $source/.git ]]; then
            if head=$(${git} -C "$source" rev-parse HEAD 2>/dev/null) && [[ $head != "$revision" ]]; then
              noteEcho "kittymacs: $source is at $head, not the pinned $revision; left as it is"
            fi
          elif [[ -d $source ]] \
            && stray=$(${coreutils}/ls -A -- "$source" | ${coreutils}/tr '\n' ' ') \
            && [[ -n ''${stray// /} && $stray != "var " ]]; then
            warnEcho "kittymacs: $source is not a checkout; it holds: $stray; move it away and activate again"
          elif [[ -e $source && ! -d $source ]]; then
            warnEcho "kittymacs: $source is not a directory; move it away and activate again"
          elif [[ -v DRY_RUN ]]; then
            echo "kittymacs: would clone $repository at $revision into $source"
          else
            parent=$(${coreutils}/dirname -- "$source")
            ${coreutils}/mkdir -p -- "$parent"
            set +e
            (
              set -e
              temp=$(${coreutils}/mktemp -d "$parent/.kittymacs.XXXXXXXX")
              trap '${coreutils}/rm -rf -- "$temp"' EXIT
              ${coreutils}/chmod u=rwx,go=rx -- "$temp"
              ${git} -C "$temp" init --quiet
              ${git} -C "$temp" remote add origin "$repository"
              ${git} -C "$temp" fetch --quiet --depth 1 origin "$revision"
              ${git} -C "$temp" checkout --quiet --detach FETCH_HEAD
              head=$(${git} -C "$temp" rev-parse HEAD)
              if [[ $head != "$revision" ]]; then
                errorEcho "kittymacs: $revision fetched as $head; give a full commit hash"
                exit 1
              fi
              if [[ -d $source ]]; then
                # Only var/ can be here (checked above): keep it, then swap the
                # directories.  From here on nothing is deleted on failure.
                trap - EXIT
                if [[ -e $source/var ]]; then
                  ${coreutils}/mv -- "$source/var" "$temp/var"
                fi
                ${coreutils}/rmdir -- "$source"
                noteEcho "kittymacs: cloned into $source, keeping the var/ that was there"
              fi
              ${coreutils}/mv -- "$temp" "$source"
            )
            cloneStatus=$?
            set -e
            if (( cloneStatus != 0 )); then
              warnEcho "kittymacs: could not clone $repository at $revision into $source; activation goes on without it, and the next one tries again"
            fi
          fi
        ''
      );

      kittymacsDaemon = lib.mkIf (cfg.daemon && pkgs.stdenv.hostPlatform.isLinux) (
        lib.hm.dag.entryAfter [ "reloadSystemd" ] ''
          systemctl=${config.systemd.user.systemctlPath}
          if [[ ! -v DRY_RUN ]] \
            && running=$("$systemctl" --user show emacs.service --property=ExecStart --value 2>/dev/null) \
            && [[ -n $running && $running != *"${emacs}"* ]] \
            && "$systemctl" --user is-active --quiet emacs.service; then
            noteEcho "kittymacs: the Emacs daemon still runs the previous Emacs, not ${emacs}; systemctl --user restart emacs when nothing is unsaved"
          fi
        ''
      );
    };

** The daemon's service

- =extraOptions= reaches the systemd unit's =ExecStart= and the launchd agent's =ProgramArguments= alike, and joins anything the home sets itself, so =initDirectory= costs a user nothing.
- A switch never restarts the daemon: Home Manager marks the unit =X-RestartIfChanged=false=, so an upgrade cannot take a session full of unsaved buffers with it.
  + The other side of that: after a switch that changes =package=, =emacsclient= keeps talking to the /old/ Emacs until you restart the service, and if the old one is too old for this configuration, every frame it opens is a stock Emacs with an init error.
  + So on Linux, once systemd has reloaded, activation compares the running unit's =ExecStart= with =package= and says in one line when they differ: =systemctl --user restart emacs=, when nothing is unsaved.
  + Where no user systemd runs (boot-time activation, nix-on-droid) =systemctl= answers nothing and the check stays quiet.
  + Its code, =kittymacsDaemon=, sits in [[id:41497b01-c9a9-4aa9-b658-7fda73fce4a8][the clone's]] =home.activation= set: =statix= rejects a third =home= key in one set, which is also why =home.file= shares a set with =home.packages=.
- A daemon that fails as it starts is retried three times, ten seconds apart, and then left failed:
  + Home Manager's unit says =Restart=on-failure= with no limit, so a configuration that cannot start (*seen* 2026-10-27: a package that failed to install) was restarted every three seconds, at ten seconds of CPU each, for as long as nobody looked;
  + three tries ride out a slow network at login; after them =systemctl --user status emacs= says =failed= and =journalctl --user -u emacs= has the reason;
  + =systemctl --user reset-failed emacs= and then =start= try again once it is fixed;
  + On macOS the launchd agent (=KeepAlive= with =SuccessfulExit= false) also restarts a failed start, but launchd has no limit to set: it only throttles, to one start every ten seconds by default, so there the loop is slower but does not stop.

** It cannot feed the Android port of Emacs :decision:
:PROPERTIES:
:ID: a8de042c-88ca-46d5-8c26-d6a498ba15bd
:END:

- The appealing idea, the Android application with nix-on-droid supplying =git=, =ripgrep= and the language servers, does not work; any one of three things stops it:
  1. =/nix= does not exist outside the PRoot. Every binary's ELF interpreter is baked in as =/nix/store/…/ld-linux-aarch64.so.1=, so the kernel cannot start it from outside.
  2. The two applications are different users: nix-on-droid is =com.termux.nix=, and the Emacs builds that share a user ID share it with =com.termux=.
  3. Android 10 and later forbid executing anything in another application's data directory.
- Pair the Android port with Termux instead ([[id:afa6b7fd-742a-4c15-86a6-32e3e8027b0e][the platform chapter]]); the two paths are alternatives, not layers.

* The apps :decision:
:PROPERTIES:

- =nix run= gives a person something to do before they have read anything, and each app needs a checkout, since the configuration is never in the store.
- So all three find one the same way, and print where they looked if there is none:
  1. =KITTYMACS_CHECKOUT=, and a name that is not a checkout is an error rather than a reason to look elsewhere;
  2. this directory;
  3. =~/.config/emacs=, under =XDG_CONFIG_HOME= when the environment sets it, where [[*Home Manager][the Home Manager module]] links one;
  4. =~/.emacs.d=.
- With no checkout, =default= and =onboard= say what to clone and exit 2. They do not clone one themselves: a command run to look at something should not create a directory in a home.
- =onboard= loads the checkout's own =lisp/kittymacs-onboard.el=, as =just onboard= does.
  + Under =nix run= the flake's copy is in the store, its neighbours too, and it would refuse to write there.
  + The checkout's copy finds its =private.el=, its catalogue and its =var/= by itself, so what it offers is what that checkout can install.
  + The flake's Emacs runs it, because the machine may have none, or an older one.
- =default= starts the flake's Emacs on the checkout, with the tools on =PATH=, passing its arguments on.
  + =--init-directory= takes the choice away from whatever else the home holds ([[id:4a4acce6-c592-4c82-a885-d7824a07594f][why]]).
- =doctor= reports and changes nothing:
  + the Emacs on the person's =PATH= and whether it is new enough;
  + the checkout, and the host-layer files;
  + each tool the selection needs, found on that same =PATH=, so =doctor= alone does not put the tools on it;
  + it reads the selection with onboarding's reader, which [[file:22-onboarding.org][never runs a setting]], using the flake's Emacs; =tests/kittymacs-onboard-tests.el= fails if a function named here goes away;
  + with no checkout it lists every tool, and a missing tool is a note, because every chapter degrades quietly without one;
  + a missing tool ends with a hint on [[*The tools of a host][how to get it]], which matters most for a feature =private.el= turned on, because Nix cannot see that;
  + it exits 1 only for what stops a start: no Emacs, an old one, or no checkout.
- =doctor= and [[file:36-remote.org][=SPC o B=]] keep separate lists, because they answer different questions.
  + =doctor= asks what this machine needs for its selection, with no Emacs to read an option from, so it takes =commands=, each with a feature. That brings =gpg= and =hunspell=, which a backend never runs.
  + =SPC o B= asks what a project can use on another machine, so it takes =kittymacs-backend-tools=, which a person can change. That brings =inotifywait=, =nix= and =claude-agent-acp=, which no local feature in this table asks for.
  + So the =doctor= reading the option's default would lose the features and report the wrong tools.
  + =tests/kittymacs-startup-tests.el= holds what they share: each command =backendPrograms= picks from the table is in the option, and only those three named tools are in the option and not the table.

* The flake's checks
:PROPERTIES:
:header-args:nix: :tangle ../nix/checks.nix :eval never :comments no :padline no :mkdirp yes
:END:

- CI evaluates and does not build, so each check here does its work at evaluation, and =nix flake check --no-build= fails on a false one.
  + Each is a trivial derivation behind the claim, which is the form =checks= requires.
- These are the claims nixpkgs alone can test, so they cost a consumer no input. Home Manager and nix-darwin hosts are in [[id:1c9a5e37-d482-4b06-97f1-e3a80c6b42d5][the selection check]] and [[*The evaluation matrix][the matrix]], which are flakes of their own.
- =tool-features= :: every feature [[*The tools][the tool list]] names is in the catalogue, so a renamed feature cannot quietly take its tool out of a profile.
- =profiles-narrow= :: =minimal= has fewer tools than =full=, and =full= leaves out what only an optional feature needs. Without this, keying the tools could stop meaning anything.
- =backend-headless= :: the backend's tools include direnv and, on Linux, =inotify-tools=, and no name in the list is an Emacs, a font or a GUI toolkit.
  + By name, because evaluation cannot read a closure. =just nix-backend-closure= reads the real one, and CI does not run it.
- =system-module= :: on x86_64 Linux, real NixOS evaluations:
  + a plain host writes nothing to =/etc/kittymacs=;
  + a selection writes =10-nix.el=;
  + an old Emacs fails the assertion, naming =package=;
  + an old Emacs with =backend.enable= passes it.
  + The two Emacs packages are stand-ins, so the answer is the same on every nixpkgs: the check reads only their version.
- =tools-follow-selection= :: on x86_64 Linux, the real NixOS module's =environment.systemPackages=, against [[*The tools of a host][what the selection says]]:
  + a feature turned off loses its tools and keeps every other tool;
  + a feature turned on over =minimal= brings its tools, and only those;
  + a host that chose nothing lacks only the optional features' tools;
  + =backend.enable= installs the same names whatever the selection says.
  + [[id:1c9a5e37-d482-4b06-97f1-e3a80c6b42d5][The selection check]] holds the same answer through Home Manager and nix-darwin, against a real start.
- =overlay= :: =pkgs.kittymacs.backend= under =overlays.default= is the same derivation as =packages.backend=.
- =rpc-server-opt-in= :: on x86_64 Linux, the real NixOS module installs [[*The server behind wsl-rpc][the server]] only when =backend.rpcServer= asks:
  + a backend and a plain host without the option lack it, and so do the backend's tools;
  + a backend with it has it, and so does a full host, with Emacs and no =backend.enable=.
  + [[*The evaluation matrix][The matrix]]'s =home-rpc-server= holds the same for a full Home Manager home.

* The evaluation matrix
:PROPERTIES:
:ID: 3bd7a0e4-96c1-4f28-8d53-c2e1f47ab906
:header-args:nix: :tangle ../nix/eval-matrix/flake.nix :eval never :comments no :padline no :mkdirp yes
:END:

- =just nix-matrix= evaluates each host to the derivation a switch would build, once on the lock and once on [[file:../justfile][the justfile's]] stable release.
- Each case runs in its own process, because a real NixOS evaluation is heavy and several in one process hold all their memory until the end.
- On stable, =kittymacs/nixpkgs= stays on unstable, so =package= is Emacs 31 while everything else comes from the stable release, as on a real host that dropped the =follows=.
- What each case proves:

| Case                | Proves                                                                                   |
|---------------------+------------------------------------------------------------------------------------------|
| =home-plain=        | a plain Linux home evaluates whole: link, clone step, tools, fonts, activation           |
| =home-daemon=       | =daemon = true=: the systemd unit, its limits and =--init-directory=                     |
| =home-packages=     | =packagesFromNix = true=: Emacs with every package                                       |
| =home-darwin=       | the launchd agent and the Mac's tool list, through Home Manager                          |
| =home-xdg=          | a custom =xdg.configHome= writes the host layer in both places                           |
| =home-backend=      | =backend.enable= installs no Emacs and no fonts                                          |
| =home-backend-rpc-server= | so does =backend.rpcServer=, which only adds the server                            |
| =home-rpc-server=   | a full home with =backend.rpcServer= installs the server beside Emacs                    |
| =home-old-unused=   | an old =package= the home neither installs nor runs passes: the assertion's guard        |
| =nixos=             | a NixOS system evaluates whole with this module                                          |
| =nixos-full=        | the same with =daemon=, =packagesFromNix= and a selection                                |
| =nixos-backend=     | a NixOS backend has no Emacs                                                             |
| =darwin=            | a nix-darwin system evaluates whole on Linux; building it needs a Mac                    |
| =darwin-full=       | the same with =daemon= and =packagesFromNix=                                             |

- =mustFail= holds the old =package= through each module, which must fail naming the option.
  + It also holds =floor= and =dependency=, the two selection conflicts through Home Manager, which share the assertion list the first three prove in each module.
  + =mustFailSays= holds the sentence each case must print, so a case that fails for another reason still fails the recipe.
- =defaultEmacs= is a home with no =package= at all. It must pass where nixpkgs' Emacs is 31 or later, and fail naming the option where it is older, which is the case on =nixos-26.05=.
- The templates, on both channels, are the matrix's other half: =just nix-templates=.
- To compare a change with its base, evaluate =home-plain=, =home-daemon=, =home-packages=, =home-darwin=, =darwin= and =darwin-full= against both, and the paths must match: these set no option newer than the base.

- =just nix-check= lints the generated Nix and evaluates the flake on every system, then both example hosts against this checkout; nothing is built.
- =just nix-selection=, part of =nix-check=, starts Emacs once per host in [[id:1c9a5e37-d482-4b06-97f1-e3a80c6b42d5][the selection check]], and fails if =kittymacs-feature-p= disagrees with the options.
