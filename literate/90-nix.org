#+TITLE: Nix: the flake, its modules and example hosts
#+FILETAGS: :nix:
#+STARTUP: overview
#+PROPERTY: header-args:nix :eval never :comments no :padline no :mkdirp yes

- The repository is a flake, but it does not put the configuration in the Nix store.
  + The configuration installs its Emacs packages under =var/= and keeps =private.el= beside its modules; both must stay writable.
- What the flake provides is everything /around/ the configuration: Emacs, every program the chapters look for, and the icon font.
  + A fresh Mac needs one =darwin-rebuild switch= and one =git clone=; with the Home Manager module, not even the clone.
- The Nix layer is a convenience: Homebrew, a package manager or a manual install work as well, and every chapter degrades quietly when a program is missing.
- Each top heading writes one file; =just lint= and =just eval= check them ([[id:9ea539a0-f1a3-4d05-aa10-6f2d2ff3e335][the loop]]).

* What the flake provides

| Output                       | What it is                                                                                         |
|------------------------------+----------------------------------------------------------------------------------------------------|
| =darwinModules.default=      | nix-darwin: =programs.kittymacs.enable= installs Emacs, the tools and the font system-wide          |
| =homeManagerModules.default= | Home Manager: clones a checkout, links it to =~/.config/emacs=; can install the tools and run a daemon |
| =packages.<system>.default=  | the Emacs the modules install (=pkgs.emacs=)                                                       |
| =packages.<system>.tools=    | one environment with every tool, for =nix profile install=                                         |
| =devShells.<system>.default= | Emacs, the tools, =just= and the Nix linters, for the recipes                                      |

- Each module is also exported as =kittymacs=, beside =default=, for a host that imports several flakes' modules by name.

* The flake
:PROPERTIES:
:header-args:nix: :tangle ../flake.nix :eval never :comments no :padline no :mkdirp yes
:END:

- One input, nixpkgs-unstable, so a host's =follows= decides the Emacs version.
- Three systems: Apple Silicon, ARM Linux (phones, through nix-on-droid) and x86_64 Linux.
  + nixpkgs-unstable dropped =x86_64-darwin= in 26.11; an Intel Mac points this flake's =nixpkgs= input at the =nixpkgs-26.05-darwin= branch.
- =forEachSystem= hands every per-system output the package set and [[*The tools][the tool list]], so that list is read in one place.
- The Home Manager module is a function of the flake itself, so its clone can default to the revision the host locked ([[*Cloning the checkout on first activation]]).
- The dev shell adds =just=, =nixfmt=, =deadnix= and =statix= to Emacs and the tools: everything =just all= needs.

#+begin_src nix
# Generated from literate/90-nix.org; edit the Org source, then tangle.
{
  description = "kittymacs: a Meow-first Emacs configuration, with the tools it looks for";

  inputs.nixpkgs.url = "github:NixOS/nixpkgs/nixpkgs-unstable";

  outputs =
    { self, nixpkgs }:
    let
      # nixpkgs-unstable dropped x86_64-darwin in 26.11; an Intel Mac can
      # point this flake's nixpkgs input at the nixpkgs-26.05-darwin branch.
      systems = [
        "aarch64-darwin"
        "aarch64-linux"
        "x86_64-linux"
      ];
      # Each per-system output gets the package set and the tool list.
      forEachSystem =
        f:
        nixpkgs.lib.genAttrs systems (
          system:
          let
            pkgs = nixpkgs.legacyPackages.${system};
          in
          f pkgs (import ./nix/tools.nix { inherit pkgs; })
        );
    in
    {
      darwinModules.default = import ./nix/darwin-module.nix;
      darwinModules.kittymacs = self.darwinModules.default;

      # The module is given the flake itself, so the clone can default to
      # this flake's revision.
      homeManagerModules.default = import ./nix/home-module.nix { inherit self; };
      homeManagerModules.kittymacs = self.homeManagerModules.default;

      packages = forEachSystem (
        pkgs: tools: {
          tools = pkgs.buildEnv {
            name = "kittymacs-tools";
            paths = tools.programs ++ tools.fonts;
          };
          default = tools.emacs;
        }
      );

      # Emacs and the tools, plus just and the Nix linters for the recipes.
      devShells = forEachSystem (
        pkgs: tools: {
          default = pkgs.mkShell {
            packages = [
              tools.emacs
            ]
            ++ tools.programs
            ++ [
              pkgs.just
              pkgs.nixfmt
              pkgs.deadnix
              pkgs.statix
            ];
            shellHook = ''
              echo "kittymacs: just --list"
            '';
          };
        }
      );
    };
}

** The checkout: source, repository, revision

- =source= :: where the checkout lives; =~/.config/emacs= becomes a link to it.
  + The link points outside the store on purpose: the checkout must stay writable.
  + Null leaves cloning and placing to you; nothing is linked or cloned, and =repository= and =revision= do nothing. The other options still install Emacs, the tools and the font, and run the daemon.
- =repository= :: the Git URL to clone from; point it at a fork to start from your own copy.
- =revision= :: the commit to check out; defaults to the kittymacs revision the host's =flake.lock= pins, so the lock decides what a new machine starts from.
  + The pin applies to the /first clone only/ ([[*Cloning the checkout on first activation]]).
  + Null when the flake has no revision (a =path:= input, or a dirty Git tree); then nothing is cloned. Set it to null yourself to never clone.

** Why the daemon names its init directory :decision:
:PROPERTIES:
:ID: 4a4acce6-c592-4c82-a885-d7824a07594f
:END:

- =initDirectory= :: the directory the daemon passes to Emacs as =--init-directory=; defaults to the link, =~/.config/emacs=, and to null when =source= is null.
- Emacs reads =~/.config/emacs= only when =~/.emacs.d= does not exist, and an empty =~/.emacs.d= is enough to win.
  + On a home that ran Emacs before this module, the daemon would serve a stock Emacs with no error anywhere.
  + That Emacs then writes an =~/.emacs.d= of its own as it starts, which keeps it that way.
- Naming the directory takes the decision away from the home directory.
  + The default is the link rather than =source=, so =user-emacs-directory= reads as it does on a home with no =~/.emacs.d= at all.
- Needs Emacs 29 or later; null passes nothing and leaves the choice to Emacs, as for an Emacs started by hand.

** Cloning the checkout on first activation :decision:
:PROPERTIES:
:ID: 41497b01-c9a9-4aa9-b658-7fda73fce4a8
:END:

- The checkout is ordinary user data, so activation clones it into the home directory rather than building it into the generation.
- Three cases:
  1. A symbolic link to nothing (probably a disk that is not mounted) stops activation instead of being cloned over.
  2. Nothing there: fetch only the pinned commit, with =origin= set to =repository= so the checkout can pull later.
     + The work happens in a temporary directory beside =source=, moved into place only once =HEAD= is that commit: a failed fetch leaves nothing half-made.
     + A failure only warns: the network may not be up yet (Home Manager runs at boot on NixOS), and the rest of the home should not wait for it. The next activation tries again; until then =~/.config/emacs= points at nothing.
     + The subshell runs with =errexit= and not as an =if= condition, where bash would ignore =set -e= and go on past a failed fetch.
  3. A Git checkout at another commit: say so in one line, and touch nothing.
- So bumping the input in =flake.lock= never rewrites your configuration: from the first clone on, the checkout is yours to pull, commit in and switch branches in.
- The first clone is shallow and detached; =git fetch --unshallow origin= then =git switch main= turns it into an ordinary checkout.
- =DRY_RUN= (=home-manager switch --dry-run=) prints what would be cloned and does nothing.

#+begin_src nix :padline yes
    home.activation.cloneKittymacs = lib.mkIf (cfg.source != null && cfg.revision != null) (
      lib.hm.dag.entryAfter [ "writeBoundary" ] ''
        source=${lib.escapeShellArg cfg.source}
        repository=${lib.escapeShellArg cfg.repository}
        revision=${lib.escapeShellArg cfg.revision}
        if [[ -L $source && ! -e $source ]]; then
          errorEcho "kittymacs: $source is a symbolic link to nothing"
          exit 1
        elif [[ ! -e $source ]]; then
          if [[ -v DRY_RUN ]]; then
            echo "kittymacs: would clone $repository at $revision into $source"
          else
            parent=$(${coreutils}/dirname -- "$source")
            ${coreutils}/mkdir -p -- "$parent"
            set +e
            (
              set -e
              temp=$(${coreutils}/mktemp -d "$parent/.kittymacs.XXXXXXXX")
              trap '${coreutils}/rm -rf -- "$temp"' EXIT
              ${git} -C "$temp" init --quiet
              ${git} -C "$temp" remote add origin "$repository"
              ${git} -C "$temp" fetch --quiet --depth 1 origin "$revision"
              ${git} -C "$temp" checkout --quiet --detach FETCH_HEAD
              head=$(${git} -C "$temp" rev-parse HEAD)
              if [[ $head != "$revision" ]]; then
                errorEcho "kittymacs: $revision fetched as $head; give a full commit hash"
                exit 1
              fi
              ${coreutils}/mv -- "$temp" "$source"
            )
            cloneStatus=$?
            set -e
            if (( cloneStatus != 0 )); then
              warnEcho "kittymacs: could not clone $repository at $revision into $source; activation goes on without it, and the next one tries again"
            fi
          fi
        elif [[ -e $source/.git ]] \
          && head=$(${git} -C "$source" rev-parse HEAD 2>/dev/null) \
          && [[ $head != "$revision" ]]; then
          noteEcho "kittymacs: $source is at $head, not the pinned $revision; left as it is"
        fi
      ''
    );
#+end_src

* nix-on-droid :android:
:PROPERTIES:
:ID: a79575e0-a404-48ee-83b0-1edfbc4b6522
:header-args:nix: :tangle ../nix/example-nix-on-droid/flake.nix :eval never :comments no :padline no :mkdirp yes
:END:

- nix-on-droid runs Nix on Android and consumes Home Manager modules, so [[*Home Manager][the module above]] is the whole integration: no Android-specific Nix exists here.
- The example is a complete device; on the phone, =nix-on-droid switch --flake .#default --impure= applies it.
  + =--impure= is nix-on-droid's own requirement: proot-static cannot be built on the device, so nix-on-droid reaches a pre-built one through =builtins.storePath=, which pure evaluation forbids.
  + So =just eval= checks the package list the module produces, which stays pure, rather than the activation script; building needs an =aarch64-linux= machine.
- Inside nix-on-droid, =system-type= is =gnu/linux=: an ordinary GNU/Linux Emacs that happens to be on a phone.
  + None of the configuration's Android branches apply and nothing degrades; ghostel works.
  + The cost: the PRoot is slow, and being graphical needs a display server, [[https://github.com/termux/termux-x11][Termux:X11]].
- Emacs builds:
  + =pkgs.emacs-pgtk= speaks Wayland and X11 both, so one build serves Termux:X11 either way;
  + =pkgs.emacs-nox= with =installFonts = false= stays in the console, and the configuration turns its icons off by itself.
- The frame policy hands window arrangement to a desktop window manager, which Termux:X11 lacks unless you install one: run a window manager, or turn the policy off in =private.el=:

(setq kittymacs-frames-only nil)
#+end_src

# A complete nix-on-droid device with kittymacs: copy it as a starting point.
# On the phone:
#
#   nix-on-droid switch --flake .#default --impure
#

  description = "Example nix-on-droid device with kittymacs";

  inputs = {
    nixpkgs.url = "github:NixOS/nixpkgs/nixpkgs-unstable";

    nix-on-droid = {

** It cannot feed the Android port of Emacs :decision:
:PROPERTIES:
:ID: a8de042c-88ca-46d5-8c26-d6a498ba15bd
:END:

- The appealing idea, the Android application with nix-on-droid supplying =git=, =ripgrep= and the language servers, does not work; any one of three things stops it:
  1. =/nix= does not exist outside the PRoot. Every binary's ELF interpreter is baked in as =/nix/store/…/ld-linux-aarch64.so.1=, so the kernel cannot start it from outside.
  2. The two applications are different users: nix-on-droid is =com.termux.nix=, and the Emacs builds that share a user ID share it with =com.termux=.
  3. Android 10 and later forbid executing anything in another application's data directory.
- Pair the Android port with Termux instead ([[id:afa6b7fd-742a-4c15-86a6-32e3e8027b0e][the platform chapter]]); the two paths are alternatives, not layers.

* Without a module

- The Emacs and the tools, into your profile:

#+begin_src sh :tangle no
nix profile install github:Mihir-Null/kittymacs#default github:Mihir-Null/kittymacs#tools
#+end_src

- On macOS, an Emacs.app started from the Dock inherits no shell =PATH=: [[id:40302e33-d2b2-4c0b-9bc3-1f9e121307e1][the startup chapter]] puts the Nix profiles and Homebrew on =exec-path= before anything runs, and [[id:d2e0bc37-0bd4-4b28-a8ee-04f94ac451f8][the shells chapter]] imports the login shell's environment.

* Check

- =just nix-check= lints the generated Nix and evaluates the flake on every system, then both example hosts against this checkout; nothing is built.
- =nix develop= then =just --list=: the shell has every recipe's tools.
- CI also reads the clone options as a device would see them. It overrides the input with =git+file=, not =path:=, because a =path:= input has no revision, and without one the module defines no clone step:

#+begin_src sh :tangle no
nix eval --no-write-lock-file --override-input kittymacs "git+file://$PWD?shallow=1" \
  --json ./nix/example-nix-on-droid#nixOnDroidConfigurations.default.config.home-manager.config \
  --apply 'c: { inherit (c.programs.kittymacs) repository revision daemon initDirectory;
              clones = builtins.isString c.home.activation.cloneKittymacs.data; }'
#+end_src

- On a clean checkout, =revision= comes out as =git rev-parse HEAD=.
