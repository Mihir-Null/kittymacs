#+TITLE: Shells: Eshell and remote files
#+FILETAGS: :apps:
#+STARTUP: overview
#+PROPERTY: header-args:emacs-lisp :tangle ../lisp/kittymacs-shell.el :eval never :comments no :padline no :mkdirp yes

- Eshell, a shell written in Lisp, and Tramp, which opens files on remote machines over SSH as if they were local.
  + Distilled from Lambda-Emacs by Colin McLear (=lem-setup-shell=, =lem-setup-eshell=).
- Eshell runs ordinary programs, but =cd=, =ls= and friends are Lisp.
  + So Emacs commands run from the prompt (=ff file.txt= opens a file), with the same completion machinery as everywhere else.
  + It cannot draw a full-screen program, so it hands those to [[id:bd2638bc-735d-4849-bafe-3dab5e8e30b7][the terminal]]: =htop=, =less= and =git log= open there and behave.
- [[id:afa6b7fd-742a-4c15-86a6-32e3e8027b0e][The platform chapter]] chooses the system shell and [[id:bd2638bc-735d-4849-bafe-3dab5e8e30b7][the terminal chapter]] owns =SPC o e=; this chapter configures Eshell and remote files, with its =SPC m= menu from [[id:e5942eb0-4389-447d-9317-d9178adcaaae][the leader]].

* Pagers, and killing a shell

- Programs such as =git log= and =man= send long output through a /pager/ like =less=, which waits for keys and redraws the screen.
  + In Eshell or =M-x shell= the output lands in an ordinary Emacs buffer you can already scroll and search, so the pager only gets in the way.
  + Emacs's =comint-pager= tells those shells, and only them, to set =PAGER=cat= for the programs they start; Eshell honours the same option.
  + A real terminal from [[id:bd2638bc-735d-4849-bafe-3dab5e8e30b7][the terminal chapter]] keeps your usual pager: there =less= works as it does anywhere else.
- Killing a buffer whose process is still running normally asks first.
  + For a shell that is noise: ending the process is why you kill it.
  + So the function that asks is taken off =kill-buffer-query-functions=.

* The environment on Linux and macOS :decision:
:PROPERTIES:
:ID: eff5924c-3ac1-43a0-be28-6e442dc1e8e3
:END:

- A graphical Emacs started from a launcher does not run your shell's profile, so =PATH= can be wrong.
- =exec-path-from-shell= copies your shell's =PATH= and =MANPATH=, the locale (=LANG=), and the two variables the =nix= commands read (=NIX_PATH=, =NIX_PROFILES=).
  + On Linux it asks a plain non-interactive shell, which reads =~/.zshenv= or =$BASH_ENV=.
  + On macOS it asks a login shell: that is where the system's =path_helper= and Homebrew's =shellenv= line in =~/.zprofile= run.
  + [[id:40302e33-d2b2-4c0b-9bc3-1f9e121307e1][The startup chapter]] already put Homebrew and the Nix profiles on =exec-path=, so on macOS this import only refines it.
- The import replaces =exec-path= whole, so a login shell that does not list a Nix profile would drop the one the startup chapter found.
  + Determinate's Nix, for one, sets =PATH= only for interactive shells, and this is a login shell that is not interactive.
  + Every program in that profile would vanish at once: pdf-tools' =epdfinfo= (it then offers to build one), the agent's =claude-agent-acp=, Copilot's server.
  + So the directories =early-init.el= found (=kittymacs-launcher-path=) go back on the end of =exec-path= and =PATH= when the import left them out; the shell's own order still wins.
  + It runs only in a graphical Emacs or a daemon.
- Two platforms keep the environment Emacs inherited; the =:if= line means the package is not even installed there.
  + Windows: the importer would ask PowerShell to evaluate POSIX shell syntax, which it cannot, and Windows programs inherit a correct environment anyway.
  + Android, for the opposite reason: the import would succeed, and that is the problem. =/system/bin/sh= evaluates the POSIX syntax happily and reports a =PATH= that has never heard of Termux, replacing the entries [[id:afa6b7fd-742a-4c15-86a6-32e3e8027b0e][the platform chapter]] has just added.

#+begin_src emacs-lisp
(defun kittymacs--restore-launcher-path ()
  "Put back the directories `early-init.el' found and the shell import dropped.
They go at the end of `exec-path' and of the PATH that subprocesses see."
  (dolist (directory (reverse (bound-and-true-p kittymacs-launcher-path)))
    (unless (member directory exec-path)
      (setq exec-path (append exec-path (list directory)))
      (setenv "PATH" (concat (getenv "PATH") path-separator directory)))))

(use-package exec-path-from-shell
  :ensure t
  :if (not (memq system-type '(windows-nt android)))
  :custom
  (exec-path-from-shell-variables '("PATH" "MANPATH" "LANG" "NIX_PATH" "NIX_PROFILES"))
  (exec-path-from-shell-arguments (and (eq system-type 'darwin) '("-l")))
  :config
  (when (or window-system (daemonp))
    (exec-path-from-shell-initialize)
    (kittymacs--restore-launcher-path)))

#+end_src

* A project's own environment: direnv :decision:
:PROPERTIES:
:ID: a121fda8-198e-498c-8867-eb1ecba8236d
:END:

- The import above gives Emacs /one/ environment, your shell's; a project often wants its own: its Python, its compiler, its =PYTHONPATH=.
- [[https://direnv.net][direnv]] is the shell's answer: a =.envrc= file at a project's root says how to build that environment, and the shell enters it on =cd= and leaves it on the way out.
  + =use flake= in a =.envrc= enters the project's =nix develop= shell; [[https://github.com/nix-community/nix-direnv][nix-direnv]] caches it, so entering takes milliseconds after the first time.
  + A =.envrc= runs code, so direnv refuses one until you allow it, and again after every change to it.
- [[https://github.com/purcell/envrc][envrc]] does the same per /buffer/: a buffer visiting a file under a =.envrc= gets that environment as buffer-local =process-environment= and =exec-path=.
  + So everything started from that buffer sees the project's programs: =compile=, Eglot's language server, =run-python=, a Jupyter kernel, Eshell, =shell-command=.
  + Buffer-local, not global: two projects with two Pythons stay open side by side, each buffer with its own.
  + It also wraps the few commands that run programs from a temporary buffer (=shell-command=, =vc=, Org Babel's evaluation) so they see the buffer's environment too.
- Why envrc and not its older cousin direnv.el: direnv.el changes the /global/ environment whenever you switch buffers, so a process started in the background by one project can see another's.
- It turns on last, at depth 90 of =after-init-hook=:
  + envrc's minor mode puts itself at the front of other modes' hooks, so it must be enabled after them, as its README asks;
  + depth 90 is the slot [[id:6c9aefe0-32af-453b-a075-6ed429993d3a][private.el]]'s late settings use.
- Where =direnv= is not on =exec-path= (native Windows, a machine without it) envrc enables itself in no buffer, so it costs nothing.
  + =direnv= comes from [[id:d25a5063-1439-4ae0-8fbe-b0162d05a0e0][the tool list]] on a Nix machine.
  + nix-direnv is the /shell's/ configuration (=programs.direnv.nix-direnv.enable= in Home Manager), not Emacs's; envrc runs the same =direnv= and finds it there.
- The mode line shows =envrc= in green when a buffer has its project's environment, yellow when the =.envrc= waits to be allowed, red when it failed.
- The commands are on =SPC p E= ([[id:53ad53ed-155f-47dc-973d-7be18de2893c][the keys chapter]]): =a= allow, =d= deny, =r= reload after editing a flake, =l= the log of the last =direnv= run.

(use-package envrc
  :ensure t
  :commands (envrc-allow envrc-deny envrc-reload envrc-show-log)
  :init
  (add-hook 'after-init-hook #'envrc-global-mode 90))

* Eshell's history, completion and prompt

- History (10,000 entries, duplicates dropped) and the last-directory ring persist under =var/etc/eshell/=, or wherever =kittymacs-eshell-dir= points if =private.el= sets it.
- Completion and globbing ignore case; a glob that matches nothing is an error.
- Programs that need a terminal run in one:
  + =eshell-visual-commands= gains =htop=, =top=, =less=, =more=, =vim=, =nano=, =ssh= and =tail=, and =git log=, =diff= and =show=;
  + [[id:bd2638bc-735d-4849-bafe-3dab5e8e30b7][the terminal chapter]] turns on =ghostel-eshell-visual-command-mode=, so they open in ghostel.
- The buffer keeps 20,000 lines, scrolls to the bottom on input and output, has no banner, and is killed when its process dies.
- The prompt shows the directory, the Git branch when there is one, and a =λ= on its own line, so long paths do not squeeze your command.

#+begin_src emacs-lisp
(defcustom kittymacs-eshell-dir (expand-file-name "eshell/" kittymacs-etc-dir)
  "Directory for Eshell history, aliases and the directory ring."
  :type 'directory
  :group 'kittymacs)

(setopt eshell-directory-name kittymacs-eshell-dir
        eshell-history-file-name (expand-file-name "history" kittymacs-eshell-dir)
        eshell-last-dir-ring-file-name (expand-file-name "lastdir" kittymacs-eshell-dir)
        eshell-aliases-file (expand-file-name "alias" kittymacs-eshell-dir)
        eshell-buffer-maximum-lines 20000
        eshell-scroll-to-bottom-on-input 'all
        eshell-scroll-to-bottom-on-output 'all
        eshell-cmpl-ignore-case t
        eshell-history-size 10000
        eshell-hist-ignoredups t
        eshell-glob-case-insensitive t
        eshell-error-if-no-glob t
        eshell-destroy-buffer-when-process-dies t
        eshell-banner-message ""
        eshell-prompt-regexp "^λ ")

(with-eval-after-load 'em-term
  (dolist (command '("htop" "top" "less" "more" "vim" "nano" "ssh" "tail"))
    (add-to-list 'eshell-visual-commands command))
  (add-to-list 'eshell-visual-subcommands '("git" "log" "diff" "show")))

(defun kittymacs--eshell-git-branch ()
  "Return the current Git branch for the prompt, or nil."
  (when (and (not (file-remote-p default-directory))
             (locate-dominating-file default-directory ".git"))
    (car (vc-git-branches))))

(defun kittymacs-eshell-prompt ()
  "A two-line prompt: directory and branch, then λ."
  (let ((branch (kittymacs--eshell-git-branch)))
    (concat "\n"
            (propertize (abbreviate-file-name (eshell/pwd)) 'face 'font-lock-constant-face)
            (when branch (propertize (format " (%s)" branch) 'face 'font-lock-comment-face))
            "\n"
            (propertize "λ" 'face 'font-lock-keyword-face)
            (propertize " " 'face 'default))))
(setopt eshell-prompt-function #'kittymacs-eshell-prompt)

* Aliases, jumps and an Eshell per project

- Aliases are defined in Lisp, so they are versioned with this file; Eshell never writes its own alias file.

| Alias            | Runs                             |
|------------------+----------------------------------|
| =ff=, =e=        | =find-file=                      |
| =d=              | =dired=                          |
| =gs=             | =magit-status=                   |
| =g=              | =git --no-pager=                 |
| =gd=, =gl=       | coloured diff, last 20 commits   |
| =l=, =la=, =ll=  | =ls=, =ls -la=, =ls -lah=        |
| =fr=, =bb=, =pp= | recent files, buffers, projects  |
| =up=             | a parent directory (=eshell-up=) |
| =q=, =x=         | =exit=                           |

- =z= jumps to any directory you have visited, with completion; =z REGEXP= goes to the most recent match.
- =SPC o s= opens an Eshell named =*eshell: PROJECT*= at the project root, or in this directory outside a project.
  + [[id:bd2638bc-735d-4849-bafe-3dab5e8e30b7][The terminal]] falls back to it for =SPC o p= where ghostel is off.
- In every Eshell buffer =C-l= clears it, =imenu= lists the prompts, lines wrap visually and the current line is not highlighted.
- Small packages add syntax highlighting, the =up= command, Eldoc help for commands (=esh-help=) and richer argument completion (=pcmpl-args=, =pcomplete-extension=).

(defun eshell/z (&optional regexp)
  "Change to a previously visited directory chosen with completion.
With REGEXP, go to the most recent directory matching it."
  (let ((dirs (delete-dups (mapcar #'abbreviate-file-name (ring-elements eshell-last-dir-ring)))))
    (eshell/cd (if regexp
                   (eshell-find-previous-directory regexp)
                 (completing-read "Directory: " dirs nil t)))))

(defun kittymacs-eshell-clear ()
  "Clear the Eshell buffer."
  (interactive)
  (let ((inhibit-read-only t))
    (erase-buffer)
    (eshell-send-input)))

(defun kittymacs-eshell-project ()
  "Open an Eshell for the current project, or for this directory."
  (interactive)
  (require 'eshell)
  (let* ((root (if-let* ((project (project-current))) (project-root project) default-directory))
         (name (file-name-nondirectory (directory-file-name root)))
         (eshell-buffer-name (format "*eshell: %s*" name))
         (default-directory root))
    (eshell)))

(defun kittymacs--eshell-setup ()

  (setq-local imenu-generic-expression '(("Prompt" "^λ \\(.*\\)" 1)))
  (hl-line-mode -1)
  (visual-line-mode 1))
(add-hook 'eshell-mode-hook #'kittymacs--eshell-setup)

(use-package eshell-syntax-highlighting

* Meow in shells :meow:
:PROPERTIES:
:ID: 992e0cae-874f-4e0c-b84d-ae85ae647c87
:END:

- Eshell, =M-x shell= and =term= start in Insert state: the keys belong to the prompt, and =SPC= types a space.
- =ESC= enters Normal state, for the selection grammar on the output.
  + The leader is available there; in Eshell, =SPC m= offers its own menu.
- =C-c C-SPC= reaches the leader without leaving Insert.

| Key      | In Eshell's =SPC m=               |
|----------+-----------------------------------|
| =c=      | clear the buffer                  |
| =h=      | history, with Consult             |
| =d=      | another directory (=consult-dir=) |
| =p=, =n= | previous, next prompt             |
| =i=      | back to Insert                    |
| =?=      | the Casual menu for Eshell        |

#+begin_src emacs-lisp
(with-eval-after-load 'meow
  (dolist (entry '((eshell-mode . insert) (shell-mode . insert) (term-mode . insert)))
    (add-to-list 'meow-mode-state-list entry)))

(kittymacs-define-localleader 'eshell-mode
  "c" (cons "clear" #'kittymacs-eshell-clear)
  "h" (cons "history" #'consult-history)
  "d" (cons "directory" #'consult-dir)
  "p" (cons "previous prompt" #'eshell-previous-prompt)
  "n" (cons "next prompt" #'eshell-next-prompt)
  "i" (cons "insert" #'meow-insert)
  "?" (cons "menu" #'casual-eshell-tmenu))

(provide 'kittymacs-shell)

* Check

- =SPC o s= opens an Eshell for this project; =SPC o e= opens a real terminal.
- =M-x eshell=, type =ff init.el=: the file opens. =z=, then pick a directory.
- Type =htop= in Eshell: it opens in a terminal buffer and works.
- =ESC= in Eshell, select some output with =x=, =y= copies it; =i= goes back to typing.
- =M-x shell=, then =git log=: the output lands in the buffer, with no pager waiting for keys.
- In a project with a =.envrc=, open a file: the mode line shows =envrc= as waiting; =SPC p E a= allows it, and =M-: (executable-find "python3")= then names the project's Python, not the system's.
- =just test-packages= replays a real startup: this module must load and every =SPC= key must run a command.
