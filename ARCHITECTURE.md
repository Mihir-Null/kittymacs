# kittymacs — architecture and decisions

The single source of truth for the design: what the configuration is, how it is put together, and why. It describes the design as it is now; how it got here is in the Git history. The learner-facing explanation lives in [`literate/index.org`](literate/index.org); this file is for whoever changes the design.

## 1. Intent (the user's words)

kittymacs is a user-friendly, batteries-included, opinionated and extensible Emacs configuration for one person, built on a small sane starter kit (Lambda-Emacs, Colin McLear's config) plus liked packages. It is Meow-first: selection → extension → action, with visual hints. It prefers spawning frames over windows so the desktop window manager manages them. Its main thrust is to be for Meow what Doom/evil-collection are for Evil: retire the Meow keypad, replace on-screen hints and internal keymaps with real literal maps, and integrate the initial package set with the Meow grammar in a clean, extensible way. It must stay learner-friendly: discoverable actions, visual hints, simple to modify and extend, with a heavily explanatory, tutorialised, wiki-style literate config.

## 2. Shape

```
early-init.el, init.el   generated from literate/10-startup.org
literate/*.org           the chapters (NN-name.org), the reading guide and the conventions; the source of truth
lisp/kittymacs-*.el      one generated module per chapter; keybindings.org (cheat sheet); themes/; private.el
tests/                   kittymacs-tangle-tests, kittymacs-doc-tests, kittymacs-platform-tests, kittymacs-treesit-tests, kittymacs-org-table-tests (no packages);
                         kittymacs-leader-tests, kittymacs-org-roam-tests, kittymacs-theme-tests, verify-config (installed packages);
                         kittymacs-frames-tests (graphical session, by hand)
tools/tangle.el          finds the chapters, validates their targets, tangles and copies the outputs
flake.nix, nix/          generated from literate/90-nix.org: system and home-manager modules, tool list, selection options, packages, apps, checks, templates, dev shell, example hosts
justfile                 the recipes: tangle, check, test, lint, eval, update
var/                     packages, caches, custom.el; ignored
```

Startup is a flat list of `require`s in `init.el`, ordered by dependency; from the UI on, each goes through `kittymacs-require-module`, so an error while one chapter loads (typically a package that failed to install, whose variables then do not exist) is a warning naming it and the later chapters still load, while `--debug-init` still gets the backtrace. The order is: defaults → platform → `private.el` → UI → literate commands → dashboard → completion → help → Dired → Treemacs → VC → navigation → Meow → keys → shells → programming → Tree-sitter → languages → terminal → Org → Org extras → Org-roam → reading → agents → suggestions → EXWM → frames → `custom.el`. There are no staged hooks; the little that must wait until `init.el` has finished (restoring `*scratch*`, turning Tabspaces on) adds itself to `after-init-hook`. The leader module is not in the list: the modules that define localleaders require it.

## 3. The Meow layer

**Leader.** `SPC` is bound to `kittymacs-leader-map`, an ordinary keymap, in Meow's Normal and Motion state maps through Meow's own `meow-normal-define-key` / `meow-motion-define-key`. Because it is a real keymap, `C-h k`, `C-h b`, `where-is`, which-key and Marginalia see the physical keys with no adapter. `C-c C-SPC` opens the same map from Insert state and non-Meow buffers. `meow-keypad` is not bound; `kittymacs-keypad-key` binds it under the leader when set. (`literate/41-leader.org`)

**Localleader.** Meow has no per-mode state maps, so `SPC m` uses one buffer-local entry in `emulation-mode-map-alists`, keyed on `meow-normal-mode` / `meow-motion-mode`, whose map is composed along `derived-mode-all-parents` (most specific first). A `prog-mode` menu is inherited by every language; `emacs-lisp-mode` overrides the keys it redefines. `kittymacs-define-localleader` is one form per mode. The leader map must leave `m` unbound. (`literate/41-leader.org`)

**Integrations.** Each package chapter states which Meow state its buffers start in (`meow-mode-state-list`) and defines its localleader with labelled entries, evil-collection style but literate. Application buffers (Dired, Magit, Help, Info, the agenda, the dashboard) start in Motion so their own keys keep working; shells and commit messages start in Insert.

**Keys.** A key belongs to the module that owns its feature, so a feature that is off has no keys. `literate/41-leader.org` defines the labelled groups, empty, because every group must exist before any chapter binds into it: buffers, files, search, projects, VC, windows/frames, workspaces, code, eval, language server, diagnostics, insert, notes, agent, open, toggle, config, help, quit and a reserved user group. Each module requires the leader and binds its own keys with `keymap-set`, at the top level, never in a `:config` that waits for a package: the Consult keys in the completion chapter, `SPC v` in the VC chapter, `SPC n` in the Org-roam chapter, and the Cape map as a nested group from the completion chapter. `literate/42-keys.org` binds what no feature owns, which is Emacs's own commands and commands of modules that always load, and keeps a table of each group for reading. `SPC p` is `kittymacs-project-map`, whose `:parent` is Emacs's `project-prefix-map`: the `C-x p` commands work under `SPC p` and the map adds a few, while `C-x p` stays exactly Emacs's own menu. Three keys are overridden: `SPC p p` opens the project in a tabspaces workspace (`C-x p p` is plain `project-switch-project`), `SPC p b` is `consult-project-buffer` instead of `project-switch-to-buffer`, and `SPC p G` is `magit-project-status`, so `project-or-external-find-regexp` is only on `C-x p G`. `SPC p E` is envrc's group (allow, deny, reload, log); capital because `SPC p e` is the inherited `project-eshell`. `lisp/keybindings.org` is the learner cheat sheet; the startup verifier checks every `SPC` row in it against the live map.

## 4. Decisions

User decisions:

1. Extract the vendored Lambda tree fully into our own literate chapters rather than trim it.
2. Literal `SPC` leader; the keypad bound to nothing by default, with `kittymacs-keypad-key` as the opt-in.
3. This file is the only decision record; there is no ADR folder, validator, inventory, progress ledger or catalogue.
4. `early-init.el` and `init.el` are our own short files, tangled from a chapter.
5. There is no GUI test runner; `tests/kittymacs-frames-tests.el` is run by hand in a graphical Emacs.
6. First integrations: Magit, Dired, Org, the terminal and Eshell, Vertico/Consult/Embark, Help and Info.
7. One `private.el` for machine settings, not a second, late file.
8. The personal configuration is an overlay package, not a fork (see below).
9. Emacs 31.1 is the oldest supported Emacs: its Tree-sitter modes map their file types, pin their grammars and offer to build them, so kittymacs builds on that instead of keeping its own tables (see Tree-sitter below). `init.el` stops on an older Emacs with a message naming the version.

Design decisions, with the reason:

### Structure and startup

- **No registry, no transactions.** `with-eval-after-load`, hooks and `derived-mode-p` are the lazy-readiness and specificity mechanisms Emacs already has. The prototype's descriptor validation, readiness states and reentrancy guards solved problems the native design does not have.
- **Tangle with tracked outputs.** Startup never tangles, a clone works without a build step, and `tools/tangle.el` stays proportionate. Nix sees only tracked files, so the generated `.nix` is tracked for the same reason.
- **Everything generated comes from a chapter, the Nix layer included.** `flake.nix` and `nix/` are tangled from `literate/90-nix.org`, so the modules are explained where they are written, as the Lisp is. Their comments are only what a user copying an example needs; the reasons live in the chapter.
- **The justfile is the one interface to the loop.** Every check a contributor runs, and every CI step, is a recipe, so CI and a laptop run the same commands. The Emacs recipes need only Emacs (Windows included, through Git for Windows' `sh`); the Nix recipes need Nix, and `nix develop` provides both with the linters.
- **The chapters follow one page grammar.** Every page has an ID, a title and one kind tag from a closed vocabulary; chapters link by `id:`, end with a Check, and the checkout is an Org-roam project graph through `.dir-locals.el`. `literate/conventions.org` states the rules; `tests/kittymacs-doc-tests.el` enforces the mechanical half. `README.md` stays outside that grammar: it is GitHub's front page for newcomers, in Markdown, organised by task (install per platform, configure, update, troubleshoot) in the manner of Doom's and Lambda-Emacs's READMEs, and it links to chapters by path.
- **The chapter list is derived from file names.** Every `literate/NN-name.org` is a chapter and its `:tangle` headers name its outputs, so adding a chapter needs no second place to register it. The builder keeps its safety rules: an Emacs Lisp target must be `early-init.el`, `init.el` or a file in `lisp/` other than `private.el`, a Nix target `flake.nix` or a file in `nix/` at most one directory deep, and a block's language must match its target's; no two chapters may write one file; all targets are read before anything is written; and a `lisp/kittymacs-*.el` or `nix/**.nix` that no chapter produces is an error, because startup would go on loading a module, or the flake importing a file, whose source is gone.
- **`early-init.el` uses `setq`.** Everywhere else options are set with `setopt`, but in `early-init.el` it would load Customize and, for the package options, `package.el` with url and EIEIO, tens of milliseconds before the first frame. The file also calls `(menu-bar-mode -1)` next to the frame parameter that hides the menu bar, so the mode agrees with what is on screen and the first `SPC t m` shows the bar.
- **Options are set with `setopt`, so values must satisfy the option's type.** A value the `:type` rejects raises a warning, on every start or, for an option whose library has not loaded, when it loads (Org 9.7 spells "open unfolded" as `nofold`, and wants `org-agenda-start-with-log-mode` to be a list). When a warning names an option, read its `:type`. Only values that differ from Emacs's defaults are set; restating a default hides which choices are ours.
- **The `kittymacs` option group is defined in the defaults module**, the first that loads, and every chapter's group hangs from it.
- **Global modes are switched on one way.** A built-in mode is turned on with `(mode 1)` at top level; a package's global mode in the `:config` of its `use-package`, with `:demand t` when `:bind` or `:hook` would otherwise defer loading. No startup hook turns a mode on, with two exceptions: `tabspaces-mode` reads `tabspaces-use-filtered-buffers-as-default`, `tabspaces-session`, `tabspaces-session-auto-restore` and `tabspaces-echo-area-enable` once, as it turns on, and none of them has a `:set`, so it is turned on from `after-init-hook` at depth 95, after `custom.el` and the `private.el` function at depth 90; `envrc-global-mode` must be enabled after every other mode, as its README asks, so it turns on at depth 90.
- **Helpers are top-level functions.** Functions that a hook runs are defined at top level, not inside `:config`, and have the private `kittymacs--` prefix. Functions that are the value of an option (`kittymacs-eshell-prompt`, `kittymacs-magit-display-buffer`, `kittymacs-guess-major-mode` and the like) keep public names, since a user may name them in `private.el`.
- **Built-in commands over wrappers.** Where Emacs or a package already has the command, the key runs it: `dired-up-directory`, `org-insert-structure-template`, `eglot`, `magit-project-status`. Buffer switching skips Emacs's own buffers through `switch-to-prev-buffer-skip-regexp` rather than helper functions, and the dashboard's buttons all go through one `kittymacs--dashboard-run`.
- **Customize and `private.el` get the last word.** `init.el` loads `private.el` early, right after the platform chapter, because chapters read `kittymacs-*` options while they load, and it loads `custom-file` on its last line, so Customize overrides every chapter. A package option that a chapter also sets cannot be set at the top of `private.el`: the chapter runs later and replaces it. It goes in an `after-init-hook` function at depth 90, which runs once `init.el` has finished, and inside it in `with-eval-after-load` when the chapter sets the option only as the package loads. A top-level `with-eval-after-load` in `private.el` would not do: after-load forms run in the order they were registered, so it would run before the chapter's. The verifier replays a real startup and checks that both kinds of override survive.
- **The personal configuration is an overlay package.** Features that are one person's rather than the configuration's (the justfile recipe runner with its just-mode declaration, running a host's recipes in NixOS on WSL on Windows, and an `M-x` that offers only the commands that apply to the current buffer) live in a separate package, `kittymacs-personal`, which `private.el` loads from `after-init-hook`. It binds its key in the public `kittymacs-project-map` (`kittymacs-leader-map` is public for the same use) and never edits this repository, so the shared configuration can change without a merge. Personal machine settings, packages, caches and notes stay out of the public repository.
- **UI loads first.** Theme and fonts before the first frame is drawn, with one theme at startup. Theme-dependent faces hang on Emacs 29's `enable-theme-functions`.
- **The look does not need doom.** `kittymacs-ui` loads the theme by itself rather than from doom-themes' `:config`, and nothing but the `use-package` forms of doom-themes and doom-modeline, and code behind `featurep`, names either package. So a gate on those two forms is enough, and the built-in Modus themes are the default. A `doom-` theme needs its package, the tracked Sonokai port too, so without doom-themes `kittymacs-theme` falls back to `modus-vivendi` and `kittymacs-light-theme` to `modus-operandi`; the check is `featurep`, not `locate-library`, so a machine that still has the package installed but the feature off gets what it asked for. `tests/kittymacs-theme-tests.el` runs the module without the two forms and without their packages activated, and the lint suite holds the rest. (`literate/50-appearance.org`)
- **Org loads on first use.** Startup sets Org's options and loads nothing of Org, which the verifier checks before it does anything else. Startup sets the values, rather than a `with-eval-after-load`, because Customize's file and `private.el`'s `after-init-hook` functions run after the chapters and must win; a form waiting for Org would run after them and undo them. `setopt` on an unloaded option only sets it, and Emacs checks the type when the library loads, unless Customize's index (`cus-load`) lists a library for that name, in which case `setopt` loads it: `org-agenda-time-grid` is also a group's name and `org-agenda-custom-commands` has an autoload, so those two use `setq`, and a lint test keeps others out. Interpreted modules run `eval-when-compile` as they load, so a module cannot `(eval-when-compile (require 'org))` either; it declares what it uses. (`literate/70-org.org`)
- **Org-roam loads with Org, not at startup.** It loads Org as it loads, so `use-package org-roam` has `:after org` with `:demand t`, which runs at the end of Org's own load: every Org buffer finds Org-roam's hooks and its `id:` lookup in place, and a session without Org pays for neither. `SPC n` commands load it themselves. (`literate/71-org-roam.org`)
- **Org, its extras, Org-roam and reading stand apart.** `kittymacs-org` declares no package; `kittymacs-org-extras` holds the catalogue's `org-extras` packages and leans on it, and neither Org-roam nor reading needs the others. `kittymacs-org-agenda-refresh` stays in `kittymacs-org`, because `SPC m g` must work in any agenda, and it only asks whether the buffer is an Org QL list. Reading's notes folder is Org-roam's directory when that variable exists and the Org directory otherwise, so nothing changes while Org-roam is on. The lint suite reads the four modules and fails on a name, package or module of another used without `bound-and-true-p`, `fboundp` or `with-eval-after-load`.
- **Org table cells wrap on save, per table.** Org cannot wrap text inside a cell: `org-table-wrap-region` is a one-off edit and a width cookie with `org-table-shrink` truncates. `kittymacs-org-table-wrap` fills each cell onto continuation rows no wider than its column's `<N>` cookie, and a buffer-local `before-save-hook` runs it on every table when `kittymacs-org-table-wrap-on-save` is on (the default; `:safe`, so a file can turn it off). A table opts in with a cookie row, because the widths must come from somewhere and a plain table must never be rewritten by surprise. Hlines delimit entries: each run joins an entry's rows column by column and fills them again, which makes it idempotent and lets an edit on any continuation row re-flow the cell; a table with no hline, or with a `#+TBLFM` line whose row references would shift, is left alone. Links and `~code~`/`=verbatim=` spans are never split, and no character is dropped. The table is rewritten only when the wrapped rows differ, so saving a wrapped file does not move point or add undo. (`literate/70-org.org`)
- **Org prose is proportional, by buffer-local remapping.** The editing font, Google Sans Code, is also `fixed-pitch`, and the prose font, Google Sans Flex, is `variable-pitch`; each new frame gets both, and neither has a height of its own. `kittymacs-org-prose-mode`, on in every Org buffer, turns on `variable-pitch-mode` and remaps code, tables, metadata, `org-indent` and `org-hide` to `fixed-pitch` and the headings to semi-bold, with `face-remap-add-relative`. A remap touches one buffer (the agenda keeps its columns), sits over any theme (so `SPC t t` keeps it), and inherits its height (so `C-x C-+` scales prose and code together). `mixed-pitch` was not used: it pins its fixed faces at the editing font's absolute height, so text scaling left code behind, and it sets the cursor, which is Meow's.
- **The fonts come from the flake, on any nixpkgs a host makes it follow.** `nerd-fonts.googlesanscode` is in nixpkgs-unstable but not nixos-26.05, so `nix/tools.nix` falls back to the plain `googlesans-code`, which the font resolver also accepts (icons come from Symbols Nerd Font Mono either way); an unconditional attribute broke evaluation for every host following nixos-26.05, while this flake's own CI, on unstable, stayed green. Google Sans Flex is not yet in nixpkgs' `google-fonts`, so `nix/tools.nix` fetches its one file from a pinned commit of Google's font repository, to be replaced by `google-fonts.override` once nixpkgs catches up. Without them the configuration falls back to the platform's fonts.
- **Packages declared where used** with `:ensure t`. One Corfu formatter, `nerd-icons-corfu`.
- **The archive index is refreshed only when something must be installed.** `kittymacs-ensure-package` is `use-package-ensure-function`; it owns the refresh policy and hands the install itself to `use-package-ensure-elpa`. MELPA keeps only each package's latest build, so a cached index a few weeks old names tarballs that answer 404, and `use-package-ensure-elpa` refreshes only when a package is missing from the index, not when the version it names is gone. `init.el` no longer refreshes an empty index up front: with Nix supplying the packages, a start that installs nothing touches no network.
- **A machine may start from a quickstart file, and nothing changes until it writes one.** `kittymacs-activate-packages` loads Emacs's own `package-quickstart-refresh` output when a current one exists for this Emacs and these package directories, and otherwise calls `package-initialize`. `just bench` on one Linux machine, in a terminal, with the `full` profile and no host files, median of 20 in each of two runs per side: first idle falls from 0.965 s to 0.79 s, and CPU up to settling from 0.915 s to 0.74 s. The first `.org` opens 0.03 s slower, because the scan's allocation brought a garbage collection forward into startup and that collection now lands there, so the saving through the first Org file is 0.15 s. Having the file is the opt-in because packages activate before host files and `private.el`, too early for an option to decide. `package-activate-all` runs only on that path: with no file it would leave `package--initialized` nil, the archive index unread and `finder-inf` unloaded, so `package-installed-p` would answer from another branch, and a machine that has not asked must see no change. A hash of `emacs-version` and the true names of `package-user-dir` and `package-directory-list` names the file, so one written for anything else is never loaded, and true names because a Nix profile keeps its path while its contents move. A file older than any package directory counts as stale, which catches every install and removal whoever made it, and needs no hook in the code path that made it. Once a machine has a file of any name, a hook after init writes the right one when this start could not load it, and sets `package-quickstart` so that Emacs refreshes it after each later change, including a `:vc` upgrade, which leaves the directory's time alone. The hook waits for the end of init because Emacs's refresh calls `package-initialize`, which warns when called twice during init.
- **Hook functions get the same guard as chapters.** `kittymacs-require-module` catches errors while a chapter loads, but a function the chapter puts on `after-init-hook` runs after that guard has returned, and an uncaught error there aborts startup; under `--fg-daemon` the server exits, and systemd restarts it into the same error. Such functions are added with `kittymacs-after-init`, which skips an undefined function and turns an error into a warning. Both after-init modes (Tabspaces, envrc) use it.
- **The platform module may not declare a package.** `tests/kittymacs-platform-tests.el` loads it with no packages available, so `use-package … :ensure t` there would try to install at test time. Spell-checker discovery lives in the platform chapter because it is a property of the machine; its two front ends (`flyspell-correct`, `consult-flyspell`) are declared in the completion chapter.
- **Never add to a hook that the package later aliases.** `defvaralias` discards the value of the variable it turns into an alias. Magit's `git-commit.el` makes `git-commit-mode-hook` an alias of `git-commit-setup-hook` when it loads, so a function added to the old name before that (as `:hook (git-commit-mode . flyspell-mode)` on a deferred Magit did) silently never runs, and the warning `defvaralias` prints raised a `*Warnings*` frame over the first Magit window. Functions for such a hook are added to its final name inside `with-eval-after-load` of the file that defines it.
- **The default `major-mode` must be a symbol.** Every buffer made by `get-buffer-create` carries it, and `get`, `symbol-name` and `derived-mode-parent` all assume a mode name; `kittymacs-guess-major-mode` is a named function for that reason.
- **Licence is GPL-3.0-or-later**, matching the sources the code is distilled from.

- **Responsiveness outranks ambient polish.** Emacs does Lisp and redisplay on one thread, and on a managed Mac long stalls ended in Force Quit. So work that scales with open buffers or runs per save is off or event-driven: auto-revert relies on notifications (`auto-revert-avoid-polling`, interval 5 s), the `diff-hl` gutter updates on save rather than through flydiff, Magit's status does not refresh on save, undo keeps about 16 MB per buffer, and agent output stays collapsed and unhighlighted. `envrc-async` is 1 second, so each buffer opened during a Nix evaluation waits at most about that long while the evaluation carries on in the background; opening many such buffers adds up, and a mode hook that outruns direnv sees the global environment until `SPC p E r`.

### Keys and Meow

- **Buffer-local emulation entry over a `menu-item :filter`.** Both work; only the emulation entry is visible to `where-is`, which Marginalia uses for M-x annotations.
- **Motion state for Magit and Dired.** In Normal state Meow's grammar shadows Magit's `s`, `u`, `c`; Motion keeps the package's keys and adds only `j`/`k` and the leader.
- **Meow colours its own expansion hints.** `meow-use-dynamic-face-color` is at its default: Meow derives the hint backgrounds from the cursor and region colours of the active theme and recomputes them through its `enable-theme` advice. doom-themes and the Sonokai port style none of Meow's faces, so turning it off left the numbered hints as plain text.
- **The home page is the first landing page.** It carries the kittymacs `:3` banner, buttons for every place the README sends a new user (cheat sheet, reading guide, keys chapter, Meow tutor) and a six-key guide at the bottom, so a fresh install explains itself before anything is opened.

### Frames

- **Frames mean full buffers, not panels.** The frames preference covers buffers you read or edit; sidebars, menus, gutters and the minibuffer stay inside each frame. Treemacs is a side window and `diff-hl` is the git gutter (both under `SPC t`). `frames-only-mode` remaps the split commands, so every key bound to them, `SPC w h`/`SPC w v` included, makes a frame while the mode is on.
- **A reading session splits its frame.** org-noter shows the PDF and its notes side by side in one frame, because reading needs both in view and in step. `org-noter-always-create-frame` is `reuse-if-free`, so a session takes the frame it was started from (a new frame only when that one already hosts a session) instead of opening a maximised frame a tiling window manager has to undo; org-noter splits with `split-window-right`, which frames-only mode's key remaps do not touch. (`literate/75-reading.org`)
- **Diagnostics stay inside the frame.** `*Warnings*`, `*Backtrace*` and the compilation logs are things Emacs says, not buffers you work in, so `display-buffer-alist` gives them a window at the bottom of the current frame. Without it any warning, from any package, becomes a focus-stealing OS window.
- **WSLg frames are undecorated.** Under WSLg (recognised by `/mnt/wslg`, since a systemd-started daemon may lack `WSL_DISTRO_NAME`) `default-frame-alist` gets `(undecorated . t)` in `early-init.el`. WSLg's compositor otherwise draws its own title bar and border inside the Windows window, a second frame inside the one Windows already shows; moving and resizing happen on the Windows side, by a tiling window manager or the keyboard.
- **Frames resize by the pixel.** `frame-resize-pixelwise` is set in `early-init.el`, before the first frame. Without it Emacs rounds every size it is given down to whole character cells, so a frame that a tiling window manager places (komorebi, LeopardWM, a Wayland compositor, WSLg's RAIL windows) stops a few pixels short of its tile, and a manager that checks the result asks again.
- **`magit-status` asks in a better order.** From a buffer with no file, `default-directory` is wherever the buffer was born, and `magit-status` there offers to create a repository. `kittymacs-magit-status` tries this buffer's repository, then the current project's, and only then Magit's own prompt. The display function ends with `display-buffer-use-some-window`, because Magit selects whatever window it is handed and a `nil` there is an error.

### The window manager

- **Emacs is the X window manager only when the session asks.** EXWM turns on when `KITTYMACS_EXWM=1` is set and the first frame is on X, so the daemon, WSLg and the Mac never load it; the session that sets the variable is the host's business, a remote desktop for one. It loads just before the frames chapter, which reads `kittymacs-exwm`. (`literate/44-exwm.org`)
- **The keys are LeopardWM's, kept as data.** `kittymacs-wm-keys` maps a key to an action named as LeopardWM names it, on Hyper, with the same grammar (the key acts on the focus, Shift moves it); `kittymacs-exwm-actions` maps the action to an EXWM or Emacs command. A Wayland compositor such as EWM can bind the same table with its own actions. What only a scrolling-column tiler can do (centre, consume, expel, the strip's ends) stays unbound, listed with why; the monitor keys wait for a session with more than one screen.
- **EXWM follows the screen's size.** A remote desktop's screen changes size with the client's window (an RDP display update, then RandR), and EXWM sizes its workspaces only at start; `exwm-randr-mode` refits them on every RandR change. With one screen it needs no monitor list.
- **Frames-only mode is off under EXWM.** There is no outside window manager to hand frames to: an EXWM frame is a workspace, so the policy's default is off there as on Android, and Emacs's own windows are what the keys arrange.
- **The session's Emacs takes over the daemon's server.** The session stops the daemon (saving its buffers) before Emacs starts, the defaults chapter's "start a server if none runs" starts one in the session's Emacs, and `emacsclient`, over SSH too, reaches one Emacs with one set of buffers; the session starts the daemon again when it ends. A daemon cannot be the window manager, because it has no X frame while `init.el` runs.

### Platforms

- **Each operating system is a section of the platform chapter, not a module.** A platform is a set of answers to *where does this machine keep things*. Because `system-type` is a plain variable, `tests/kittymacs-platform-tests.el` binds it per test and exercises every operating system's branch on any machine without packages.
- **macOS.** Lambda's macOS choices were kept where they fit a frames-first Meow configuration: Option is Meta and Command is Super with the right Option left to macOS (one `kittymacs-macos-modifiers` option), non-native full screen, a UTF-8 `LANG` when the Dock supplied none, the Trash through the `trash` tool or `~/.Trash`, Keychain in `auth-sources`, `⌘⇧Z` redo, `⌘Q` that closes a frame while others remain, `C-⌘-f` full screen, and a title bar that follows the theme. Fn is not Hyper, because that turns Fn-arrow paging into Hyper chords; `kittymacs-reveal-in-file-manager` on `SPC f o` covers Finder, Explorer and xdg-open instead of three packages.
- **A Dock-launched Emacs.app sees no shell `PATH`**, so `early-init.el` puts the Nix profiles and Homebrew on `exec-path` on macOS before the GNU ELPA signature check. `exec-path-from-shell` then imports the login shell's environment; its whole policy is the `:if` in the shells chapter, which leaves it out on Windows and Android. **The import replaces `exec-path` whole, so the directories `early-init.el` found go back afterwards:** it records them in `kittymacs-launcher-path`, and any the login shell's `PATH` lacks are appended to `exec-path` and `PATH`. Determinate's Nix sets `PATH` only for interactive shells and the import runs a non-interactive login shell, so without this every program in `~/.nix-profile` vanished at once: pdf-tools then offered to build its own `epdfinfo`, and `claude-agent-acp` and Copilot's server went missing. Dired uses GNU `ls` as `gls` when coreutils is installed, since BSD `ls` has no `--group-directories-first`.
- **GNU ELPA needs a native gpg.** Emacs verifies the signed GNU ELPA index with the first `gpg` on `exec-path`. On Windows that is Git for Windows' MSYS `gpg`, which cannot open a Windows keyring directory, so every signature fails as "no public key" and the archive silently disappears. `early-init.el` puts Gpg4win's directory first on `exec-path` when it is installed, and leaves `PATH` alone, so subprocesses see no change; on Windows without it, or anywhere without `gpg`, it skips the check.
- **Git for Windows' Unix tools go last on `exec-path`.** Magit's hunk refinement, Ediff and diff-hl call `diff`, `diff3` and `patch` by name, and Windows has none. The platform policy appends Git's `usr/bin` (or MSYS2's) after every other entry, so native programs keep winning, and leaves `PATH` alone.
- **Spelling is decided per buffer, and Ispell is told its dictionary first.** The Flyspell hooks are always added and ask for a checker when a buffer opens, so a checker that `private.el` or `exec-path-from-shell` makes visible later is still found. `DICTIONARY` is set before `ispell-program-name`, whose setter asks Hunspell for its dictionaries; a checker that fails is reported once and Ispell stays loaded. Emacs's text-mode dictionary completion is off: with `corfu-auto` it would start a process a few times per word, and `SPC c p w` (`cape-dict`) is the explicit version.
- **Android is a platform branch, not a port.** The Android build reports `system-type` as `android`. The shell prefers Termux's `bash`, then Termux's `sh`, then `/system/bin/sh`. Termux is discovered, never assumed, because Android lets one application read another's files only when they share a user ID; `LD_LIBRARY_PATH` is cleared rather than set. The volume keys stay the port's way to quit (`kittymacs-android-volume-keys` hands them back). Text conversion follows Meow's state through `set-text-conversion-style`, since input methods edit the buffer directly, which is right only in Insert. Dired lists with `ls-lisp`, and `kittymacs-frames-only` defaults to off, because an Android frame is an entry in the task switcher.
- **The terminal does not follow to Android, and Eshell stands in.** ghostel is a native module, and the port is commonly built without dynamic module support (upstream's `aarch64-android` module is built for Termux's Emacs), so `kittymacs-terminal-ghostel` is off there, ghostel is not installed, and `SPC o e` opens Eshell.
- **A Linux virtual machine is a Tramp host, not a platform.** Android's Terminal app runs a Debian virtual machine with its own kernel. Inside it `system-type` is `gnu/linux` and the Linux branch already applies, so it needs no branch of its own. From the Android port it is a remote machine: the port runs Termux's `ssh` and opens the machine's files through Tramp, which then runs Eglot's server, `git`, `rg` and Eshell's commands there. `tramp-remote-path` begins with `tramp-own-remote-path`, so a remote program is found on the login shell's `PATH` (a Nix profile included); this helps every SSH host, not only the telephone. The setup is documentation, not code: the host name, port and user are the user's, and the SSH configuration carries the connection sharing that `tramp-use-ssh-controlmaster-options` leaves off.
- **The paired Termux is a local backend, not a Tramp host.** A paired Termux shares the port's user ID, so the port already runs its programs as local processes on local files; going through `sshd` would add a connection, a shell round trip per file operation and a second view of the same files, for nothing. An unpaired Termux cannot be reached over Tramp either, because the port cannot run the `ssh` client without the pairing. So Tramp is used only where there is a real boundary to cross: a virtual machine, or another computer.

### Remote

- **A remote machine must not stall Emacs, and that is enforced by a test with a hung connection.** Emacs has one thread, and a Tramp call on a dead connection waits with no timeout. `literate/36-remote.org` holds the Tramp settings, the backends and the guards, and it is core. `tests/kittymacs-remote-tests.el` runs real starts against Tramp methods defined in `tests/kittymacs-remote-fixture.el`, based on the `mock` method in Emacs's own `tramp-tests.el`: `khang` is a login that never answers, and `kmock` is a working connection whose shell the test can stop with SIGSTOP, which leaves the process running and silent, as an ssh on a dead network is.
- **Tramp stays unloaded until a remote name appears.** `setopt` of a `tramp-` option does not load it, because Customize's index ties no such name to a library, and everything else waits in `with-eval-after-load`. `kittymacs-check-start` fails a start that loads it, under every selection.
- **A backend is a named machine, and its transport is a key the code dispatches on.** `kittymacs-backends` holds transport, host and root; `kittymacs-remote-transports` maps a transport to the function that names a directory there, and any method Tramp already offers needs no row. A later transport is one row. The keys are `SPC o b` and `SPC o B`, in the remote module because a key belongs to the module that owns its feature, and lint holds them there.
- **Guards are on behaviour, not on being remote.** Each stops something that reaches the machine with nobody asking; a command you run still reaches it, so Magit, Eglot, `compile` and agent-shell work on a working connection. Corfu's automatic popup keeps to a list of sources known not to read files, rather than excluding the known bad ones, because a source nobody has read must not get to stall Emacs. A guard costs a local buffer one `file-remote-p`, measured at about 1.4 microseconds.
- **Remote buffers give up automatic saving, on purpose.** `remote-file-name-inhibit-auto-save-visited` stops the idle write. `remote-file-name-inhibit-auto-save` stops the auto-save file too, which is the expensive choice: the file is local, but before writing it Emacs asks the visited file's modes, from C, on an idle timer, and no advice can reach that. A crash loses what was typed in a remote buffer since its last save. A timeout is no alternative for a write.
- **Known projects are pruned lazily, and only the local ones.** `project-forget-zombie-projects` at load logged in to every remote project, so a machine that did not answer stalled the start for `tramp-connection-timeout`. `project-prune-zombie-projects` with `list-first-read` uses `project.el`'s own predicate instead, and no longer scans at load at all.
- **A wait during startup also eats memory, so nothing during startup may wait on a connection.** `early-init.el` held the garbage collector off until the start ended, and Tramp's wait is a busy loop that allocates. Measured on that code with a login that never answers: 200 MB a second until the kernel's OOM killer ended Emacs at 6.4 GB, and flat at 140 MB with the collector on. So the test's child runs under `ulimit -v`.
- **The threshold during a start is 128 MB, not unlimited.** Without a limit, any start that hangs runs the machine out of memory. Measured with `tools/bench.el`'s functions, 5 rounds in a rotated order, through first idle and opening one `.el` and one `.org` file, against no limit, under `full` and `minimal`, in a terminal and a frame: a normal start collects as often as before, and the paired difference stays within 10 ms, inside the spread of the runs. A start that allocates in a loop now stays under 180 MB, where it grew by about 160 MB a second without the limit, so the memory limit in the remote tests is a second line of defence.
- **`~/` in `tramp-remote-path` needs help.** Tramp's existence check quotes each name, so no shell expands `~`, and the entry is dropped as missing despite what its manual implies. `kittymacs--remote-expand-home` expands it around `tramp-get-remote-path`.
- **Direct asynchronous processes are per backend.** They are quicker and cannot ask for a password, and Tramp's connection sharing is off here, so an arbitrary `/ssh:` file keeps Tramp's own start, and a backend, which someone set up, gets the direct one where Tramp's method table allows it.
- **What is not guarded, and why.** A command you run waits: a save, `SPC F s`, a file open. So does the first edit after a save, since `tramp-handle-lock-file` compares the file's modification time, and removing that would lose the check for a file changed underneath you. `C-g` ends each of them.

### Terminal, tree and tools

- **ghostel is the terminal.** It is a thin Emacs layer over `libghostty-vt`, so a program in it cannot tell it from a terminal window (Kitty keyboard and graphics protocols, OSC 8 and OSC 7, synchronised output, true colour, automatic shell integration). It uses ConPTY directly on Windows, so no POSIX helper is needed. It has its own chapter (`34-terminal.org`); the MSYS2 root and spell-checker discovery are platform questions and live in `30-platform.org`. The native module lives in `var/ghostel/`, not the package directory, so `package-upgrade` cannot delete a library this Emacs has mapped, and it is downloaded on the first `SPC o e`, never at startup.
- **The terminal comes from MELPA.** `ghostel` and `consult-ghostel` are ordinary `:ensure t` packages, as upstream's README installs them, so no `git` is needed at first start and package-vc's spec handling plays no part. Both `use-package` forms sit inside `(when kittymacs-terminal-ghostel ...)`, because `:ensure` installs a package even when its `:if` is nil. package.el counts a Git checkout left by an earlier `:vc` install as installed and keeps it; deleting it (`consult-ghostel` first) and restarting installs MELPA's, and the verifier names a checkout it finds.
- **Meow's states drive ghostel's input modes.** Terminals start in Insert, where ghostel forwards the keys and `C-c` still reaches Emacs. Leaving Insert freezes the terminal into copy mode, so the scrollback is an ordinary buffer for the selection grammar; entering Insert thaws it. `ESC` goes to the program exactly while the alternate screen is active (`kittymacs-terminal-escape`, overridable with `SPC m ESC`); this bridge is ours because there is no `meow-ghostel`.
- **Which ghostel integrations are on.** The additive ones: Eshell's visual commands, `M-x shell`'s VT parser (only when the native module is present), `ghostel:` Org links, bookmarks, desktop, input methods, `consult-ghostel` with `consult-ghostel-mode` (terminals behind `g` in `consult-buffer` and `consult-bookmark`, their titles in Marginalia, `consult-line` across soft-wrapped rows; on once ghostel and Consult have loaded, never at startup) and `ghostel-project`. `ghostel-compile-global-mode` is not, because it replaces `compilation-start` for every command built on it; `ghostel-compile` is on `SPC m t` and the global mode is one line in `private.el`.
- **envrc gives each buffer its project's environment.** A buffer under a `.envrc` gets direnv's environment as buffer-local `process-environment` and `exec-path`, so compilation, Eglot, `run-python` and Jupyter kernels see the project's programs, and two projects with two Pythons coexist. envrc rather than direnv.el, which rewrites the global environment on every buffer switch. `envrc-global-mode` turns on from `after-init-hook` at depth 90, after the other global modes, as its README asks; with no `direnv` on `exec-path` it enables itself nowhere. `direnv` is in `nix/tools.nix`; nix-direnv is shell configuration and stays with the host. It lives in the shells chapter, beside the login-shell import, because it changes every buffer's environment, not only notebooks'.
- **Treemacs is the file-tree sidebar.** It is a panel, so it uses a side window, and `treemacs-is-never-other-window` keeps "other window" from landing in it. `treemacs-project-follow-mode` shows the project you are in, `treemacs-tab-bar` scopes a tree per workspace, `treemacs-magit` notices index changes that file watching cannot, and its state goes under `var/`. Git-ignored files stay visible.
- **Tree-sitter rides on Emacs 31's own machinery.** Emacs 31's Tree-sitter modes declare their remaps (`treesit-major-mode-remap-alist`), map the file types that have no classic mode (`yaml-ts-mode-maybe` and friends) and pin their grammars to exact commits; `treesit-enabled-modes` is `t` and `treesit-auto-install-grammar` is `ask`, so kittymacs keeps no remap table and no pins for the languages Emacs ships. The exception is Markdown: Emacs 31.1 ships `markdown-ts-mode` and its pins but no autoload, file mapping or remap, so kittymacs declares those three itself (`.md` → `markdown-ts-mode-maybe`, `markdown-mode` → `markdown-ts-mode`) and its fallback is `text-mode` when `markdown-mode` is not installed; remove them once Emacs declares the mode. It pins only what Emacs does not (`nix`, for `nix-ts-mode`), and `kittymacs-treesit-register-mode` gives a package's mode the same remap and grammar offer. `kittymacs-treesit-grammar-directory` (`var/cache/tree-sitter/`) is first in `treesit-extra-load-path`, so every install lands there. Emacs leaves a Tree-sitter mode running without highlighting when its grammar is missing, so `:around` advice on `set-auto-mode-0` replaces one that made no parser, or signalled an error, with its classic mode (`fundamental-mode` when there is none) and leaves it out of `treesit-enabled-modes` for the session, so a declined grammar is asked about once per session; an oversized file falls back without disabling the mode. On Windows the Nix recipe uses MSYS2's UCRT64 GCC by absolute path.

### Org queries

- **Org QL finds, org-super-agenda groups.** `SPC s q` (`org-ql-find`) jumps to the heading a query picks and `SPC s Q` (`org-ql-search`) lists the matches grouped by file (`:auto-category`), both over the Org files here: the project's when the buffer belongs to one, every file under `org-directory` otherwise. Org QL requires org-super-agenda. Its mode is on so that an agenda command in `private.el` can group by setting `org-super-agenda-groups`; the dashboard does not group.
- **Super-agenda headers carry no keymap.** A header's `keymap` text property outranks the emulation and minor-mode maps, so the default, a copy of the agenda's map, made `j`, `k` and `SPC` agenda commands on a header line. `org-super-agenda-header-map` is nil, which leaves the property off; the verifier checks that `SPC` on a header is the leader.
- **One refresh key for both kinds of agenda buffer.** Org QL's lists are `org-agenda-mode` buffers in which `org-agenda-redo` leaves the list as it was, so `SPC m g` runs `kittymacs-org-agenda-refresh`: `org-ql-view-refresh` in an Org QL list, `org-agenda-redo` anywhere else.
- **org-super-agenda loads with the agenda.** `:after org-agenda` waits for the first agenda or query; its mode's message is off. Org QL itself loads on the first query.
- **`with-peg-rules` expands under lexical binding.** Org QL parses a plain query by `eval`ing a `with-peg-rules` form with dynamic binding (upstream issue 498). Emacs 31's `peg` makes each rule an OClosure, whose macro asserts `lexical-binding`, so every plain query signalled `(cl-assertion-failed lexical-binding)`. `:around` advice on the macro turns a dynamic expansion into `(eval '(with-peg-rules …) t)` and leaves lexical ones alone, so it goes inert once Org QL passes `t` itself. The verifier's `SPC s Q` check runs a plain query in CI.

### Linked notes

- **A graph is Org-roam's own pair of variables, set once per buffer.** `org-roam-directory` and `org-roam-db-location` are made buffer-local when the buffer's graph is decided, from `hack-local-variables-hook` for Org files, `org-roam-mode-hook` for the backlinks panel (whose major mode restarts on every refresh, so its graph is permanent-local) and `org-capture-mode-hook` for a capture. Org-roam's own code then finds the graph where it looks for it, without being wrapped. There is no graph registry, custom schema or project loader.
- **Databases live in the user cache, named by the graph's real path.** A project checkout never contains a generated file and a read-only one can be indexed. The name is a hash of the `file-truename`, so aliases share an index and worktrees do not. The personal root is resolved with `file-truename` when the module loads, so direct upstream calls share its connection. Nothing syncs at startup and upstream's autosync mode stays off, because turning it on rebuilds the index; `C-u SPC n s` rebuilds a graph from nothing after the same checks as every command.
- **A project graph is declared by the project.** A repository's `.dir-locals.el` sets `kittymacs-org-roam-project`, and the folder holding that file is the root. `kittymacs-org-roam-excluded-directories` is safe as a directory local, so a project names its own exclusions; they become `org-roam-file-exclude-regexp`, which upstream's listing already honours. The default exclusions are generic (Git's folder and cache folders).
- **Tags are part of the prompt.** Upstream showed each note's tags in the prompt until 2.2.1 and the bare title since, so a tag typed at `SPC n f` matched nothing. `org-roam-node-display-template` is `${title:*} ${tags:24}`; tags past the column are invisible, not cut off, so they still match, and links that `SPC n i` makes keep the title because they come from `org-roam-node-formatted`. The graph suite's fixture binds the template to the bare title so that its stubbed prompts can answer with a title.
- **The tag commands read the index.** `SPC n t` reads a tag, each with the number of notes carrying it, then offers only those notes; `SPC n T` writes every tag with links to its notes into an Org buffer that is given the graph, so the links resolve there. A file note is listed under its file tags and a heading note under the tags its file note lacks, so a page appears once per tag rather than once per heading.
- **The only advice is `:before-while` on `org-roam-id-find`.** It lets Org's own ID index answer when the current graph cannot be used, because Emacs has no SQLite or the root does not exist.

### Reading

- **pdf-tools for PDFs, its server from Nix.** `pdf-loader-install` registers `pdf-view-mode` and defers loading to the first PDF. `epdfinfo` comes ready-built from `nix/tools.nix`, linked out of nixpkgs' pdf-tools build, and pdf-tools finds it on `exec-path`; the Lisp still comes from MELPA. Without Nix, `M-x pdf-tools-install` builds the server. PDFs start in Motion state.
- **One notes file per paper, beside it.** `org-noter-default-notes-file-names` is nil, so org-noter offers `<paper>.org`, found in the PDF's folder or any folder above it, then in the notes folder (`org-noter-notes-search-path`, Org-roam's personal graph when that chapter has loaded, the Org directory otherwise). A paper inside a project keeps its notes in that project's Org-roam graph.
- **org-noter-pdftools ties notes to annotations.** Notes record their place as a `pdf:` link to the annotation they were made from, and activating an annotation jumps to its note; each note heading gets an Org ID, which also makes it a node of the graph. It loads only once org-noter and pdf-tools both have, because it loads `pdf-annot`, which queries `epdfinfo` as it loads. The two org-noter commands its README redefines are left alone: the maintained fork already has them. org-pdftools supplies the `pdf:` link type. It is never loaded from Org: loading it loads `pdf-annot`, which signals an error where `epdfinfo` is missing, and its README's `org-mode-hook` setup broke every Org buffer on such a machine (the verifier's `SPC s Q` caught it). Org knows only how to follow a `pdf:` link (`kittymacs-reading-follow-pdf-link` loads org-pdftools, then opens it); `org-pdftools-setup-link`, storing included, runs from `pdf-view-mode-hook`, where the server is known to work. Without a server neither package byte-compiles, so they stay as source until one is installed.
- **pdf-text reads a PDF as Org text, from Git and MuPDF.** `SPC m r` in a PDF opens a reflowed companion buffer in `pdf-text-mode`, derived from `org-mode`, kept on the same page as the PDF; it is a view rebuilt from the PDF, and notes stay in org-noter's file. The text comes from MuPDF's `mutool` (`mupdf-headless` in `nix/tools.nix`), beside poppler's `epdfinfo`, because only MuPDF reports the fonts its headings and emphasis are read from. It is not on MELPA, so it is a `:vc` install pinned to a commit and wrapped in `condition-case`, as agent-shell-attention is. Loading it touches neither pdf-tools nor `epdfinfo`, so it autoloads.
- **The reading keys in Org are added, not defined.** `SPC m N` in Org is a group added to the map the Org chapter built, since `kittymacs-define-localleader` would replace Org's whole menu.

### Notebooks

- **A notebook is a Jupytext percent script.** Notebooks are edited as `.py` files with `# %%` cells, paired with `.ipynb` by Jupytext for JupyterLab users; Emacs never edits the JSON. code-cells provides the cells (`code-cells-mode-maybe` on `python-base-mode-hook`, so only buffers with markers), `M-n`/`M-p`/`C-c C-c` in its map, and `SPC m n` in Python; a cell runs in an attached Jupyter kernel, otherwise in `run-python`. EIN was not chosen: it edits the JSON. code-cells' `.ipynb` converter runs as a major mode, before envrc applies, so `jupytext` is in `nix/tools.nix`; saving a converted `.ipynb` drops its outputs, so the chapter says to edit the paired script. (`literate/76-notebooks.org`)
- **emacs-jupyter is opt-in, because of ZeroMQ's module.** `kittymacs-notebooks-jupyter` is nil, and the package is not even installed until it is set. emacs-zmq loads its native module at load and byte-compile time and otherwise downloads one (v1.0.2 has x86_64 Linux and Windows and `arm64-apple-darwin`, which Apple Silicon's `aarch64-apple-darwin` does not match, and the Linux one does not run on NixOS) or builds one with `make`, prompting; on a first start or in CI that is unacceptable. `jupyter-use-zmq` nil was rejected: it runs kernels through a `jupyter notebook` server started with no token or password.
- **The ZeroMQ module comes from Nix and is linked beside `zmq.el`.** `nix/tools.nix` adds `kittymacs-zmq-module`, a script printing the path of the module nixpkgs builds for `(emacsPackagesFor emacs).zmq`, the Emacs the tool list was given (a `bin/` entry is what every installation route links). `:before` advice on `zmq-load`, added before `use-package jupyter` so install-time compilation sees it, links that module into zmq's package directory; loading it into the running Emacs alone is not enough, because emacs-jupyter's I/O loop and the native compiler run `zmq-load` again in `emacs -Q -batch` subprocesses, which look only there. A link to an older store path is replaced; a real file (a module downloaded or built without Nix) is never touched. Without the script, emacs-zmq's own download or build applies.
- **Kernels start fresh in the buffer's environment.** `SPC m n j` refreshes the kernelspec list before `jupyter-run-repl`, because emacs-jupyter caches kernelspecs by host and `VIRTUAL_ENV`, which Nix shells do not set; the kernel and `jupyter` itself are started from the notebook buffer, so envrc's environment applies. `SPC m n J` attaches to a running kernel (JupyterLab's) by connection file. With the option off, both commands are a `user-error` naming the setting. The REPL starts in Insert.
- **math-preview renders Markdown cells only.** `kittymacs-notebooks-preview-math` sends each `# %% [markdown]` cell (or those in the region) to `math-preview-region`, because `math-preview-all` would also read dollar signs in code strings. The Node `math-preview` program is in `nix/tools.nix`. A multi-line `$$` block in `#`-comment cells carries the `#` of each line into the TeX, so the chapter recommends Jupytext's `cell_markers = '"""'`.

### Agents

- **agent-shell over ACP, Claude Code as the agent.** agent-shell runs `claude-agent-acp` (the default command) with the subscription login (the default authentication) and skips the agent picker (`agent-shell-preferred-agent-config` is `claude-code`). The adapter inherits Emacs's environment (`:inherit-env t`), copied when agent-shell first loads, because a Dock-launched Emacs gives a subprocess only what the shells chapter imported, and a corporate proxy's variables travel the same way.
- **The agent's policy lives with the agent.** Permissions, output style, commit attribution, skills and the switch for claude.ai connectors live in `~/.claude`, so the command line and agent-shell share them. This repository holds only what is about Emacs. The two share one name, the command `claude-agent-acp`.
- **MCP servers are declared, never ambient, and by the host.** `kittymacs-agent-mcp-servers` is empty by default and feeds `agent-shell-mcp-servers` as the agents module loads, because which servers to run is a person's or a host's choice. An empty list leaves agent-shell's option alone, so setting it directly still works. A server's `headers` may be a lambda that agent-shell calls at session start. The list is global: every agent started here gets it.
- **agent-shell-attention from Git, pinned, and allowed to fail.** It is not on MELPA, so it is installed with `use-package :vc` at a fixed commit. That install is a `git clone` on first start, which can fail where archive installs succeed (one corporate Mac's first start did); `use-package` signals an error there, which stopped `init.el` and left every later chapter unloaded. The form is wrapped in `condition-case`, so a failed install is a warning naming the cause and the `git` Emacs found, and a restart retries. Its notification function is per platform: `osascript` on macOS, `notifications-notify` elsewhere, silent where there is no D-Bus.
- **Agent buffers' Meow states.** The shell starts in Insert, like the other shells; the diff of a proposed edit and the viewport's view buffer in Motion, so their own keys (`y`, `n`, `p`, `q`) work.

### Suggestions

- **Copilot through copilot.el, for ghost text and next edits.** Inline suggestions are GitHub Copilot's, through copilot.el and GitHub's own `copilot-language-server`: it is the maintained Emacs client, and the only one whose next-edit suggestions (`copilot-nes-mode`) are more than experimental. Supermaven is closed and codeium.el is quiet; minuet-ai.el speaks to any model, but its next edits are experimental and Claude would need an API key besides the subscription the agent uses. Eglot does not request `textDocument/inlineCompletion`, so a language-server route without the package does not exist. copilot.el's chat and agent mode are bound to nothing: the agent is Claude Code. (`literate/78-suggestions.org`)
- **Off by default, per buffer, never for excluded files.** A buffer with `copilot-mode` on is sent to GitHub, so `kittymacs-suggestions` is nil and `SPC t a` turns suggestions on in one buffer. With the option on, a programming buffer that visits a file starts with them, read as each buffer opens so Customize and a late `setopt` work; scratch buffers never do, so the server does not start with Emacs. `kittymacs-suggestions-excluded-files` is checked before the mode turns on, because the mode, not a request, sends the buffer; `SPC a c` is a kittymacs command rather than `copilot-complete` for the same reason, since `copilot-complete` works without the mode.
- **The server comes from the flake's modules, opt-in.** Both modules install `copilot-language-server` when `programs.kittymacs.suggestions.enable` is on, from `suggestions.package` (default the host's `pkgs.copilot-language-server`; nixos-26.05 has 1.495, and next edits need 1.434). It is off by default and not in `nix/tools.nix`, because nixpkgs marks it unfree and the tool list would make every user of the flake allow an unfree package; a host that turns it on allows that one package. Installing it turns nothing on in Emacs. copilot.el finds it on `PATH`; without Nix, `copilot-install-server` puts it under `var/cache/copilot/`. `copilot-lsp-server-version` stays nil, so the pinned server is used without a version warning. A missing server is a message once per buffer, never a warning, and copilot.el loads only when a buffer turns suggestions on.
- **Ghost text in Insert state only.** copilot.el's default trigger predicate is `evil-insert-state-p`, which it counts as passed when undefined, so in Meow it would ask after every Normal-state command; `kittymacs-suggestions-typing-p` asks in Meow's Insert state, or where Meow is off. Next edits are not limited by state, since a Normal-state edit is an edit. Neither Meow's Normal nor its Insert map binds `TAB` or `C-g`, so next edits' minor-mode keys reach them in both.
- **Corfu's popup goes first.** Ghost text's `TAB` is a `keymap` overlay property, which outranks Corfu's map in `minor-mode-overriding-map-alist`, so with both on screen `TAB` would take the ghost text. Ghost text is not drawn while `completion-in-region-mode` is on, and is cleared when the popup opens over it.
- **copilot.el's indentation warning is off.** For a mode it has no indentation entry for, it uses `tab-width` and says so in a `*Warnings*` window; the fallback is right and the window is noise.

### Nix

- **Nix installs what surrounds the configuration, and the packages it loads, never the configuration.** `flake.nix` exposes a nix-darwin module, a home-manager module, a `tools` environment and a dev shell, all drawing from one list in `nix/tools.nix`. The configuration keeps `private.el` beside the modules and its state under `var/`, so it must be a writable clone; the home-manager module links it to `~/.config/emacs` through an out-of-store symlink. `x86_64-darwin` is not in the flake's systems, because nixpkgs-unstable dropped it.
- **Nix can build the declared Emacs packages into the Emacs it installs; by default it does not.** `nix/packages.nix` reads every `:ensure t` package from `nix/features.json`, so the catalogue is the one list, and wraps the Emacs with `emacs.pkgs.withPackages`, the package set of that Emacs's own nixpkgs, so the packages are built against it even when a host takes Emacs from a second nixpkgs. Both modules do this under `packagesFromNix`, and the flake exports it as `packages.<system>.with-packages`. The option is off by default: Hydra does not build nixpkgs' Emacs package sets, so no binary cache carries them, and every flake update made each machine fetch every source and compile every package, with one unreachable source host stopping the whole switch (a Mac's Home Manager switch did, on `ws-butler`). The archives fail one package at startup instead. When it is on, the configuration does not know: `:ensure t` sees the packages on `package-directory-list` as installed and fetches nothing. The flake's lock therefore pins the packages as it pins Emacs, and a start needs no archive. `copilot` (unfree, like its server) and `consult-ghostel` (not in nixpkgs) are left to the archives; `tests/kittymacs-startup-tests.el` holds the list and the declarations equal, with those two as the only exceptions. The cost is that `package-upgrade-all` no longer moves these packages; `nix flake update` does.
- **A Nix host chooses features with options, and Elisp still decides.** `programs.kittymacs` in every module has `profile`, `features.<name>.enable` generated from `nix/features.json`, `settings`, `hostFiles.<name>` and `extraPackages`. The home-manager module renders them to `~/.config/kittymacs/conf.d/10-nix.el` and the system modules to `/etc/kittymacs/conf.d/10-nix.el`, an ordinary host file either way, so `private.el` still wins and `kittymacs-features-resolve` remains the one answer. That file is a link into the store holding only settings; the configuration stays a writable checkout. With no option set the module writes nothing, and a host's generation keeps its store path. `nixpkgs` stays the only input, and the check's Home Manager lives in a flake of its own, `nix/selection-check`. (`literate/90-nix.org`)
- **`enable` has three values.** Null means no opinion, true adds to `kittymacs-features`, and false adds to `kittymacs-features-excluded`. Two values could not tell "off" from "leave this to the profile", so every host would have excluded every feature.
- **A typo fails at evaluation, while Elisp only warns.** The options exist only for the catalogue's names, so the module system rejects any other and names it, where a mistake is cheapest. Elisp keeps its warning, because a checkout and the flake that wrote the file can drift apart.
- **`packagesFromNix` builds only the chosen features, and all of them when a host chose none.** `nix/selection.nix` repeats the four steps of `kittymacs-features--compute`, because evaluation needs the package list, and `just nix-selection` holds the two equal on real starts. With no `profile` it starts from `full`, whatever `kittymacs-default-profile` says: it cannot see the rule for a machine with no choice, and too many packages cost only build time. It cannot see `private.el`, and what that adds installs from the archives. The list keeps its old order, sorted with hyphens ignored, because order is part of the derivation and a host that chose nothing must not rebuild.
- **No Emacs package's source is a clone of a whole ELPA repository.** MELPA builds a package that moved to GNU or NonGNU ELPA from that ELPA's Git repository on Savannah, which holds every package's history; nixpkgs fetches it whole, slowly, from a host that is often unreachable, and it slowed CI and every machine's build. Such a package comes from `elpaPackages` or `nongnuPackages`, ELPA's own release tarball (today `ws-butler`, bound in a `let` in `nix/packages.nix`), and `just sources`, run by `just eval` on unstable and on stable, fails if any derivation behind the package build, dependencies included, fetches from `savannah.gnu.org/git/elpa`. MELPA snapshots are kept for every other package: moving the thirty that ELPA also carries to its releases would change their versions without fixing anything.
- **The daemon gives up after three failed starts.** Home Manager's unit restarts on failure without limit; the module adds `StartLimitBurst=3` in 120 seconds and `RestartSec=10`, so a configuration that cannot start shows as `failed` instead of looping at ten seconds of CPU a try. launchd has no equivalent limit and only throttles.
- **The home-manager module clones a pinned revision, once.** When `source` is missing, activation fetches exactly `revision`, which defaults to the kittymacs revision the host's `flake.lock` records, from `repository`, and moves it into place only once `HEAD` is that commit. A failed clone warns and lets the rest of the activation run, since home-manager can run at boot before the network is up; the next activation tries again. After that the checkout is user state: a later activation that finds another commit prints a notice and changes nothing. `daemon` turns on home-manager's `services.emacs` (systemd on Linux, launchd on macOS); the nix-darwin module keeps its own `daemon`, and a Mac should use one of the two. **The daemon names its init directory rather than letting Emacs find one:** `initDirectory`, default the link the module creates, becomes `--init-directory` in the service, because Emacs reads `~/.config/emacs` only when no `~/.emacs.d` exists and an empty one is enough to win. Without the flag a directory an earlier install left behind makes every `emacsclient` frame a stock Emacs with nothing anywhere saying why, and the configuration-less daemon then writes an `~/.emacs.d` itself, so the state repairs nothing and sustains itself. The nix-darwin module's `daemon` is left alone: it installs Emacs system-wide and names no checkout, so it has no directory to point at.
- **nix-on-droid is a second device, not a layer under the Android port.** A Nix store path exists only inside nix-on-droid's PRoot, so the Android port could not execute anything installed there; the two applications are also different users, and Android 10 forbids executing another application's files. nix-on-droid consumes home-manager modules, so `homeManagerModules.default` is the whole integration; `installFonts` is separate from `installPackages` because a console-only Emacs has no use for the icon font.
- **nix-darwin and NixOS share one module.** Both install into a system the same way, so `nix/system-module.nix` serves both, and `flake.nix` gives it only the module's name and a note on its Emacs builds. Neither clones anything, because a system module has no user to clone for. (`literate/90-nix.org`)
- **An Emacs older than 31 fails evaluation only where the module uses it.** `init.el` would refuse it at every start, further from the cause, so `selection.assertions` refuses it first and names the `package` option. The guard is `usesPackage`: a home with `installPackages = false` and no daemon, or a `backend.enable` host, reads no Emacs from the module, so a stable nixpkgs says nothing about it. A home that installs the default on a release with no Emacs 31 does now fail where it used to evaluate, and start with an error. The templates set `package` from `kittymacs.packages`, so such a host drops one `follows`. (`literate/90-nix.org`)
- **A selection that contradicts itself fails evaluation, and Elisp still only warns.** `selection.assertions` refuses `false` on a feature the `minimal` profile keeps, and `true` on a feature whose dependency, direct or further down, is `false`, each naming its options from `nix/features.json`. A mistake in a host's own file costs least there. Elisp keeps its warnings for hand-written settings, because a checkout can drift from the flake. Excluding a feature that others get only from the profile stays allowed: they drop quietly. (`literate/90-nix.org`)
- **`packages.minimal` and `packages.full` come from the catalogue, and each tool names its feature.** `selection.profileFeatures` answers from `nix/features.json`, and each entry in `nix/tools.nix` names the feature that needs it. `tools.programs` stays the whole list in its old order, and the modules go on installing it whatever a host selects, so no host loses a tool and none moves its store path. (`literate/90-nix.org`)
- **`packages.backend` and `backend.enable` are headless.** They hold `git`, `rg`, `fd`, `direnv`, `inotify-tools` on Linux and three language servers, with no Emacs, no fonts and no GUI, for a machine Emacs reaches from elsewhere. A project's own servers come through its `.envrc`, which keeps the set small. A check holds this by name, because evaluation cannot read a closure, and `just nix-backend-closure` reads the real one. (`literate/90-nix.org`)
- **The apps need a checkout and never make one.** `nix run` starts Emacs, runs onboarding or reports, and the configuration is never in the store, so each finds a checkout: `KITTYMACS_CHECKOUT`, this directory, then where Emacs itself would look. With none, it says what to clone and exits 2, since a command run to look at something should not create a directory in a home. `onboard` loads the checkout's own module, whose neighbours are that checkout's, rather than pointing the store's copy at its `private.el`, so what it offers is what that checkout can install. `doctor` has no tools on its own `PATH`, so what it finds is the person's. (`literate/90-nix.org`)
- **The flake's checks fail at evaluation.** CI does not build, so a check that ran in a builder would never run there. Each is a trivial derivation behind a claim Nix evaluates, and it covers what nixpkgs alone can test, a real NixOS evaluation included. Hosts that need Home Manager or nix-darwin are in flakes of their own, `nix/selection-check` and `nix/eval-matrix`, which keeps `nixpkgs` the only input here. (`literate/90-nix.org`)
- **CI evaluates every way of using the modules, on the lock and on stable.** `just nix-matrix` evaluates each host to what a switch would build, in a process of its own, and `just nix-templates` instantiates each template with `nix flake init` in an empty directory. On stable, `kittymacs/nixpkgs` stays on unstable, because that release has no Emacs 31, and a host with the default `package` must fail naming the option. (`literate/90-nix.org`)
- **The Windows backend template stops at the Linux side.** `templates.wsl-backend` is `backend.enable` with no Emacs and no checkout. The transport from Windows is not chosen yet, so nothing in it assumes one. (`literate/90-nix.org`)
- **CI evaluates, it does not build.** The example hosts are evaluated against the checkout with the `kittymacs` input overridden: the nix-darwin system needs a Mac to build, and nix-on-droid's activation needs `--impure`, so both checks read the package list the modules produce. The home-manager clone options are read with a `git+file` override, because a `path:` input has no revision to pin.

### Features

- **A host plugs in through a directory, not through hooks in this repository.** Every `*.el` file in `/etc/kittymacs/conf.d/`, then `~/.config/kittymacs/conf.d/`, loads in name order just before `private.el`, so a new integration needs no change here and the user still wins. A broken host file or `private.el` warns and startup carries on. (`literate/10-startup.org`)
- **Nothing that loads before those files declares a package.** They load too early to choose otherwise, so the defaults are built-ins only and their small packages live in `kittymacs-basics`, which loads right after. (`literate/26-basics.org`)
- **One catalogue says which packages make up which feature.** `lisp/kittymacs-catalogue.el` is a single `defconst`, so `emacs -Q` can read it before any package exists, and `tools/tangle.el` writes `nix/features.json` from it by reading, never evaluating, so Elisp, Nix and onboarding share one list. A profile of `minimal` is the default on a new machine, `full` is what a machine had before that default, and `optional` is what stays off even then. Tests hold the list to the code: each declared package appears once, in the feature of the module that declares it. The gates, the installer and onboarding all read it. (`literate/20-catalogue.org`)

- **Every feature can be off, and the default is `minimal`.** `kittymacs-profile` (`minimal` or `full`), `kittymacs-features` and `kittymacs-features-excluded` go in a host file or `private.el`, and `lisp/kittymacs-features.el` turns them and the catalogue into one answer that every gate asks through `kittymacs-feature-p`. Customize's file loads too late to set them. A dependency-free module rather than more of the catalogue, because the catalogue must stay one `defconst` for `tools/tangle.el` to read. (`literate/21-features.org`)
- **`kittymacs-profile` starts as nil, and `kittymacs-default-profile` says what nil means.** The rule that keeps a machine from shrinking (no choice, plus a sign of use, means `full` and a warning) has to tell a machine that chose `minimal` from one that never chose. One value could not say both.
- **A new installation gets `minimal`, and no machine shrinks unannounced.** Removing doom and icons changes how kittymacs looks, so a machine that wants them says `full` by name, and a new installation sees Modus. A real two-start run showed that the rule as first written defeated the default: it took any package for a sign of use, so a fresh clone's second start found the packages its first had installed, moved to `full` and installed everything. The fix is a stamp, `var/started-on-default`, written by a start that finds no choice and no sign, before the installer runs, and read before the signs. A stamp rather than comparing what is installed with what `minimal` needs, because a package added by hand or a feature selected later would then read as an older machine. The rule can only err towards `full`: a lost stamp costs a warning and some installs, never a feature. (`literate/21-features.org`)
- **An unknown feature warns and changes nothing.** A checkout and a host's settings drift apart, and ending startup there would leave no editor to fix it with. A selected feature that an exclusion or an unmet `:deps` rules out warns too; `:not-on` does not, because one `private.el` can serve several machines. Excluding a `minimal` feature warns and leaves it on, since they are the floor the rest stands on.
- **The older switches keep working by selecting features.** `kittymacs-language-packages`, `kittymacs-notebooks-jupyter`, `kittymacs-exwm`, `KITTYMACS_EXWM=1` and `kittymacs-terminal-ghostel` are read as part of the selection, because a machine may already set them and the installer has to see them before the modules that define them load.
- **A catalogue-driven step installs, before the modules load.** A compiled module drops `:ensure` at runtime, because `use-package-handler/:ensure` installs while it compiles and leaves nothing to run later, so `:ensure` alone could not install a later opt-in. `:ensure t` stays on each declaration, which a source load still reads and `nix/packages.nix` is checked against. The step leaves `:vc` packages to their declarations, listed by the catalogue's `:vc`, so they clone as before. A failed install is a warning, remembered so the declaration that follows neither retries nor warns again.
- **A chapter that equals a feature is gated in `init.el`; a mixed one gates inside, with `when`.** Treemacs, the dashboard, Org extras, Org-roam, reading, notebooks, agents and suggestions load only when their feature is on. In mixed chapters a `when` surrounds a package and its keys, because `:if` does not stop `:ensure`. A test reads every declaration and fails on an optional package its feature cannot stop.
- **The terminal and EXWM chapters always load, though each is one feature.** `SPC o e` and `SPC o p` fall back to Eshell where there is no terminal, and `kittymacs-wm-keys` is public on any machine. So they gate inside: `kittymacs-terminal-ghostel` now follows the `terminal` feature, and every key needing ghostel sits behind it. On Android and anywhere else without the feature, `SPC o E`, `SPC o m`, `SPC m t` and `SPC m T` are now unbound rather than dead.
- **An empty group leaves the tree at the end of startup.** Every group is attached by the leader chapter and only an empty one is detached, at depth 100 of `after-init-hook`, so the order of a full tree cannot change; attaching a group when something first binds into it would have reordered `where-is-internal`. `SPC u` stays under `full`, empty or not, because that profile's tree must not change, and leaves under any other profile.
- **A nil definition leaves a key out of a `SPC m` menu.** So a menu names an optional command beside its neighbours, and a menu with nothing left is no menu at all. Without `help-extras`, `SPC h k` and its five neighbours run Emacs's own describe commands, so the keys stay.
- **Structural editing is a list of modes, not a fixed hook.** `kittymacs-structural-editing-modes` defaults to the modes the hook had, because it varies between people and between languages for one person. (`literate/72-programming.org`)
- **Onboarding runs under `emacs -nw -Q`, in Elisp, with no packages.** It has to work with nothing installed, on the machine that is deciding what to install. So `lisp/kittymacs-onboard.el` uses built-in libraries, finds its neighbours through `load-file-name`, and has no rule of its own about features: it calls `kittymacs-features--compute` and shows the catalogue, and the same selection gives the same answer at startup. (`literate/22-onboarding.org`)
- **Onboarding owns a marked block in `private.el`, and nothing else.** `private.el` is a person's file, so only the lines between two markers change, and everything outside them goes back byte for byte, with the file's mode. It reads the file as bytes, checks the new text with `read`, keeps `private.el~`, writes through a symbolic link to the real file, and renames atomically in that file's directory. It refuses rather than guesses, with a message and no change, when the file does not read as Lisp, when the markers are unbalanced, repeated, reversed or inside a form, or when the target cannot be written, such as a path in the Nix store. (`literate/22-onboarding.org`)
- **Onboarding reads settings and never runs them.** `10-nix.el` and `private.el` may do anything when loaded, and asking a question must not run them. A value only running could tell is named on the first screen, and a setting after the block, which beats it, is named on the last and left alone. The block always names all three selection options, because `setopt` replaces what a host file set rather than adding to it, and holds only the differences from the profile, so changing profile leaves nothing behind. (`literate/22-onboarding.org`)
- **Structural editing is asked by language, with no answer preselected.** The option's default would decide for a person who was never asked, so the screen waits for an answer on each line, and says that no to every line leaves Puni installed and on in no buffer. An answer already in a setting on this machine does show, because someone gave it. (`literate/22-onboarding.org`)
- **A start never loads onboarding.** The maintenance chapter holds an `autoload`, `SPC C o`, and a hint from `emacs-startup-hook`, so the module costs a start nothing, and a verifier check fails if a start loads it. The hint is a `message`, shown only while `kittymacs-profile`, `kittymacs-features` and `kittymacs-features-excluded` are all unset, and it starts nothing, because a first start should not begin with a program a person did not ask for. (`literate/80-maintenance.org`)

### CI

- **`flake.lock` updates itself each week.** Dependabot opens the pull request and CI's last job merges it once the `tangle`, `startup`, `features` and `nix` jobs pass, because bumping by hand was tedious and a bump changes no code here. A job with `needs:` rather than GitHub's auto-merge, so `main` needs no required checks or bypass rules, and renaming a job cannot silently remove the condition. It runs on a schedule rather than on each commit, since a bump is itself a commit to `main`. Only Nix bumps merge themselves: a new version of an action runs with this repository's permissions, so a person still reviews it. CI evaluates and does not build, so a merged bump can still fail on a machine, which `git revert` undoes.

- **Budgets may only fall, and a rise says why in its commit.** `just budget-check` compares `tests/budgets.eld`, with what `just size` counts in place of the recorded numbers, against the merge base, and a rise fails unless a `Budget-rise:` trailer since then names that budget. A trailer rather than a label or a file: it works locally and in CI, needs no repository setting, and stays beside the change. The counts `just size` makes depend only on this repository, so they are compared as measured, and a `flake.lock` bump cannot fail them, nor `merge-flake-bump` with them. The counts from a start move with the Emacs build and upstream packages, so they are compared as recorded, and a real rise in one shows only in the `bench` job's report: enforcing it would fail changes for a reason nobody could state. The check that would close that gap measures the merge base and the change in one job, with one Emacs and one package directory. Counts from a start are of the default profile, and times stay a report. (`literate/80-maintenance.org`)
- **Each profile has its own run and its own package cache.** Linux also installs `minimal` and runs `just test-minimal`, where the verifier fails on a package too many or too few. Its cache has no `restore-keys`, so leftovers cannot hide a removal, and it skips `just compile`, which is the same code and which runs a `:vc` declaration whatever gate surrounds it.
- **Each feature is switched for real, in a job that gates a merge.** `just test-features` starts Emacs once per feature, off in turn from `full` and on in turn from `minimal`, activating only what each selection needs through `package-load-list`. One directory stands in for a separate one per selection, so this stays cheap enough for every pull request, and `merge-flake-bump` needs it, since a bump can break one selection and no other.
- **One startup job, every system.** A matrix runs the fresh install, a byte-compilation of every module, the package suites and the verifier on Linux with Emacs 31.1, and informationally on macOS and Windows. Every step is written once in bash. The setup actions are pinned to commits and Dependabot proposes updates; Windows takes GNU's own `emacs-31.1.zip` directly, because setup-emacs-windows names every release after 30.2 with an `-x86_64` suffix that GNU's 31.1 zip does not have. The byte-compile step fails on errors only; its warnings are mostly about functions a module calls without loading them.
- **CI refreshes archive metadata after restoring the package cache**, with a non-interactive call because Emacs 31 refreshes asynchronously when the command is called interactively: cached MELPA metadata can name tarballs the archive has since replaced. Where the `linked-notes` feature is on, the install step requires org-roam explicitly, so a failed installation stops there instead of cascading into the graph tests. A weekly run skips the cache.
- **The flake is evaluated on stable as well as unstable.** A host that makes kittymacs follow its nixpkgs evaluates it on that release, so `just eval` runs `nix flake check` a second time with `nixpkgs` overridden to the justfile's `stable` (nixos-26.05). Checking only this flake's own unstable pin let `nerd-fonts.googlesanscode`, which 26.05 lacks, reach hosts on that release; `packages.tools` holds the fonts and programs, so the check forces every attribute a host would. `stable` moves with each release.

- **Startup cost is measured from outside, and reported before it is enforced.** `tools/bench.el` starts Emacs under a pty, without `tmux`, `hyperfine` or any other tool, and counts from before the process starts rather than from `before-init-time`. Times are compared with `emacs -Q` in the same job because runners differ; only exact counts can hold a budget, in `tests/budgets.eld`. CPU after a settling period, and the first file and key, are timed so that moving work behind a timer does not read as an improvement. (`literate/80-maintenance.org`)

## 5. Verification

From the repository root, through the `justfile`:

```sh
just check          # tangle-check, doc-test, and the tangle, startup, platform and Tree-sitter tests: no packages
just install        # start init.el in batch, installing what this machine's profile needs into var/elpa
just compile        # byte-compile lisp/*.el, under full
just test-packages  # leader, Org-roam and remote tests, and the verifier, under full: KITTYMACS_TEST_PROFILE=full just install
just test-minimal   # the same on a directory with the minimal profile alone: KITTYMACS_TEST_PROFILE=minimal just install
just test-features  # a real start per feature, off and on: KITTYMACS_TEST_PROFILE=every just install
just test-quickstart  # the verifier, starting from a quickstart file it writes first
just budget-check   # no budget rose against the merge base without a stated reason
just nix-check      # deadnix, statix, nixfmt; nix flake check; both example hosts evaluate; the selection options reach a real start; the matrix and every template evaluate, on the lock and on stable
```

`.github/workflows/ci.yml` runs the same recipes on every push and pull request: `just check` on Emacs 31.1; then, on Emacs 31.1 on Linux and informationally on macOS and Windows, `just install`, `just compile` and `just test-packages` on a fresh clone. A Nix job runs `just nix-check` inside `nix develop`, which starts Emacs from real Home Manager hosts' generated files, and checks the home-manager module's clone options; a weekly run skips the package cache, and the cache key carries a number that is raised when a package changes source, since a restored directory keeps whatever it holds.

The verifier starts the real configuration in an isolated copy with installation forbidden, in the order of a real startup (`after-init-time` nil during init, then `after-init-hook` and `delayed-warnings-hook`), and prints `KITTYMACS-VERIFY` with its result. It asserts: no warning is displayed; `private.el` loads once and its overrides survive (top-level and `after-init-hook` ones, including one that `tabspaces-mode` reads as it turns on); `custom.el` loads from `var/etc` and wins over the chapters; every `lisp/kittymacs-*.el` module is loaded; every key in the `SPC` tree runs a command; `ghostel` and `consult-ghostel` are MELPA's packages, not Git checkouts, and loading ghostel and Consult turns on `consult-ghostel-mode`; `SPC` is `kittymacs-leader-map` in both Meow state maps; `SPC l e` is `eglot` and `SPC s l` is `vertico-repeat`; Org-roam neither syncs nor opens a database at startup, and its prompt shows tags; `SPC s Q` lists exactly a tagged heading, `SPC m g` runs its query again, and `SPC` on a super-agenda group header is the leader; the dashboard's two buttons open the guide and the cheat sheet; theme toggling never stacks themes; every cheat-sheet `SPC` row resolves to its command; and emacs-jupyter is neither enabled nor loaded by default.

Not covered by CI, for the user to check on the real host:

- A graphical startup and the frame tests (`M-x ert RET ^kittymacs-frames- RET` after loading `tests/kittymacs-frames-tests.el`).
- macOS on a real Mac: the modifier keys, the Trash, the title bar and the Dock-launched `PATH`. The platform tests cover the branches with `system-type` bound to `darwin`, the informational macOS job covers batch startup, and the nix-darwin example is evaluated but not built.
- The home-manager activation itself: CI evaluates the clone script but never runs it.
- EXWM in a real X session: the Hyper key, the key table's actions, the scratchpad and the takeover of the daemon's server. A batch test resolved every key in the table to an action; nothing in CI starts an X server.
- A real ssh host: a real login, `ControlMaster`, a real network dying, and a backend's direct processes over `ssh`. The remote tests run Tramp's own code, but through a shell on the same machine.
- A remote connection hung in a graphical session: the tests call each timer's function under a limit, rather than leaving the command loop to run it, and they cannot press a key during `while-no-input`.
- Android on a real device. The platform tests cover every branch with `system-type` bound to `android`, and no CI runner is an Android telephone. Unverified, in rough order of how likely they are to want adjusting: whether a paired Termux's `bash` starts cleanly through the executable loader; whether `set-text-conversion-style` on each Meow state transition is quick enough with a particular on-screen keyboard (`kittymacs-android-modal-text-conversion` exists for that); whether the port in use has dynamic module support; and how the default font size reads at phone density. `nix-on-droid switch` is evaluated but not applied to a device. The virtual machine backend is documented from the Terminal app's behaviour, not tried end to end: the port forwarding prompt, which home directory the port's `ssh` reads, and whether Android stops the machine in the background.

## 7. Extending

- **A key:** `(keymap-set kittymacs-leader-map "u x" #'my-command)` in `private.el`, or a group in `41-leader.org`. Labels: `(cons "label" #'command)`. Project keys go in `kittymacs-project-map`, for example `(keymap-set kittymacs-project-map "j" #'my-project-command)`, which leaves `C-x p` alone.
- **A mode menu:** `(kittymacs-define-localleader 'python-mode "r" (cons "run" #'python-shell-send-buffer))` next to the package.
- **A package:** a chapter named `literate/NN-name.org` with a `use-package … :ensure t` block, a Meow section and a `require` in the startup chapter. The builder finds the chapter by its name; there is nothing else to register.
- **Something personal:** the `kittymacs-personal` overlay, or `private.el` for a single machine, never a branch of this repository.
