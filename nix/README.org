#+TITLE: Deploying kittymacs with Nix

The repository is a flake. It does not put the configuration in the Nix
store: the configuration installs its Emacs Lisp packages under =var/= and
keeps =private.el= beside the modules, and both must stay writable. What the
flake provides is everything *around* the configuration: Emacs itself, every
program the chapters look for, and the icon font, so a fresh Mac needs one
=darwin-rebuild switch= and one =git clone=.

| Output | What it is |
|---+---|
| =darwinModules.default= | nix-darwin module: =programs.kittymacs.enable= installs Emacs, the tools and the font system-wide |
| =homeManagerModules.default= | home-manager module: clones a checkout, links it to =~/.config/emacs=; can install the tools and run the daemon per user |
| =packages.<system>.default= | the Emacs the modules install (=pkgs.emacs=, 31.1 at the time of writing) |
| =packages.<system>.tools= | one environment with every tool, for =nix profile install= |
| =devShells.<system>.default= | Emacs plus the tools, for running the batch checks |

The tools are listed once, in [[file:tools.nix][tools.nix]], each with the chapter that discovers
it: =git=, =ripgrep=, =fd=, =gnupg=, =hunspell= with an English dictionary,
and on macOS GNU =ls= as =gls= (Dired) and =trash= (the platform chapter).
Google Sans Code, the preferred editing font, is not in nixpkgs; the
platform font is used until it is installed by hand.

* nix-darwin

Add the flake as an input and import the module:

#+begin_src nix
{
  inputs.kittymacs.url = "github:Mihir-Null/kittymacs";
  inputs.kittymacs.inputs.nixpkgs.follows = "nixpkgs";

  outputs = { nix-darwin, kittymacs, ... }: {
    darwinConfigurations.mac = nix-darwin.lib.darwinSystem {
      modules = [
        kittymacs.darwinModules.default
        { programs.kittymacs.enable = true; }
      ];
    };
  };
}
#+end_src

Then clone the configuration somewhere writable, or let [[*home-manager][the home-manager
module]] clone it for you. Emacs looks in =~/.config/emacs= when =~/.emacs.d=
does not exist:

#+begin_src sh
git clone https://github.com/Mihir-Null/kittymacs.git ~/.config/emacs
#+end_src

Options under =programs.kittymacs=:

- =package= :: the Emacs to install. Default =pkgs.emacs=, the Cocoa build;
  =pkgs.emacs-macport= is the Mitsuharu port. kittymacs needs 30.1 or later.
- =daemon= :: start the Emacs server at login through launchd, so
  =emacsclient= opens files as frames of one running Emacs. Off by default;
  the configuration starts a server itself whenever it has a display. The
  home-manager module has the same option; turn on one of them, not both.

* home-manager

The home-manager module looks after the checkout itself: it clones it on the
first switch, links it to =~/.config/emacs=, and keeps its hands off it after
that. The link points outside the store on purpose. It works with
nix-darwin's home-manager module, with a standalone home-manager on any
Linux, and on nix-on-droid.

#+begin_src nix
home-manager.users.me = {
  imports = [ kittymacs.homeManagerModules.default ];
  programs.kittymacs = {
    enable = true;
    source = "/Users/me/src/kittymacs";  # where the writable clone lives
    installPackages = false;           # nix-darwin already installed them
  };
};
#+end_src

Options under =programs.kittymacs=:

- =source= :: where the checkout lives. =~/.config/emacs= becomes a link to
  it. Leave it null to clone and place the configuration by hand; then
  nothing is linked or cloned, and =repository= and =revision= have no
  effect. The other options still install Emacs, the tools and the font,
  and run the daemon.
- =repository= :: the Git URL to clone from. Default
  =https://github.com/Mihir-Null/kittymacs.git=; point it at a fork to start
  from your own copy.
- =revision= :: the commit to check out. It defaults to the revision of the
  kittymacs flake your host locked, so =flake.lock= decides what a new
  machine starts from. The pin applies to the *first clone only*. Activation
  clones when nothing is at =source=: it fetches just that commit into a
  temporary directory beside =source=, checks that =HEAD= is that commit,
  and moves the result into place, with =origin= set to =repository=. From
  then on the checkout is yours to pull, commit in and switch branches in,
  so when a later activation finds it at another commit it prints one line
  saying so and changes nothing. Bumping the input in =flake.lock= therefore
  never rewrites your configuration. If the clone fails (no network yet, as
  on a NixOS machine's first boot, or a commit the repository does not
  have), activation prints a warning and carries on with the rest of your
  home configuration, and the next activation tries again; until then
  =~/.config/emacs= points at nothing. A =source= that is a symbolic link to
  nothing (an unmounted disk, say) stops activation instead of being cloned
  over. The first clone is shallow and detached; =git fetch --unshallow
  origin= followed by =git switch main= turns it into an ordinary checkout.
  Set =revision= to null to never clone.
- =daemon= :: run Emacs as a server for this user, through home-manager's
  =services.emacs= with =package=: a systemd user service on Linux and a
  launchd agent on macOS, plus an "Emacs Client" desktop entry on Linux.
  Off by default. Where no systemd user session runs (nix-on-droid, WSL
  without systemd) the service file is written but nothing starts it. On a
  Mac use this option or the nix-darwin module's, not both.
- =package= :: the Emacs to install and, with =daemon=, to run. Default
  =pkgs.emacs=.
- =installPackages= :: install Emacs and the tools into the user profile.
  Turn it off when nix-darwin already installs them, as above; without
  nix-darwin, leave it on and the same tools go into the user profile.
- =installFonts= :: follows =installPackages= and can be turned off on its
  own for a terminal Emacs, which has no use for the icon font.

[[file:example/flake.nix][example/flake.nix]] is a complete host with both modules.

* nix-on-droid

nix-on-droid runs Nix on Android, and it consumes home-manager modules, so
the module above is the whole integration: no Android-specific Nix code
exists in this repository. [[file:example-nix-on-droid/flake.nix][example-nix-on-droid/flake.nix]] is a complete
device; =nix-on-droid switch --flake .#default --impure= applies it. Use
=pkgs.emacs-pgtk=, which serves Wayland and X11 both, with [[https://github.com/termux/termux-x11][Termux:X11]] for a
display; or =pkgs.emacs-nox= with =installFonts = false= to stay in the
console.

The =--impure= is nix-on-droid's own requirement rather than anything this
repository does. proot-static cannot be built on the device, so nix-on-droid
hardcodes the store path of a pre-built one and reaches it through
=builtins.storePath=, which pure evaluation forbids; every flake-based
nix-on-droid build needs the flag. CI therefore checks the package list the
module produces rather than the activation script, which is the same check
the nix-darwin example gets and stays inside pure evaluation.

Inside nix-on-droid, =system-type= is =gnu/linux=. This is an ordinary
GNU/Linux Emacs that happens to be on a telephone, so *none* of the
configuration's Android branches apply and nothing degrades: every package
works, ghostel included. What you pay is the PRoot, which is slow, and the
need for a display server to be graphical.

One thing to set in =private.el=: this repository's frame policy hands
window arrangement to a desktop window manager, and Termux:X11 does not have
one unless you install one. Either run a window manager, or turn the policy
off:

#+begin_src emacs-lisp
(setq kittymacs-frames-only nil)
#+end_src

** It cannot feed the Android port of Emacs

The appealing idea — run the Android application and let nix-on-droid supply
=git=, =ripgrep= and the language servers — does not work, and it is worth
knowing why rather than trying it. Three separate things stop it, any one of
them sufficient:

1. =/nix= does not exist. nix-on-droid fakes it with PRoot; the store really
   lives inside the application's private directory. Every binary's ELF
   interpreter is baked in as =/nix/store/…-glibc/lib/ld-linux-aarch64.so.1=,
   which resolves only inside that PRoot, so the kernel cannot start the
   program at all from outside it.
2. The two applications are different users. nix-on-droid is =com.termux.nix=;
   the Emacs builds that share a user ID share it with =com.termux=.
3. Android 10 and later forbid executing anything in another application's
   data directory regardless.

For the Android port, pair it with Termux; [[file:../README.md][the README]] has that path. The
two are alternatives, not layers.

* Developing

=nix develop= in the repository gives a shell with Emacs and the tools; the
batch checks from [[file:../AGENTS.md][AGENTS.md]] run unchanged inside it. To evaluate the
example host against the checkout you are in, override its input:

#+begin_src sh
nix flake check --no-build
nix eval --no-write-lock-file --override-input kittymacs path:$PWD \
  --json ./nix/example#darwinConfigurations.example.config.environment.systemPackages \
  --apply 'ps: map (p: p.name) ps'
nix eval --no-write-lock-file --override-input kittymacs path:$PWD \
  --json ./nix/example-nix-on-droid#nixOnDroidConfigurations.default.config.home-manager.config.home.packages \
  --apply 'ps: map (p: p.name) ps'
nix eval --no-write-lock-file --override-input kittymacs "git+file://$PWD?shallow=1" \
  --json ./nix/example-nix-on-droid#nixOnDroidConfigurations.default.config.home-manager.config \
  --apply 'c: { inherit (c.programs.kittymacs) repository revision daemon;
              clones = builtins.isString c.home.activation.cloneKittymacs.data; }'
#+end_src

The last one reads the clone options as a device would see them. It
overrides the input with =git+file= rather than =path:= because a =path:=
input has no revision, and without one the module has nothing to pin and
defines no clone step; on a clean checkout, =revision= comes out as =git
rev-parse HEAD=.

CI runs all of them on Linux; building the nix-darwin example needs a Mac
and building the nix-on-droid one needs an =aarch64-linux= machine, so both
are evaluated rather than built. nixpkgs-unstable
dropped =x86_64-darwin= in 26.11, so an Intel Mac should point the flake's
=nixpkgs= input at the =nixpkgs-26.05-darwin= branch.

* What the configuration does on its own

The Nix module is a convenience; the configuration works with Homebrew or a
manual install too. On macOS the startup chapter puts the Nix profiles
(=/run/current-system/sw/bin=, the per-user profile, =~/.nix-profile/bin=)
and Homebrew on =exec-path= before anything runs, because an Emacs.app
started from the Dock inherits no shell =PATH=; the shells chapter then
imports the login shell's environment. The platform chapter's macOS section
explains the keys, the Trash and the title bar.
